# 安全工程 · 软件供应链

### 依赖、构建与软件供应链

- 依赖、基础制品和构建扩展必须来自受控来源并固定到不可变身份，浮动引用会破坏可重现性与审计。
- 引入依赖需评估维护状态、传递范围、安装行为、权限和替代成本，功能便利不能自动抵消新增攻击面。
- 不受信代码与受信构建必须隔离，外部变更不能接触签名材料、发布凭据或生产秘密。
- 最终制品应能够追溯到源码、依赖与构建环境，并具有可验证的组件清单、完整性和来源证明。
- 供应链验证必须绑定制品身份、来源身份和政策，存在签名或清单本身不能证明内容可信。
- 漏洞风险应结合实际版本、配置、可达性、攻击前提和补偿控制判断，通用等级不能替代适用性分析。

# 安全工程 · 检测、审计与事件响应

### 安全日志、检测与审计

- 认证、授权、特权操作、秘密访问、数据导出和安全策略变化应在权威决策点记录成功与拒绝。
- 审计事件必须包含可信时间、主体、动作、对象、租户、来源、结果和关联标识，同时禁止记录秘密与完整敏感载荷。
- 检测规则应从真实攻击路径反推所需信号组合、时间关系和盲区，单一静态阈值不能表达复杂入侵行为。
- 检测需要区分主体与资源基线，并通过聚合、抑制和升级控制噪声，避免无界事件逐条打断值守。
- 原始审计应防篡改、访问受限且独立保留，产生业务事件的同一权限不能静默删除或停采。
- 检测链必须通过受控事件从产生、采集、存储、判断到通知完整验证，并用攻击变体与正常高峰校准。

### 安全事件响应与取证

- 安全事件应按资产敏感性、攻击者活跃度、影响范围、持续时间和未知量分级，并保持单一指挥与清晰分工。
- 易失证据必须在破坏性恢复动作前保全，证据应记录来源、时间、采集者、完整性和传递过程。
- 遏制应优先缩小攻击面和信任范围，同时权衡业务影响与证据损失，不能以恢复可用性为唯一目标。
- 根除必须覆盖攻击入口、持久化、恶意制品、过宽权限和受损凭据，封禁单一来源不能消除根因。
- 恢复必须来自可信制品、配置、身份和密钥基线，并轮换所有可能受影响的信任材料。
- 受影响主体、数据、租户、地域和第三方范围需要区分已证实事实与未知项，以支持必要沟通和披露。
- 事件关闭必须以安全不变量复测、检测回放和稳定观察期证明信任已恢复，服务重新在线不能单独作为关闭依据。

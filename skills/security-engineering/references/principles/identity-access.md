# 安全工程 · 身份、会话与授权

### 身份认证、联合身份与多因素认证

- 认证强度必须与账户价值、动作风险和攻击者能力相称，高风险操作应要求近期且更强的身份凭据。
- 联合身份应采用成熟标准并完整验证签发方、接收方、有效期、请求关联和返回位置，不能只接受结构正确的声明。
- 本地密码必须使用专门设计的抗离线猜测机制并为每个凭据独立加盐，成本参数应结合当前运行能力定期复核。
- 多因素应来自相互独立的信任来源，并优先抵抗钓鱼与中间人攻击；弱恢复流程不能绕过较强的正常认证。
- 登录、注册、找回和验证码响应不得泄露账户是否存在，限制策略需同时考虑主体、来源和自动化滥用。
- 人类身份与工作负载身份必须分离，机器凭据应短期、定向且不可被其他服务或环境复用。
- 认证挑战、拒绝与恢复应让合法主体理解当前状态和可行下一步，同时不泄露账户、策略或验证细节；反复弹窗、模糊失败和人工绕过不能替代可恢复的安全交互。

### 会话、令牌与账户恢复

- 会话必须具备签发、轮换、续期、撤销和过期语义，身份提升与敏感资料变化后不能沿用原有会话强度。
- 会话凭据必须不可预测、最小暴露且适合客户端保护能力；不能把长期高价值秘密交给无法可靠保密的客户端环境。
- 令牌验证必须覆盖完整性、来源、接收方、时间、作用范围和绑定上下文，仅解析内容不能建立可信会话。
- 刷新与并发续期必须识别凭据重用和竞争，未知结果不能无限签发新的有效凭据。
- 退出、密码重置、账户停用、认证因子变化和风险事件应能使相关会话在业务要求内失效。
- 账户恢复凭据必须一次性、短期、限次且与目标账户绑定，恢复成功后应收敛旧会话并通知既有可信渠道。

### 授权、对象访问与租户隔离

- 授权模型应依据角色稳定性、主体与资源属性以及关系语义选择，任何模型都必须默认拒绝并在服务端可信路径执行。
- 决策必须同时包含主体、动作、具体对象、租户和必要上下文，只判断“已登录”或全局角色不足以保护对象。
- 列表、搜索、计数、聚合、导出、批处理和后台任务必须应用与详情访问相同的对象与租户约束。
- 租户上下文必须来自可信身份或服务端映射，不能由请求方提供的可变参数决定；缓存、消息和派生结果也必须携带相同作用域。
- 权限变化必须影响缓存、长会话与异步工作，防止旧决策在安全语义已经变化后继续生效。
- 特权能力应细分、限时并加强再认证与审计，无边界管理员身份不能成为常规业务路径。
- 客户端可见性控制不能替代服务端授权，数据取得后再过滤也不能修复已经发生的越权读取。

# 安全工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/security-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始安全相关工作前，读取已有事实。
- 当前权威优先于旧事实；两者冲突时，以当前代码、策略、配置和受控系统所共同确认的认知为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程或一次性结果。

## 核心记忆

### 信任边界与安全责任

- 记住产品的信任域、外部参与方、敏感数据流和跨域入口，以及每道边界由哪个组件或系统承担安全责任。
- 记住仍被产品接受的威胁边界、明确不受保护的表面和必须重新评估这些边界的变化。

### 身份、认证与会话

- 记住各类主体的身份来源、认证方式、账户生命周期和身份关联不变量。
- 记住会话的签发、绑定、续期、撤销与失效传播机制，以及高风险操作要求的身份强度。

### 授权与隔离

- 记住服务端权限模型、角色或能力的权威来源，以及对象、租户和环境隔离所依赖的稳定边界。
- 记住委托、服务身份和管理员能力的作用域，以及拒绝访问时必须保持的行为。

### 入口防护与外部通信

- 记住不可信输入进入解析、上传、执行或持久化前经过的约束，以及跨服务请求的来源验证和重放防护机制。
- 记住面向浏览器、客户端、回调和外部集成的安全边界，以及失败时不得绕过的保护。

### 秘密与密码学

- 记住秘密的来源、注入、轮换和撤销机制，哪些组件可以取得何类秘密，以及秘密不可用时的失败行为。
- 记住加密、签名和密钥管理的用途边界、算法或密钥来源的权威，以及历史数据所依赖的解密兼容关系。

### 隐私与数据生命周期

- 记住敏感数据类别在采集、存储、传输、日志、导出和删除各阶段的允许用途与最小化边界。
- 记住数据保留、删除传播、脱敏和审计所跨越的系统，以及无法自动覆盖的外部副本或备份边界。

### 供应链与运行时防护

- 记住依赖、构建来源和部署制品必须维持的来源关系，以及运行组件允许的权限、网络和文件系统边界。
- 记住第三方组件、插件和外部服务进入产品信任域的方式，以及它们失陷时的隔离范围。

### 检测、响应与漏洞处置

- 记住安全事件采用的审计身份、关联信号、保留与脱敏约束，以及哪些异常必须跨系统追踪。
- 记住遏制、凭据撤销、数据保护和恢复的责任边界，以及漏洞修复或风险例外不得突破的产品约束。

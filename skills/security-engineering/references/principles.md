# 安全工程能力准则

## 能力索引

1. 资产分类与威胁建模
2. 身份、认证与会话
3. 授权、资源作用域与租户隔离
4. 输入边界与 API 滥用防护
5. 秘密、密钥与密码学
6. 隐私与数据保护
7. 依赖、构建与供应链
8. 安全配置与纵深防御
9. 安全观测与事件准备
10. 漏洞证据与风险处置

## 1. 资产分类与威胁建模

**判断**：枚举资产、主体、入口、数据流、信任边界、管理面和外部依赖；按机密性、完整性、可用性、隐私与业务价值分级。威胁必须写清攻击者能力、前提、步骤、受影响资产、现有控制和剩余风险。

**产出**：资产/数据分类、攻击面、滥用场景、威胁模型、控制缺口、风险等级和重审触发。

**证据**：当前 Route、调用链、数据流、配置、部署边界、公开端口、第三方集成和脱敏复现。

信任边界拓扑由 `$software-architecture` 拥有；本技能拥有其上的威胁与控制政策。

## 2. 身份、认证与会话

**判断**：区分用户、服务、设备、租户与委托主体；验证凭据签发、校验、绑定、过期、轮换、撤销、登出、并发会话、固定与重放风险。认证失败必须默认拒绝且不泄露敏感差异。

**产出**：认证流程、会话/令牌生命周期、撤销传播、再认证条件、服务身份和失败行为。

**证据**：签发与校验代码、Cookie/令牌属性、会话存储、时钟边界、撤销测试、固定/重放测试和日志脱敏检查。

## 3. 授权、资源作用域与租户隔离

**判断**：每项高价值操作按“主体、动作、资源、作用域、上下文”裁定；资源所有权与租户必须从可信服务端事实解析。列表、详情、导出、批处理、后台作业和管理入口均要覆盖水平/垂直越权。

**产出**：授权矩阵、政策执行点、默认拒绝、委托/审批、租户隔离、拒绝错误和审计要求。

**证据**：服务端政策代码、资源加载顺序、正反权限测试、跨租户枚举、后台任务身份和审计事件。

前端隐藏、网关鉴权和“已登录”均不能替代资源级服务端授权。

## 4. 输入边界与 API 滥用防护

**判断**：对每个外部入口限制类型、长度、格式、业务范围、嵌套深度、文件内容、目标地址和资源消耗；分析注入、SSRF、路径穿越、反序列化、重放、枚举、批量放大和自动化滥用。

**产出**：校验与规范化顺序、允许列表、解析隔离、速率/配额、幂等、防重放、安全错误和资源预算。

**证据**：边界/模糊测试、恶意样本、并发滥用测试、网络出口策略、错误响应和资源指标。

## 5. 秘密、密钥与密码学

**判断**：确认秘密来源、用途、作用域、存储、注入、轮换、撤销和泄露处置；密码、数据加密、签名与传输安全使用成熟库、当前推荐参数和算法敏捷性。不得混淆编码、哈希、加密与签名。

**产出**：秘密清单、最小访问、密钥/证书生命周期、算法与参数、轮换兼容、失败关闭和应急撤销方案。

**证据**：秘密管理引用、配置扫描、库调用、证书链/协议检查、轮换演练和日志/制品泄露扫描。

生产轮换由 `$release-engineering` 执行；本技能不接触真实秘密内容。

## 6. 隐私与数据保护

**判断**：以用途、最小化、访问、保留、删除、导出、备份和日志链路追踪个人/敏感数据。开发、测试、分析和支持副本同样受约束；删除承诺须说明备份与派生数据边界。

**产出**：数据清单与流向、采集依据、最小字段、保留/删除、导出、脱敏、访问审计和泄露影响边界。

**证据**：Schema/DTO、日志、导出、备份、分析管道、删除测试、访问策略和脱敏样本。

数据库物理保留、脱敏和清除机制由 `$database-engineering` 落实。

## 7. 依赖、构建与供应链

**判断**：核验直接/传递依赖、来源、版本锁、完整性、维护状态、已知漏洞、构建脚本、制品签名和发布权限。漏洞是否适用须由可达性、配置与攻击前提判断。

**产出**：依赖风险清单、升级/替换决定、锁定与来源政策、构建隔离、SBOM/制品证明要求和例外期限。

**证据**：锁文件、依赖图、官方公告、可达性分析、构建配置、制品摘要与签名验证。

## 8. 安全配置与纵深防御

**判断**：检查默认账户、调试入口、CORS/CSRF、安全头、TLS、文件权限、网络出口、容器权限、管理面和错误信息。每层控制须说明它覆盖的独立故障，不能用重复配置冒充纵深。

**产出**：环境基线、默认关闭、最小权限、隔离、降权、错误披露和配置漂移要求。

**证据**：配置 Schema、部署清单、策略检查、运行探针、权限枚举和环境差异验证。

## 9. 安全观测与事件准备

**判断**：高价值操作和拒绝事件须可关联主体、对象、动作、结果与时间，同时避免记录凭据和非必要个人数据。告警要能区分攻击、误用和系统故障，并有明确处置动作。

**产出**：审计事件、关联标识、检测规则、告警阈值、证据保全、封禁/撤销入口和响应升级条件。

**证据**：结构化日志、审计存储、脱敏检查、检测回放、告警演练、访问控制和保留验证。

生产响应由 `$release-engineering` 或既有事件流程执行。

## 10. 漏洞证据与风险处置

**判断**：先在授权范围内复现，确认前提、可达路径、受影响版本/资源、影响、现有控制与稳定复现率。风险等级由业务影响、可利用性、暴露和检测/恢复能力共同决定。

**产出**：脱敏复现、根因、影响边界、风险等级、修复要求、临时缓解、重测场景、风险接受人和到期条件。

**证据**：最小复现、代码/配置根因、正反测试、扫描复核、修复前后对照和回归范围。

最终控制有效性由 `$quality-engineering` 证明；扫描器标签不能单独闭环。

## 常见误判

- 把认证当授权，把管理员、内网或前端隐藏当可信边界。
- 只验证正常输入，不限制资源消耗、枚举与批量滥用。
- 自创密码学、长期不轮换秘密或把令牌写入日志。
- 只做依赖扫描，不判断漏洞可达性与配置条件。
- 用合规勾选、CVSS 或扫描器严重度代替当前影响分析。
- 修复单个端点却遗漏同策略的列表、导出、后台任务和管理入口。
- 未获授权便扫描外部目标，或把真实攻击样本和用户数据写入制品。

# 安全工程

以资产、攻击者能力、信任边界和可复现证据裁定安全政策与控制。安全不是末尾扫描清单；每个关键控制都要有 Owner、拒绝行为、失败模式和验证办法。

## 唯一决策权

本技能是以下事项的唯一 Owner：

- 资产、数据敏感度和保护等级分类。
- 威胁模型、攻击面、滥用场景、风险等级、接受条件与修复优先级。
- 身份证明、认证流程、会话生命周期、令牌撤销与服务身份要求。
- 授权政策、资源作用域、租户隔离、委托与高价值操作的再认证/审批要求。
- 输入边界、API 滥用、速率/配额、安全错误和资源消耗控制要求。
- 秘密、密钥、证书、密码学算法与轮换撤销政策。
- 隐私最小化、用途、保留、删除、导出、日志脱敏与数据主体边界。
- 依赖和构建供应链、安全基线、安全观测、漏洞证据和风险处置标准。

安全可以阻止不满足政策或证据门槛的交付，但不独占实现代码与生产操作。

## 输入门禁

开始前确认：

- 资产、主体、用户角色、租户、数据流、入口、外部依赖、管理面和信任边界。
- `$product-management` 给出的业务政策、风险承受和合规承诺。
- `$software-architecture` 给出的边界、数据主权、身份传播责任和控制落点。
- 当前认证/授权/会话实现、数据存储、日志、秘密来源、依赖清单、部署配置和历史漏洞证据。
- 威胁假设、环境、目标版本、公开面、攻击者能力与本轮授权测试范围。

法规、合规、攻击面或风险承受未知时标记未知并索取权威依据，不编造结论。

## 专业能力

先查看 [安全工程能力准则](references/principles.md) 的能力索引，完整读取命中的能力段落。每项命中能力必须给出判断、产出与证据。

## 工作流程

1. 枚举资产、主体、入口、数据流、管理操作和信任边界，区分当前事实、推断和未知。
2. 建立滥用路径：攻击前提、步骤、受影响资产、现有控制、剩余风险和可观察信号。
3. 依据影响、可利用性、暴露和现有控制确定风险等级与处置优先级。
4. 裁定最小安全政策、控制位置、默认拒绝、失败行为、审计与恢复要求。
5. 为工程实现明确控制契约、禁止条件和可观察结果，并列出风险相称的验证场景；高风险结论须复现并保留脱敏证据。
6. 新证据改变威胁、控制有效性或风险等级时原位重审，不以扫描器标签替代分析。

## 交付物

- 资产/数据分类、信任边界、攻击面和威胁模型。
- 认证、会话、授权、租户、秘密、加密、隐私和供应链政策。
- 控制矩阵：威胁、控制位置、实现 Owner、拒绝/失败行为、观测与验证。
- 漏洞复现、影响范围、风险等级、修复要求、临时缓解、重测和风险接受条件。
- 安全日志、告警、事件响应入口和未验证边界。

## 专业边界

- `$software-architecture` 拥有信任边界拓扑、身份上下文传播责任和控制的系统落点；本技能拥有具体安全政策与风险裁决。
- `$backend-engineering` 实现服务端认证/授权、输入校验、安全错误、审计事件和外部集成防护；不得自行放宽政策。
- `$frontend-engineering` 实现安全交互、会话界面和客户端数据最小暴露；前端隐藏不能替代服务端授权。
- `$database-engineering` 落实数据库权限、加密、脱敏、保留和删除的物理机制；不得重新定义安全依据。
- `$quality-engineering` 最终以测试、扫描、复现与重测证据判定控制是否成立。
- `$release-engineering` 执行秘密轮换、证书切换、生产基线、应急发布和观察；本技能不直接操作生产。

## 终态事实候选

请求范围已形成可交付终态，并由风险相称的测试、扫描、脱敏复现或配置证据验证时，依据 [安全事实规则](references/memory.md) 检查本次实际核验范围，对命中主题给出 `ADD`、`UPDATE`、`DELETE` 或 `NO_CHANGE` 语义裁决。只有事实确有新增、改变或消失才形成写入候选；`NO_CHANGE` 不触碰文件。

候选须包含唯一 `product-id`、稳定 locator、主题合并键、四态动作、四栏正文或删除依据及脱敏当前证据。本技能不自行写入 `security-engineering.md`；验证失败、证据不足或尚未形成终态时只报告 `DEFERRED`，漏洞利用细节、秘密和用户数据不得入册。

## 禁区

- 不把前端隐藏、内网位置、调用方声明、弱默认值或“管理员可信”当作授权。
- 不以 OWASP 名称、CVSS、扫描器严重度或合规清单代替当前攻击路径和影响证据。
- 不自创密码学算法，不在代码、日志、事实册或测试制品中保存真实秘密与个人数据。
- 不替 `$software-architecture` 划系统边界，不替工程技能实现所有代码，不替 `$quality-engineering` 宣告控制有效。
- 不直接扫描未授权外部目标，不执行生产密钥轮换、封禁、数据删除或风险接受。
- 不以“先上线再补安全”豁免高价值状态、租户隔离、秘密和数据泄露风险。

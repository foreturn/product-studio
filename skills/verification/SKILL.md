# 独立验证

从用户原始意图、当前契约和完整差异建立独立验收标准，不以实现现状倒推成功。只有每项适用必需标准都获得匹配当前修订、环境、输入与断言的直接证据，才能判定通过。

## 输入门禁

- 明确 Git 仓库根、当前产品与稳定的 `product-id`、相关项目根、仓库指令、待验收修订或制品、完整差异、目标环境、身份、数据和已知既有失败。
- 读取相关产品、架构、后端、前端和验证当前事实，以及存在时的 `docs/product-studio/<product-id>/verification.md` 中与本次检查、覆盖和约束有关的总结性验证事实。
- 固定用户原始意图、范围、业务不变量、架构决定、接口与数据契约、迁移约束和适用验收标准；用户结果、业务闭环或体验语义不足时交给 `$design`，系统边界、所有权、共享不变量或质量约束不足时交给 `$architecture`，具体接口、Schema 或实现契约不足时交给 `$backend`，不得从当前实现或测试名称反推要求。
- 任务已经由 `$router` 编排时，沿用其跨技能顺序与验证门禁；单一实现技能直交的常规验收无需补唤 `$router`。验证限于本地、测试夹具或明确隔离的测试环境，结论不得外推到未取证环境。

## 专业能力

先查看 [独立验收专业准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及整体验收、证据裁决或风险复核时，再读“常见误判”。

## 验证流程

按风险与改动面裁剪证据层级；未执行但适用的必需项报告为失败或阻塞，不适用分支写明判据。

1. 将原始意图、当前范围、架构与实现契约和验收标准转为稳定测试用例或检查项，写明来源、输入、动作、期望结果、禁止结果、环境和失效条件。
2. 检查完整差异、调用链、共享依赖、消费者、配置、Schema 和数据影响，按严重度、可能性、可发现性、可逆性、权限及外部副作用排序风险。
3. 为每项要求选择成本最低且能直接证明它的证据层级；高层证明用户结果和协作，低层证明规则与组合，不能用测试数量代替断言对应。
4. 先运行可快速阻断的格式、静态、类型、单元和聚焦契约检查，再按风险执行真实数据库、浏览器、集成、端到端、迁移、并发或故障验证。
5. 前端行为受影响时，从真实入口操作核心旅程和高价值失败或恢复路径，并绑定身份、数据、浏览器、视口、页面状态、控制台、网络和修订；纯视觉改动聚焦其真实状态和不得破坏的交互。
6. 后端、接口或数据受影响时，逐项核对请求响应、错误、权限、数据范围、事务、幂等、并发、消息、依赖故障、Schema、迁移兼容和最终数据不变量，只执行本次风险涉及的子集。
7. Schema、配置、依赖、共享组件或历史行为变化时，才进入迁移或回归分支，固定前后修订、配置、数据与环境，检查适用的新旧组合、回填、重入、暂停、恢复和清理条件。
8. 对失败记录最小复现、预期、实际、首个可行动错误、影响范围与归因证据；区分本次回归、既有问题、环境阻塞、证据缺失和归因未定。
9. 对每项检查给出通过、失败、阻塞或不适用；总体优先级为失败高于阻塞、阻塞高于通过，仅当所有适用必需项都有当前直接证据且通过时总体通过。
10. 获准写入的编码、验收或明确记忆维护任务完成后执行记忆同步检查；以本次实际核验的当前代码与证据为本轮增量范围，只同步最终仍成立的检查能力、覆盖关系或持续约束，事实是否在本次被修改不影响收录；单次通过、临时结果及重构、迁移过程留在本轮报告。

## 当前产品事实记忆

开始工作时，先从用户范围、仓库原生产品身份、产品入口与元数据、相关项目根、目标代码与调用链确定 Git 仓库根及仓库内唯一、稳定且可安全作为单级目录名的 `product-id`；优先复用已确认属于同一产品的既有事实目录，不从任一项目目录名机械推导。同一 Git 仓库包含多个产品时，只处理本轮命中的产品。若 `<Git仓库根>/docs/product-studio/<product-id>/verification.md` 存在，只读取命中的事实主题及直接关联。获准写入的编码、验收或明确记忆维护任务收口前完整读取 [verification 记忆规则与实例格式](references/memory.md)，以本次实际核验的当前代码、配置、契约和验证结果为本轮增量范围，仅同步 `verification` 自己的当前事实；事实册整体是 `verification` 对该产品的累计专业事实视图，不受本轮范围限制，事实是否在本次被修改不影响收录，最终差异不构成事实边界。首次确有事实时在已确认的产品记忆目录创建同名事实册，不得预建产品记忆目录或空册；跨产品任务逐产品同步对应事实册，不把不同产品事实合并，产品归属无法唯一确定时不创建事实目录并报告歧义。单次验收、重构、迁移和变更过程不入册。只读任务未获事实册写入授权时只报告候选事实；完成当前范围核对后无增、改、删则报告 `memory: 0 facts changed`。

产品归属或 `product-id` 无法唯一确定时，不把任何候选事实册作为当前产品事实读取或写入，也不创建目录，并报告歧义。

## 输出与裁决

- 新增或补充的测试用例、测试代码与夹具，以及它们对应的要求、风险和证据边界；只读验收任务不强制写入测试文件。
- 逐项检查结果及直接证据，绑定要求、修订、环境、关键输入、命令、退出码或制品。
- 总体结论：失败、阻塞、通过或不适用；列明未执行项、未覆盖边界、剩余风险和证据失效条件。
- 失败的最小复现、预期、实际、影响、归因状态、应退回的实现技能与重验条件。
- 任务包含发布时，向 `$release` 交付通过验收的不可变制品或修订、适用检查、环境边界、阻塞和未覆盖风险；验收通过本身不构成生产操作授权。

## 完成门禁

- 每项适用必需标准可从来源追溯到实现位置、当前修订、环境和直接证据；每项改动可反向追溯到仍有效的要求。
- 静态、单元、契约、集成、端到端、真实渲染和运行观测证据各守其证明边界，没有跨层外推。
- API、权限、数据、迁移、前端旅程及适用非功能风险均取得与风险匹配的当前证据。
- 未执行项均明确归为失败、阻塞或经证据证明的不适用；没有从总体结论中消失。
- 本次回归、既有失败、环境问题、证据缺失和归因未定彼此分开；旧报告、其他分支和其他环境结果只作参考。
- 迁移与兼容结论绑定同一代码修订、Schema 版本、夹具和验证环境，只对记录范围成立。

## 独立性与边界

- 可独立选择验证深度、拒绝不匹配的证据，并判定通过、失败、阻塞、不适用、既有问题或归因未定。
- 可按用户请求新增或修正测试用例、测试代码和夹具，但默认不修改业务实现；发现缺陷后先保存独立证据：产品语义与体验目标退回 `$design`，系统边界、所有权与共享不变量退回 `$architecture`，具体接口与服务端实现退回 `$backend`，界面实现退回 `$frontend`。用户另行授权修复时，也必须在修复后重新独立验证。
- 不降低验收标准、删除有效测试、弱化断言或反向改写需求来制造通过。
- 本技能只验证代码、测试夹具及明确隔离的测试环境，不执行外部环境写入或环境操作。

# 独立验证

从用户原始意图、当前契约和完整差异建立独立验收标准，不以实现现状倒推成功。只有每项适用必需标准都获得匹配当前修订、环境、输入与断言的直接证据，才能判定通过。

## 输入门禁

- 明确当前项目根、仓库指令、待验收修订或制品、完整差异、目标环境、身份、数据和已知既有失败。
- 读取相关产品、系统、前端和后端当前事实，以及 `docs/product-studio/verification.md` 中与本次检查、覆盖和约束有关的当前验证事实。
- 固定用户原始意图、范围、业务不变量、接口与数据契约、迁移约束和适用验收标准；要求语义不足时交给 `$design`，不得从当前实现或测试名称反推需求。
- 任务已经由 `$router` 编排时，沿用其跨技能顺序与验证门禁；单一实现技能直交的常规验收无需补唤 `$router`。验证限于本地、测试夹具或明确隔离的测试环境，结论不得外推到未取证环境。

## 专业能力

先查看 [独立验收专业准则](references/verification-principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及整体验收、证据裁决或风险复核时，再读取“专业决策顺序”“交付证据”和“常见误判”。该 reference 只提供测试验证专业能力准则，触发、验证流程和代码事实更新规则以本文件为准。

按风险选择：

- 任一验收任务：需求追溯、风险建模、证据审计。
- 选择静态、单元、契约、集成、端到端层级：分层测试设计。
- 页面、交互、响应式或可访问性：用户体验验收。
- API、权限、数据库、缓存、消息、任务或外部依赖：服务端与数据验收。
- 性能、安全、可靠性、兼容或可观测性：非功能验证。
- Schema 迁移同时触及数据正确性与兼容回归：组合服务端与数据验收、回归分析。

## 验证流程

先按风险与改动面裁剪证据层级，只执行适用分支；前端局部修复不机械展开后端和迁移核验，后端局部改动也不虚构浏览器旅程。未执行但适用的必需项必须报告为失败或阻塞，真正不适用的分支写明判据。

1. 将原始意图、当前范围、契约和验收标准转为稳定检查项，写明来源、输入、动作、期望结果、禁止结果、环境和失效条件。
2. 检查完整差异、调用链、共享依赖、消费者、配置、Schema 和数据影响，按严重度、可能性、可发现性、可逆性、权限及外部副作用排序风险。
3. 为每项要求选择成本最低且能直接证明它的证据层级；高层证明用户结果和协作，低层证明规则与组合，不能用测试数量代替断言对应。
4. 先运行可快速阻断的格式、静态、类型、单元和聚焦契约检查，再按风险执行真实数据库、浏览器、集成、端到端、迁移、并发或故障验证。
5. 前端行为受影响时，从真实入口操作核心旅程和高价值失败或恢复路径，并绑定身份、数据、浏览器、视口、页面状态、控制台、网络和修订；纯视觉改动聚焦其真实状态和不得破坏的交互。
6. 后端、接口或数据受影响时，逐项核对请求响应、错误、权限、数据范围、事务、幂等、并发、消息、依赖故障、Schema、迁移兼容和最终数据不变量，只执行本次风险涉及的子集。
7. Schema、配置、依赖、共享组件或历史行为变化时，才进入迁移或回归分支，固定前后修订、配置、数据与环境，检查适用的新旧组合、回填、重入、暂停、恢复和清理条件。
8. 对失败记录最小复现、预期、实际、首个可行动错误、影响范围与归因证据；区分本次回归、既有问题、环境阻塞、证据缺失和归因未定。
9. 对每项检查给出通过、失败、阻塞或不适用；总体优先级为失败高于阻塞、阻塞高于通过，仅当所有适用必需项都有当前直接证据且通过时总体通过。
10. 当前修订的验证结论形成终态后，才按实际增量更新项目记忆；记忆写入失败不改变由证据成立的验收结论。

## 当前代码事实记忆

`docs/product-studio/verification.md` 只记录当前代码库可复用的验证事实，不记录本轮命令流水、临时失败、任务摘要、动作队列、完成宣言或历史报告。开始工作前读取与本次检查、覆盖面和约束相关的语义键；只有验证终态已成立且当前代码的验证事实发生变化时才写入。无变化、单次只读验收、临时环境结果或用户明确排除记忆时不写。

文件使用 schema 3。每个三级标题是唯一语义键，只能使用以下前缀：

- `verification:check:<surface>:<behavior>`：可重复执行的验证目标、入口、前置条件、动作和终态断言。
- `verification:coverage:<risk>:<scope>`：某项风险当前由哪些层级、测试和环境直接覆盖，以及明确未覆盖边界。
- `verification:constraint:<surface>:<invariant>`：验证必须持续检查的数据、安全、兼容、体验或环境不变量。

每条事实固定且仅含以下字段：

```markdown
### verification:check:api:order-idempotency

- **当前实现**：
- **源码锚点**：
- **关联与消费者**：
- **验证证据**：
- **重验条件**：
```

写入规则：

- “当前实现”写当前代码中可复用的测试入口、夹具、断言、覆盖层级或稳定限制；不得把某次“测试通过”写成永久事实。
- “源码锚点”指向当前测试、配置、脚本、契约、页面或被验证实现的文件及 Symbol。
- “关联与消费者”列明对应要求、实现、前端旅程、API、Schema、迁移或测试套件。
- “验证证据”绑定当前命令、工作目录、测试标识、环境与结果；若结论只对特定制品或时间窗成立，应留在本轮报告而非代码事实记忆。
- “重验条件”列出使检查、覆盖或约束失效的实现、契约、夹具、环境、依赖或浏览器变化。
- 同一语义键原位更新；新增事实添加新键；代码删除对应测试、脚本或约束且全部消费者消失后，移除事实。不得建立 superseded 历史卡，历史由 Git 承担。
- 只改本技能拥有且本次受影响的键，保持其他内容不变。首次确有事实需要创建文件时使用 `../../templates/verification.md`，之后只作增量更新。

## 输出与裁决

- 逐项检查结果及直接证据，绑定要求、修订、环境、关键输入、命令、退出码或制品。
- 总体结论：失败、阻塞、通过或不适用；列明未执行项、未覆盖边界、剩余风险和证据失效条件。
- 失败的最小复现、预期、实际、影响、归因状态、应退回的实现技能与重验条件。
- 存在稳定代码验证事实增量时更新 `docs/product-studio/verification.md`；单次结果或无增量时不写。

## 完成门禁

- 每项适用必需标准可从来源追溯到实现位置、当前修订、环境和直接证据；每项改动可反向追溯到仍有效的要求。
- 静态、单元、契约、集成、端到端、真实渲染和运行观测证据各守其证明边界，没有跨层外推。
- API、权限、数据、迁移、前端旅程及适用非功能风险均取得与风险匹配的当前证据。
- 未执行项均明确归为失败、阻塞或经证据证明的不适用；没有从总体结论中消失。
- 本次回归、既有失败、环境问题、证据缺失和归因未定彼此分开；旧报告、其他分支和其他环境结果只作参考。
- 迁移与兼容结论绑定同一代码修订、Schema 版本、夹具和验证环境，只对记录范围成立。

## 独立性与边界

- 可独立选择验证深度、拒绝不匹配的证据，并判定通过、失败、阻塞、不适用、既有问题或归因未定。
- 默认不修改业务实现；发现缺陷后先保存独立证据并退回 `$frontend`、`$backend` 或 `$design`。用户另行授权修复时，也必须在修复后重新独立验证。
- 不降低验收标准、删除有效测试、弱化断言或反向改写需求来制造通过。
- 本技能只验证代码、测试夹具及明确隔离的测试环境，不执行外部环境写入或环境操作。

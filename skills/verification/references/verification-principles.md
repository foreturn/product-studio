# 独立验收专业准则

按风险加载适用能力卡；所有验收判断必须追溯到已确认要求、当前修订、指定环境、关键输入和直接证据。

## 核心能力

### 需求追溯

- **启用**：执行任何验收、联调、回归、质量审计或交付结论更新时启用。
- **输入**：
  - 用户原始意图、已确认范围、业务不变量、架构决定、接口契约、迁移约束和验收标准。
  - 待验收代码或制品修订、工作区差异、目标环境、身份与数据条件。
  - 要求的历史版本、取代关系、责任角色和实现位置。
- **执行**：
  - 为原始意图、范围、不变量、接口与验收标准分配或沿用稳定 ID。
  - 区分用户明确要求、仓库事实、已接受决定、假设和推断；为假设记录状态、依据和影响。
  - 将抽象要求改写为不改变业务含义的可观察判据，写明输入、动作、预期结果、禁止结果和适用环境。
  - 将跨层要求拆为前端、后端、数据、权限、迁移和运行子证据，最终汇总到同一用户结果。
  - 要求变化时记录“取代／被取代”关系，不在原记录上静默改写。
- **裁决**：
  - 用户明确要求、仓库事实和已接受决定可构成强制验收依据；假设和推断只能限定验证或形成待确认项。
  - 缺少权威要求时，阻塞受影响结论并说明缺口，不以当前代码、测试快照或个人偏好倒推产品目标。
  - 当前结论只引用仍有效的要求版本；风险分析不能擅自把行业惯例升级成需求。
- **产出**：
  - 验收追溯矩阵，至少包含 `AC-ID`、要求来源、版本、责任角色、实现位置、可观察判据、直接证据、结果、环境或修订和证据失效条件。
  - 无来源改动、遗漏要求、镀金实现、假设、待决项与被取代要求清单。
- **验证**：
  - 正向检查每项适用要求都有实现位置与直接证据。
  - 反向检查每项改动都有仍有效的要求来源，识别无来源扩张。
  - 抽查跨层子证据能否回到同一用户结果，且没有改变原业务含义。
- **完成**：
  - 每项适用要求均可从来源追溯到实现和当前证据，每项改动均可追溯到要求。
  - 缺口、假设、镀金实现、取代关系和阻塞范围均有显式状态与影响。
- **边界**：
  - 不得从实现结果或已有测试反向定义“成功”，使错误行为因“与代码一致”而通过。
  - 不得静默改写要求、降低标准，或将个人偏好、候选风险和改进建议并入强制验收。

### 风险建模

- **启用**：确定验证范围、深度、顺序、资源投入或剩余风险时启用。
- **输入**：
  - 完整差异、调用链、共享依赖、直接与间接消费者、配置、数据和环境变化。
  - 用户影响、数据敏感度、权限边界、外部副作用、可逆性、历史缺陷和迁移复杂度。
  - 外部依赖稳定性、测试环境可控程度及测试夹具可信度。
- **执行**：
  - 按影响严重度、发生可能性、可发现性、可逆性、数据敏感度、权限扩大和外部副作用评估风险。
  - 结合差异规模、共享组件、调用方数量、历史缺陷、并发路径和迁移复杂度判断回归半径。
  - 建立“风险—失败模式—触发条件—检测方式—缓解证据”映射。
  - 将环境不确定、外部依赖和夹具可信度作为风险因子，不把偶然通过视为稳定证据。
- **裁决**：
  - 优先覆盖高影响且低可发现的风险，如静默数据错写、权限穿透、重复扣款、兼容断裂和不可恢复迁移。
  - 低风险局部改动可聚焦验证，但须以写入集、依赖和消费者确实局部为依据，不能只看文件数量。
  - 测试深度随已确认风险和行为分支变化，不套固定测试数量或比例。
- **产出**：
  - 带来源、严重度、可能性、可发现性、可逆性、触发条件、影响对象、检测方式和缓解证据的风险覆盖表。
  - 按阻断价值排序的验证优先级，以及可接受剩余风险的发现手段和责任人。
- **验证**：
  - 对照完整差异和调用链检查风险表是否遗漏共享消费者、权限、数据、迁移或外部副作用。
  - 对宣称“局部”的范围复核写入集、依赖与消费者证据。
  - 对剩余风险核对触发条件、影响对象、监测方式、责任人和重新验收条件。
- **完成**：
  - 高影响、低可发现风险先取得直接证据，回归范围有差异和调用链支撑。
  - 每项剩余风险均具体说明触发、影响、发现、处置责任与失效条件，而非笼统写“仍有风险”。
- **边界**：
  - 风险清单只用于选择验证、决定深度和表达不确定性，不得暗造新需求。
  - 不得因能力目录列有安全、性能或兼容性，就强制引入产品未确认且差异也未触发的目标。

### 分层测试设计

- **启用**：需要选择静态、单元、契约、集成、端到端、真实渲染或运行观测证据时启用。
- **输入**：
  - 逐项可观察要求、风险优先级、行为分支、跨组件边界和可用测试环境。
  - 时间、随机、网络、并发、外部系统等不确定源，以及可控制时钟、种子、替身或隔离环境。
  - 空值、边界值、重复、乱序、过期、权限差异、旧版本、部分成功和真实规模等数据条件。
- **执行**：
  - 用静态检查证明语法、类型和规则，用单元测试证明局部逻辑，用契约测试证明调用边界，用集成与端到端证明协作和旅程。
  - 为每项关键要求选择成本最低且能直接证明它的层级，再以更高层证据覆盖跨组件协作。
  - 核心业务规则优先采用确定性测试；控制时间、随机、网络、并发和外部系统的不确定性。
  - 每条关键快乐路径配至少一个高价值边界、失败或恢复路径；测试数量由风险和行为分支决定。
  - 契约测试同时检查成功结构、错误语义、兼容约束与调用方假设，不只检查状态码或字段存在。
  - 端到端只承担关键旅程和跨层协作；局部组合爆炸下沉到单元或契约层。
  - 对不稳定测试记录重现率、波动来源、隔离条件和失败样本。
- **裁决**：
  - 直接证据优先于间接覆盖；重复证明同一实现细节不增加结论强度。
  - 高层测试用于用户结果和协作，低层测试用于规则与组合定位，不让端到端承担全部分支。
  - 反复重跑直至绿色不能证明缺陷消失；未解释的不稳定结果不得作为通过证据。
- **产出**：
  - 要求—风险—测试层级—数据—环境—断言—执行顺序映射。
  - 确定性控制方案、关键旅程、失败和恢复用例，以及不稳定测试调查记录。
- **验证**：
  - 核对每个测试的断言是否直接证明对应要求，而不只看名称、数量或覆盖率。
  - 检查数据是否覆盖适用的空值、边界、重复、乱序、过期、权限、旧版本、部分成功和真实规模。
  - 检查跨层旅程与局部规则没有因层级错置而出现证明空洞或难以定位。
- **完成**：
  - 核心规则、边界契约、关键用户旅程和至少一个高价值失败或恢复路径均有匹配层级与直接断言。
  - 所有不确定源已有控制、隔离或证据边界；不稳定测试已有可复现分类而非机械重跑。
- **边界**：
  - 测试数量、覆盖率、整套构建绿色和测试名称都不能替代要求与断言的对应关系。
  - 不得为了绿色删除有效测试、弱化断言，或用单个聚焦测试替代原始用户旅程。

### 用户体验验收

- **启用**：用户可见页面、文案、交互、状态、响应式、媒体或可访问性受影响时启用。
- **输入**：
  - 核心用户、真实入口、任务成功结果、适用且可达状态、身份和边界数据。
  - 项目支持的浏览器、桌面与移动视口、可访问性标准和性能或交互参数。
  - 当前修订、成功与错误契约、真实或代表性内容；缺少项目参数时记录显式假设。
- **执行**：
  - 从真实入口走完核心任务，观察发现性、步骤数、重复输入、反馈时机、迷失点和失败恢复成本。
  - 依据契约和触发条件检查初始、加载、刷新、空白、权限不足、禁用、提交中、部分成功、失败、成功和恢复中的适用可达状态。
  - 检查信息层级、主次动作、内容密度、对齐、间距、长文本、国际化和动态内容。
  - 在代表性桌面和移动视口检查重排、溢出、裁切、触控、虚拟键盘、滚动和布局跳动。
  - 用键盘完成核心流程，检查焦点顺序与恢复、标签、辅助名称、错误关联、对比和减少动画。
  - 查看控制台、网络请求、资源加载和运行警告。
- **裁决**：
  - 只验收由契约和触发条件证明适用且可达的状态；不适用状态记录依据，不机械要求全套状态。
  - 文案须说明当前状态、原因、可执行动作和下一步；内部枚举、接口名或无行动价值的错误码不算可用反馈。
  - 项目未给浏览器、视口或标准时，显式限定假设和结论，不私设通用参数后宣告全面通过。
- **产出**：
  - 入口—步骤—身份—数据—结果—失败恢复的旅程记录。
  - 适用且可达状态矩阵，以及绑定页面状态、视口、浏览器、数据条件和修订的截图或录屏。
  - 键盘、焦点、语义、名称、错误关联、对比、网络和控制台检查记录。
- **验证**：
  - 用真实内容和边界内容重复核心旅程及至少一个高风险失败或恢复路径。
  - 核对截图或录屏中的页面状态、视口、浏览器、数据和修订标识。
  - 对浏览器、键盘、辅助技术或设备无法验证之处标为证据缺口并缩小结论。
- **完成**：
  - 核心任务和适用的失败或恢复路径可完成，反馈及时且可行动。
  - 视觉、响应式、交互和文案符合项目标准；可访问性在声明范围内有直接证据。
  - 所有未覆盖状态、视口、浏览器和辅助技术均已明列。
- **边界**：
  - 静态截图、DOM 存在、构建成功或自动工具零告警不能外推为完整体验通过。
  - 不得只看理想截图，遗漏权限、长文本、慢网络、重复提交、部分失败或真实设备行为。

### 服务端与数据验收

- **启用**：API、认证授权、持久化、缓存、消息、任务、迁移或外部依赖受影响时启用。
- **输入**：
  - 当前请求与响应契约、成功和错误语义、消费者与版本兼容范围。
  - 身份、角色、租户、对象权限、敏感字段、数据不变量、Schema、索引和代表性数据量。
  - 事务、幂等、重试、消息顺序、补偿、迁移计划及外部依赖超时和限流约束。
- **执行**：
  - 核对请求、响应、错误语义、数据范围、分页、筛选、排序和版本兼容。
  - 分别验证认证与授权，覆盖无身份、错误角色、跨租户、对象级权限和敏感字段裁剪。
  - 检查事务边界、幂等键、重复请求、并发更新、乱序消息、重试、部分失败、补偿和最终状态。
  - 验证数据库约束、索引、默认值、空值、级联行为和代表性数据量下的查询计划。
  - 迁移覆盖执行前条件、新旧代码共存、回填、数量核对、失败重入、暂停、恢复和回滚后的数据状态。
  - 模拟依赖超时、错误、限流和不可用，检查超时预算、降级、隔离与重试不会放大故障。
  - 检查日志、事件和审计轨迹可关联且不泄密，指标能反映业务结果。
- **裁决**：
  - 每个受影响边界都按当前契约和真实消费者验证，不能只验证提供方内部实现。
  - 重试只用于安全且有预算的操作；写操作须以幂等、事务或补偿证明不会重复产生外部影响。
  - 迁移结论须同时满足代码兼容和数据不变量，单次 SQL 成功或备份存在均不足。
- **产出**：
  - 调用方和兼容清单、请求响应与错误样本、身份权限矩阵。
  - 事务、幂等、并发、消息、补偿与依赖故障证据。
  - Schema、约束、索引、查询计划、迁移批次、数量核对和恢复结果。
- **验证**：
  - 使用代表性身份、租户、对象、数据规模以及重复、并发、乱序和失败输入执行适用路径。
  - 对最终数据库、缓存、消息、审计和外部结果核对业务不变量，不以中间响应代替最终状态。
  - 涉及迁移时复验重入、暂停、恢复、旧代码共存和回滚或前向修复后的数据状态。
- **完成**：
  - 成功、错误、权限、数据范围和兼容语义均有当前直接证据。
  - 幂等、并发、事务、补偿和依赖故障不会破坏数据不变量或放大副作用。
  - 迁移在代表性条件下可核对、可暂停、可重入并有明确恢复结果。
- **边界**：
  - HTTP 200、数据库行存在、健康端点或日志出现不能单独证明业务成功与一致性。
  - 不得以空库、小数据、单一身份或仅最新客户端的结果外推到真实数据量、权限和兼容窗口。

### 非功能验证

- **启用**：已确认验收标准或当前高风险差异涉及性能、安全、可靠性、可访问性、兼容性、可观测性或发布就绪时启用。
- **输入**：
  - 明确的非功能目标、负载模型、数据量、设备或资源、环境、基线、指标和阈值。
  - 当前信任边界、支持的浏览器与客户端、Schema 和配置组合、故障模式及发布制品。
  - 生产或高风险测试的授权范围、隔离方式、停止条件和清理能力。
- **执行**：
  - 性能验证绑定负载、数据量、设备或资源、环境、指标与阈值；没有基线时只报告测量值和趋势。
  - 安全验证围绕当前信任边界检查认证、授权、输入、输出、敏感数据、审计、高价值操作与依赖风险。
  - 可靠性覆盖重启、超时、重试、积压、容量、资源耗尽和恢复，按风险选择压力、峰值、耐久或故障注入深度。
  - 可访问性覆盖语义、键盘、焦点、名称、错误、对比、缩放和适用辅助技术。
  - 兼容性覆盖受支持浏览器、客户端版本、Schema 版本、配置组合和前后端滚动窗口。
  - 可观测性检查告警是否可行动，日志与指标能否按请求、用户或任务关联，并核对敏感信息边界。
  - 发布就绪核对制品、配置、迁移、健康信号、停止条件和回滚步骤与当前验收版本一致。
- **裁决**：
  - 验证深度服从已确认目标或当前风险，不因能力目录存在便强制引入新合规、性能或平台目标。
  - 无基线或阈值时不得宣告“达标”；只能提供测量结果、环境、假设与趋势。
  - 高风险生产测试、写入探针和主动故障注入须受独立授权与安全边界约束。
- **产出**：
  - 适用维度、目标来源、参数、环境、基线、阈值、命令、结果、未覆盖范围和失效条件。
  - 安全、可靠性、兼容性、可访问性、可观测性或发布就绪的直接证据与剩余风险。
- **验证**：
  - 核对所有结论均绑定当前制品、环境、负载或设备及适用分群。
  - 对工具结果复查实际断言，不把零告警、无报警或进程存活外推为用户结果。
  - 对未执行生产测试记录授权、隔离或环境阻塞，而非伪造结果。
- **完成**：
  - 每项已确认非功能要求均有当前、有边界、可复现的直接证据。
  - 无目标项仅报告现状，不宣告达标；未覆盖组合和剩余风险有明确触发条件与责任人。
- **边界**：
  - 不得凭能力卡暗造需求或把行业通用目标冒充项目标准。
  - 不得以工具零告警、单次低负载、最新版本组合或无告警外推全面性能、安全、兼容或健康结论。

### 回归分析

- **启用**：存在代码、配置、Schema、依赖、默认值、权限、公共接口或共享组件变化，或出现需归因的失败时启用。
- **输入**：
  - 完整工作区差异、提交前后修订、调用链、直接改动、共享依赖和间接消费者。
  - 配置、数据、缓存和环境条件，以及历史失败、基线结果和测试变更。
  - 原始用户旅程、受影响层级和失败样本。
- **执行**：
  - 列出直接改动、共享依赖、间接消费者、配置、数据与环境影响。
  - 按变更语义选择回归范围；重命名、默认值、公共组件、Schema 和权限变化通常超出改动文件。
  - 固定数据、配置和环境比较改动前后行为，避免环境漂移或缓存污染归因。
  - 对失败建立最小复现，记录首个出现修订或可靠前后对照。
  - 修复后重跑直接失败、受影响层级、必要回归和原始用户旅程。
  - 删除或修改测试时核对其代表的要求是否仍有效。
- **裁决**：
  - 只有改动前证据或明确影响边界能证明失败既有时，才归为既有问题；否则记为归因未定。
  - 环境前置条件可复现地不满足时记环境阻塞；不能把未知失败随意归给环境。
  - 单个聚焦测试转绿不终止回归，须回到原失败层级与用户结果。
- **产出**：
  - 直接和间接影响面、回归范围、固定环境与数据条件。
  - 最小复现、首现修订或前后对照、失败分类及修复后的重验记录。
- **验证**：
  - 复查差异外的共享消费者、默认值、权限和 Schema 语义是否纳入回归。
  - 在相同数据、配置和环境下重现前后行为，排除旧制品与缓存差异。
  - 核对测试删除或修改没有移除仍有效的要求断言。
- **完成**：
  - 每项失败分类都有可复现证据；既有问题和本次回归有可靠区分，无法区分者保持归因未定。
  - 修复后的直接失败、受影响层级、必要回归和原始用户旅程均已重跑。
- **边界**：
  - 不得通过删除测试、降低阈值、改写要求或把必需项降为剩余风险制造通过。
  - 不得把环境漂移、偶然缓存或反复重跑后的绿色误作回归已经消失。

### 证据审计

- **启用**：接收、生成、汇总、引用或更新任何验收证据和结论时启用。
- **输入**：
  - 要求 ID、当前修订或制品、工作目录、运行环境、关键输入、断言和证据制品。
  - 静态、单元、契约、集成、端到端、真实渲染和运行观测结果。
  - 历史报告、其他分支或环境结果、失败记录、未执行项与剩余风险。
- **执行**：
  - 核对证据是否同时匹配要求、当前修订、环境、关键输入和断言；任一不匹配只作参考。
  - 记录可复现命令、工作目录、退出码、关键输出和制品位置；截断时保留首个可行动错误与完整日志位置。
  - 为截图和录屏标注视口、浏览器、页面状态、数据条件与修订。
  - 查看测试断言是否真正证明要求，不以测试名称和覆盖率推断结论。
  - 区分直接证据、支持证据和推断；历史、其他分支或其他环境结果标为过期或参考。
  - 结论变化时记录新证据和被取代结论，不覆盖失败痕迹。
- **裁决**：
  - 一项必需标准缺少直接证据时，不得通过；“未发现错误”“人工看过”和“应该没问题”均非证据。
  - 未执行本身不是结论：因可复现的外部前置条件无法满足而不能执行，判为阻塞；本可执行却遗漏、主动跳过或验证本身失败，判为失败。
  - 结果优先级为失败高于阻塞、阻塞高于通过；支持材料只能解释，不能替代必需项直接证据。
- **产出**：
  - 逐项证据封套、当前结果、证据类型、适用范围和失效条件。
  - 失败记录，至少包含最小复现、预期、实际、首个可行动错误、影响范围和建议退回角色。
  - 未执行项及其阻塞或失败归类、历史结论取代链和总体汇总依据。
- **验证**：
  - 抽查证据可在记录的工作目录、修订、环境和输入下重现。
  - 检查截图、日志、命令、报告和制品没有跨版本或跨环境错配。
  - 对总体结论逐项反查直接证据，确认未执行、失败和阻塞没有从报告中消失。
- **完成**：
  - 每项必需标准均获得通过、失败或阻塞，且分类理由和直接证据可审计。
  - 当前结论仅引用当前修订和环境；所有参考、过期、未执行和剩余风险均明确标注。
- **边界**：
  - 不得把浏览器截图外推为交互、权限或数据正确，把接口成功码外推为业务成功，或把进程存活外推为产品可用。
  - 验收者若直接参与修复，须保留原失败证据并重新执行独立验证，不得沿用修复前结论。

## 能力组合

1. 先固定用户意图、要求版本、代码或制品修订、工作区差异、环境和数据条件；组合需求追溯、风险建模与证据审计，建立要求、影响面和证据账本。
2. 按用户影响、数据与权限风险、可逆性、历史缺陷和不确定性排序；先运行成本低、反馈快且能阻断后续浪费的静态与聚焦检查。
3. 用户可见变更组合用户体验验收；服务端、数据或迁移变更组合服务端与数据验收；跨层旅程再组合分层测试设计，先证明业务规则、接口与数据不变量，再走完整旅程和高风险失败或恢复路径。
4. 共享依赖、公共契约、Schema、权限、默认值或历史行为可能受影响时追加回归分析；只有已确认要求或当前高风险差异触发非功能验证。
5. 失败先最小化复现并分类，修复后重跑直接失败、受影响层级、必要回归和原始用户旅程；随后重新审计证据是否仍匹配当前修订、环境和要求。
6. 各能力分支只收集证据，不自行宣告总体通过；最后在同一要求版本、修订和环境下逐项汇总，并列明未覆盖范围、剩余风险、下一责任角色和重新验收条件。

## 完成判据

- 为每项适用必需标准记录 `AC-ID`、来源、实现位置、当前修订、环境、关键输入、直接证据、结果与证据失效条件；要求、实现和证据须双向可追溯。
- 静态检查只证明检查范围内的语法、类型、格式或规则；须记录命令、工作目录、修订、退出码和关键输出，不得外推运行时或用户旅程。
- 单元测试只证明指定输入下的局部规则和边界；须记录测试标识、数据、断言、修订和结果，不得外推跨服务、真实浏览器或生产行为。
- 契约测试只证明指定提供方、消费者和版本的边界、Schema、错误与兼容假设；须保存请求、响应和结果，不得外推完整业务流程。
- 集成测试只证明多组件在指定环境、依赖版本和夹具下协作；不得外推未覆盖的用户状态或非功能目标。
- 端到端旅程只证明当前环境、入口、身份和数据下的关键用户结果与失败恢复；不得外推未覆盖角色、状态和规模。
- 真实渲染只证明指定浏览器、视口和页面状态的界面表现；不得外推接口权限、数据一致性或性能达标。
- 运行观测只证明指定环境、制品和时间窗内的技术或业务信号；须绑定查询、基线、阈值和结果，不得外推未观察时段或不同制品。
- 明列所有未执行项：可复现的外部前置条件阻止执行时判阻塞；本可执行却遗漏、主动跳过或验证本身失败时判失败；不得省略或暗示已覆盖。
- 按“失败 > 阻塞 > 通过”汇总：任一必需项失败则总体失败；无失败但有阻塞则总体阻塞；仅当所有必需项均获当前直接证据并通过时，总体才通过。
- 分开记录本次回归、既有失败、环境问题、证据缺失、归因未定和可接受剩余风险；既有问题须有改动前证据或明确边界，无法证明时保持归因未定。
- 通过结论仍须说明未覆盖范围和剩余风险；若风险面已闭合，说明为何闭合。风险清单保持在已确认契约与当前差异内，改进机会另列候选，不并入强制要求。
- 指明下一责任方、退回原因、重新验收条件及会使结论失效的变化；未经单独授权，不修改业务实现，不执行生产写操作或高风险探针。

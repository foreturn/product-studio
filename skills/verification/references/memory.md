# verification 当前代码事实记忆

本文件是 `verification` 记忆的唯一规则与首建骨架，目标实例为 `<项目根>/docs/product-studio/verification.md`。只由 `verification` 维护；其他技能可链接事实键，不复制正文。

## 收录门槛

- 事实已由当前代码库中的稳定检查资产或持续约束支持，且预计后续验收仍会使用。
- 事实具有唯一验证 Owner 和权威代码定位，并至少具备一项价值：跨风险或层级、无法从单文件立即看出、重查成本高或误判风险大。
- 一个键只概括一个共同检索、共同失效的稳定语义单元；不按任务、提交、测试文件、用例、命令、环境或制品机械建卡。
- 单次验收通过、临时失败和一次性证据不自动形成长期记忆。

## 事实键

键在当前项目内全局唯一；`<slug>` 只用小写字母、数字和短横线表达稳定业务语义，不写路径、日期、任务号或临时方案名。`<type>` 只取下列值：

- `verification:check:<slug>`：可重复执行的检查入口、关键断言和适用环境。
- `verification:coverage:<slug>`：风险当前由哪些层级直接覆盖，以及稳定未覆盖边界。
- `verification:constraint:<slug>`：必须持续成立的数据、安全、兼容、体验或环境不变量。

## 实例骨架

首次确有事实时复制下列骨架并替换所有尖括号占位；没有事实时不得创建文件。`project_root: "."` 固定指事实册所在的当前项目根，不得改为绝对路径或父目录。

```markdown
---
memory: verification
project_root: "."
updated_at: "<带时区 RFC3339 时间>"
---

# verification 代码事实

## 当前代码事实

### verification:<type>:<slug>

- **事实摘要**：<一项可重复执行的检查、稳定风险覆盖或必须持续守住的验证约束>
- **代码定位**：<一至三个 `仓库相对路径#精确位置`，精确位置使用权威测试、脚本、配置、夹具、被测入口或实现 Symbol>
- **依赖与影响**：<所验证的 design、backend、frontend 事实键、要求、实现或测试套件；无则写“无”>
- **验证入口**：<稳定测试、脚本、命令和适用环境，关键断言与证据边界>
- **失效条件**：<哪些被测代码、契约、夹具、环境能力、依赖或浏览器变化后必须同步本卡>
```

## 终态同步

1. 编码任务完成验收，或部分完成中已有独立可用且验证成立的切片时，对照最终差异与现有相关卡列出 `+`、`~`、`-` 键。
2. 同一语义原位更新；仅搬代码时只改“代码定位”；检查资产、覆盖关系、约束或最后消费者消失时删除卡。
3. 只有五字段之一变化才写文件并更新 `updated_at`；没有总结事实变化时报告 `memory: 0 keys changed`，不制造时间戳差异。
4. 最后一张卡删除后移除整册，不留空文件；写后检查键、链接、定位和占位，再运行项目校验。

## 禁止内容

- 任务摘要、文件清单、进度、待办、责任人、候选方案、过程推理和 `superseded` 历史。
- 单轮通过、临时失败、命令流水、制品、截图时间、commit SHA、未实现目标、外部资料和其他项目事实。
- 密钥、令牌、用户数据、环境秘密，以及其他 Owner 已保存的同一事实正文。

历史由 Git 承担，长期测试策略留在项目既有正式文档。静态校验只能证明当前快照的结构、定位和链接自洽；语义新鲜度必须由 `verification` 对照最终差异同步。

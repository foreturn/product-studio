## 事实册所有权与稳定位置

`product-experience` 是任务入口与旅程、信息架构与内容、动作与表单、用户可见状态与恢复、响应式能力和无障碍体验契约的唯一事实 Owner。事实实例固定为 `<Git仓库根>/docs/product-studio/<product-id>/product-experience.md`，不得在产品管理或前端工程事实册中复制同一体验语义。

产品目标、业务政策、范围和成功指标不是体验事实；组件树、状态库、CSS 与浏览器实现只可作为体验事实的证据或影响边界，不得在本册展开工程实现正文。

## 产品身份解析

- 先确认 Git 仓库根，再综合用户明确范围、仓库原生产品元数据、真实产品入口、相关项目根、目标代码和实际消费关系解析 `product-id`。
- `product-id` 必须在仓库内唯一、长期稳定且可安全作为单级目录名；不得从任一目录名、包名、应用壳名称或仓库名机械推导。
- 多产品仓库按产品隔离。跨产品旅程的共同体验事实写入拥有权威入口或体验契约的产品，其他产品只在自身主题的影响边界中描述衔接。
- 产品归属、体验 Owner 或权威入口不能唯一确认时，不读取或写入任何候选事实册，也不创建候选目录。

## 统一事实实例格式

首次确有体验事实时，同次创建产品目录与 `product-experience.md`；没有事实时不得预建空册。一个主题聚合一组共同检索、共同变化的稳定体验语义，不按任务、提交、页面文件、组件、`AC-ID` 或本轮动作机械拆分。

```markdown
# product-experience 当前产品事实

## <稳定体验事实主题>

- **当前事实**：<依照本文件对应事实类型的写法，陈述当前用户实际能够观察和完成的体验>
- **权威依据**：<一至三个 `仓库相对路径#精确位置`，定位实际路由、页面状态逻辑、内容来源、契约或稳定测试 Symbol>
- **影响边界**：<依照对应事实类型列明适用角色、入口、设备、视口、输入方式、数据前置、直接消费者及不适用处；无则写“无”>
- **复核入口**：<可重复测试、脚本或真实操作旅程，并写明身份、数据、设备、关键观察、环境限制、未覆盖边界和重审触发>
```

四栏必须同时存在。`当前事实` 只写当前可见体验；`权威依据` 的路径必须存在且位置可定位；`影响边界` 必须写清角色和使用条件；`复核入口` 必须能重复观察体验，而不是只写“查看页面”或“截图确认”。同一语义原位维护，不另建“新版”“迁移后”或日期化主题。

## 通用证据与写入约束

- 事实必须由当前执行代码、配置或权威契约，真实渲染或操作，以及与风险相称的可重复验证共同证明。设计稿、原型、竞品、个人审美、进行中实现、失败或阻塞结果不能单独成为当前事实。
- 本轮未修改但当前检查已证实、稳定且值得复用的既有体验可以入册；历史提交和单张截图只能帮助定位，不得代替当前可操作证据。
- 只读任务或未获事实文件写入授权时，只报告候选动作、主题、四栏草案及证据，不修改事实册。
- 只有对应事实类型判定为 `ADD`、`UPDATE` 或 `DELETE` 时才触碰文件；`NO_CHANGE` 必须保持文件字节不变。
- 删除最后一个主题时删除整册；产品目录因此为空时一并删除。Git 保存历史，事实册不保存设计演进或本轮摘要。
- 写后检查 `product-id`、Owner 唯一性、主题合并键、四栏完整性、依据路径、操作可复核性及跨册重复。

## 事实类型：任务入口与端到端旅程

- **入册条件**：目标角色能够从当前真实入口连续完成具有稳定用户结果的任务，主路径及会改变完成结果的关键替代路径已由实际路由、状态逻辑和操作验证共同证实，并会约束后续界面改动。
- **主题合并键**：使用 `<角色或资格组>|<用户任务>|<完成结果>`；同一任务从多个等价入口进入时合并并在边界中列入口，角色、任务目标或完成结果实质不同才分主题，不按页面或步骤拆题。
- **当前事实写法**：依次写明角色与触发、可发现入口、必要前置、关键决定和动作、等待或交接、完成反馈及完成后的去向；只保留影响理解、选择、完成或恢复的步骤，不复述组件层级。
- **权威依据**：定位真实路由与入口、页面流程或状态机 Symbol、任务所消费的权威契约，以及覆盖主路径和关键替代路径的浏览器或端到端测试；流程图和原型不能独立证明当前旅程。
- **影响边界**：列明适用身份、入口、前置数据、设备或输入限制、涉及的跨角色可见交接、直接依赖完成结果的后续任务，以及不适用入口和外部系统未覆盖处。
- **复核入口**：以代表性身份和数据从每个等价入口完成任务，观察发现、步骤连续性、反馈、刷新／返回行为和最终去向，并明确外部身份、支付、通知或真实设备无法本地证明的部分。
- **变更规则**：当前稳定旅程尚未入册为 `ADD`；入口、前置、关键步骤、用户决定、交接、完成反馈、去向、证据或边界变化为 `UPDATE`；任务或最后一个真实入口消失为 `DELETE`；仅组件重构而四栏及定位均未改变为 `NO_CHANGE`。
- **专属禁项**：不得记录未实施旅程图、页面开发任务、点击流水、会话录像摘要、个体用户行为、无结果的导航细节、产品范围决定或具体组件和接口实现。

## 事实类型：信息架构与内容术语

- **入册条件**：业务对象、内容层级、导航关系、关键术语或用户可见文案语义已在当前产品稳定呈现，并由真实渲染和目标任务走查证明其承担发现、理解或决策作用。
- **主题合并键**：使用 `<用户任务或业务对象>|<信息域>`；为同一对象和决策目的服务的导航、层级与术语合并，用户心智模型或信息域不同才分主题，不以页面区域、文案文件或单个字符串作键。
- **当前事实写法**：写明用户从何处发现该信息、对象如何分组和分层、首要与渐进披露内容、导航与返回关系、采用的标准术语、关键标签或警示语义及其帮助用户作出的决定。
- **权威依据**：定位实际路由或导航配置、渲染内容模型、权威文案来源、设计令牌中的语义名称及覆盖可发现性和关键内容的浏览器测试；设计稿和翻译表只有被当前界面消费时才可作为补充依据。
- **影响边界**：列明适用角色、任务、入口、语言或地区、数据状态、直接消费术语的页面或帮助内容，以及刻意不展示、延后披露或不适用的信息域。
- **复核入口**：从真实入口按目标任务检查导航、层级、返回、搜索或筛选语义，核对长内容、空数据、不同语言及关键警示，断言相同业务对象没有出现冲突术语。
- **变更规则**：当前稳定信息模型或术语尚未记录为 `ADD`；分组、层级、导航关系、首要信息、术语语义、关键内容来源、适用语言或证据变化为 `UPDATE`；对象或信息域不再对用户可见且无消费者为 `DELETE`；仅不改变语义的措辞润色为 `NO_CHANGE`。
- **专属禁项**：不得收录全量文案清单、翻译流水、SEO 草稿、个人审美评价、像素排版、数据库字段名、内部服务名、未渲染设计稿或只在一次营销活动中成立的临时内容。

## 事实类型：动作、表单与确认语义

- **入册条件**：关键动作或表单输入已在当前产品可用，其可用条件、输入要求、风险披露、反馈和完成结果已由实际交互及相称验证证实，并会影响用户能否正确、完整或可逆地完成任务。
- **主题合并键**：使用 `<业务对象>|<用户动作>|<作用范围>`；同一动作在多个入口语义一致时合并，作用对象、范围、风险或结果不同才分主题；同一表单中共同完成一次业务动作的字段归入该动作主题。
- **当前事实写法**：写明动作名称与对象、可用和禁用条件、作用范围、必要输入及默认来源、触发方式、风险确认或撤销条件、提交中反馈、成功去向，以及适用的取消、重复和输入保留行为。
- **权威依据**：定位实际动作入口、表单定义与校验、用户可见反馈映射、权威业务契约及覆盖键鼠／触控操作和关键输入边界的浏览器测试；仅有接口定义不能证明用户侧动作语义。
- **影响边界**：列明适用角色、业务对象、入口、表单模式、设备与输入方式、危险或不可逆范围、直接消费提交结果的任务，以及不支持的批量、草稿或撤销情形。
- **复核入口**：以有效、边界和无效输入执行动作，检查可用性、标签、风险披露、错误定位、重复提交、取消或撤销、数据保留与完成反馈，并注明自动填充、虚拟键盘或外部确认的环境限制。
- **变更规则**：当前稳定动作契约尚未入册为 `ADD`；名称语义、对象、作用范围、可用条件、输入要求、确认／撤销、反馈、结果、证据或边界变化为 `UPDATE`；动作及所有入口消失为 `DELETE`；仅控件实现替换而四栏及定位均未改变为 `NO_CHANGE`。
- **专属禁项**：不得记录组件 API、字段类型清单、CSS、接口参数、校验库实现、未采纳交互稿、低风险微动效、一次性提示语或把业务政策资格当作体验自行裁定。

## 事实类型：用户可见状态、反馈与恢复

- **入册条件**：加载、空白、权限、提交、成功、部分成功、失败、过期、等待或恢复等状态当前确会改变用户理解、可执行动作或最终结果，并已由状态触发证据和真实操作验证其显示与恢复行为。
- **主题合并键**：使用 `<用户任务或业务对象>|<状态族>|<恢复责任>`；共享进入条件、可见反馈和恢复路径的状态合并，用户可采取的恢复动作或结果不同则分主题，不按错误码、异常类或接口拆题。
- **当前事实写法**：写明状态的用户可理解名称、进入条件、可见信息、允许与禁止动作、即时反馈、退出条件、恢复方法、恢复后的去向，以及刷新、返回、重进或重复操作时的可见结果。
- **权威依据**：定位页面状态映射、错误与结果内容来源、恢复动作 Symbol、权威业务状态契约，以及能稳定触发并断言该状态的组件、浏览器或端到端测试；孤立截图不能证明触发与恢复闭环。
- **影响边界**：列明适用角色、任务、入口、数据与网络条件、状态持续范围、恢复责任、直接依赖恢复结果的后续动作，以及外部等待、后台处理或不可恢复情形。
- **复核入口**：用受控数据、响应或网络条件触发各状态，检查信息、允许动作、焦点或通知、重试／修正／等待／人工处理路径、刷新重进及最终结果，并明确无法稳定模拟的生产故障。
- **变更规则**：当前稳定状态恢复契约尚未入册为 `ADD`；进入条件、信息、允许动作、反馈、退出、恢复、重进结果、证据或边界变化为 `UPDATE`；状态不再可达且无当前消费者为 `DELETE`；仅内部错误码或状态变量重命名且四栏未变为 `NO_CHANGE`。
- **专属禁项**：不得记录堆栈、内部错误码清单、事故时间线、瞬时故障、单次测试失败、理论上不可触发的状态、后台重试算法或把系统级容灾机制抄入体验事实。

## 事实类型：响应式能力保留

- **入册条件**：同一核心任务在当前支持的视口、方向、设备或输入方式下存在稳定的能力保留、重排、折叠或详情访问规则，并由真实渲染与操作验证不会静默丢失关键信息或动作。
- **主题合并键**：使用 `<核心任务或信息对象>|<响应式能力>`；跨多个视口保持同一任务能力的规则合并，任务能力或交互模式实质不同才分主题，不按单个断点、媒体查询或设备型号作键。
- **当前事实写法**：写明各代表场景必须保留的任务、关键信息与动作，内容如何重排、折叠、转详情或横向浏览，被收起能力如何发现和返回，以及长内容、键盘、滚动和方向变化时的连续性。
- **权威依据**：定位响应式布局与可见性逻辑、设计系统相关约束、真实组件入口及覆盖代表视口和输入方式的浏览器测试或截图断言；单一桌面截图和未执行媒体查询不能独立入册。
- **影响边界**：列明支持的最小／最大代表视口、方向、触控或键鼠方式、适用任务与内容长度、直接依赖能力的角色，以及尚未验证的设备、嵌入容器或极端缩放。
- **复核入口**：在固定代表视口、方向和输入方式下完成同一任务，检查关键信息与动作可达、无非预期遮挡溢出、折叠内容可发现、滚动与方向切换连续，并记录真实设备或软键盘限制。
- **变更规则**：当前稳定能力保留规则尚未入册为 `ADD`；保留能力、重排／折叠方式、可发现性、代表场景、支持边界、证据或未覆盖设备变化为 `UPDATE`；产品不再支持该任务或响应场景为 `DELETE`；仅像素微调且能力、边界和四栏均未改变为 `NO_CHANGE`。
- **专属禁项**：不得记录完整 CSS、逐断点像素表、设备市场清单、视觉稿尺寸、仅装饰性差异、未经真实渲染的响应式声明，或把桌面能力静默删除解释为移动端适配。

## 事实类型：无障碍体验契约

- **入册条件**：当前关键任务已有稳定的语义、键盘、焦点、辅助名称、错误关联、动态通知、对比、缩放或等价操作行为，并由自动检查加适用的人工操作证明其对真实任务有效。
- **主题合并键**：使用 `<关键任务或交互模式>|<无障碍能力>`；同一交互模式共享的语义与操作规则合并，任务或所需等价能力不同才分主题，不按单个 WCAG 条款、DOM 节点或缺陷编号拆题。
- **当前事实写法**：写明语义结构与阅读顺序、键盘可达和激活方式、焦点进入／返回／错误去向、辅助名称与关系、异步状态通知、颜色或图像替代、缩放与等价操作，以及适用标准或平台边界。
- **权威依据**：定位实际语义标记、交互与焦点逻辑、内容替代来源、项目采用的无障碍配置，以及覆盖关键任务的自动扫描、键盘测试和适用辅助技术测试；合规声明或扫描报告不能脱离当前实现独立支撑入册。
- **影响边界**：列明适用任务、角色、平台、浏览器、输入与辅助技术、缩放级别或标准版本、直接复用该模式的界面，以及尚未验证的辅助技术组合和第三方嵌入内容。
- **复核入口**：按真实任务执行键盘走查、焦点顺序与恢复、名称／角色／状态检查、错误关联、动态通知、对比与缩放验证，并记录所用浏览器和辅助技术版本及自动工具无法证明的人工边界。
- **变更规则**：当前稳定无障碍能力尚未入册为 `ADD`；语义、操作、焦点、名称、通知、替代、标准、平台边界、证据或复核组合变化为 `UPDATE`；交互模式和所有消费者消失为 `DELETE`；仅 DOM 重排且可观察无障碍契约及定位均未改变为 `NO_CHANGE`。
- **专属禁项**：不得记录“完全无障碍”等无限合规声明、只凭自动扫描得出的结论、缺陷工单流水、辅助技术用户个人数据、纯视觉偏好、组件内部实现清单或未验证的浏览器兼容推断。

## 全册安全与历史边界

- 不记录任务摘要、设计过程、研究流水、进度、待办、责任人、候选方案、历史版本、前后对比、提交说明、截图集或本轮变更摘要。
- 不记录凭据、令牌、密钥、个人信息、真实用户输入、受限业务数据或可被用于越权的敏感操作细节；操作证据必须使用安全身份和脱敏数据。
- 不因文字润色、标题变化或事实顺序调整制造变更；每一处写入都必须能够归入上述某一事实类型并通过其八项规则。

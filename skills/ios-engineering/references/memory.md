# iOS 工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/ios-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始相关工作前读取已有事实；仓库中的当前权威实现与契约优先于旧事实。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程和一次性结果。

## 核心记忆

### Target 与交付边界

- 记住 App、Extension、Package 与共享能力的稳定职责和依赖方向，以及 App Group、Entitlement、签名能力与分发渠道形成的交付边界。
- 记住各 Target 的入口、资源与运行配置来源，避免共享代码调整越过扩展进程、沙箱或系统时限。

### Scene 生命周期与恢复

- 记住关键任务状态由 App、Scene 还是持久层持有，以及前后台、Scene 重建、系统终止后重启时必须恢复或失效的内容。
- 记住多窗口之间的状态隔离与共享关系，并确保 Scene 释放、任务取消和恢复不会重复执行外部副作用。

### 导航与系统入口

- 记住核心任务的导航状态、完成去向与返回关系，以及 Universal Link、自定义 URL、通知、Spotlight 和系统分享入口如何映射到既有任务。
- 记住冷启动与暖启动、多 Scene 选择、重复入口、非法参数和无权访问时的统一承接边界。

### UI 状态与平台适配

- 记住页面和共享组件的状态所有者、一次性事件归属，以及 SwiftUI 与 UIKit 并存时的数据流和生命周期边界。
- 记住 iPhone、iPad、多任务窗口、键盘指针、Dynamic Type、VoiceOver、深浅外观和 RTL 下必须保留的内容、操作与焦点关系。

### 数据权威、离线与并发

- 记住服务端、本地持久层、缓存和内存状态各自的权威角色，以及离线启动、账户切换、App 与 Extension 共享数据时的隔离边界。
- 记住持久模型迁移、同步冲突与部分失败的收敛原则，以及任务取消、Actor 隔离和主线程更新必须维持的并发所有权。

### 后台工作、通知与扩展

- 记住后台刷新、处理任务、音频或定位等获准模式与通知唤醒各自承担的职责，以及系统调度和到期终止下不可承诺的时效。
- 记住后台任务和 Extension 的幂等、取消、数据共享与资源上限，避免重复唤醒或进程分离造成重复业务副作用。

### 隐私、身份与受保护数据

- 记住每项隐私授权与用户任务的绑定关系，以及拒绝、撤销、受限状态和系统设置变更后的替代路径。
- 记住 Keychain、Data Protection、凭据和敏感缓存的可用与清理边界，以及 URL、WebView、粘贴板和跨进程数据的信任边界。

### 系统兼容与性能退化

- 记住最低系统范围、能力可用性检查和缺失能力时的退化路径，包括不同设备形态与多任务状态下必须保留的核心任务。
- 记住启动、主线程、渲染、内存、能耗和安装体积的项目级约束，以及哪些判断必须以代表性真机和发布构建为准。

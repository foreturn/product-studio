# iOS 工程执行契约

## 目标

约束被本专业命中的 iOS 工作，使结论、实现、验证和项目记忆均以当前仓库证据为准，并保持在 iOS 工程所有权内。

## 执行协议

1. 确认本次 iOS 工程裁决范围、受影响入口、消费者与验证边界。
2. 阅读 [专业能力准则](references/principles.md) 的能力索引，并完整读取本次实际命中的能力条目。
3. 阅读 [项目记忆](references/memory.md) 的使用方式与本次命中的核心主题，依其定位规则唯一确认目标 Git 根与 `product-id` 后，再读取 `docs/product-studio/<product-id>/ios-engineering.md` 中与本次工作相关的已有事实；项目记忆只作背景，当前代码、配置、调用链与设备证据优先。
4. 在授权范围内完成最小充分实现或审查，不改写其他专业已确认的语义。
5. 运行与风险相称的检查，核对最终差异、设备可观察结果及未覆盖边界。
6. 若本轮改变了 [项目记忆](references/memory.md) 所列的核心认知，在既有写权限内更新或移除事实册中的旧内容；没有变化时不触碰事实册。

## 输出契约

- 给出 iOS 工程裁决、实现或审查结果及其适用边界。
- 列出实际修改的文件、保持不变的关键契约和剩余未知项。
- 记录已运行验证、关键结果、证据能证明的范围与不能证明的范围。
- 项目记忆不得收录任务摘要、实施过程、文件改动清单、当前运行快照或一次性验证结果。

## 完成条件

- 请求范围内的 iOS 工程目标已经实现或形成有证据的裁决。
- 受影响行为取得风险相称的静态、自动化、模拟器或真实设备验证。
- 最终差异仅含授权范围，外部契约、风险与证据缺口均已明示。
- 已读取相关项目记忆；核心认知发生变化时，事实册已在授权范围内更新并与当前权威一致。

## 停止条件

- 缺少会实质改变实现方向、用户结果或安全边界的必要契约。
- 仓库状态、目标产品、Target 或授权范围无法唯一确认。
- 所需设备、系统能力、签名身份或外部决定不可得，且替代证据不足以支持结论。
- 继续操作将越过用户授权或其他专业的唯一决策权。

## 权限与边界规则

- 只修改请求授权且属于当前产品范围的文件，不回滚或整理无关改动。
- iOS 工程拥有 Apple 移动端客户端实现裁决；产品价值、系统边界、服务端契约、安全政策和发布授权不由本技能重定义。
- 不因本技能命中而规定其他技能的选择、顺序、并行关系或交接方式。
- 不实施未经授权的签名、TestFlight 或 App Store 分发、生产数据操作及外部系统变更。
- 不把交付摘要、排查过程、设备或模拟器快照、当前版本与运行状态写入事实册。

## 项目记忆

- 工作前读取 `references/memory.md` 的使用方式与本次命中的核心主题，依其定位规则唯一确认目标 Git 根与 `product-id` 后，再读取 `docs/product-studio/<product-id>/ios-engineering.md` 中的相关内容；归属不唯一或名称不安全时不猜测或创建事实册，事实册不存在时以当前仓库为准。
- 项目记忆仅作上下文；与当前代码、配置、契约或已验证设备行为冲突时，以当前权威为准。
- 本轮改变核心认知时，在现有写权限内更新或移除旧内容；不得因本节扩大写入范围。
- 只保留当前仍成立的项目核心认知，不记录秘密、用户数据、任务过程或一次性结果。

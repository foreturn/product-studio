# frontend 当前代码事实记忆

本文件是 `frontend` 记忆的唯一规则与实例格式，目标实例为 `<项目根>/docs/product-studio/frontend.md`。只由 `frontend` 维护；其他技能可读取相关主题，不复制正文。

## 收录门槛

- 只记最终代码当前已经执行的界面任务、交互状态、恢复行为、布局、响应式、可访问性和共享设计约束；事实须有权威代码定位、可复用验证入口，且预计后续编码仍会使用。
- 每个主题只描述一个共同检索、共同变化的稳定语义，不按任务、提交、文件、路由、组件、样式值、选择器、Symbol、截图或测试机械拆分。
- 重构、迁移、改名、组件替换和样式改造只是重新核对记忆的触发器，不得成为主题或事实正文；未完成阶段、临时双轨和执行进度不入册。
- 可从路由、组件注册、令牌或源码生成的完整清单不抄入记忆；只有最终仍成立的用户行为和多消费者约束才按当前状态记录。

## 实例格式

首次确有事实时创建同名事实册；没有事实时不得创建文件。主题使用简短、可读且稳定的业务语义，不含 Owner、类型前缀、路径、日期、任务号或变更动作。

```markdown
# frontend 当前代码事实

## <稳定事实主题>

- **当前事实**：<最终代码现在执行的一项界面任务、状态转换、恢复行为、布局或共享设计约束>
- **代码定位**：<一至三个 `仓库相对路径#精确位置`，精确位置使用权威路由、组件、令牌、hook、store 或样式 Symbol>
- **影响范围**：<直接依赖的页面、组件、请求、状态拥有者、下游复用者及不得破坏的当前关系；无则写“无”>
- **验证入口**：<可重复使用的测试、浏览器旅程或检查入口，以及关键状态、视口、断言和稳定未覆盖边界>
```

## 终态同步

1. 编码任务完成且最终代码取得相称验证后，对照最终差异与现有主题重新判断当前事实。
2. 同一语义原位改写；代码搬移只改“代码定位”；事实或最后消费者消失时删除主题，不追加变更、重构或迁移历史。
3. 只有四字段之一实质变化才写文件；没有总结事实变化时报告 `memory: 0 facts changed`。
4. 最后一个主题删除后移除整册；写后检查主题、定位、消费者和验证入口，再运行项目校验。

## 禁止内容

- 任务摘要、文件清单、进度、待办、责任人、候选方案、过程推理、前后对比、取代关系和历史版本。
- “从 A 迁移到 B”“本轮重构”“临时兼容”“改造阶段”等过程事实，以及单轮通过、临时失败、命令流水、制品、截图时间和 commit SHA。
- 未实现目标、外部资料、其他项目事实、密钥、令牌、用户数据、环境秘密，以及其他 Owner 已保存的同一事实正文。

历史由 Git 承担，长期设计缘由留在项目既有 ADR 或正式文档。静态校验只能证明当前快照的结构和定位自洽；语义新鲜度必须由 `frontend` 对照最终差异同步。

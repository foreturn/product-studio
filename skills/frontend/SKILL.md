# 前端工程与体验

以已确认的用户任务和接口契约为准，只作最小必要修改；不得以视觉偏好改写业务规则。

## 输入门禁

- 明确当前项目根、仓库指令、目标用户、真实入口、核心任务、成功结果和不得破坏的现有能力。
- 读取相关产品事实、存在时的 `docs/product-studio/frontend.md` 中与目标页面、令牌、组件、布局和状态有关的总结性代码事实，以及现有设计系统、路由、组件、样式和请求层。
- 核对 API 请求、响应、错误、权限、分页、幂等和兼容行为；接口语义不清时交给 `$backend`，不得在前端猜造服务端规则。
- 用户、旅程、业务闭环、范围或体验目标未定时调用 `$design`；跨模块系统边界、数据所有权、共享不变量、信任边界或系统级质量约束未定时交给 `$architecture`；具体接口字段、错误、权限和一致性实现未定时交给 `$backend`。仅限前端内部的组件与状态边界由本技能裁定。
- 同时牵涉前后端共享契约时由 `$router` 选择最小代码技能链；单一局部前端改动可直接执行本技能并交 `$verification` 验收，常规终端验收本身不触发 `$router`。

## 专业能力

先查看 [前端设计与用户体验专业准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及整体体验、交付收口或风险复核时，再读“常见误判”。

## 实施流程

按实际改动裁剪步骤；纯令牌、样式或响应式修复只追踪相关源码、消费者与可见不变量，并作聚焦渲染验证，不扩成页面重设计或接口重审。

1. 从与改动直接相关的真实入口走查现状，建立所需的页面、组件、样式、请求或状态调用链；只记录本次会改变或必须保持的令牌、组件与消费者。
2. 信息架构、主动作或页面结构受影响时，先固定任务顺序、关键内容与最短路径；明确的令牌或样式修复可直接从权威变量、组件变体和使用方入手，不重做无关旅程。
3. 数据、动作或异步状态受影响时，建立适用且可达的状态矩阵，覆盖初始、加载、刷新、空白、权限、禁用、提交、部分成功、失败、成功、取消、重试、乱序响应和恢复；不适用状态须有契约依据，并防止重复提交及旧响应覆盖新状态。
4. 复用现有语义令牌、组件、图标和交互模式；只有现有体系无法表达当前稳定需求且有真实消费者时才新增公共令牌或组件。
5. 布局或响应式行为受影响时，按内容优先级设计容器、网格、断点、重排、溢出和滚动；只选择与目标表面相关的长文案、密集数据、国际化、触控、虚拟键盘或安全区域边界样本。
6. 使用语义元素实现键盘、焦点、名称、错误关联、动态通知、对比、减少动画和缩放支持；ARIA 或组件库声明不能代替实际检查。
7. 运行聚焦测试、静态或类型检查、代码检查和构建；随后在项目规定的浏览器、设备与视口，用真实或边界数据完成核心任务和高价值失败或恢复路径。
8. 检查控制台、网络、资源加载、文本溢出、裁切、滚动、布局跳动和交互结果；截图只证明对应帧，不能代替真实操作。
9. 核对最终差异和消费者。
10. 在终态回复前执行记忆同步检查，报告实际增改删的事实主题；没有总结性事实变化时报告 `memory: 0 facts changed`。

## 当前代码事实记忆

开始工作时，若 `<当前项目根>/docs/product-studio/frontend.md` 存在，只读取命中的事实主题及直接关联。每次编码任务收口前完整读取 [frontend 记忆规则与实例格式](references/memory.md)，仅按最终代码同步 `frontend` 自己的事实册；首次确有事实时使用其中格式，不得预建空册。重构、迁移和变更过程不入册；没有总结性事实变化时报告 `memory: 0 facts changed`。

## 输出与交接

- 符合现有技术栈与设计系统的页面、组件、样式、状态逻辑和聚焦测试，以及信息架构、令牌、组件变体、交互状态、响应式与可访问性决定的实现说明。
- 真实浏览器、视口、状态、数据、控制台和网络证据，以及执行过的检查和已知缺口。
- 向 `$verification` 交付真实入口、身份、数据、状态矩阵、浏览器／视口要求和复现步骤。
- 实现发现系统边界、数据所有权或共享不变量冲突时退回 `$architecture`；发现具体 API 字段、错误或权限实现不清时退回 `$backend`。

## 完成门禁

- 核心任务从真实入口可完成；主动作、结果、恢复路径及所有适用且可达状态均有明确界面行为。
- 页面信息层级与任务顺序一致，设计令牌和组件变体来自真实源码且消费者明确，没有无依据的局部视觉体系。
- 重复、取消、乱序、过期、权限和部分失败不会形成矛盾状态。
- 目标视口下的重排、溢出、触控、虚拟键盘、长内容和布局稳定性经真实检查。
- 核心旅程在声明范围内支持键盘、可见焦点、语义、名称、错误关联、对比、缩放和减少动画。
- 聚焦测试、类型或构建检查与真实渲染证据各自守住证据边界；无法取得的浏览器或设备证据明确标为缺口。

## 边界

- 可在已确认产品和接口契约内裁决信息层级、交互反馈、组件边界、令牌使用、响应式布局、可访问性和前端状态实现。
- 不自行发明产品范围、业务规则、权限模型、接口错误或服务端一致性语义；产品与体验目标缺口交给 `$design`，系统架构缺口交给 `$architecture`，具体接口缺口交给 `$backend`。
- 新依赖、公共组件或设计令牌必须有现有方案不足和真实消费者证据，不为未来预留抽象。
- 本技能止于前端代码和浏览器验证，不执行外部环境操作；是否通过由 `$verification` 独立裁决。

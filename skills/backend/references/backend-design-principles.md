# 后端工程能力准则

按当前改动涉及的服务端行为与风险选择能力卡。后端能力把已确认的产品行为和架构不变量落实为具体领域规则、API、Schema、权限、一致性、运行信号与测试，不重新发明产品范围或跨边界语义。

## 能力目录

- **领域建模**：业务状态、允许动作、拒绝原因或规则在多个服务端入口间需要统一时启用。
- **API 与错误契约**：HTTP、RPC、事件或自动化调用方的字段、错误、分页、幂等、版本与兼容行为发生变化时启用。
- **数据建模与迁移**：持久化结构、约束、索引、查询、生命周期、回填或新旧 Schema 共存发生变化时启用。
- **权限与安全**：身份、资源、租户、数据范围、敏感信息、审计或滥用风险涉及服务端可信边界时启用。
- **一致性与并发**：状态变化可能遭遇重复请求、竞态、乱序、跨资源部分成功或进程中断时启用。
- **集成与可靠性**：外部依赖、缓存、消息、批任务、定时任务、Webhook 或回调参与业务结果时启用。
- **性能与可观测性**：关键路径需要容量控制、性能证据、背压、日志、指标、追踪或健康语义时启用。
- **测试策略**：按改动风险证明领域、契约、权限、真实持久化、迁移、并发、幂等和故障行为时启用。

## 核心能力

### 领域建模

- **启用**：
  - 改动引入或改变业务动作、状态转换、拒绝原因、领域不变量或跨入口共享规则。
  - 同一规则可能经 HTTP／RPC、消息消费者、定时任务、批处理、管理脚本或回调触发。
- **输入**：
  - 已确认的产品行为、架构不变量、授权边界、兼容承诺和验收标准。
  - 当前控制器、服务、任务、消费者、数据库、缓存、消息和外部副作用调用链。
  - 现有实体、状态字段、约束、历史数据语义和全部调用方。
  - 外部协议或其他项目实现只作为带版本、来源和差异的参考，不作为当前事实。
- **执行**：
  - 从业务动作、状态变化和拒绝条件识别实体、值对象、聚合与领域服务。
  - 为有生命周期的对象建立状态转换表，列出起始状态、动作、前置条件、目标状态、副作用、失败语义和可否重试。
  - 将不变量写成可执行断言，放在拥有状态的模块中；控制器、任务和消费者只适配输入，不各自复制判断。
  - 明确金额的币种、精度和舍入，时间的时区、日界线和精度，标识的租户或全局作用域，以及空值、枚举和删除状态的单一语义。
  - 用命令表达改变状态的业务意图，用查询表达读取需求；查询不产生隐藏业务副作用，命令返回足以识别结果和后续状态的稳定信息。
- **裁决**：
  - 数据库实体只是持久化表达，不自动等同于完整领域模型。
  - 聚合只覆盖一次事务必须保持的规则；跨聚合行为必须选择最终一致、补偿、对账或人工处置，不能用超大事务掩盖边界问题。
  - 若状态转换或拒绝条件散落在控制器、任务和消费者中，判定规则尚无唯一责任位置。
  - 若共享不变量、数据所有权或跨服务语义尚未确认，暂停具体实现并请求 `architecture` 裁决。
- **产出**：
  - 领域与不变量表：实体、值对象、状态、动作、前置条件、目标状态、拒绝原因、执行位置、数据库保护和恢复方式。
  - 状态转换表和命令／查询清单。
  - 所有服务端入口到领域规则、权威数据、下游副作用与用户结果的调用图；图中同时标明正常、拒绝和失败路径，并消歧重复规则与权威来源。
  - 规则唯一执行位置及各适配入口的责任映射。
- **验证**：
  - 沿 HTTP／RPC、消费者、任务、批处理、脚本和回调逐一验证同一动作共享同一状态转换规则。
  - 覆盖每条状态转换、不变量、边界值、非法动作和时间相关规则，断言业务结果而非内部方法调用次数。
  - 通过数据库约束或并发场景证明不可违反事实，不能只靠入口校验或模拟仓储。
  - 核验查询无隐藏写入，命令在成功、拒绝与重试时均返回稳定语义。
- **完成**：
  - 产品行为和架构不变量均有唯一领域规则位置、明确拒绝语义及数据库保护责任。
  - 全部服务端入口共享规则，没有控制器或任务旁路。
  - 金额、时间、标识、空值、枚举和删除语义无歧义。
  - 领域测试与真实持久化证据可以映射到每项关键不变量。
- **边界**：
  - 不重新定义未经确认的用户旅程、业务范围或跨边界不变量。
  - `architecture` 裁决跨边界状态所有权和一致性目标；本能力决定这些约束在服务端代码中的具体归属。

### API 与错误契约

- **启用**：
  - HTTP、RPC、事件或自动化入口的操作语义、请求响应、错误、认证授权上下文、分页、幂等、版本或兼容行为发生变化。
  - 新增调用方，或旧客户端需要在兼容期继续工作。
- **输入**：
  - 已确认的用户动作、领域状态转换、权限和数据范围。
  - 前端、其他服务、任务、消费者、脚本及外部集成的当前调用样本。
  - 现有路由、DTO、权威 Schema、序列化结果、错误处理和使用观测。
  - 外部 API 文档的版本、来源、差异与拟借鉴部分。
- **执行**：
  - 让操作名称及 HTTP、RPC 或事件语义对应真实副作用，并明确创建、替换、局部更新、删除和动作型操作的重复调用行为。
  - 请求只包含调用方有权控制的字段；主体身份、租户、权限、审计字段和服务端计算结果从可信上下文生成或复核。
  - 分层校验结构、类型、长度、格式、跨字段关系、资源存在性和业务规则，让错误定位到可行动字段或业务条件而不泄露实现。
  - 使响应最小、稳定且可扩展，统一标识、时间、金额与枚举表达；显式区分资源缺失、字段未返回和值为空。
  - 至少区分参数无效、认证失败、授权不足、资源不存在、状态冲突、重复操作、限流、依赖失败和内部故障，并规定调用方能否修正或重试。
  - 列表契约规定稳定排序、游标或偏移的适用条件、筛选组合、最大页长、空结果和数据变化期间的翻页一致性。
  - 写操作规定幂等键作用域、请求指纹、有效期、并发竞争、处理中反馈和重复响应。
- **裁决**：
  - 所有失败返回同一状态或错误码会使调用方无法区分修正输入、重新认证、停止重试和稍后恢复，判定契约不完整。
  - 只保存幂等键却不关联原请求、处理中状态与最终结果，不能证明幂等。
  - 契约演进优先增加式兼容；破坏性变化必须有版本、迁移窗口、使用观测、退役条件和旧客户端失败行为。
  - 外部示例响应或其他项目 Schema 未经本地代码、权限模型和调用方核验，不得直接成为当前契约。
- **产出**：
  - 请求、响应、错误码、认证授权、数据范围、分页、筛选、幂等、超时、版本和兼容定义。
  - 每类调用方的成功、拒绝、失败、重试和旧版本样例。
  - 权威 Schema 与实际序列化结果的对应关系。
  - 调用方兼容清单、迁移窗口、退役条件和剩余风险。
- **验证**：
  - 契约测试覆盖请求响应、字段兼容、错误分类、分页、幂等和旧调用方样本。
  - 比对权威 Schema、实际序列化结果与运行时错误映射。
  - 验证相同幂等键同请求返回同一结果、不同请求被拒绝、处理中重入有确定反馈。
  - 逐一核对前端、服务、任务、消费者、脚本和外部集成在兼容期的行为。
- **完成**：
  - 每类调用方无需猜测字段来源、错误可否重试、分页一致性、重复调用和版本退役行为。
  - 不可信字段不能覆盖身份、租户、权限、价格、审计或服务端计算结果。
  - 权威 Schema、实现与契约测试一致，旧调用方的失败方式明确且可观察。
- **边界**：
  - 跨服务操作语义、数据主权或兼容承诺由 `architecture` 裁决。
  - 本能力决定已确认语义的具体字段、状态码、错误码、序列化、分页和幂等表达。

### 数据建模与迁移

- **启用**：
  - 表、字段、关系、约束、索引、查询模式、删除或保留语义发生变化。
  - 需要回填、滚动发布、新旧 Schema 共存、大表变更或数据修复。
- **输入**：
  - 数据所有者、业务含义、来源、访问模式、生命周期、合规保留和恢复要求。
  - 当前 Schema、数据分布、行数与增长、查询谓词、连接、排序和执行计划。
  - 新旧应用与 Schema 版本、历史脏数据、发布方式和数据库运行限制。
  - 搜索索引、缓存、事件、备份与审计链等派生或关联数据。
- **执行**：
  - 用唯一、外键、非空、检查约束和合法状态组合承接不可违反事实；应用校验提供友好错误，但不独自承担并发安全。
  - 为表和字段记录数据所有者、业务含义、来源、生命周期、保留、归档、软删或硬删、审计及恢复要求，避免临时派生值成为无主事实源。
  - 依据查询谓词、连接、排序和数据分布设计索引，检查组合顺序、选择性、覆盖收益、写放大、重复索引及执行计划。
  - 识别 N+1、全表扫描、无界结果、重复聚合和过宽行；批量读取、投影与预计算仍须保持权限范围和陈旧度语义。
  - 让隔离级别对应实际竞态；读后写、范围约束和库存扣减使用唯一约束、条件更新、锁或序列化策略。
  - 删除与匿名化覆盖外键、搜索索引、缓存、事件、备份和审计链，说明立即消失、延迟清理和合法保留的数据。
  - 按兼容扩展、应用双兼容、分批回填、校验、读写切换、约束收紧和旧结构清理编排迁移。
- **裁决**：
  - 不为每个字段机械建索引；没有查询与数据分布依据的索引不进入方案。
  - 不能依赖低并发假设解决读后写或范围竞态。
  - 大表变更必须评估锁模式、扫描量、事务时长、复制延迟、日志增长和磁盘余量，并采用小批次、断点、限速和可重入设计。
  - 新旧应用与新旧 Schema 的所有允许组合必须安全读写；旧版本或旧数据使用量未归零前不得清理。
  - 迁移命令成功退出不等于数据正确。
  - 代码、Schema、数据和外部副作用的可逆性分别判断；无法安全逆向的数据采用前滚修复、备份恢复或人工纠正。
- **产出**：
  - Schema、约束、索引、查询模式和执行计划依据。
  - 数据生命周期、删除、匿名化、归档、审计及恢复设计。
  - 迁移阶段、兼容矩阵、回填批次、检查点、限速、暂停／恢复和清理条件。
  - 回填范围、游标、成功数、跳过数、失败样本和重跑方式。
  - 代码、Schema、数据与外部副作用分别对应的回滚、前滚或人工方案。
- **验证**：
  - 使用真实数据库验证唯一、外键、非空、检查约束、事务、锁和隔离行为；模拟仓储不能替代此证据。
  - 用真实参数与数据分布检查执行计划、扫描行数、选择性、排序和写放大。
  - 从包含边界与脏数据的旧版本样本执行升级、重跑、暂停、恢复和校验。
  - 回填期间持续写入，确认没有永久空洞，检查点可恢复且步骤可重入。
  - 校验行数、非空率、唯一性、聚合对账、抽样语义和业务指标，并验证滚动发布兼容矩阵。
- **完成**：
  - 不可违反事实具有数据库保护，查询和索引有实际访问模式与执行计划依据。
  - 每个迁移阶段具有独立进入条件、完成判据、暂停和恢复路径。
  - 所有允许的新旧代码与 Schema 组合均经验证。
  - 数据正确性由对账和语义抽样证明，旧结构仅在使用量归零后清理。
- **边界**：
  - 跨系统数据主权和迁移兼容承诺由 `architecture` 裁决。
  - 本能力负责具体 DDL、约束、索引、查询、回填批次和服务端兼容实现；生产迁移授权与执行由 `release` 管理。

### 权限与安全

- **启用**：
  - 请求涉及认证主体、动作权限、资源所有权、租户或数据范围。
  - 改动处理密码、令牌、密钥、个人数据、高价值动作或高成本入口。
  - 新增外部输入、导出、批量、搜索、文件、回调或管理入口。
- **输入**：
  - 架构确认的信任边界、身份来源、数据分类与授权责任。
  - 所有服务端入口、资源关系、租户模型、角色和权限版本。
  - 敏感信息在传输、存储、缓存、日志、异常、追踪和备份中的流向。
  - 按实际入口识别注入、越权、重放、SSRF、路径穿越、不安全反序列化、文件炸弹、批量枚举与资源耗尽风险。
- **执行**：
  - 认证后逐项校验动作权限、资源所有权、租户和数据范围。
  - 让列表、详情、搜索、导出、批量和间接关联入口使用一致授权规则。
  - 在同一可信服务端边界完成授权查询和业务读取，禁止“先取全部再过滤”。
  - 对外部输入使用结构化解析、参数化查询和允许范围。
  - 保护密码、令牌、密钥和个人数据，错误响应不暴露堆栈、查询或内部拓扑。
  - 按滥用成本为登录、验证码、搜索、导出及高成本操作设置速率、配额、并发和结果大小限制，并使限制维度适配代理网络。
  - 高价值状态变化记录主体、代理主体、资源、前后状态或摘要、动作、结果、时间和关联标识。
- **裁决**：
  - 客户端隐藏、网络位置、调用方传入的角色与租户均不能代替服务端授权。
  - 安全失败默认不扩大权限；依赖不可用时明确拒绝、受控降级或只读行为。
  - 缓存授权结果必须包含主体、资源、权限版本和失效条件。
  - 拒绝响应应按契约决定是否隐藏资源存在性，不能泄露越权对象信息。
  - 审计日志自身须有访问和防篡改边界，不能为排障记录完整令牌或非必要敏感载荷。
- **产出**：
  - 身份、动作、资源、租户和数据范围的授权矩阵及具体检查点。
  - 输入边界、滥用场景、速率／配额／并发限制和失败策略。
  - 敏感字段在传输、存储、缓存、日志、追踪和备份中的保护清单。
  - 高价值动作审计事件定义与访问、防篡改边界。
- **验证**：
  - 至少覆盖匿名、无权、资源所有者、他人资源、跨租户、列表、详情、搜索、导出和批量路径。
  - 验证拒绝时不泄露资源存在性或数据，安全依赖故障时权限不扩大。
  - 对实际入口执行适用的注入、越权、重放、SSRF、路径穿越、反序列化、文件炸弹和资源耗尽测试。
  - 检查响应、日志、异常、追踪、缓存、备份和审计中无完整凭据与非必要个人数据。
  - 验证审计可关联主体、对象、动作、结果与时间。
- **完成**：
  - 每个受保护入口在可信服务端同时校验身份、动作、资源、租户与数据范围。
  - 敏感信息全链路保护，真实滥用路径具有控制及测试映射。
  - 高价值动作可审计，授权依赖失效或缓存陈旧不会扩大权限。
- **边界**：
  - `architecture` 裁决跨边界身份传播、数据分类和授权责任。
  - 本能力负责具体服务端权限查询、输入校验、限流、凭据处理和审计持久化。

### 一致性与并发

- **启用**：
  - 写操作可能被重复提交、并发竞争或乱序处理。
  - 状态变化跨事务、聚合、消息或外部副作用，可能部分成功或进程中断。
- **输入**：
  - 架构确认的一致性目标、允许中间状态、失败语义和恢复责任。
  - 状态机、事务提交点、锁定资源、唯一约束、调用重试和消息投递语义。
  - 每项外部副作用的可撤销性、补偿资格与人工恢复入口。
- **执行**：
  - 为每个状态变化标明原子边界、锁定资源和提交时刻。
  - 把不受控网络调用放在数据库事务之外，通过状态机、事务发件箱或补偿衔接。
  - 冲突较少且可反馈重试时使用乐观锁；短事务和高价值竞争可使用悲观锁，同时规定锁顺序、等待上限与死锁处理。
  - 用唯一约束和条件更新承担最终竞态裁决，应用层预查询只用于改善提示。
  - 使幂等记录与业务提交具有原子关系，保存请求指纹、处理中状态和最终响应；相同键不同请求拒绝，处理中重入返回确定反馈。
  - 消费者处理重复、乱序与毒消息，使去重状态和业务副作用处于同一事务或可恢复协议中，并在确认消息前完成可证明持久化。
  - 为跨资源部分失败保留每一步完成状态、关联标识与补偿资格，使恢复动作自身也幂等。
- **裁决**：
  - “先查询再创建”不能防止并发重复，最终唯一性必须由约束、条件写或锁裁决。
  - 悲观锁没有统一锁顺序、等待上限和死锁处理时不得采用。
  - 在数据库事务内等待不受控网络调用会延长锁、耗尽连接并放大外部故障，判定不可接受。
  - 幂等只记键、不校验请求指纹、不保存处理中和最终结果时，判定无法抵御并发重入。
  - 无法自动撤销的外部副作用必须进入对账或人工队列，不能伪装为事务回滚。
- **产出**：
  - 状态变化的原子边界、锁定资源、提交点和冲突裁决表。
  - 幂等键作用域、请求指纹、处理中状态、最终响应和有效期设计。
  - 重复、竞态、乱序、部分成功和进程中断到事务、锁、去重、补偿与最终状态的矩阵。
  - 发件箱、补偿、对账或人工恢复的状态与关联标识。
- **验证**：
  - 用同步屏障或并行请求制造竞态、重复和重试。
  - 断言最终状态、响应一致性、唯一性和外部副作用次数。
  - 在事务提交、消息确认和外部调用前后中断进程，核验持久化、重放与恢复。
  - 制造相同键不同请求、处理中重入、消息重复、乱序和毒消息。
  - 使用真实数据库验证隔离、锁、条件更新和唯一约束，不能仅依赖 mock。
- **完成**：
  - 每个写操作具有明确原子边界、冲突裁决和重复调用行为。
  - 幂等状态与业务提交可恢复，消息确认前已有可证明持久化。
  - 每个部分成功状态可观察、可重放、可补偿、可对账或可人工处理。
- **边界**：
  - `architecture` 决定跨边界一致性目标和业务可接受的中间状态。
  - 本能力选择并实现具体事务、锁、唯一约束、幂等记录、发件箱、补偿和对账机制。

### 集成与可靠性

- **启用**：
  - 外部 API、数据库外依赖、缓存、消息、批处理、定时任务、Webhook 或回调参与用户结果或状态变化。
- **输入**：
  - 外部契约版本、认证、配额、超时、错误分类、幂等、数据敏感性和降级承诺。
  - 缓存权威来源、消息生产事务、任务执行方式、回调安全机制和当前运行指标。
  - 用户总超时、允许陈旧度、重复与乱序语义、恢复责任和人工入口。
- **执行**：
  - 用适配层隔离外部模型与领域模型，并记录外部版本和本地差异。
  - 设置连接与请求的分层超时；重试只覆盖明确可恢复且幂等的操作，并规定次数、退避、抖动和总时限。
  - 用熔断、并发隔离和背压保护核心资源。
  - 为缓存定义键空间、权威来源、TTL、主动失效、容量、淘汰、陈旧容忍和故障行为，并分析穿透、击穿、雪崩及权限或租户串读。
  - 选择旁路、写穿、写后或事件失效时，写明数据库成功而缓存失败、消息延迟和并发更新下的可接受结果。
  - 为消息定义生产事务、Schema、分区键、顺序、投递语义、消费者幂等、重试、死信、重放和版本兼容。
  - 让批处理和定时任务使用稳定分页或游标、检查点、并发限制、租约或唯一执行、失败项隔离和可重入步骤。
  - Webhook 与回调校验来源、签名、时间窗、重放、乱序和重复，先持久化可恢复事实，再触发可能失败的后续处理。
- **裁决**：
  - 网关、服务、客户端和任务不得在缺少共享总超时与幂等语义时叠加重试。
  - 缓存键遗漏租户、用户或权限版本，或把缓存当权威数据，会造成越权串读和不可恢复不一致，判定不可接受。
  - 消息进入可持久化队列不等于业务可靠完成；生产事务、消费者提交、重复、乱序、毒消息、死信和对账缺一不可。
  - 批任务不得一次加载全部数据；Webhook 不得在验证和持久化前直接触发不可恢复副作用。
- **产出**：
  - 外部依赖适配契约、超时预算、错误映射、重试与降级表。
  - 缓存键、权威来源、失效、陈旧和故障矩阵。
  - 消息生产、消费、去重、重试、死信、重放与对账契约。
  - 批任务检查点、限速、租约、失败隔离和重入设计。
  - Webhook／回调验签、防重放、持久化及后续处理流程。
- **验证**：
  - 注入依赖超时、限流、断连和不可用，核验错误映射、总超时、重试次数、熔断、降级与资源隔离。
  - 制造缓存失效失败、消息延迟、重复、乱序、毒消息和进程中断。
  - 验证租户与权限维度缓存隔离，缓存清空后可从权威源重建。
  - 暂停并重启批任务，验证检查点、失败项隔离和可重入。
  - 对 Webhook 执行签名错误、过期、重放、乱序和重复样本。
- **完成**：
  - 每项依赖都具有明确超时、错误分类、幂等、降级、恢复和人工入口。
  - 缓存不会成为第二事实源或跨租户串读。
  - 消息、任务和回调在重复、乱序、失败及重启后均能收敛到可证明的业务状态。
- **边界**：
  - `architecture` 裁决跨边界同步或异步选择、允许陈旧度和恢复责任。
  - 本能力实现具体适配器、超时、重试、缓存、消息、任务和回调协议。

### 性能与可观测性

- **启用**：
  - 改动触及高频、高并发、大数据量、外部依赖、锁竞争或积压路径。
  - 关键旅程需要新增或修改日志、指标、追踪、健康检查和运行诊断信号。
- **输入**：
  - 业务关键路径、用户延迟与容量目标、实际或代表性负载和数据分布。
  - 查询、外部调用、序列化、锁、队列、内存、线程和连接池的当前基线。
  - 架构规定的业务成功、拒绝、失败、积压和健康语义。
- **执行**：
  - 测量查询、外部调用、序列化、锁等待、队列等待、内存和连接占用；优化前保留基线，优化后用同一负载复测收益和副作用。
  - 用真实参数和数据分布检查执行计划、扫描行数、回表、临时排序和锁；高频快查询仍计算总成本。
  - 为批量、并发和连接池设置上限与背压，避免把等待转移到线程、内存或队列；超载时优先保护核心写入和恢复能力。
  - 日志使用请求、任务或业务对象关联标识，记录动作、阶段、结果和错误分类。
  - 指标覆盖业务成功／拒绝／失败、延迟分位、吞吐、数据库与依赖错误、连接池、队列积压、重试和死信。
  - 追踪标出数据库、缓存、消息和外部调用的耗时与失败，并保持异步上下文关联。
  - 健康检查区分存活、就绪和核心业务依赖可用性。
- **裁决**：
  - 没有基线、瓶颈证据和失效语义时，不为假设高并发预先引入缓存、队列、分库或新服务。
  - 单次延迟改善若造成写放大、资源争用或长期复杂度，必须以总成本和用户收益重新判断。
  - 指标标签不得使用用户 ID 等高基数值。
  - 日志不得记录完整令牌、密码、敏感载荷或无边界堆栈；日志量增加不等于可观测。
  - 进程存活不得代替核心业务可用。
- **产出**：
  - 优化前后基线、同负载对比、资源预算和容量上限。
  - 查询执行计划、扫描和锁等瓶颈证据。
  - 背压、批量、并发和连接池限制及超载行为。
  - 业务旅程到日志、指标、追踪和健康信号的映射。
- **验证**：
  - 使用同一数据分布和负载复测延迟分位、吞吐、错误率及资源占用。
  - 在超过上限时核验背压和降级，不发生线程、内存、连接池或队列无界增长。
  - 从业务拒绝、依赖失败和积压样本通过关联标识定位具体阶段。
  - 检查指标基数、日志敏感字段、异步追踪连续性和存活／就绪／业务可用语义。
- **完成**：
  - 性能结论有可复现基线和同负载收益，副作用与容量上限明确。
  - 超载行为保护核心写入和恢复能力。
  - 运行人员可凭有限基数、无敏感泄露的信号区分业务拒绝、可恢复故障和系统缺陷。
- **边界**：
  - 跨服务质量目标和健康语义由 `architecture` 裁决。
  - 本能力实现具体查询优化、资源限制、日志、指标、追踪和健康端点；生产容量与告警门禁由 `release` 管理。

### 测试策略

- **启用**：
  - 任何服务端行为、契约、权限、Schema、一致性、依赖或运行信号发生变化时启用。
  - 风险涉及真实数据库、并发、迁移、消息或外部故障，单元测试不足以证明行为时重点启用。
- **输入**：
  - 产品验收标准、架构不变量、领域状态转换、调用方承诺和风险矩阵。
  - 实际改动面、所有入口、Schema 与迁移、依赖和现有测试覆盖。
  - 可使用的真实数据库、协议环境、故障注入方式和授权边界。
- **执行**：
  - 领域测试覆盖状态转换、不变量、边界值、非法动作和时间规则，断言业务结果。
  - 契约测试覆盖请求响应、字段兼容、错误分类、分页、幂等和旧调用方样本，并比对权威 Schema 与实际序列化。
  - 权限测试覆盖匿名、无权、所有者、他人资源、跨租户、列表、详情、导出和批量，验证拒绝时不泄露资源或数据。
  - 持久化测试使用真实数据库约束与隔离行为，覆盖唯一、外键、事务、锁、索引相关查询和旧数据兼容。
  - 迁移测试从含边界与脏数据的旧版本样本执行升级、重跑、暂停、恢复和校验，并覆盖滚动兼容矩阵。
  - 并发和幂等测试用同步屏障或并行请求制造竞态、重复和重试，断言最终状态、响应一致性和外部副作用次数。
  - 故障测试注入依赖超时、限流、断连、消息重复、进程中断和部分成功，验证错误映射、恢复、告警和敏感信息保护。
- **裁决**：
  - 测试层级按风险选择，不追求无关的全量覆盖。
  - 模拟仓储不能证明数据库约束、隔离、锁、索引或迁移行为。
  - 快乐路径单元测试不能证明并发、幂等、外部故障或恢复。
  - 外部协议 mock 只能证明本地分支；真实协议或真实依赖结论需要对应环境证据。
  - 未执行的测试不得标记通过，既有失败与本次回归必须分开。
- **产出**：
  - 风险到测试层级、用例、环境、命令和证据的映射。
  - 领域、契约、权限、数据库、迁移、并发、幂等和故障测试结果。
  - 实际序列化、真实约束、竞争结果、迁移校验和故障恢复等原始证据。
  - 未覆盖项、影响、阻塞原因与补证条件。
- **验证**：
  - 将每项结果反向映射到具体不变量、调用方承诺、Schema 约束或失败场景。
  - 核验测试使用的入口、数据库、协议和配置与声明的证据层级一致。
  - 对高风险结论复查实际最终状态、外部副作用次数和运行信号，不只看命令退出码。
  - 区分实现缺陷、环境阻塞、既有失败和本次回归。
- **完成**：
  - 适用的快乐、拒绝、边界、并发和恢复路径均有与风险相称的证据。
  - 模拟测试未冒充真实数据库、真实协议或真实故障证据。
  - 未覆盖项具有明确影响、补证条件和责任，不能被笼统“测试通过”掩盖。
- **边界**：
  - 本能力负责实现级和模块级验证。
  - 跨系统端到端验收由 `verification` 编排，生产迁移、容量和运行验证由 `release` 执行。

## 能力组合

1. 先确认产品行为、架构不变量、授权边界、调用方、兼容承诺和验收结果，将外部协议与当前项目事实分开；再从 HTTP／RPC、消息、任务、脚本和回调追到领域逻辑、数据库、缓存、依赖及用户结果。
2. 使用“领域建模”先固定实体、状态转换、允许动作、拒绝原因和规则唯一位置；涉及调用接口时组合“API 与错误契约”，使全部调用方的成功、拒绝、失败和重试行为确定。
3. 状态需要持久化时组合“数据建模与迁移”，依据访问模式决定 Schema、约束、索引和隔离；任何受保护资源同时组合“权限与安全”，在可信服务端检查动作、资源、租户和数据范围。
4. 存在重复、竞态、乱序或跨资源副作用时组合“一致性与并发”；接入外部依赖、缓存、消息、任务或回调时再组合“集成与可靠性”，推演依赖失败、缓存失效、积压和进程中断。
5. 需要结构演进时按兼容扩展、双兼容、回填、校验、切换、约束收紧和清理编排，逐一验证新旧代码和数据组合及代码、Schema、数据、外部副作用各自的恢复边界。
6. 沿用当前架构和既有约定实施最小完整改动；新服务、中间件或抽象必须解决已证明的边界或质量问题。遇到共享不变量、数据所有权、信任边界、跨服务质量目标或演进约束变化时，暂停实现并取得 `architecture` 裁决。
7. 对关键路径组合“性能与可观测性”，先保留基线，再布置业务状态、拒绝、失败、延迟、积压和依赖信号；最后使用“测试策略”按风险验证实现并核对全部调用方。

## 完成判据

- **领域证据完整**：领域与不变量表明确实体、状态、动作、前置条件、目标状态、拒绝原因、执行位置、数据库保护和恢复方式；所有入口共享规则，数据库表未被误作完整领域模型。
- **契约证据完整**：请求、响应、错误、授权、数据范围、分页、幂等、超时、版本和调用方样例与实际实现及权威 Schema 一致；旧调用方的适配、退役窗口和失败行为明确。
- **数据证据完整**：Schema、约束、索引、查询模式、执行计划或容量基线、生命周期与删除恢复具有可检查依据；迁移包含阶段、兼容矩阵、回填检查点、限速、校验、暂停／恢复、回滚或前滚和清理条件。
- **并发与可靠性可证明**：竞态、重复、乱序、超时、限流、部分成功和进程中断分别映射到事务、锁、去重、重试、补偿、对账和最终状态；不能用“先查后写”、单个幂等键或消息入队冒充可靠完成。
- **安全证据完整**：身份、动作、资源、租户和数据范围检查点，输入边界、敏感字段、审计事件及真实威胁用例均有实现和测试映射；客户端声明、前端隐藏或缓存不得扩大权限。
- **运行证据完整**：关键业务结果、错误分类、延迟、吞吐、积压和依赖信号可通过日志、指标或追踪定位，标签基数受控且不泄露敏感数据，健康检查区分存活、就绪和业务可用。
- **验证层级诚实**：领域、契约、权限、真实数据库、迁移、并发、幂等和故障测试按风险完成；模拟证据未冒充真实行为，未覆盖项有影响与补证条件，既有失败与本次回归已区分。
- **职责边界清楚**：后端已把产品行为和架构不变量落实为具体 API、Schema、授权、一致性和测试；未经确认的产品范围和跨边界语义未被实现细节反向决定。

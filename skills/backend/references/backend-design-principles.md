## 角色职责

- 将已确认的产品行为和架构不变量落实为领域操作、服务端契约、持久化约束与可观察结果，不以控制器流程或数据库表结构代替业务语义。
- 追踪所有服务端入口与调用方，包括 HTTP／RPC、消息消费者、定时任务、批处理、管理脚本和回调，明确同一规则在各入口的唯一执行位置。
- 定义实体、值对象、状态机、允许操作、拒绝原因和领域不变量，并在应用逻辑与数据库约束之间分配一致的执行责任。
- 设计请求、响应、错误、认证、授权、数据范围、幂等、分页、筛选、版本与兼容行为，使前端、服务和自动化调用方能够独立实现与恢复。
- 为每次状态变化确定事务、锁或冲突检测、去重、重试和部分失败语义，保证重复请求、并发竞争和进程中断不会悄然破坏数据。
- 依据实际查询和写入模式设计 Schema、约束、索引与生命周期，并把结构变化、数据回填、切换、校验和清理编排为可观察的迁移阶段。
- 将外部依赖、缓存、消息与后台任务纳入可靠性设计，明确超时、背压、降级、死信、重放、对账与人工恢复，而非假设基础设施自动可靠。
- 在服务端执行身份、资源和数据范围校验，保护敏感数据与凭据，对高价值动作形成可关联审计，并分析当前入口真实存在的滥用风险。
- 为核心业务状态、错误、延迟、吞吐、积压和依赖提供日志、指标与追踪，使运行人员能区分业务拒绝、可恢复故障和系统缺陷。
- 按风险验证领域规则、契约、权限、真实持久化、迁移、并发、幂等和失败恢复；测试证据能够映射到具体不变量与调用方承诺。
- 外部 API 文档、协议示例和其他项目实现属于设计参考；记录版本、来源、差异与拟借鉴部分，经当前代码、Schema 和调用链核验后才形成当前契约。

## 核心能力

### 领域建模

- 从业务动作、状态变化和拒绝条件识别实体、值对象、聚合与领域服务；数据库实体是持久化表达，不自动等同于完整领域模型。
- 为有生命周期的对象建立状态转换表，列出起始状态、动作、前置条件、目标状态、副作用、失败语义和可否重试；所有入口共享同一转换规则。
- 将不变量写成可执行断言并放在拥有状态的模块中。控制器、任务和消费者负责适配输入，不各自复制业务判断。
- 金额明确币种、精度和舍入；时间明确时区、日界线和精度；标识明确租户或全局作用域；空值、枚举和删除状态具有单一语义。
- 命令表达改变状态的业务意图，查询表达读取需求；查询不产生隐藏业务副作用，命令返回足以识别结果和后续状态的稳定信息。
- 聚合只覆盖一次事务必须保持的规则。跨聚合行为写出最终一致、补偿、对账或人工处置，不以超大事务掩盖边界问题。

### API 与错误契约

- 操作名称与 HTTP、RPC 或事件语义对应真实副作用；创建、替换、局部更新、删除和动作型操作具有清晰的重复调用行为。
- 请求只包含调用方有权控制的字段，主体身份、租户、权限、审计字段和服务端计算结果由可信上下文生成或复核。
- 输入校验分层处理结构、类型、长度、格式、跨字段关系、资源存在性和业务规则；错误定位到可行动字段或业务条件而不泄露内部实现。
- 响应保持最小、稳定且可扩展，统一标识、时间、金额和枚举表达；资源缺失、字段未返回与值为空具有不同含义时显式区分。
- 错误至少区分参数无效、认证失败、授权不足、资源不存在、状态冲突、重复操作、限流、依赖失败和内部故障，并规定调用方能否修正或重试。
- 列表契约定义稳定排序、分页游标或偏移的适用条件、筛选组合、最大页长和空结果；数据持续变化时说明翻页的一致性预期。
- 写操作定义幂等键作用域、请求指纹、有效期、并发竞争和重复响应；只保存键而不关联原请求与最终结果，无法证明幂等。
- 契约演进识别所有调用方，优先增加式兼容；破坏性变化具有版本、迁移窗口、使用观测、退役条件和旧客户端失败行为。

### 数据建模与迁移

- 数据库约束承接不可违反的事实，例如唯一、外键、非空、检查约束和合法状态组合；应用校验提供友好错误，但不能独自抵御并发写入。
- 表与字段说明数据所有者、业务含义、来源、生命周期、保留、归档、软删或硬删、审计及恢复要求，临时派生值不演化成无主事实源。
- 索引由查询谓词、连接、排序和数据分布决定，检查组合顺序、选择性、覆盖收益、写放大、重复索引和执行计划，而非为每个字段机械建索引。
- 查询设计识别 N+1、全表扫描、无界结果、重复聚合和过宽行；批量读取、投影与预计算须保持权限范围和陈旧度语义。
- 事务隔离级别对应实际竞态；读后写、范围约束和库存扣减等场景需要唯一约束、条件更新、锁或序列化策略，而非依赖低并发假设。
- 删除与匿名化考虑外键、搜索索引、缓存、事件、备份和审计链，明确哪些数据可立即消失、延迟清理或因合法目的保留。

- 迁移通常分为兼容扩展、应用双兼容、分批回填、校验、读写切换、约束收紧和旧结构清理，各阶段具有独立完成判据。
- 大表变更评估锁模式、扫描量、事务时长、复制延迟、日志增长和磁盘余量；采用小批次、断点、限速和可重入设计控制影响。
- 回填记录范围、游标、成功数、跳过数、失败样本和重跑方式，并防止新写入在回填期间产生永久空洞。
- 新旧应用版本与新旧 Schema 建立兼容矩阵，滚动发布期间任何允许组合都能安全读写；清理发生在旧版本和旧数据使用量归零之后。
- 校验包含行数、非空率、唯一性、聚合对账、抽样语义与业务指标；迁移命令成功退出不等于数据正确。
- 回滚分别说明代码、Schema、数据和外部副作用的可逆程度。无法安全逆向的数据变换采用前滚修复、备份恢复或人工纠正。

### 权限与安全

- 认证后仍逐项校验动作权限、资源所有权、租户和数据范围；列表、详情、搜索、导出、批量和间接关联入口使用一致规则。
- 授权查询与业务读取在同一可信边界内完成，避免“先取全部再过滤”、仅依赖客户端隐藏或接受调用方传入的角色与租户。
- 外部输入使用结构化解析、参数化查询和允许范围；按入口评估注入、越权、重放、SSRF、路径穿越、不安全反序列化、文件炸弹和资源耗尽。
- 密码、令牌、密钥和个人数据在传输、存储、缓存、日志、异常、追踪和备份中具有明确保护；错误响应不暴露堆栈、查询或内部拓扑。
- 登录、验证码、搜索、导出和高成本操作依据滥用成本设计速率、配额、并发和结果大小限制，限制维度与代理网络场景相匹配。
- 高价值状态变化记录主体、代理主体、资源、前后状态或变更摘要、动作、结果、时间和关联标识；审计日志自身具有访问与防篡改边界。
- 安全失败默认不扩大权限，依赖不可用时明确拒绝、降级或只读行为；缓存授权结果时包含主体、资源、权限版本和失效条件。

### 一致性与并发

- 每个状态变化标明原子边界、锁定资源和提交时刻；外部网络调用通常位于数据库事务之外，并通过状态机、发件箱或补偿衔接。
- 乐观锁适合冲突较少且可向调用方反馈重试的场景；悲观锁适合短事务、高价值竞争，但需要锁顺序、等待上限和死锁处理。
- 唯一约束和条件更新承担最终竞态裁决，应用层“先查询再创建”只能改善提示，无法防止并发重复。
- 幂等记录与业务提交具有原子关系，保存请求指纹、处理中状态和最终响应；相同键不同请求明确拒绝，处理中重入有确定反馈。
- 消息消费同时处理重复、乱序和毒消息，去重状态与业务副作用在同一事务或可恢复协议内；确认消息之前已完成可证明的持久化。
- 跨资源部分失败保留每一步完成状态、关联标识和补偿资格，恢复动作本身也满足幂等，无法自动撤销的副作用进入对账或人工队列。

### 集成与可靠性

- 外部依赖契约记录版本、认证、配额、超时、错误分类、幂等、数据敏感性和降级行为，并用适配层隔离外部模型与领域模型。
- 连接与请求设置分层超时，重试仅覆盖明确可恢复且幂等的操作，具有次数、退避、抖动和总时限；熔断与并发隔离保护核心资源。
- 缓存定义键空间、权威来源、TTL、主动失效、容量、淘汰、陈旧容忍和故障行为，并分析穿透、击穿、雪崩以及权限或租户串读风险。
- 缓存更新选择旁路、写穿、写后或事件失效时，写出数据库成功而缓存失败、消息延迟和并发更新下的可接受结果。
- 消息定义生产事务、Schema、分区键、顺序、投递语义、消费者幂等、重试、死信、重放和版本兼容；队列可持久化不等于端到端业务可靠。
- 批处理和定时任务使用稳定分页或游标、检查点、并发限制、租约或唯一执行、失败项隔离和可重入步骤，不一次加载全部数据。
- Webhook 与回调校验来源、签名、时间窗、重放、乱序和重复，先持久化可恢复事实，再触发可能失败的后续处理。

### 性能与可观测性

- 从业务关键路径测量查询、外部调用、序列化、锁等待、队列等待、内存与连接占用；优化前保留基线，优化后用同一负载验证收益和副作用。
- 查询性能结合真实参数与数据分布检查执行计划、扫描行数、回表、临时排序和锁；单次快查询在高频调用下仍需计算总成本。
- 批量、并发和连接池具有上限与背压，避免把等待从一个依赖转移到线程、内存或队列；超载时优先保护核心写入和恢复能力。
- 日志使用请求、任务或业务对象关联标识，记录动作、阶段、结果和错误分类；不记录完整令牌、密码、敏感载荷或无边界堆栈。
- 指标覆盖业务成功／拒绝／失败、延迟分位、吞吐、数据库与依赖错误、连接池、队列积压、重试和死信；标签避免用户 ID 等高基数值。
- 追踪标出数据库、缓存、消息和外部调用的耗时与失败，异步上下文保持关联；健康检查区分存活、就绪和核心业务依赖可用性。

### 测试策略

- 领域测试覆盖每条状态转换、不变量、边界值、非法动作和时间相关规则，断言业务结果而非内部方法调用次数。
- 契约测试覆盖请求响应、字段兼容、错误分类、分页、幂等和旧调用方样本；权威 Schema 与实际序列化结果保持一致。
- 权限测试至少包含匿名、无权、资源所有者、他人资源、跨租户、列表与详情、导出和批量路径，验证拒绝时不泄露资源存在性或数据。
- 持久化测试使用真实数据库约束与隔离行为，验证唯一、外键、事务、锁、索引相关查询及旧数据兼容，模拟仓储不足以替代这些证据。
- 迁移测试从具有边界与脏数据的旧版本样本执行升级、重跑、暂停、恢复和校验，并验证滚动发布兼容矩阵。
- 并发和幂等测试用同步屏障或并行请求制造竞态、重复与重试，断言最终状态、响应一致性和外部副作用次数。
- 故障测试注入依赖超时、限流、断连、消息重复、进程中断和部分成功，验证错误映射、恢复路径、告警信号及无敏感信息泄露。

## 专业决策顺序

1. **确认权威行为**：提取用户动作、业务规则、架构不变量、授权边界、调用方、兼容承诺和验收结果，将外部协议与当前项目事实分开标注。
2. **追踪现有链路**：从所有入口跟到领域逻辑、数据库、缓存、消息、外部依赖和用户可见结果，识别重复规则、隐式副作用与真实权威来源。
3. **定义领域状态**：先写实体、值对象、状态转换、允许动作、拒绝原因和不变量，再决定控制器、服务、仓储或消费者的代码归属。
4. **固定服务端契约**：明确请求响应、错误、认证授权、数据范围、分页、幂等、超时和版本语义，使每类调用方都有确定行为。
5. **设计持久化与事务**：依据访问模式选择 Schema、约束、索引和隔离策略，标明事务边界、冲突裁决、数据生命周期与删除恢复。
6. **推演并发和故障**：覆盖重复请求、竞态、乱序、部分成功、依赖失败、缓存失效、消息积压和进程中断，决定重试、去重、补偿及人工路径。
7. **编排兼容迁移**：设计扩展、兼容部署、回填、校验、切换、约束收紧和清理，逐项验证新旧代码与数据组合及回滚边界。
8. **实施最小完整改动**：沿用当前架构和既有约定，把规则放入唯一责任位置；新服务、中间件或抽象须解决已证明的边界或质量问题。
9. **布置运行信号**：为关键状态、拒绝、失败、延迟、积压和依赖添加可关联日志、有限基数指标与追踪，使故障能够定位和恢复。
10. **按风险验证并核对调用方**：先验证领域与契约，再覆盖权限、真实持久化、迁移、并发、幂等和故障恢复，确认所有调用方和下游信号安全演进。

## 交付证据

- **领域与不变量表**：实体、状态、动作、前置条件、目标状态、拒绝原因、执行位置、数据库保护和恢复方式清晰对应。
- **契约定义**：请求、响应、错误、授权、数据范围、分页、幂等、超时、版本和调用方样例与实际实现或权威 Schema 一致。
- **调用与副作用图**：各入口到数据库、缓存、消息、外部依赖和用户结果的正常及失败路径完整，重复规则与权威来源已消歧。
- **数据设计依据**：Schema、约束、索引、查询模式、执行计划或容量基线、生命周期和删除恢复具有可检查依据。
- **并发与可靠性矩阵**：竞态、重复、乱序、超时、限流、部分成功和进程中断分别映射到事务、锁、去重、重试、补偿与最终状态。
- **安全证据**：身份与资源授权点、租户或数据范围、输入边界、敏感字段、审计事件和实际威胁用例均有实现及测试映射。
- **迁移包**：阶段顺序、兼容矩阵、回填检查点、限速、校验查询、暂停／恢复、回滚或前滚方案和清理条件可执行。
- **可观测证据**：关键业务结果、错误分类、延迟、吞吐、积压与依赖信号可通过日志、指标或追踪定位，且不泄露敏感数据。
- **验证结果**：领域、契约、权限、数据库、迁移、并发、幂等与故障测试按风险完成；未覆盖项有影响说明和后续验证条件。
- **调用方兼容清单**：前端、其他服务、任务、消费者、脚本及外部集成的影响、适配状态、退役窗口和剩余风险明确。

## 常见误判

- 把数据库表一比一映射为领域模型，导致状态转换和拒绝条件散落在控制器、任务与消费者中。
- 仅在入口做应用校验便认为不变量安全；并发写入和旁路入口仍需领域层与数据库约束共同裁决。
- 接受客户端传入的用户、租户、角色、价格或审计字段，等于把可信边界交给非可信输入。
- 所有失败都返回同一状态或错误码，使调用方无法区分修正输入、重新认证、停止重试与稍后恢复。
- “先查是否存在，再插入”被误作并发去重；最终唯一性需要约束、条件写或锁来保证。
- 在数据库事务内等待不受控网络调用，容易延长锁、耗尽连接并把外部故障扩大为核心数据故障。
- 在网关、服务、客户端和任务各自重试，却未共享总超时与幂等语义，导致指数级请求放大和重复副作用。
- 幂等只记录一个键，不校验请求指纹、不保存处理中与最终结果，并发重入时仍会重复执行或返回矛盾结果。
- 缓存键遗漏租户、用户或权限版本，或把缓存当权威数据，会造成越权串读和故障后不可恢复的不一致。
- 认为消息进入队列便已可靠完成业务，忽略生产事务、消费者提交、重复、乱序、毒消息、死信和对账。
- 把迁移写成一次 DDL 或一次全表脚本，没有滚动兼容、分批回填、检查点、校验与失败恢复。
- 仅依赖模拟仓储和快乐路径单元测试，无法证明数据库约束、隔离级别、迁移、并发或外部故障下的行为。
- 为排障记录完整请求、令牌或个人数据；日志量增加不等于可观测，反而扩大敏感信息和高基数成本。
- 将外部 API 文档、示例响应或其他项目 Schema 直接当作当前契约，忽略版本、调用方差异、权限模型和本地实现证据。
- 为假设中的高并发预先引入缓存、队列、分库或新服务，却没有容量基线、瓶颈证据与失效语义。

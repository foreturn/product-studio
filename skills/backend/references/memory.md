# backend 当前产品事实记忆

本文件是 `backend` 记忆的唯一规则与实例格式，目标实例为 `<Git仓库根>/docs/product-studio/<product-id>/backend.md`。只由 `backend` 维护；其他技能可读取相关主题，不复制正文。

该事实册是 `backend` 对 `product-id` 所标识产品的累计专业事实视图，不是单轮任务摘要。`product-id` 必须在仓库内唯一、稳定且可安全作为单级目录名，优先复用已确认属于同一产品的既有事实目录，并由用户范围、仓库原生产品身份、产品入口与元数据、相关项目根、目标代码和调用链共同确定，不从任一项目目录名机械推导；同一 Git 仓库包含多个产品时，各产品事实册彼此隔离。单轮只增量同步实际核验范围，整册不以该范围、最近差异或最后一次修改为边界，也不要求每轮扫描全库。

## 收录门槛

- 只记当前产品已经执行的领域行为、接口与错误语义、数据不变量、权限、事务并发、事件、缓存、集成和服务端运行约束；事实须有权威依据、可复核入口，且预计后续编码仍会使用。
- 跨产品事实正文只写入拥有权威实现或契约的产品事实册；其他产品可记录自身依赖与兼容边界，但不得复制正文。无法确认权威产品归属的共享事实不写入任一产品事实册，继续以原权威来源为准。
- 事实是否入册只由当前是否成立、是否属于 `backend`、是否值得后续复用决定，与本次是否修改相关代码无关；本次未触及但经当前权威来源核验的既有事实同样可以收录。
- 每个主题只描述一个共同检索、共同变化的稳定语义，不按任务、提交、文件、接口、字段、表、配置键、Symbol 或测试机械拆分。
- 重构、迁移、回填、改名、替换和实现变更只是重新核对记忆的触发器，不得成为主题或事实正文；未完成阶段、临时兼容路径和执行进度不入册。
- 可从 OpenAPI、Schema、迁移或源码生成的完整清单不抄入记忆；只有已成为最终运行约束的兼容行为才按其当前状态记录。

## 实例格式

首次确有事实时，在已确认的 `<product-id>` 下同次创建产品记忆目录与同名事实册；没有事实时不得创建产品记忆目录或文件。产品归属或 `product-id` 无法唯一确定时，不把任何候选事实册作为当前产品事实读取或写入，也不创建目录，并报告歧义。主题使用简短、可读且稳定的业务语义，不含 Owner、类型前缀、路径、日期、任务号或变更动作。

```markdown
# backend 当前产品事实

## <稳定事实主题>

- **当前事实**：<当前产品执行的一项领域行为、接口或错误语义、数据、授权、事务并发、事件、缓存、集成或服务端运行约束；用现在时写明必要条件、结果和边界>
- **权威依据**：<一至三个 `仓库相对路径#精确位置`，精确位置使用权威 Route、Symbol、Schema、迁移、配置键或协议契约>
- **影响边界**：<直接调用方、前端、服务、任务、消息、数据对象、外部系统、不得破坏的当前关系及明确不适用处；无则写“无”>
- **复核入口**：<可重复使用的测试、脚本、命令或检查入口，以及关键断言、稳定未覆盖边界和适用的重审触发>
```

## 终态同步

1. 获准写入的实现、验收或明确记忆维护任务形成终态且取得相称验证后，以本次实际核验的当前代码、配置、契约和验证结果为本轮增量取材范围，对照现有主题重新判断当前事实；最终差异只用于定位变化与回归风险，不构成事实边界。
2. 同一语义原位改写；权威实现或证据搬移只改“权威依据”；事实或最后消费者消失时删除主题，不追加变更、重构或迁移历史。
3. 只有需要新增主题、改写“当前事实、权威依据、影响边界、复核入口”之一或删除事实时才写文件；完成当前范围核对后无增、改、删则报告 `memory: 0 facts changed`。
4. 只读分析或审查未获事实册写入授权时，只报告候选增改删及证据，不修改文件。
5. 最后一个主题删除后移除整册，若产品目录因此为空则一并移除；写后检查主题、权威依据、影响边界和复核入口，再运行受影响项目的适用校验。

## 禁止内容

- 任务摘要、文件清单、进度、待办、责任人、候选方案、过程推理、前后对比、取代关系和历史版本。
- “从 A 迁移到 B”“本轮重构”“临时兼容”“迁移阶段”等过程事实，以及单轮通过、临时失败、命令流水、制品和 commit SHA。
- 未实现目标、外部资料、其他产品事实、系统架构候选或决定、密钥、令牌、用户数据、环境秘密，以及其他 Owner 已保存的同一事实正文。

历史由 Git 承担，长期设计缘由留在项目既有 ADR 或正式文档。静态校验只能证明当前快照的结构和依据自洽；语义新鲜度必须由 `backend` 对照当前权威实现与本次实际核验范围同步。

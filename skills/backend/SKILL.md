# 后端与系统架构

以已确认的产品结果和业务规则为输入，先在必要时形成最小系统架构，再落实服务端代码。不得从表结构、框架、外部案例或预想规模反推本项目产品需求。

## 输入门禁

- 明确项目根、仓库指令、变更范围、调用方、业务动作、成功与拒绝语义、数据范围、兼容要求、验收标准和不得破坏的行为。
- 读取相关产品事实、存在时的 `docs/product-studio/backend.md` 中命中的总结性代码事实，以及现有模块、领域模型、路由、Schema、权限、任务、消息、部署单元和调用方。
- 产品用户、旅程、业务闭环、规则、范围或体验取舍未定时交给 `$design`；系统边界、数据所有权、API、信任边界、一致性、故障、安全、质量属性和演进方案由本技能裁定。
- 同时牵涉多个实现技能或共享契约时，由 `$router` 选择最小代码技能链；本技能拥有系统与服务端契约，前端代码仍由 `$frontend` 实现，总体验由 `$verification` 独立验收。

## 条件加载专业能力

- 改动跨越模块、进程、数据所有权、信任边界或部署单元，或触及共享不变量、跨边界契约、质量属性、故障、安全、可观测性与演进时，先查看 [系统架构能力准则](references/architecture-principles.md) 的“目录”与“核心能力”，完整读取命中的能力段落；形成完整架构决定或复核风险时再读“常见误判”。
- 任一服务端实现先查看 [后端工程能力准则](references/backend-design-principles.md) 的“目录”与“核心能力”，完整读取命中的能力段落；涉及整体方案、交付收口或风险复核时再读“常见误判”。
- 只有系统架构分析时可停在架构产物，不得擅自进入代码实现；普通局部改动不因“可扩展性”加载无关架构能力。

按改动选择后端能力：

- 业务动作、状态机、不变量或多入口共享规则：领域建模。
- HTTP、RPC、事件、分页、幂等、错误码或兼容变化：API 与错误契约。
- 表、字段、约束、索引、查询、回填或新旧版本共存：数据建模与迁移。
- 身份、资源、租户、数据范围、敏感信息或滥用风险：权限与安全。
- 重复请求、竞态、乱序、部分成功或进程中断：一致性与并发。
- 缓存、消息、任务、Webhook 或外部服务：集成与可靠性。
- 性能、背压、日志、指标、追踪或健康语义：性能与可观测性。
- 任一后端代码变更：测试策略；风险触及真实数据库、迁移或并发时不得只做单元测试。

## 架构流程

只有实际存在跨边界缺口时执行本节：

1. 从用户可见结果追踪入口、模块、进程、存储、外部依赖、运行单元和副作用，区分已核验事实、假设和未知。
2. 为每项核心状态与业务不变量指定唯一责任模块和写入权威；缓存、索引、分析仓库与客户端状态只能是有刷新和重建路径的派生副本。
3. 定义同步与事件契约的操作语义、输入输出、错误、权限上下文、超时、取消、幂等、顺序、投递、版本、兼容期及调用方责任。
4. 将性能、可靠性、安全、可维护性和成本写成有基线或阈值的场景，并比较包含沿用现状或局部修补在内的最小候选方案。
5. 标明事务提交点、部分成功、重试唯一责任层、补偿、人工恢复、依赖降级、审计与业务可观测信号。
6. 涉及演进时定义兼容扩展、双版本共存、数据处理、读写切换、验证和旧路径清理的进入条件、可重入点与数据后果。
7. 输出当前实现者无需猜测的边界、所有权、不变量、契约、质量、故障、安全、运行和演进决定；没有当前消费者的抽象、服务、字段或扩展点不进入方案。

## 实施流程

1. 从入口沿控制器或适配器、领域服务、仓储、数据库、缓存、消息和外部依赖追到最终业务结果，列出全部调用方与副作用。
2. 固定领域状态、允许动作、拒绝原因和不变量的唯一执行位置；入口只做协议适配，不复制业务判断。
3. 定义 API 的请求、响应、错误、认证授权、数据范围、分页、排序、幂等、超时、版本和旧调用方行为；仓库有权威 API Schema 时同步维护。
4. 依据访问模式设计 Schema、约束和索引；迁移代码按兼容扩展、双版本共存、分批处理、校验、切换、收紧约束和清理编排。
5. 在可信服务端校验身份、动作、资源、租户与数据范围；审查输入边界、敏感信息、审计、速率和资源耗尽风险。
6. 标明事务提交点、锁定资源和失败窗口；用约束、条件更新、锁、幂等记录、发件箱、补偿或对账处理重复、竞态与部分成功。
7. 为外部依赖设置协议适配、超时预算、错误映射、有限重试、隔离、降级和恢复入口；缓存不得成为第二事实源，消息入队不得冒充业务完成。
8. 实现最小完整改动及聚焦测试，不引入没有当前消费者或风险证据的新服务、中间件和抽象层。
9. 先运行受影响模块的格式、静态、类型或编译检查，再按风险运行领域、契约、权限、真实数据库、迁移、并发、幂等和故障测试；记录工作目录、命令、退出码与首个可行动失败。
10. 核对最终差异只包含授权范围，并逐项检查调用方兼容、数据恢复、敏感信息与运行信号。
11. 在终态回复前执行记忆同步检查，报告实际增改删的事实主题；没有总结性事实变化时报告 `memory: 0 facts changed`。

## 当前代码事实记忆

开始工作时，若 `<当前项目根>/docs/product-studio/backend.md` 存在，只读取命中的事实主题及直接关联。每次编码任务收口前完整读取 [backend 记忆规则与实例格式](references/memory.md)，仅按最终代码同步 `backend` 自己的事实册；首次确有事实时使用其中格式，不得预建空册。重构、迁移和变更过程不入册；没有总结性事实变化时报告 `memory: 0 facts changed`。

## 输出与交接

- 架构任务交付系统上下文、边界与所有权、不变量、跨边界契约、质量场景、故障与安全约束、运行信号、演进条件和验证办法。
- 实现任务交付后端代码、Schema 与迁移代码、聚焦测试，以及 API、数据、权限、一致性、集成、兼容和恢复行为的说明与开发验证结果。
- 向 `$frontend` 交付实际请求、响应、错误、权限、幂等、异步状态和兼容契约；向 `$verification` 交付产品验收对应关系、架构风险、测试入口、数据条件、已知限制和可复现证据。

## 完成门禁

- 跨边界改动有明确责任模块、数据所有权、消费者、正常与失败语义、兼容责任、恢复路径和验证信号；局部改动没有无依据扩成架构工程。
- 领域规则有唯一位置，全部入口共享同一不变量和拒绝语义。
- API、权威 Schema、序列化、错误映射和真实调用方一致，破坏性变化具有明确兼容处置。
- 数据约束、查询与迁移代码有真实数据库或等效可靠证据；并发、重复、乱序和部分失败均有收敛机制。
- 每个受保护入口校验身份、动作、资源、租户和数据范围，日志、错误和记忆均不泄露敏感信息。
- 依赖故障、缓存失效、消息重放和进程中断有明确行为、恢复入口及可观察信号。
- 验证覆盖与风险相称；模拟证据未冒充真实数据库、真实协议或跨系统闭环。

## 边界

- 可裁定系统架构、领域与服务边界、数据主权、跨模块契约、质量属性、信任边界、一致性目标、故障恢复、运行约束和演进方案，并落实后端代码细节。
- 不自行改变目标用户、产品范围、用户旅程、业务闭环、交互优先级或体验目标；这些交由 `$design` 裁定。
- 可编写迁移与回填代码，并在本地或隔离测试环境验证兼容、重入、暂停、恢复和数据校验；不执行环境迁移或真实数据修复。
- 不代替 `$frontend` 决定组件、视觉、响应式与浏览器交互实现，不代替 `$verification` 宣告产品增量总体通过。

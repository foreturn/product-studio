# 后端工程

把已确认的产品行为和系统约束落实为可执行、可兼容、可恢复且可验证的服务端实现。先追踪现有调用链和权威 Schema，再改代码；不得从表结构、外部示例或预想需求反推本项目业务规则。

## 输入门禁

- 明确当前项目根、仓库指令、本次变更范围和不得破坏的行为。
- 读取相关产品与系统设计事实、`docs/product-studio/backend.md` 中与本次对象有关的当前代码事实，以及现有领域模型、路由、Schema、权限、任务、消息和调用方。
- 明确请求方、业务动作、成功结果、错误与拒绝语义、数据范围、兼容要求和适用验收标准。
- 产品规则、用户旅程或范围会因选择而改变时，调用 `$design` 的产品设计模式；数据所有权、跨服务一致性、信任边界或演进方案未定时，调用 `$design` 的系统设计模式。
- 同时牵涉多个实现技能或共享契约时，由 `$router` 选择最小代码技能链；本技能只承接其中的服务端代码与开发验证产物。

## 专业能力

先查看 [后端工程能力准则](references/backend-design-principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及整体方案、交付收口或风险复核时，再读取“专业决策顺序”“交付证据”和“常见误判”。该 reference 只提供后端专业能力准则，触发、执行流程和代码事实更新规则以本文件为准。

按改动选择而非机械加载：

- 业务动作、状态机、不变量或多入口共享规则：领域建模。
- HTTP、RPC、事件、分页、幂等、错误码或兼容变化：API 与错误契约。
- 表、字段、约束、索引、查询、回填或新旧版本共存：Schema、查询与迁移代码。
- 身份、资源、租户、数据范围、敏感信息或滥用风险：权限与安全。
- 重复请求、竞态、乱序、部分成功或进程中断：一致性与并发。
- 缓存、消息、任务、Webhook 或外部服务：集成与可靠性。
- 性能、背压、日志、指标、追踪或健康语义：性能与可观测性。
- 任一后端代码变更：测试策略；风险触及真实数据库、迁移或并发时不得只做单元测试。

## 实施流程

1. 从入口沿控制器或适配器、领域服务、仓储、数据库、缓存、消息和外部依赖追到最终业务结果，列出全部调用方与副作用。
2. 固定领域状态、允许动作、拒绝原因和不变量的唯一执行位置；入口只做协议适配，不复制业务判断。
3. 定义 API 的请求、响应、错误、认证授权、数据范围、分页、排序、幂等、超时、版本和旧调用方行为；仓库有权威 API Schema 时同步维护。
4. 依据访问模式设计 Schema、约束和索引；迁移代码按兼容扩展、双版本兼容、分批回填、校验、切换、收紧约束和清理编排。
5. 在可信服务端校验身份、动作、资源、租户与数据范围；审查输入边界、敏感信息、审计、速率和资源耗尽风险。
6. 标明事务提交点、锁定资源和失败窗口；用约束、条件更新、锁、幂等记录、发件箱、补偿或对账处理重复、竞态与部分成功。
7. 为外部依赖设置协议适配、超时预算、错误映射、有限重试、隔离、降级和恢复入口；缓存不得成为第二事实源，消息入队不得冒充业务完成。
8. 实现最小完整改动及聚焦测试，不引入没有当前消费者或风险证据的新服务、中间件和抽象层。
9. 先运行受影响模块的格式、静态、类型或编译检查，再按风险运行领域、契约、权限、真实数据库、迁移、并发、幂等和故障测试；记录工作目录、命令、退出码与首个可行动失败。
10. 核对最终差异只包含授权范围，并逐项检查调用方兼容、数据恢复、敏感信息与运行信号；实现和验证到达终态后才更新项目记忆。

## 当前代码事实记忆

`docs/product-studio/backend.md` 只记录当前代码实际怎样工作，不记录任务过程、任务摘要、动作队列、方案讨论、待办、完成宣言或历史版本。开始工作前读取与本次语义键和消费者相关的条目；只有实现与适用验证均到达终态，且实际代码事实发生变化时才写入。无事实变化、只读审计、失败未落地或用户明确排除记忆时不写。

文件使用 schema 3。每个三级标题是唯一语义键，只能使用以下前缀：

- `backend:api:<method>:<path>`：已注册 API 的方法、路径与实际请求、响应、错误和幂等契约。
- `backend:schema:<store>:<object>`：数据库、缓存或持久化对象的实际字段、约束、索引、关系与生命周期。
- `backend:auth:<resource>:<action>`：可信服务端校验点上的认证来源、动作、资源、租户和数据范围规则。
- `backend:event:<channel>:<name>`：消息、任务、回调或领域事件的生产、Schema、顺序、消费、重试与去重契约。
- `backend:integration:<system>:<operation>`：外部系统适配、超时、错误映射、重试、幂等、降级与恢复。
- `backend:config:<service>:<name>`：影响运行行为的配置、默认值与读取位置；只记配置名与行为，不记秘密值。

每条事实固定且仅含以下字段：

```markdown
### backend:api:post:/orders

- **当前实现**：
- **源码锚点**：
- **关联与消费者**：
- **验证证据**：
- **重验条件**：
```

写入规则：

- “当前实现”须写可由代码核验的具体行为，例如 method/path、字段、错误码、表约束、权限谓词、事务边界、重试次数或事件消费者；不得写“接口已完成”“安全性良好”。
- “源码锚点”须指向当前仓库文件及路由、类、函数、Schema、迁移或配置 Symbol；生成的 OpenAPI、路由表或数据库 Schema 仍是精确清单的权威来源，记忆只保存语义投影与链接。
- “关联与消费者”须列真实前端、服务、任务、消息消费者、数据表或外部系统及其依赖关系。
- “验证证据”须绑定当前命令、测试、请求样本、数据库检查或制品结果；不能只写测试名称或“已验证”。
- “重验条件”须列会使事实可能失效的路由、Symbol、Schema、依赖版本、配置或消费者变化。
- 同一语义键的实现变化就在原位置更新；新增代码事实添加新键；源码及全部消费者删除后移除对应事实。不得追加 superseded 卡或保留过程历史，历史由 Git 承担。
- 只改本技能拥有的受影响语义键，保持其他键和其他技能记忆不变。首次确有事实需要创建文件时使用 `../../templates/backend.md`，随后只作增量更新。

## 输出与交接

- 后端实现、迁移代码及与风险匹配的开发自测。
- API、数据、权限、一致性、集成、兼容和恢复行为的具体说明，以及实际验证命令与结果。
- 存在终态代码事实增量时，对 `docs/product-studio/backend.md` 作同键原位更新、新键添加或失效键移除；否则明确不写。
- 向前端交付实际请求、响应、错误、权限、幂等和兼容契约；向验证技能交付风险、测试入口、数据条件、已知限制和可复现证据。

## 完成门禁

- 领域规则有唯一位置，全部入口共享同一不变量和拒绝语义。
- API、权威 Schema、序列化、错误映射和真实调用方一致，破坏性变化具有明确兼容处置。
- 数据约束、查询与迁移代码有真实数据库或等效可靠证据；并发、重复、乱序和部分失败均有收敛机制。
- 每个受保护入口校验身份、动作、资源、租户和数据范围，日志、错误和记忆均不泄露敏感信息。
- 依赖故障、缓存失效、消息重放和进程中断有明确行为、恢复入口及可观察信号。
- 验证覆盖与风险相称；模拟证据未冒充真实数据库、真实协议或跨系统闭环。

## 边界

- 可在已确认产品与系统约束内裁决领域代码、API 字段与错误、Schema 细节、事务、幂等、集成适配、可观测性和测试实现。
- 不自行改变产品范围、用户旅程、跨系统数据主权、信任边界或一致性目标；这些分别交由 `$design` 的产品或系统设计模式裁决。
- 可编写迁移与回填代码，并在本地或隔离测试环境验证兼容、重入、暂停、恢复和数据校验；不执行环境迁移或真实数据修复。
- 不代替 `$verification` 宣告产品增量总体通过；本技能只给出后端实现与开发自测证据。

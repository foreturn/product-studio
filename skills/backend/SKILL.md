# 后端工程

以已确认的产品结果、业务规则和适用架构决定为输入，将服务端行为落实为可执行代码、权威契约、持久化约束和聚焦测试；不得在实现层暗改产品语义或建立第二套系统边界。

## 输入门禁

- 明确项目根、仓库指令、变更范围、调用方、业务动作、成功与拒绝语义、数据范围、兼容要求、验收标准和不得破坏的行为。
- 读取相关产品与架构事实、存在时的 `docs/product-studio/backend.md` 中命中的总结性代码事实，以及现有领域模型、路由、API Schema、数据库、权限、任务、消息、外部依赖和全部调用方。
- 产品用户、旅程、业务闭环、规则、范围或体验取舍未定时交给 `$design`；模块或服务边界、数据所有权、共享不变量、跨边界交互语义、质量属性、信任边界、故障或演进方案未定时交给 `$architecture`。
- 同时牵涉前端或多个实现技能、共享 API 或 Schema 时，由 `$router` 选择最小技能链；前端代码仍由 `$frontend` 实现，是否总体通过由 `$verification` 独立裁决。

## 专业能力

先查看 [后端工程能力准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及整体方案、交付收口或风险复核时，再读“常见误判”。

## 实施流程

1. 从现有入口沿服务端调用链追到权威状态、外部依赖与最终业务结果，核对全部调用方、副作用和当前证据。
2. 定位仍待实现的后端行为，完整读取本次命中的能力准则；产品语义未定时退回 `$design`，跨边界决定无法成立时退回 `$architecture`。
3. 沿用项目现有栈实现最小完整改动，并同步仓库声明的权威契约、Schema、迁移与生成文件；未受影响的能力不机械展开，没有当前消费者或风险证据的抽象不进入实现。
4. 运行项目既有的格式、静态、类型或编译检查，再执行与命中能力和风险相称的后端开发测试，区分模拟证据与真实数据库、真实协议证据。
5. 核对最终差异、全部调用方和完成门禁，再按“输出与交接”交付实际代码、契约、数据条件、验证证据、已知限制与未覆盖风险。

## 当前项目事实记忆

开始工作时，若 `<当前项目根>/docs/product-studio/backend.md` 存在，只读取命中的事实主题及直接关联。获准写入的实现、验收或明确记忆维护任务收口前完整读取 [backend 记忆规则与实例格式](references/memory.md)，以本次实际核验的当前代码、配置、契约和验证结果为本轮增量范围，仅同步 `backend` 自己的当前事实；事实册整体是 `backend` 对整个项目的累计专业事实视图，不受本轮范围限制，事实是否在本次被修改不影响收录，最终差异不构成事实边界。首次确有事实时使用其中格式，不得预建空册；重构、迁移和变更过程不入册。只读任务未获事实册写入授权时只报告候选事实；完成当前范围核对后无增、改、删则报告 `memory: 0 facts changed`。

## 输出与交接

- 交付后端代码、权威 API Schema、数据库 Schema 与迁移代码、聚焦测试，以及领域、接口、数据、权限、一致性、集成、兼容和恢复行为的说明与开发验证结果。
- 向 `$frontend` 交付实际请求、响应、错误、权限、幂等、分页、异步状态和兼容契约；前端不得从服务端实现细节猜造第二套语义。
- 向 `$verification` 交付产品验收对应关系、架构约束、测试入口、数据条件、已知限制和可复现证据。
- 实现证据推翻系统边界、数据所有权、共享不变量、跨边界语义或质量约束时，退回 `$architecture` 裁决后再继续。

## 完成门禁

- 领域规则有唯一位置，全部入口共享同一不变量和拒绝语义。
- API、权威 Schema、序列化、错误映射和真实调用方一致，破坏性变化具有明确兼容处置。
- 数据约束、查询与迁移代码有真实数据库或等效可靠证据；并发、重复、乱序和部分失败均有收敛机制。
- 每个受保护入口校验身份、动作、资源、租户和数据范围，日志、错误和记忆均不泄露敏感信息。
- 依赖故障、缓存失效、消息重放和进程中断有明确行为、恢复入口及可观察信号。
- 开发测试覆盖与风险相称；模拟证据未冒充真实数据库、真实协议或跨系统闭环，最终产品结论仍交给 `$verification`。

## 边界

- 可裁定并实现领域模型、局部模块边界、具体 API、Schema、事务、权限、缓存消息、外部集成、可观测性和后端测试细节。
- 不自行改变目标用户、产品范围、用户旅程、业务闭环、交互优先级或体验目标；这些交给 `$design`。
- 不重新裁定跨模块或跨服务边界、数据主权、共享不变量、跨边界语义和系统级质量取舍；出现缺口或冲突时交给 `$architecture`。
- 可编写迁移与回填代码，并在本地或隔离测试环境验证兼容、重入、暂停、恢复和数据校验；不执行环境迁移或真实数据修复，已验收制品的环境操作交由 `$release` 在精确授权内处理。
- 不代替 `$frontend` 决定组件、视觉、响应式与浏览器交互实现，不代替 `$verification` 宣告产品增量总体通过。

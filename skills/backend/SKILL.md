# 后端工程

以已确认的产品结果、业务规则和适用架构决定为输入，将服务端行为落实为可执行代码、权威契约、持久化约束和聚焦测试；不得在实现层暗改产品语义或建立第二套系统边界。

## 输入门禁

- 明确项目根、仓库指令、变更范围、调用方、业务动作、成功与拒绝语义、数据范围、兼容要求、验收标准和不得破坏的行为。
- 读取相关产品与架构事实、存在时的 `docs/product-studio/backend.md` 中命中的总结性代码事实，以及现有领域模型、路由、API Schema、数据库、权限、任务、消息、外部依赖和全部调用方。
- 产品用户、旅程、业务闭环、规则、范围或体验取舍未定时交给 `$design`；模块或服务边界、数据所有权、共享不变量、跨边界契约语义、质量属性、信任边界、故障或演进方案未定时交给 `$architecture`。
- 同时牵涉前端或多个实现技能、共享 API 或 Schema 时，由 `$router` 选择最小技能链；前端代码仍由 `$frontend` 实现，是否总体通过由 `$verification` 独立裁决。

## 专业能力

先查看 [后端工程能力准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及整体方案、交付收口或风险复核时，再读“常见误判”。

按改动选择能力：

- 业务动作、状态机、不变量或多入口共享规则：领域建模。
- HTTP、RPC、事件、分页、幂等、错误码或兼容变化：API 与错误契约。
- 表、字段、约束、索引、查询、回填或新旧版本共存：数据建模与迁移。
- 身份、资源、租户、数据范围、敏感信息或滥用风险：权限与安全。
- 重复请求、竞态、乱序、部分成功或进程中断：一致性与并发。
- 缓存、消息、任务、Webhook 或外部服务：集成与可靠性。
- 性能、背压、日志、指标、追踪或健康语义：性能与可观测性。
- 任一后端代码变更：测试策略；风险触及真实数据库、迁移或并发时不得只做单元测试。

## 实施流程

1. 从入口沿控制器或适配器、领域服务、仓储、数据库、缓存、消息和外部依赖追到最终业务结果，列出全部调用方与副作用。
2. 固定领域状态、允许动作、拒绝原因和不变量的唯一执行位置；入口只作协议适配，不复制业务判断。若发现既定架构的所有权或共享不变量无法成立，暂停受影响实现并退回 `$architecture`。
3. 定义 API 的请求、响应、错误、认证授权、数据范围、分页、排序、幂等、超时、版本和旧调用方行为；仓库有权威 API Schema 时同步维护，不得偏离已确认的跨边界语义。
4. 依据访问模式设计 Schema、约束和索引；迁移代码按兼容扩展、双版本共存、分批处理、校验、切换、收紧约束和清理编排。
5. 在可信服务端校验身份、动作、资源、租户与数据范围；审查输入边界、敏感信息、审计、速率和资源耗尽风险。
6. 标明事务提交点、锁定资源和失败窗口；用约束、条件更新、锁、幂等记录、发件箱、补偿或对账处理重复、竞态与部分成功。
7. 为外部依赖设置协议适配、超时预算、错误映射、有限重试、隔离、降级和恢复入口；缓存不得成为第二事实源，消息入队不得冒充业务完成。
8. 实现最小完整改动及聚焦测试，不引入没有当前消费者或风险证据的新服务、中间件和抽象层。
9. 先运行受影响模块的格式、静态、类型或编译检查，再按风险运行领域、契约、权限、真实数据库、迁移、并发、幂等和故障测试；记录工作目录、命令、退出码与首个可行动失败。
10. 核对最终差异只包含授权范围，并逐项检查调用方兼容、数据恢复、敏感信息与运行信号，再将实际请求、响应、错误和数据条件交给 `$frontend` 与 `$verification`。

## 当前代码事实记忆

开始工作时，若 `<当前项目根>/docs/product-studio/backend.md` 存在，只读取命中的事实主题及直接关联。每次编码任务收口前完整读取 [backend 记忆规则与实例格式](references/memory.md)，仅按最终代码同步 `backend` 自己的事实册；首次确有事实时使用其中格式，不得预建空册。重构、迁移和变更过程不入册；没有总结性事实变化时报告 `memory: 0 facts changed`。

## 输出与交接

- 交付后端代码、权威 API Schema、数据库 Schema 与迁移代码、聚焦测试，以及领域、接口、数据、权限、一致性、集成、兼容和恢复行为的说明与开发验证结果。
- 向 `$frontend` 交付实际请求、响应、错误、权限、幂等、分页、异步状态和兼容契约；前端不得从服务端实现细节猜造第二套语义。
- 向 `$verification` 交付产品验收对应关系、架构约束、测试入口、数据条件、已知限制和可复现证据。
- 实现证据推翻系统边界、数据所有权、共享不变量、跨边界语义或质量约束时，退回 `$architecture` 裁决后再继续。

## 完成门禁

- 领域规则有唯一位置，全部入口共享同一不变量和拒绝语义。
- API、权威 Schema、序列化、错误映射和真实调用方一致，破坏性变化具有明确兼容处置。
- 数据约束、查询与迁移代码有真实数据库或等效可靠证据；并发、重复、乱序和部分失败均有收敛机制。
- 每个受保护入口校验身份、动作、资源、租户和数据范围，日志、错误和记忆均不泄露敏感信息。
- 依赖故障、缓存失效、消息重放和进程中断有明确行为、恢复入口及可观察信号。
- 开发测试覆盖与风险相称；模拟证据未冒充真实数据库、真实协议或跨系统闭环，最终产品结论仍交给 `$verification`。

## 边界

- 可裁定并实现领域模型、局部模块边界、具体 API、Schema、事务、权限、缓存消息、外部集成、可观测性和后端测试细节。
- 不自行改变目标用户、产品范围、用户旅程、业务闭环、交互优先级或体验目标；这些交给 `$design`。
- 不重新裁定跨模块或跨服务边界、数据主权、共享不变量、跨边界语义和系统级质量取舍；出现缺口或冲突时交给 `$architecture`。
- 可编写迁移与回填代码，并在本地或隔离测试环境验证兼容、重入、暂停、恢复和数据校验；不执行环境迁移或真实数据修复。
- 不代替 `$frontend` 决定组件、视觉、响应式与浏览器交互实现，不代替 `$verification` 宣告产品增量总体通过。

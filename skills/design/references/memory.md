# design 当前代码事实记忆

本文件是 `design` 记忆的唯一规则与首建骨架，目标实例为 `<项目根>/docs/product-studio/design.md`。只由 `design` 维护；其他技能可链接事实键，不复制正文。

## 收录门槛

- 事实已在当前代码中成立，有与风险相称的验证入口，且预计后续编码仍会使用。
- 事实具有唯一设计 Owner 和权威代码定位，并至少具备一项价值：跨消费者、无法从单文件立即看出、重查成本高或误判风险大。
- 一个键只概括一个共同检索、共同失效的稳定语义单元；不按任务、提交、文件、路由、字段、Symbol、AC-ID、ADR 或测试机械建卡。
- 只记已实现的旅程、规则、边界、契约、不变量和当前迁移阶段；候选方案、未落地决定与纯设计产物不入册。

## 事实键

键在当前项目内全局唯一；`<slug>` 只用小写字母、数字和短横线表达稳定业务语义，不写路径、日期、任务号或临时方案名。`<type>` 只取下列值：

- `design:journey:<slug>`：代码实际支持的核心用户任务、反馈和恢复路径。
- `design:rule:<slug>`：已实现的业务规则、例外和权限差异。
- `design:boundary:<slug>`：模块或领域边界、数据所有权和权威写入责任。
- `design:contract:<slug>`：跨模块、前后端或外部系统的共享契约与兼容关系。
- `design:invariant:<slug>`：实现必须维持的一致性、安全、可靠性或性能不变量。
- `design:migration:<slug>`：当前仍生效的兼容阶段、数据演进顺序和不可逆边界。

## 实例骨架

首次确有事实时复制下列骨架并替换所有尖括号占位；没有事实时不得创建文件。`project_root: "."` 固定指事实册所在的当前项目根，不得改为绝对路径或父目录。

```markdown
---
memory: design
project_root: "."
updated_at: "<带时区 RFC3339 时间>"
---

# design 代码事实

## 当前代码事实

### design:<type>:<slug>

- **事实摘要**：<代码已经执行的一项旅程、规则、边界、契约或不变量，以及未来修改不得破坏的关键约束>
- **代码定位**：<一至三个 `仓库相对路径#精确位置`，精确位置使用权威 Symbol、契约、路由或 Schema>
- **依赖与影响**：<直接调用方、消费者、数据所有者或相关事实键；无则写“无”>
- **验证入口**：<可重复使用的测试、脚本、命令或检查旅程，关键断言与稳定未覆盖边界>
- **失效条件**：<哪些产品契约、所有权、边界、数据流或实现变化后必须同步本卡>
```

## 终态同步

1. 编码任务完成，或部分完成中已有独立可用且验证成立的切片时，对照最终差异与现有相关卡列出 `+`、`~`、`-` 键。
2. 同一语义原位更新；仅搬代码时只改“代码定位”；事实或最后消费者消失时删除卡。
3. 只有五字段之一变化才写文件并更新 `updated_at`；没有总结事实变化时报告 `memory: 0 keys changed`，不制造时间戳差异。
4. 最后一张卡删除后移除整册，不留空文件；写后检查键、链接、定位和占位，再运行项目校验。

## 禁止内容

- 任务摘要、文件清单、进度、待办、责任人、候选方案、过程推理和 `superseded` 历史。
- 单轮通过、临时失败、命令流水、制品、截图时间、commit SHA、未实现目标、外部资料和其他项目事实。
- 密钥、令牌、用户数据、环境秘密，以及其他 Owner 已保存的同一事实正文。

历史由 Git 承担，长期设计缘由留在项目既有 ADR 或正式文档。静态校验只能证明当前快照的结构、定位和链接自洽；语义新鲜度必须由 `design` 对照最终差异同步。

# design 当前代码事实记忆

本文件是 `design` 记忆的唯一规则与实例格式，目标实例为 `<项目根>/docs/product-studio/design.md`。只由 `design` 维护；其他技能可读取相关主题，不复制正文。

## 收录门槛

- 只记最终代码当前已经执行的目标用户与业务结果、用户旅程、业务规则、交互闭环、范围和体验约束；事实须有权威代码定位、可复用验证入口，且预计后续编码仍会使用。
- 每个主题只描述一个共同检索、共同变化的稳定语义，不按任务、提交、文件、路由、字段、Symbol、AC-ID、ADR 或测试机械拆分。
- 重构、迁移、改名、替换和实现变更只是重新核对记忆的触发器，不得成为主题或事实正文；未完成阶段、临时兼容路径和候选方案不入册。
- 只有已成为最终运行约束的兼容行为才按其当前状态记录，不写形成过程、旧状态或取代关系。

## 实例格式

首次确有事实时创建同名事实册；没有事实时不得创建文件。主题使用简短、可读且稳定的业务语义，不含 Owner、类型前缀、路径、日期、任务号或变更动作。

```markdown
# design 当前代码事实

## <稳定事实主题>

- **当前事实**：<最终代码现在执行的一项目标用户与业务结果、旅程、规则、交互闭环、范围或体验约束>
- **代码定位**：<一至三个 `仓库相对路径#精确位置`，精确位置使用权威 Symbol、契约、路由或 Schema>
- **影响范围**：<直接调用方、消费者、数据所有者及不得破坏的当前关系；无则写“无”>
- **验证入口**：<可重复使用的测试、脚本、命令或检查旅程，以及关键断言和稳定未覆盖边界>
```

## 终态同步

1. 编码任务完成且最终代码取得相称验证后，对照最终差异与现有主题重新判断当前事实。
2. 同一语义原位改写；代码搬移只改“代码定位”；事实或最后消费者消失时删除主题，不追加变更、重构或迁移历史。
3. 只有四字段之一实质变化才写文件；没有总结事实变化时报告 `memory: 0 facts changed`。
4. 最后一个主题删除后移除整册；写后检查主题、定位、消费者和验证入口，再运行项目校验。

## 禁止内容

- 任务摘要、文件清单、进度、待办、责任人、候选方案、过程推理、前后对比、取代关系和历史版本。
- “从 A 迁移到 B”“本轮重构”“临时兼容”“迁移阶段”等过程事实，以及单轮通过、临时失败、命令流水、制品、截图时间和 commit SHA。
- 未实现目标、纯设计产物、外部资料、其他项目事实、密钥、令牌、用户数据、环境秘密，以及其他 Owner 已保存的同一事实正文。

历史由 Git 承担，长期产品缘由留在项目既有正式文档。静态校验只能证明当前快照的结构和定位自洽；语义新鲜度必须由 `design` 对照最终差异同步。

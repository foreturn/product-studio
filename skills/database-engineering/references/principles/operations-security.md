# 数据库工程 · 运行治理与数据安全

### 容量、维护与性能基线

- 容量模型必须覆盖数据、索引、日志、临时空间、备份、迁移和重建峰值，而非只观察主数据当前大小。
- 性能基线应使用代表性数据分布和读写组合，关注吞吐、尾延迟、等待、错误和资源饱和，不能用平均值隐藏退化。
- 维护能力必须长期跟上新增负担，统计、清理、压缩和回收被长事务或高负载阻塞时需要可观测。
- 容量需保留故障切换、恢复、回填和索引维护余量，不能把日常峰值当作可用上限。
- 资源告警必须给扩容、迁移或修复留下足够提前量，并基于增长趋势而非耗尽后的静态故障。
- 优化方案必须由等待、访问路径、热点和资源瓶颈证据决定，不能以扩容或惯例掩盖根因。

### 权限、审计与敏感数据

- 数据库身份必须按运行、迁移、分析、备份和管理用途分离，并遵循最小权限；应用运行身份不得持有结构管理或全局管理能力。
- 新对象和新环境必须继承受限默认权限，临时提升应可追溯、可过期且不能演变为长期共享高权限身份。
- 敏感数据保护必须同时考虑传输、存储、查询和密钥访问边界；加密与密钥由同一主体无条件取得时不能形成有效隔离。
- 数据级策略只能作为纵深控制，不能替代服务端对象授权；策略上下文必须可信且不会经连接复用泄漏。
- 审计应记录可信主体、动作、对象、结果和关联标识，同时避免秘密与完整敏感载荷进入日志。
- 生产数据进入非生产环境前必须脱敏、令牌化或替换为合成数据，并验证字段组合无法重新识别真实主体。

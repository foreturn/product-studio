# 数据库工程 · 事务、并发与连接

### 事务、隔离与并发控制

- 事务边界由必须共同成立的业务不变量决定，应保持短小，不包裹远程依赖、用户等待或无法回滚的外部副作用。
- 隔离级别应依据可接受的并发现象和一致性要求选择，不能一律使用最低隔离，也不能用最高隔离掩盖错误事务模型。
- 并发更新必须采用可检测冲突的机制，任何条件写入都要核对是否真正生效，不能静默覆盖竞争结果。
- 多资源操作必须保持稳定的资源访问顺序并缩小争用范围；热点、阻塞和死锁需要可观测，不能依赖无限等待恢复。
- 重试只适用于明确可重试的冲突与瞬时故障，必须有界且保证业务副作用幂等；未知提交结果不能盲目再次执行。
- 跨系统一致性必须使用可恢复的消息、补偿或对账机制明确失败语义，不能把独立写入包装成原子事务。

### 连接、会话与资源治理

- 连接预算必须按整个实例群、后台任务和管理余量统一计算，单实例配置不能在扩容后突破数据库承载上限。
- 连接池已满时必须有界排队或背压；无界建连、并发重连和立即重试会把局部故障放大为数据库雪崩。
- 会话归还前必须清理事务、游标、身份、租户和其他可变状态，防止上下文跨请求泄漏。
- 池化模式必须与应用依赖的会话语义相容；依赖跨事务状态的应用不能使用会丢弃会话连续性的模式。
- 连接、语句、锁和事务时限应服从端到端服务预算，并保留诊断和回滚时间，不能彼此矛盾或无限等待。
- 连接恢复必须限制并发并处理未知提交结果，同时保留不依赖业务连接池的管理与诊断通道。

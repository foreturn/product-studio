# 数据库工程 · 迁移、生命周期与数据交换

### 结构演进与数据迁移

- 结构变更必须允许新旧应用版本在过渡期共存，新增、切换与移除应保持向前和向后兼容。
- 在线迁移必须控制锁、日志、存储、复制和业务延迟影响；任务完成状态不能替代运行影响与数据正确性证明。
- 数据回填必须有界、幂等、可暂停、可续跑且可观测，失败后能够从已确认位置恢复而不重复破坏数据。
- 读写格式切换必须有明确权威来源和一致性规则，避免无原子保证的双写产生无法判定的分叉。
- 破坏性删除只能在所有受支持消费者停止使用后发生，并具备与新旧数据格式相容的恢复或前滚方案。
- 迁移完成需验证数量、引用、空值、领域不变量和代表性内容，不能只验证结构版本或任务状态。

### 分区、归档与生命周期

- 分区键必须同时服务主要访问模式、写入分布和生命周期操作；只按组织结构或低基数属性分区会放大元数据与热点。
- 分区不能替代索引、容量规划或跨节点扩展；跨分区唯一性、引用和全局查询必须另有明确保证。
- 查询必须能够利用分区边界缩小访问范围，否则分区只增加运维复杂度而不改善性能。
- 归档必须保留完整性、可检索性、访问控制和恢复能力；只有在目标副本验证后，源数据才可按政策清除。
- 保留期必须从明确业务事件起算，并覆盖主存储、副本、缓存、搜索、分析和备份等所有受控副本。
- 生命周期操作不得破坏仍有效的引用、保留义务或恢复链，批量清除也必须控制锁、日志和资源峰值。

### 数据同步、导入与交换

- 全量快照与增量变化必须共享可解释的一致性边界，避免切换期间遗漏、重复或用旧值覆盖新值。
- 同步协议必须定义顺序、重复、删除、断点续传和未知结果语义，消费者停机不能反向破坏权威写入。
- 每条变化应具备稳定身份或版本，使消费、重放和合并保持幂等，并能识别过时更新。
- 结构演进必须与数据事件兼容，字段增删、类型变化和消费者版本差异不能造成静默误读。
- 批量导入进入权威数据集前必须在隔离范围验证类型、唯一性、引用和数量，避免部分成功成为不可识别状态。
- 源与目标必须定期按关键身份、数量和内容一致性对账；传输完成和消费成功都不能替代终态核对。

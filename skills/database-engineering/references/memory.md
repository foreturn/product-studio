## 共同定位与写入契约

- **Owner**：`database-engineering` 唯一裁决数据库事实的主题、四栏语义与 `ADD / UPDATE / DELETE / NO_CHANGE`；其他专业只可引用，不复制或改写正文。
- **Locator**：`<Git仓库根>/docs/product-studio/<product-id>/database-engineering.md`。
- **product-id**：由用户范围、仓库原生产品身份、运行入口、相关代码、目标 Schema 与调用链共同确认；必须唯一、稳定并可安全作为单级目录名，不得从目录名机械推导。多产品仓库逐产品隔离，归属不唯一时不得写入。
- **当前证据**：只有当前目标数据库精确引擎与版本上的 DDL、Schema、查询计划、配置、迁移、维护脚本及相称验证证实的现行语义可以入册。ORM 推断、内存数据库结果、未执行方案与环境瞬时状态不得冒充数据库事实。
- **写权限**：只有获得本轮事实册写权限时方可修改；只读分析仅产出候选主题与证据，不得创建目录、空册或改动既有内容。
- **主题粒度**：一个主题承载一个共同检索、共同变化的数据库语义，不按任务、文件、单列、迁移编号或命令流水机械拆分。

## 统一实例格式

```markdown
# database-engineering 当前产品事实

## <稳定事实主题>

- **当前事实**：<目标数据库当前强制或执行的专业语义及成立条件>
- **权威依据**：<一至三个 `仓库相对路径#DDL、Schema、查询、迁移或配置精确位置`>
- **影响边界**：<表组、查询、写入者、作业、消费者、数据库版本及明确不适用处；无则写“无”>
- **复核入口**：<目标数据库上的可重复检查、关键断言、未覆盖边界与重审触发>
```

四栏必须同时存在。主题或任一栏改变均按对应事实类型的变更规则处理；删除只移除已消失事实，不在事实册保留迁移历史或删除占位。

## 事实类型：物理 Schema 与关系

- **入册条件**：目标数据库已执行会被多个查询、写入路径或维护任务复用的表、列、类型、默认值、生成列、分区或表间物理关系。
- **主题合并键**：以“业务数据集合 + 核心表组 + 关系语义”合并；同一聚合的主表、从表、关联方向和关键列写入同一主题，不按列逐项建主题。
- **当前事实写法**：写明引擎及版本、Schema 与表组、关键列类型和空值语义、关系基数、分区或生成机制及适用条件；区分数据库强制内容与应用约定。
- **权威依据**：引用目标数据库 DDL、Schema 定义、已应用迁移、元数据检查或生成列表达式；ORM 模型只能辅助定位，不可单独证明物理结构。
- **影响边界**：列出读写服务、查询、批处理、报表、复制或导出消费者、数据库版本及不适用的存储后端。
- **复核入口**：提供目标引擎的 Schema introspection、迁移后结构断言、关系读写测试与分区检查；表组、列类型、关系或引擎版本变化时重审。
- **变更规则**：`ADD` 用于新增稳定表组或关系语义；`UPDATE` 用于表列、类型、关系、分区、依据或消费者变化；`DELETE` 用于结构及最后消费者移除；四栏均未改变则 `NO_CHANGE`。
- **专属禁项**：不记录 DTO、接口字段、纯 ORM 关系或候选表设计；业务对象边界不等同于物理 Schema 事实。

## 事实类型：键、约束与完整性

- **入册条件**：目标数据库已通过主键、外键、唯一、检查、非空、排除约束、触发器或等效引擎机制强制稳定数据不变量。
- **主题合并键**：以“受保护数据集合 + 完整性不变量 + 强制机制”合并；同一不变量涉及的键、约束与冲突语义写在一个主题。
- **当前事实写法**：写明约束对象、允许与禁止状态、键组成、空值与冲突语义、级联行为、延迟检查条件及数据库未强制而由应用承担的缺口。
- **权威依据**：引用约束 DDL、Schema 元数据、触发器定义、冲突测试和目标数据库错误断言；应用校验不能替代数据库约束证据。
- **影响边界**：列出写入者、批量导入、级联对象、去重或幂等路径、历史数据与受约束数据库版本。
- **复核入口**：提供违反约束、并发冲突、级联更新删除、空值和重复键检查；约束定义、写入者或数据装载方式变化时重审。
- **变更规则**：`ADD` 用于新增数据库强制不变量；`UPDATE` 用于键组成、约束语义、级联、证据或影响范围改变；`DELETE` 用于约束和相应不变量完全移除；无四栏变化则 `NO_CHANGE`。
- **专属禁项**：不把仅存在于表单、DTO 或服务校验中的规则写成数据库完整性；不记录单次脏数据修复过程。

## 事实类型：索引、访问路径与执行计划

- **入册条件**：关键查询已在目标数据规模和引擎版本下依赖特定索引、分区裁剪、物化结构或稳定计划形态满足性能与资源边界。
- **主题合并键**：以“查询族 + 过滤排序连接形态 + 访问路径”合并；服务于同一查询族的复合、覆盖或部分索引写入同一主题。
- **当前事实写法**：写明查询族、谓词与排序、索引键顺序和包含列、部分条件或分区、期望计划节点、规模前提及不可覆盖场景。
- **权威依据**：引用索引 DDL、实际查询、`EXPLAIN` 或等效计划、统计信息配置和代表性数据量下的基准；仅凭索引名称不得入册。
- **影响边界**：列出查询调用者、写放大对象、受影响表组、数据规模区间、目标引擎版本和不适用的查询形态。
- **复核入口**：提供目标数据库计划采集、代表性基准、索引命中、排序或回表断言；查询谓词、基数、统计信息、数据规模或引擎版本变化时重审。
- **变更规则**：`ADD` 用于确立新的关键访问路径；`UPDATE` 用于查询形态、索引定义、计划预期、规模前提、证据或消费者改变；`DELETE` 用于查询族或索引依赖消失；当前四栏一致则 `NO_CHANGE`。
- **专属禁项**：不记录计划中的索引、一次性慢查询、无代表性样本的本机耗时或优化器偶然选择；普通非关键索引无需逐项入册。

## 事实类型：隔离、锁与并发

- **入册条件**：目标数据库已执行稳定事务边界、隔离级别、显式或隐式锁顺序、乐观版本、幂等写入或冲突重试机制，以维持并发不变量。
- **主题合并键**：以“并发业务操作 + 受保护数据集合 + 冲突策略”合并；同一操作的事务范围、锁对象、顺序和重试条件写在同一主题。
- **当前事实写法**：写明事务起止、隔离级别、锁类型与获取顺序、允许并发、被阻止异常、死锁或序列化失败处理、重试上限及引擎差异。
- **权威依据**：引用事务实现、锁 SQL、版本列或幂等约束、数据库配置、并发测试与目标引擎错误断言；单线程测试不足以证明并发语义。
- **影响边界**：列出并发写入者、表组、队列或作业、延迟与吞吐影响、跨实例范围及适用数据库版本。
- **复核入口**：提供真实目标引擎上的竞争、死锁、丢失更新、幻读、重复提交或重试测试；事务范围、访问顺序、实例数或隔离配置变化时重审。
- **变更规则**：`ADD` 用于建立新的并发不变量或冲突策略；`UPDATE` 用于隔离、锁顺序、重试、依据或参与者改变；`DELETE` 用于并发场景或保护机制消失；四栏无变化则 `NO_CHANGE`。
- **专属禁项**：不以 SQLite、内存数据库或 mock 结果证明 PostgreSQL、MySQL 等目标引擎语义；不记录暂时锁等待或事故现场快照。

## 事实类型：迁移、回填与兼容

- **入册条件**：当前 Schema 或数据格式仍依赖已执行的扩展收缩、双版本兼容、在线 DDL、回填、校验或可逆机制，且后续变更必须遵守这些条件。
- **主题合并键**：以“演进对象 + 兼容窗口 + 数据转换不变量”合并；同一演进的 DDL、回填、双读写、校验与回退条件写入同一主题。
- **当前事实写法**：写明当前与兼容结构、DDL 方式、回填选择键与批次语义、双读写或默认值条件、校验不变量、回退前提及结束兼容的客观条件。
- **权威依据**：引用已生效迁移、回填或校验脚本、兼容读写实现、迁移状态约束和目标引擎演练；迁移文件存在不等于已执行能力成立。
- **影响边界**：列出新旧应用版本、表组、写入者、回填作业、复制链路、锁或容量风险及适用数据库版本。
- **复核入口**：提供空库与存量数据迁移、重复执行、断点续跑、混合版本读写、回退和迁移后不变量检查；兼容窗口、数据规模或引擎能力变化时重审。
- **变更规则**：`ADD` 用于形成新的当前迁移兼容条件；`UPDATE` 用于步骤不变量、批次、兼容窗口、回退、依据或影响范围改变；`DELETE` 用于兼容窗口结束且临时机制彻底移除；四栏未变则 `NO_CHANGE`。
- **专属禁项**：不记录迁移进度、执行时间线、一次性命令输出、未来计划或已结束且无现行约束的历史迁移。

## 事实类型：容量与数据生命周期

- **入册条件**：数据库已通过分区、保留、归档、清理、压缩、配额、增长阈值或维护机制执行稳定容量和生命周期约束。
- **主题合并键**：以“数据集合 + 生命周期阶段 + 容量机制”合并；同一数据集合的增长前提、保留、归档和清理条件写在同一主题。
- **当前事实写法**：写明数据规模或增长口径、保留期限及起算点、冷热阶段、归档与删除条件、分区维护、容量阈值、失败重试和法律保留例外。
- **权威依据**：引用分区 DDL、保留或清理作业、调度配置、容量告警、归档校验及代表性规模测试；推测增长不得写成当前容量事实。
- **影响边界**：列出表组、租户或地域、查询与恢复窗口、归档存储、批处理、合规例外及目标引擎版本。
- **复核入口**：提供分区轮转、保留边界、归档可读、清理幂等、容量阈值或大规模维护测试；增长模型、保留政策、分区方式或存储规格改变时重审。
- **变更规则**：`ADD` 用于建立新的当前容量或生命周期机制；`UPDATE` 用于阈值、期限、阶段、作业、证据或影响范围改变；`DELETE` 用于数据集合或机制移除；当前四栏一致则 `NO_CHANGE`。
- **专属禁项**：不记录生产数据样本、瞬时磁盘占用、未接受容量预测或合规原文；隐私目的和合法性不属于数据库物理生命周期事实。

## 事实类型：备份、恢复与高可用

- **入册条件**：目标数据库已配置并通过相称演练证实备份、时间点恢复、复制、故障转移、仲裁或一致性校验机制，并形成可复用的 RPO/RTO 或恢复不变量。
- **主题合并键**：以“数据库或数据域 + 故障范围 + 恢复机制”合并；同一数据域的备份、复制、切换和恢复校验写在同一主题。
- **当前事实写法**：写明备份类型与频率、保留和加密边界、恢复粒度、RPO/RTO 口径、复制拓扑、一致性或切换条件、人工介入点及未覆盖故障。
- **权威依据**：引用备份与复制配置、恢复脚本、校验任务、故障转移配置和脱敏演练结果；仅有供应商能力说明不得写成当前已具备能力。
- **影响边界**：列出数据库实例、地域或可用区、数据域、应用连接切换、备份存储、密钥依赖及不在保护范围内的数据。
- **复核入口**：提供隔离环境恢复、时间点恢复、校验和比对、复制中断、主从切换和应用重连测试；拓扑、备份格式、密钥、RPO/RTO 或引擎版本变化时重审。
- **变更规则**：`ADD` 用于新增已演练的恢复或 HA 能力；`UPDATE` 用于频率、保留、拓扑、恢复目标、依据或覆盖范围改变；`DELETE` 用于保护机制或对应数据域消失；无四栏变化则 `NO_CHANGE`。
- **专属禁项**：不记录真实备份文件名、连接信息、凭据、未演练恢复承诺、事故时间线或临时切换命令。

# 数据库工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/database-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始相关工作前读取已有事实。
- 当前代码、配置和正式契约等权威信息与旧事实冲突时，以当前权威为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程和一次性结果。

## 核心记忆

### 物理模型与强制不变量

- 记住数据库实际强制的持久化身份、唯一性、关系和完整性不变量，以及依赖它们的消费者。
- 记住仍由应用层承担、数据库并未强制的关键约束，避免误判保护边界。

### 关键访问路径

- 记住决定物理模型和索引设计的关键读写路径、选择与排序规则、分页关系和规模前提。
- 记住这些路径允许的退化方式，以及不属于其保障范围的查询形态。

### 事务、隔离与锁

- 记住关键并发操作的事务边界、隔离假设、锁定对象和允许或禁止的并发现象。
- 记住冲突、死锁和重试后的确定处理，以及跨数据库或外部副作用不受事务保护之处。

### 兼容演进不变量

- 记住仍在使用同一数据边界的消费者形态、读写权威和必须同时支持的数据不变量。
- 记住迁移历史不可改变的项目约束，以及解除兼容义务所需满足的真实消费者条件。

### 生命周期、容量与高可用

- 记住关键数据的保留、归档、删除和传播规则，以及容量不足时的确定行为。
- 记住数据库故障域、读写可用性、故障转移时的一致性边界和不受保护的部署形态。

### 备份与恢复保证

- 记住可恢复的数据范围、恢复点与恢复时间目标、依赖关系和明确未覆盖的对象。
- 记住恢复后必须成立的一致性与关键消费能力，以及恢复权限和外部依赖边界。

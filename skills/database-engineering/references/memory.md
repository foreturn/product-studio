# database-engineering 当前产品事实规则

## 所有权与稳定位置

- `database-engineering` 是服务端、共享消费者或独立运行数据库之终态语义事实的唯一 Owner；其他专业只能引用，不复制或改写本册事实。
- 稳定位置为 `docs/product-studio/<product-id>/database-engineering.md`；`product-id` 必须由产品身份、运行入口、目标数据边界与调用链共同确认，且可安全作为单级目录名。
- 多产品仓库逐产品分册；产品归属、运行边界或 Owner 不唯一时，不得读取候选册作为依据，也不得创建或修改事实册。
- 本册只索引当前成立的专业语义，不保存物理定义、运行参数或证据正文。涉及长期兼容时，只记当前支持不变量、现存消费者与退出触发，不记迁移阶段、目标态或推进进度。
- 只在本轮拥有事实文件写权限时落盘；只读任务只能报告候选动作与复核证据。

## 通用入册门禁

- **终态成立**：候选语义已由当前实现与风险相称的验证共同证明，不是计划、推断、临时兼容或进行中工作。
- **稳定**：候选语义预计跨越本次任务持续成立；一次执行结果、短时负载、运行快照和阶段进度不得入册。
- **非显然**：候选语义不能从命名、目录、框架默认或单个声明轻易重新得出，否则无需占用事实册。
- **决策相关**：候选语义会实质改变后续数据库设计、实现、审查、迁移或恢复判断。
- **重查昂贵**：若不索引，未来需要跨多处代码、Schema、调用链或可重复验证才能重新确认。
- **唯一 Owner**：Git 根、当前产品、`product-id`、主题合并键和 `database-engineering` 所有权均已唯一确认，且未在他册重复。
- **可复核**：当前代码或配置中存在稳定权威定位，并有可重复入口验证所写语义、适用边界与失败结果。
- **安全**：候选内容已最小化并脱敏，不含秘密、个人或生产数据、可利用细节、物理定义全文或原始证据。

任一门禁不成立即不得写入；证据、归属或授权不足时只在本轮报告说明，不产生事实动作。新证据与既有主题冲突时先复核权威来源，不并存互斥事实。

## 主题表达规则

- 主题以稳定数据库语义命名，不含路径、日期、任务号或动作前缀；同一合并键只保留一个当前主题。
- 每个主题必须表达当前事实、权威依据、影响范围与复核方式，并写清不变量、消费者、成立条件、明确限制、证据边界和重审触发。
- 不规定固定 Markdown H2、固定四栏、固定字段标签或统一字段顺序；可依事实类型与可读性使用段落、列表或表格。
- 表达应便于沿权威入口复核和原位合并，不按 Schema 对象、查询、作业或测试用例机械拆题。
- 不收录物理定义、修改摘要、过程记录、运行快照、迁移进度、时间线、责任人或待办。

## 动作语义

- `ADD`：主题合并键尚不存在，候选终态语义通过全部入册门禁且必备语义完整；新增一个当前主题。
- `UPDATE`：同一主题的当前事实、权威依据、影响范围或复核方式实质变化，且新语义通过全部门禁；原位保留唯一当前表述。
- `DELETE`：主题所述不变量、保证或最后消费者已从当前产品消失；删除完整主题，不保留历史占位。
- `NO_CHANGE`：沿权威依据完整复核后必备语义均无实质变化；不得因改写表达、调整顺序或更换呈现方式触碰事实文件。

## 事实类型

### 物理模型与强制不变量

- **入册条件**：当前数据库已经强制某项持久化身份、关系或完整性不变量，多个读写消费者必须据此作出正确决定。
- **主题合并键**：以“受保护数据集合 + 强制不变量 + 消费边界”合并；共同变化的身份、关系与完整性保证归入同题。
- **当前事实写法**：写明数据库实际保证什么、何时成立、哪些状态被拒绝、谁依赖该保证，以及仍由应用承担的明确缺口。
- **权威依据**：定位当前 Schema、迁移结果、数据库侧强制实现与正反向验证，不复制 DDL、字段清单或物理对象定义。
- **影响边界**：列出数据集合、写入者、读取者、导入作业、兼容版本与不受该保证约束的路径。
- **复核入口**：以目标引擎验证合法与非法状态、并发写入和消费者错误映射，并说明模拟环境不能证明的边界。
- **变更规则**：不变量、强制位置、消费者、适用条件或证据边界实质变化时 `UPDATE`；仅物理命名或等价实现变化时 `NO_CHANGE`。
- **排除项**：不记录 DDL、表列或约束清单、ORM 镜像、业务字段百科、数据样本、候选模型、迁移过程和一次修复结果。

### 关键访问路径

- **入册条件**：当前关键读写任务依赖稳定访问语义，且错误的访问路径选择会改变用户结果、资源风险或可扩展边界。
- **主题合并键**：以“业务访问族 + 数据选择或顺序语义 + 消费结果”合并；共同演进的读取、连接、排序与写入访问归入同题。
- **当前事实写法**：写明访问族的选择、顺序与一致性要求，适用数据形态、消费者、可接受退化方式及明确不覆盖的查询形态。
- **权威依据**：定位真实查询构造、当前物理支持与目标引擎计划或基准断言，不抄录 SQL、索引定义、执行计划或测量快照。
- **影响边界**：列出调用者、数据集合、读写负担、代表性规模条件、数据库版本及不适用访问族。
- **复核入口**：在代表性数据形态验证结果正确性、访问形态与退化行为，并标明模拟数据或本地引擎的证明限制。
- **变更规则**：访问语义、关键消费者、物理依赖、数据形态前提或验证结论改变时 `UPDATE`；内部查询重写而终态语义不变时 `NO_CHANGE`。
- **排除项**：不记录索引或 SQL 清单、具体参数、单次慢查询、一次执行计划、临时调优、瞬时耗时和未落地优化建议。

### 事务、隔离与锁

- **入册条件**：当前并发操作依赖数据库提供的稳定原子性、可见性、冲突或锁定不变量，且多个执行者可能同时触达同一数据边界。
- **主题合并键**：以“并发业务操作 + 受保护数据集合 + 冲突结果”合并；同一不变量的事务、隔离与锁语义归入同题。
- **当前事实写法**：写明事务成立边界、允许与禁止的并发现象、冲突后的确定结果、重试责任与终止语义，以及跨资源不受保证之处。
- **权威依据**：定位事务实现、隔离或锁定声明、幂等或版本控制点与目标引擎并发测试，不复制锁语句或运行会话状态。
- **影响边界**：列出并发写入者、数据集合、后台作业、跨资源副作用、数据库版本与不参与该事务的消费者。
- **复核入口**：以可重复交错验证竞争、回滚、冲突、死锁或重试结果，说明单线程、Mock 或替代引擎不能覆盖的边界。
- **变更规则**：原子边界、隔离语义、锁定不变量、参与者、失败结果或证据改变时 `UPDATE`；内部实现等价替换时 `NO_CHANGE`。
- **排除项**：不记录事务代码全文、锁清单、重试数值、当前会话、锁等待快照、事故状态、跨服务补偿过程或一次并发结果。

### 兼容演进不变量

- **入册条件**：当前仍有两个或以上已存在消费者形态依赖同一数据边界，数据库演进必须维持明确兼容不变量直至可验证退出触发成立。
- **主题合并键**：以“演进数据边界 + 当前支持不变量 + 消费者集合”合并；同一兼容义务只保留一个当前主题。
- **当前事实写法**：只写当前必须同时支持的语义、现存消费者、读写权威、失败行为与可验证退出触发，不写阶段、目标态或推进进度。
- **权威依据**：定位当前 Schema、兼容读写实现、消费者调用点与组合测试；迁移计划、任务状态和未执行脚本不能证明当前兼容义务。
- **影响边界**：列出仍受支持的消费者、数据集合、应用版本边界、后台作业及退出前不得破坏的关系。
- **复核入口**：验证所有现存消费者组合、旧新数据交互、失败与退出条件，并明确尚未取得的环境或版本证据。
- **变更规则**：支持不变量、消费者、读写权威或退出触发改变时 `UPDATE`；退出触发已证实且兼容义务消失时 `DELETE`；否则 `NO_CHANGE`。
- **排除项**：不记录迁移编号、执行步骤、回填比例、阶段名称、目标架构、时间表、进度、日志、临时开关值或历史兼容状态。

### 生命周期、容量与高可用

- **入册条件**：当前数据集合受稳定保留、归档、清除、容量退化或数据库高可用语义约束，后续实现必须据此处理数据与故障。
- **主题合并键**：以“数据集合或运行域 + 生命周期或可用性保证 + 消费边界”合并；共同变化的保留、容量与可用性语义归入同题。
- **当前事实写法**：写明数据生命周期结果、容量不足时的确定行为、读写可用性与一致性边界、消费者及明确不覆盖的故障，不写资源参数。
- **权威依据**：定位当前生命周期策略、维护与高可用配置、消费代码及代表性容量或故障验证，不复制配置值或平台状态。
- **影响边界**：列出数据集合、读写消费者、环境、故障域、归档与删除传播、外部依赖及不适用部署形态。
- **复核入口**：验证保留与删除结果、容量退化、连接恢复和代表性故障下的读写语义，注明未演练故障与生产边界。
- **变更规则**：生命周期结果、容量失败语义、可用性保证、消费者、故障边界或依据改变时 `UPDATE`；机制与最后消费者消失时 `DELETE`。
- **排除项**：不记录分区或资源参数、容量阈值、实例拓扑清单、即时规模、复制延迟、当前主节点、维护状态、账单或事故快照。

### 备份与恢复保证

- **入册条件**：当前产品对某数据边界具有经恢复验证的稳定可恢复性保证，且后续变更必须维持其一致性、依赖或可恢复范围。
- **主题合并键**：以“可恢复数据边界 + 恢复结果语义 + 消费者”合并；共同恢复与校验的数据和依赖归入同题。
- **当前事实写法**：写明能够恢复何种终态、恢复的一致性和依赖边界、权威恢复目标引用、消费者、失败限制与明确未覆盖数据。
- **权威依据**：定位备份恢复配置、运行册、隔离恢复验证与应用级断言，不复制备份参数、任务状态、原始制品或供应商宣称。
- **影响边界**：列出数据集合、环境、故障域、应用消费者、密钥或扩展依赖、恢复权限与不在保证内的对象。
- **复核入口**：在隔离环境重复恢复并验证数据一致性与关键消费路径，说明时间点、规模、拓扑或生产权限方面的证据边界。
- **变更规则**：可恢复范围、结果语义、依赖、消费者、权威目标或验证边界改变时 `UPDATE`；恢复义务与最后消费者消失时 `DELETE`。
- **排除项**：不记录备份频率或保留参数、最近任务状态、恢复耗时快照、备份内容、密钥、生产样本、事故时间线或未演练承诺。

## 全册安全与删除规则

- 不记录真实连接串、账户、密码、密钥、个人或生产数据、原始查询结果、备份内容、内部网络细节及可直接利用的信息。
- 权威依据只写仓库相对路径与精确 Symbol、配置或测试位置；不得把 DDL、索引、SQL、物理拓扑、参数或外部原始证据复制进事实册。
- 删除前确认终态语义、最后消费者、退出触发和所有当前依据均已消失；不因文件改名、一次验证失败或暂时不可达而误删。
- 删除最后主题时移除事实文件；仅在产品目录无任何 Owner 事实文件时才移除产品目录，不留下空册或空目录。
- 同一事实不得复制到其他 Owner 册；跨专业影响只以稳定引用和影响边界表达，不改写他册正文。

# 架构设计能力准则

按当前改动触及的边界与风险选择能力卡。架构能力裁决跨边界不变量、数据所有权、信任边界、质量属性与演进约束；具体 API、Schema、权限检查和一致性代码由实现能力落实。

## 能力目录

- **系统建模**：模块、进程、数据所有权或部署关系尚不清晰，或现有结构无法解释完整用户旅程时启用。
- **边界与契约设计**：共享不变量、核心数据主权或跨边界交互的操作语义、时序与兼容责任发生变化时启用。
- **质量属性权衡**：性能、容量、可靠性、恢复、扩展、维护性或成本会改变方案选择时启用。
- **一致性与故障设计**：业务动作跨资源、跨进程或包含异步副作用，可能重复、乱序、超时、部分成功或恢复重放时启用。
- **安全与权限边界**：主体身份、租户上下文、敏感资产或受限数据跨越客户端、服务、网络或存储边界时启用。
- **可观测与可运行性**：核心旅程跨组件，故障隔离、降级、恢复或值守依赖统一运行信号时启用。
- **演进与迁移**：契约、数据所有权、信任边界或部署拓扑改变，新旧代码、契约或数据需要过渡期共存时启用。

## 核心能力

### 系统建模

- **启用**：
  - 改动跨越模块、进程、数据所有权、信任边界或部署单元。
  - 局部实现不足以解释共享规则、跨边界副作用或完整用户结果。
  - 若只涉及单一模块内部的类、查询或组件组织，不形成架构裁决。
- **输入**：
  - 读取当前代码、Schema、部署拓扑、协议、运行信号和已有决定。
  - 收集用户目标、受影响旅程、入口、调用方、依赖与团队责任。
  - 将已核验事实、合理假设、未知项和外部参考及其原始适用条件分开标注。
- **执行**：
  - 从业务能力、规则聚合、变化频率、数据一致性和责任归属识别边界，不从目录、表名、类名或框架分层机械推导领域。
  - 对每个入口追踪“参与者 → 接入层 → 业务能力 → 权威数据 → 下游副作用 → 用户可见结果”。
  - 补齐回调、定时任务、批处理、事件消费者、缓存和人工操作等非请求链路。
  - 为每个边界写明拥有的业务事实、允许的操作、公开的契约和不承担的责任。
  - 使依赖指向更稳定的业务契约；共享库只承载稳定通用能力。
- **裁决**：
  - 只有独立演进、故障隔离、数据主权或共享不变量存在真实收益时才拆分边界。
  - 同时计算网络调用、数据同步、部署和值守成本，不能只计拆分收益。
  - 两个模块都能任意修改同一事实时，判定数据主权未建立。
  - 共享库夹带特定领域规则、数据库访问或隐式全局状态时，判定依赖边界失真。
  - 不得把产品范围、用户旅程或业务规则的不确定性包装成架构选择。
- **产出**：
  - 上下文与影响图，覆盖入口、模块、数据所有者、上下游、协议、部署、信任边界和运行信号。
  - 入口、调用方和副作用清单，以及核心数据所有权表。
  - 每个边界的“拥有、公开、不承担”职责句和依赖方向。
  - 循环依赖、跨边界隐式写入、共享数据库写入等显式风险清单。
- **验证**：
  - 从每个入口正向追到用户可见结果，再从核心事实反向核对唯一写入权威与全部调用方。
  - 核验回调、任务、事件、缓存、批处理和人工入口未遗漏。
  - 用当前代码、Schema、部署和运行证据校正外部案例。
  - 组件图或模式名称不能替代调用链、数据主权和失败路径证据。
- **完成**：
  - 核心事实具有唯一责任边界和写入权威。
  - 所有入口、调用方、依赖、副作用、部署位置、信任边界与运行信号均能在影响图中定位。
  - 边界拆分的可验证收益足以覆盖新增耦合与运维成本。
- **边界**：
  - 不裁决类、目录、表字段或局部组件结构。
  - 局部服务端实现交给 `backend`，局部界面实现交给 `frontend`。
  - 只规定跨边界必须保持的语义与约束，不代替产品能力确认。

### 边界与契约设计

- **启用**：
  - 共享业务规则、核心状态或数据主权发生变化。
  - 跨边界调用的输入输出、错误、时序、一致性、版本或消费者责任发生变化。
- **输入**：
  - 已确认的用户动作、业务状态、兼容承诺、当前消费者、数据分类与调用链。
  - 相关聚合和事务边界的现状。
  - 缓存、搜索索引、分析仓库和客户端副本的来源、刷新与使用现状。
  - 正常路径、拒绝路径和失败返回路径。
- **执行**：
  - 把不变量写成可证伪陈述，例如“同一租户内标识唯一”“已结算订单金额不可改变”。
  - 为不变量标明所有者、执行点、事务范围、异常语义、违规信号和修复动作。
  - 为每类核心数据指定唯一写入权威。
  - 把缓存、搜索索引、分析仓库和客户端状态标为派生副本，注明刷新机制、可接受陈旧度与重建路径。
  - 统一时间的时区与精度、金额的币种与舍入、身份和租户的作用域、生命周期与删除语义。
  - 画出正常与失败数据流，标明触发者、数据分类、延迟预算、重试责任和最终观察者。
- **裁决**：
  - 聚合边界以一次业务动作必须原子保持的不变量为尺度。
  - 聚合过大会造成锁竞争和扩展困难；过小会把关键规则推入脆弱的分布式协调。
  - 跨边界规则必须在同步拒绝、预留或锁定、事件驱动补偿、对账修复或业务接受短暂不一致之间明确选择，并对应用户可见后果。
  - 调用方必须立即得到确定结果或参与同一一致性边界时优先同步。
  - 只有副作用可延迟、需要削峰或故障隔离时才采用异步，同时承担最终一致、积压、重复和恢复成本。
  - 循环依赖和跨边界隐式写入必须作为风险处理，不能藏在实现细节中。
- **产出**：
  - 同步契约：操作语义、请求响应、错误分类、超时、取消、幂等键、权限上下文、版本和兼容责任。
  - 事件契约：生产条件、事实发生时间、Schema、分区或顺序键、投递语义、重复处理、重放、死信和消费者兼容策略。
  - 数据主权表和派生副本的刷新、陈旧度与重建约束。
  - 跨边界不变量清单及正常、拒绝和失败数据流。
- **验证**：
  - 证明实现方无需猜测谁拥有数据、何时算成功、失败由谁重试、重复或乱序如何收口、新旧消费者如何共存。
  - 核验查询契约不暗含不可见的状态修改。
  - 以当前消费者核对每个字段、事件和扩展点；没有当前消费者的字段、插件点或“通用能力”不得进入方案。
  - 模拟权威源故障、派生副本失效延迟或重建，确认仍能判断哪份数据可信。
- **完成**：
  - 不变量、数据主权、同步或异步选择、正常与失败语义及兼容责任可被实现与测试直接采用。
  - 派生副本具有明确的陈旧容忍和重建路径。
  - 共享数据库直接改表却称逻辑解耦、必须立即确定的结果被无依据异步化、缓存成为第二事实源等误判已被消除或显式接受。
- **边界**：
  - 只裁决跨边界语义、责任与不变量。
  - 具体 API 字段、状态码、错误码、Schema、索引、序列化形式和数据库约束由 `backend` 设计并验证。

### 质量属性权衡

- **启用**：
  - 候选方案取决于延迟、吞吐、容量、可用性、数据恢复、扩展路径、维护性或成本。
  - 有人以“高可用”或“未来增长”主张新增服务、队列、缓存或分布式协调。
- **输入**：
  - 具体用户旅程和现有运行基线。
  - 峰值请求、数据规模及增长、读写比例、并发连接、消息积压、批任务窗口和资源上限。
  - 未知值以假设记录，并为每项假设设置压测、监测或重审触发点。
- **执行**：
  - 用“刺激—环境—受影响组件—预期响应—量化指标”描述质量属性场景。
  - 例如：“依赖超时 2 秒时，创建请求在 3 秒内返回可重试错误且不产生重复订单”。
  - 把关键路径拆为网络往返、查询次数、扫描行数、序列化、锁等待、队列等待、缓存命中和 CPU／内存／连接池预算。
  - 把可用性和恢复目标落实到具体旅程及数据，区分进程存活、服务就绪、业务成功率、允许数据丢失窗口和恢复时长。
- **裁决**：
  - 候选集必须包含“沿用现状”或局部修补这一简单基线。
  - 按不变量、安全、可靠性、兼容、可逆性、交付和长期成本比较候选。
  - 扩展优先评估消除无界操作、批处理、背压、无状态化和明确分区键。
  - 以扩容或性能为由引入新服务、队列、缓存或分布式协调时，必须有当前负载、增长和瓶颈证据，不能用抽象“未来高并发”代替。
  - 以数据所有权、故障隔离或独立演进为由拆分服务边界时，必须分别证明对应收益，并计入网络、部署、监控和值守成本；这类边界证据不能冒充负载证据。
  - 服务拆分不自动证明需要队列、缓存或分布式协调；每项机制仍须单独证明一致性、故障恢复或容量问题及其失效语义。
  - 小幅性能收益若换来长期复杂度，必须有可验证业务价值。
- **产出**：
  - 质量属性场景、容量和性能基线及可测阈值。
  - 至少包含简单基线、采用方案和未采用方案的候选对比。
  - 每个候选的约束满足度、依赖与耦合、开发和迁移成本、基础设施和监控值守成本、认知负担、验证办法、可逆性及放弃理由。
- **验证**：
  - 以同一旅程、数据分布和负载比较采用前后结果。
  - 核验指标对应用户感受，不能用单一可用性百分比覆盖所有能力。
  - 核验外部基准的拓扑、规模与约束同当前系统相符。
  - 未知容量不得写成当前事实，必须保留假设和补证条件。
- **完成**：
  - 采用方案相对简单基线具有可复现收益。
  - 阈值、预算、适用范围与重审条件明确。
  - 可信增长得到覆盖，未证实增长未被预先实现。
  - 开发、迁移、运行、监控和值守成本均已计入。
- **边界**：
  - 不替实现层选择局部查询写法、缓存参数或资源数值。
  - `backend` 负责具体优化和性能测试，`release` 负责生产容量门禁与运行验证。

### 一致性与故障设计

- **启用**：
  - 状态变化跨数据库、缓存、消息或外部依赖。
  - 可能遭遇依赖不可用、超时、重复、乱序、部分成功、容量耗尽、数据损坏、进程中断或恢复重放。
- **输入**：
  - 用户承诺、状态机、事务和提交点、外部副作用、投递语义、调用层级与错误分类。
  - 每个故障点的可观察症状、已提交状态、最终观察者和自动或人工恢复条件。
- **执行**：
  - 建立故障矩阵，逐项记录故障点、症状、已提交状态、重试主体、幂等机制、补偿动作、用户反馈、告警和人工入口。
  - 从用户承诺向下分配端到端超时，为子调用保留取消与清理时间。
  - 把重试放在最了解幂等和错误分类的一层，限定次数、退避、抖动及总时限。
  - 对跨资源状态变化标明事务边界和部分成功状态。
  - 选择事务发件箱、Saga、补偿或对账时，同时写出不可自动补偿的人工路径。
  - 恢复步骤包含数据校验、重放范围、恢复顺序、速率限制和重复副作用防护。
- **裁决**：
  - 无限等待或下游超时大于上游预算会造成资源滞留，判定不可接受。
  - 多层叠加重试会放大流量并延迟真实失败，必须收敛到唯一责任层。
  - “至少一次”要求消费者按重复和乱序设计。
  - 声称“恰好一次”必须说明去重边界、持久化原子性和提交前后故障窗口，不能仅引用中间件名称。
  - 服务重启只证明进程恢复，不能判定业务恢复。
- **产出**：
  - 一致性决定和端到端超时预算。
  - 故障与恢复矩阵、部分成功状态和最终观察者。
  - 恢复顺序、重放范围、速率限制、重复副作用防护及不可自动补偿项。
  - 用户反馈、告警、人工处置入口和业务恢复判据。
- **验证**：
  - 制造适用的重复、乱序、依赖超时、部分成功、进程中断、数据损坏或迁移中断。
  - 核验状态可观察、重试不放大、补偿和人工入口可达。
  - 执行数据校验与受控重放，核对恢复后的业务事实和外部副作用。
  - 局部单元测试不得冒充跨边界重复、乱序、超时和部分失败证据。
- **完成**：
  - 每个故障状态都有唯一处理责任、确定的用户语义、可观察信号和收口路径。
  - 至少一次投递、幂等、重试、补偿、对账及不可逆副作用均有证据。
  - 不存在未归属或被服务重启掩盖的跨边界部分成功状态。
- **边界**：
  - 裁决跨边界一致性目标、失败语义和恢复责任。
  - 事务、锁、幂等记录、发件箱、Saga、重试和补偿代码由 `backend` 实现。
  - 生产故障演练由 `release` 在授权边界内执行。

### 安全与权限边界

- **启用**：
  - 主体身份、服务身份、租户上下文、敏感资产或受限数据跨越客户端、服务、网络、存储或外部供应商边界。
- **输入**：
  - 资产、参与者、入口、信任边界、身份来源、资源归属、数据流和高价值动作。
  - 按实际入口收集注入、越权、重放、SSRF、反序列化、批量枚举与资源耗尽等适用滥用路径。
- **执行**：
  - 区分认证“主体是谁”与授权“主体能对哪个资源执行何种动作”，指定可信服务端决策点。
  - 把数据标为公开、内部、敏感或受限。
  - 规定数据采集、传输、存储、日志、导出、备份、保留和删除要求。
  - 要求服务身份、用户身份与租户上下文在跨边界调用中显式传播并校验。
  - 为外部输入规定长度、格式、类型、业务范围和资源消耗限制。
- **裁决**：
  - 网络位置、前端隐藏和调用方声明不得代替授权。
  - 身份、角色、租户或资源范围不能由非可信输入直接决定。
  - 安全控制必须对应当前资产和真实入口，不能用抽象威胁扩张产品范围。
  - 依赖故障时必须选择拒绝、受控降级或只读，不得默认扩大权限。
- **产出**：
  - 信任边界图、资产和数据分级表。
  - 授权责任矩阵及跨边界身份传播规则。
  - 实际威胁与缓解矩阵。
  - 高价值动作审计语义，至少关联主体、对象、动作、结果和时间。
- **验证**：
  - 沿每个入口核验身份来源、资源与租户授权点和数据范围。
  - 以跨租户、越权、重放、批量枚举及适用注入路径验证拒绝行为。
  - 检查日志、追踪、备份和审计不保存密钥、令牌与非必要个人数据。
  - 证明高价值动作可以关联主体、对象、结果与时间。
- **完成**：
  - 每次跨边界调用都有唯一可信身份与授权决策点。
  - 数据全生命周期和失败时权限行为明确。
  - 真实滥用路径具有控制及证据。
  - 审计可关联且不扩大敏感信息暴露。
- **边界**：
  - 裁决信任边界、数据分类和授权责任。
  - 具体权限查询、输入校验、限流、密钥处理和审计落库由 `backend` 实现。
  - 是否采集和保留某类数据由产品契约确认。

### 可观测与可运行性

- **启用**：
  - 核心用户旅程跨多个组件。
  - 故障定位、依赖隔离、降级、数据恢复或值守需要统一业务与技术信号。
- **输入**：
  - 核心旅程、状态机、拒绝与失败分类、依赖图、用户承诺和恢复步骤。
  - 现有日志、指标、追踪、健康检查、告警和运行手册。
  - 各信号的责任团队、覆盖范围与缺口。
- **执行**：
  - 先从旅程定义业务成功、拒绝、失败、延迟和积压，再补充 CPU、内存、连接池与依赖健康。
  - 用请求、任务或业务对象关联标识串联同步与异步阶段。
  - 保持指标标签有限基数，让追踪覆盖跨进程和异步传播。
  - 为每个 SLI 规定阈值依据、用户影响、责任边界和处置动作。
  - 区分存活、就绪和核心业务可用。
- **裁决**：
  - 没有用户影响或处置动作的告警降级为诊断信息。
  - 非关键依赖短暂失败不应触发重启风暴。
  - 进程存活不得掩盖核心旅程失效。
  - 只增加日志量却不能回答“何处失败、影响何人、如何恢复”不算可观测性。
  - 没有状态所有权、错误语义和运行信号的组件图不能作为可运行证据。
- **产出**：
  - 用户旅程到日志、指标和追踪的映射。
  - SLI、阈值、告警责任与处置动作表。
  - 存活、就绪和业务可用的健康语义。
  - 覆盖定位入口、依赖隔离、降级开关、数据核验、恢复步骤和升级条件的运行手册约束。
- **验证**：
  - 从用户症状出发，使用关联标识定位责任边界和失败阶段。
  - 触发适用的业务拒绝、依赖失败与积压场景，核验告警可行动。
  - 核验指标标签基数受控，异步链路关联不断裂。
  - 按运行手册完成隔离、数据校验和恢复判断。
- **完成**：
  - 运行人员无需阅读全部代码即可区分业务拒绝、可恢复故障和系统缺陷。
  - 能够定位边界、隔离依赖、核验数据并判断业务恢复。
  - 健康检查不会因语义混淆造成重启风暴或虚假健康。
- **边界**：
  - 裁决跨组件信号语义和运行责任。
  - 日志字段、指标名、追踪埋点与健康端点由 `backend` 实现。
  - 生产告警、值守和恢复执行由 `release` 管理。

### 演进与迁移

- **启用**：
  - 契约、数据所有权、信任边界或部署拓扑改变，新旧代码、契约或数据不能一次切换。
  - 迁移包含不可逆数据变化、已发送事件或外部副作用。
- **输入**：
  - 当前和目标状态、全部消费者与部署单元、代码和数据版本及兼容承诺。
  - 已有 ADR、流量与使用观测。
  - 不可逆步骤、已发送事件、外部副作用、数据恢复来源和授权门禁。
- **执行**：
  - 按“扩展 → 兼容部署 → 数据迁移或回填 → 读写切换 → 验证 → 收缩”编排。
  - 每步写明新旧代码与数据兼容矩阵、进入条件、完成判据、暂停点、回滚范围、清理时机和数据后果。
  - ADR 记录问题、当前事实、约束、不变量、候选、选择、代价、可逆性、迁移、验证、重审触发和取代关系。
  - 把决定拆成可独立验证的切片，为每片指定前置契约、责任模块、契约影响、验证信号和失败收口。
- **裁决**：
  - 优先选择可逆且变更半径较小的方案，并明确逆转成本。
  - 不可逆决策要求更强证据、明确停止条件和提前演练的恢复路径。
  - 抽象仅在重复问题、稳定共性和明确消费者同时存在时产生。
  - 未证实的租户、规模、供应商或扩展场景只作为重审条件，不预置框架。
  - 回滚代码不等于回滚已写入数据、已发送事件或外部副作用。
- **产出**：
  - ADR、阶段计划、兼容矩阵和实现切片。
  - 流量切换、数据校验、暂停和清理条件。
  - 代码、Schema、数据和外部副作用分别对应的回滚、前滚修复、备份恢复或人工纠正方案。
  - 未决风险、重审触发和决定取代关系。
- **验证**：
  - 逐一验证过渡期允许的新旧代码、契约和数据组合可安全交互。
  - 演练暂停、重试、回滚或前滚路径。
  - 核对代码回滚后的数据可读性、已发事件和外部副作用。
  - 外部案例须记录来源、版本、原始条件与借鉴部分，并以当前拓扑和负载核验适用性。
- **完成**：
  - 每个阶段可单独进入、观察、暂停和收口。
  - 旧路径只在使用量归零且数据校验通过后清理。
  - 不可逆步骤具备停止条件和恢复方案。
  - 所有实现切片都有责任模块、验证信号和重新设计触发点。
- **边界**：
  - 裁决跨边界演进顺序、兼容责任和恢复约束。
  - 具体 DDL、索引、回填批次和服务端兼容代码由 `backend` 决定。
  - 生产灰度、切换、回滚授权和执行由 `release` 管理。

## 能力组合

1. 先用“系统建模”写清用户目标、受影响旅程和成功判据，读取代码、Schema、部署、运行与既有决定；若问题不触及共享不变量、数据主权、信任边界、部署边界或有证据的质量属性风险，停止架构裁决并交还实现能力。
2. 根据影响图提取业务不变量、授权边界、兼容承诺、数据分类、延迟和恢复目标；使用“边界与契约设计”固定状态所有权、事务尺度、同步或异步语义以及正常、拒绝和失败路径。
3. 按风险组合“安全与权限边界”“一致性与故障设计”和“质量属性权衡”，逐项推演竞态、重复、乱序、部分成功、依赖超时、容量耗尽、安全滥用、迁移中断和回滚后数据状态。
4. 形成包含“沿用现状或局部修补”的最小候选集；用不变量、安全、可靠性、兼容、可逆性、交付和长期成本作出可审计取舍，不以技术新颖度、模式名称或个人偏好计分。
5. 对跨组件旅程使用“可观测与可运行性”定义验证和恢复信号；存在新旧并存时追加“演进与迁移”，编排兼容发布、迁移、灰度、观测、切换、回滚和清理。
6. 将决定拆成可独立交付的实现切片，为每片指定前置契约、影响边界、验证命令或运行信号、失败处置和重新设计触发条件；将 API 字段、Schema、授权、事务、幂等和补偿等具体实现交给 `backend`。

## 完成判据

- **上下文证据充分**：上下文与影响图包含参与者、入口、模块、数据所有者、调用方、上下游、部署位置、信任边界、运行信号及正常／失败数据流；事实、假设、未知项与外部参考明确分开。
- **约束可以执行**：每项不变量写明责任边界、执行点、事务范围、违规表现、监测方式和恢复动作；契约的请求、响应、事件、错误、超时、幂等、顺序、权限、版本和兼容责任可供实现与测试直接使用。
- **权衡可以审计**：质量属性具有适用条件和量化判据；候选对比包含简单基线、采用和未采用方案，列明约束满足度、依赖、迁移难度、运行成本、可逆性及放弃理由。
- **决定可以追溯**：每项架构裁决均记录问题、选择与代价、适用范围、当前证据及外部参考来源、未决风险、重审触发、状态和被取代关系；纯边界、契约、安全或质量属性决定也不得因不涉及迁移而省略 ADR 留痕。
- **风险已有收口**：故障与威胁矩阵把重复、乱序、超时、部分成功、容量、滥用和数据损坏映射到隔离、降级、补偿、审计、告警、用户反馈和人工处置；不能用重试、中间件名称或局部单元测试冒充分布式证据。
- **演进能够执行**：迁移方案逐项列明阶段、兼容矩阵、数据校验、流量切换、暂停点、代码和数据的回滚边界、不可逆步骤、恢复与清理条件；不得把代码回滚误作完整回滚。
- **切片能够验证**：每个实现切片对应责任模块、契约、不变量、聚焦测试或运行信号，没有未归属的跨边界风险；架构裁决与 `backend` 的具体 API、Schema、权限及一致性实现边界清楚。
- **结论基于当前证据**：外部拓扑、负载、合规结论和参考实现仅作为候选证据，并已按当前系统核验；目录、共享数据库、“为了未来”的微服务或队列、只画正常路径等误判没有成为设计依据。

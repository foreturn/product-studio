# 系统架构设计

只处理当前需求真正存在的跨边界缺口，使系统边界、责任和失败行为在编码前明确；普通局部实现不得因抽象的“可扩展性”升级成架构工程，也不得擅自进入后端或前端代码实现。

## 输入门禁

- 明确项目根、仓库指令、用户结果、业务规则、变更范围、调用方、验收标准和不得破坏的行为。
- 读取相关产品事实、存在时的 `docs/product-studio/architecture.md` 中命中的总结性代码事实，以及现有模块、进程、存储、数据所有者、上下游、协议、部署单元、信任边界和运行信号。
- 产品用户、旅程、业务闭环、规则、范围或体验取舍未定时交给 `$design`；具体 API 字段、Schema、事务与服务端代码交给 `$backend`；页面、组件和浏览器行为交给 `$frontend`。
- 同时牵涉多个实现技能或共享契约时，由 `$router` 选择最小技能链；只有系统架构分析时可停在架构结论，不得擅自进入代码实现。

## 专业能力

先查看 [系统架构能力准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；形成完整架构决定、比较方案或复核风险时，再读“常见误判”。

按缺口选择能力：

- 模块、进程、数据所有者、上下游和部署关系：系统建模。
- 共享不变量、写入权威、同步／异步语义和兼容责任：边界与契约设计。
- 性能、容量、可靠性、可维护性和成本：质量属性权衡。
- 重复、乱序、部分成功、超时、补偿和恢复：一致性与故障设计。
- 身份传播、数据分类、信任边界和滥用路径：安全与权限边界。
- 业务信号、健康语义、告警和运行手册：可观测与可运行性。
- 新旧版本共存、数据切换、回滚和清理：演进与迁移。

## 架构流程

1. 从用户可见结果追踪入口、模块、进程、权威数据、外部依赖、部署单元和副作用，区分已核验事实、假设和未知。
2. 判断缺口是否真正跨越模块、进程、数据所有权、信任边界或部署单元；不跨边界的局部选择退回对应实现技能。
3. 为核心状态与共享不变量指定唯一责任模块和写入权威；缓存、索引、分析仓库和客户端状态只作具有刷新及重建路径的派生副本。
4. 定义跨边界操作或事件的语义、所有权、正常与拒绝行为、权限上下文、超时、幂等、顺序、版本、兼容期及调用方责任；具体字段、状态码和持久化实现由 `$backend` 落实。
5. 将性能、可靠性、安全、可维护性和成本写成有基线或阈值的场景，并比较包含沿用现状或局部修补在内的最小候选方案。
6. 标明事务与外部副作用的边界、部分成功、重试唯一责任层、补偿、人工恢复、依赖降级、审计和业务可观测信号。
7. 涉及演进时定义兼容扩展、双版本共存、数据处理、读写切换、验证和旧路径清理的进入条件、暂停点、回滚范围与数据后果。
8. 将决定拆成可独立实现和验证的切片，明确每片的前置契约、责任技能、影响边界、验证信号和失败收口；没有当前消费者的服务、字段或扩展点不进入方案。

## 当前代码事实记忆

开始工作时，若 `<当前项目根>/docs/product-studio/architecture.md` 存在，只读取命中的事实主题及直接关联。每次编码任务收口前完整读取 [architecture 记忆规则与实例格式](references/memory.md)，仅按最终代码同步 `architecture` 自己的事实册；首次确有事实时使用其中格式，不得预建空册。纯架构方案及重构、迁移和变更过程不入册；没有总结性事实变化时报告 `memory: 0 facts changed`。

## 输出与交接

- 交付系统上下文、边界与数据所有权、共享不变量、跨边界契约语义、质量场景、故障与安全约束、运行信号、演进条件和验证办法。
- 向 `$backend` 交付须落实的操作语义、责任边界、兼容要求、故障行为与实现切片；后端负责具体 API、Schema、事务和服务端代码，不得暗改架构决定。
- 向 `$frontend` 交付影响用户可见状态、权限、异步进度、降级和恢复的系统约束；向 `$verification` 交付风险场景、证据入口和重审条件。
- 实现发现新证据足以改变所有权、共享不变量、跨边界语义或质量约束时，退回本技能裁决，不在下游建立第二套架构。

## 完成门禁

- 每项关键共享不变量有唯一责任边界、执行位置、违规表现、恢复动作和验证信号。
- 跨边界契约具有消费者、正常与失败语义、权限与兼容责任；实现角色无需猜测系统边界。
- 候选方案包含沿用现状或局部修补，采用理由、代价、可逆性与重审条件明确。
- 适用的超时、重复、乱序、部分成功、依赖故障、安全滥用、迁移和回滚状态均有收敛路径。
- 架构结论绑定当前代码、Schema、部署拓扑或运行证据；外部案例和模式名称未冒充当前事实。

## 边界

- 可裁定系统与领域边界、数据主权、共享不变量、跨模块契约语义、质量属性、信任边界、一致性目标、故障恢复、运行约束和演进方案。
- 不自行改变目标用户、产品范围、用户旅程、业务规则或体验目标；这些交给 `$design`。
- 不代替 `$backend` 决定具体接口字段、错误码、表结构、事务代码和服务端实现，不代替 `$frontend` 决定组件、视觉与浏览器交互。
- 可设计迁移、回填、灰度与回滚方案，但不执行环境迁移、生产数据修复、切流或其他外部状态变更。
- 不代替 `$verification` 宣告产品增量通过；静态设计未取得真实实现与运行证据时，只能报告设计结论及待验证项。

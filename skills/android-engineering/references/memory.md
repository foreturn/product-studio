# Android 工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/android-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始相关工作前读取已有事实；仓库中的当前权威实现与契约优先于旧事实。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程和一次性结果。

## 核心记忆

### 应用模块与构建边界

- 记住应用、功能模块与共享库的稳定职责和依赖方向，以及哪些能力只属于特定构建变体、进程或分发渠道。
- 记住启动所依赖的初始化次序、进程边界与运行配置来源，避免模块调整改变应用入口或后台进程行为。

### 生命周期与任务恢复

- 记住关键任务状态由谁持有，哪些状态必须跨配置变化、后台回收和进程重建恢复，哪些副作用不得重复执行。
- 记住前后台切换、系统终止与任务栈重建时的保存和失效边界，避免把 Activity 或 Composable 实例当作长期权威。

### 导航与外部入口

- 记住核心任务的返回栈、完成去向和跨模块导航边界，以及 Deep Link、App Link、通知与分享入口映射到既有任务的方式。
- 记住冷启动与暖启动、重复外部入口、非法参数和无权访问时如何汇入同一导航状态，避免生成冲突任务栈。

### UI 状态与系统适配

- 记住页面和共享组件的状态所有者、一次性事件归属，以及 View 与 Compose 等界面体系并存时的互操作边界。
- 记住窗口尺寸、横竖屏、字体缩放、TalkBack、深浅主题和键鼠触控下必须保留的内容、操作与焦点关系。

### 数据权威、离线与同步

- 记住服务端、本地数据库、缓存与内存状态各自的权威角色，以及账户切换、离线启动和进程重建时的数据可用边界。
- 记住本地模型跨版本兼容、同步冲突、重复提交与部分失败的收敛原则，以及退出账户时必须清除或隔离的持久数据。

### 后台工作与消息唤醒

- 记住哪些业务允许在后台继续，定时工作、前台服务和推送消息各自承担的职责，以及系统调度限制下不可承诺的时效。
- 记住后台任务的唯一性、幂等与取消关系，并确保重复唤醒、进程重启和网络恢复不会重复产生业务副作用。

### 权限、身份与敏感数据

- 记住每项系统权限与用户任务的绑定关系，以及拒绝、永久拒绝、撤销和受限设备状态下仍可使用的替代路径。
- 记住凭据、敏感缓存和账户态的存储与清理边界，以及导出组件、Intent、WebView 和跨进程通信的信任边界。

### 设备兼容与性能退化

- 记住最低支持范围、设备能力检测和能力缺失时的退化路径，包括大屏、折叠屏、多窗口与厂商限制下必须保留的核心任务。
- 记住启动、主线程、渲染、内存、电量和包体的项目级约束，以及哪些判断必须以代表性真机而非模拟器为准。

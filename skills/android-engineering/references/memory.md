# Android 工程当前产品事实规则

## 所有权与稳定位置

`android-engineering` 是 Android 客户端实现事实的唯一语义 Owner。稳定位置为 `docs/product-studio/<product-id>/android-engineering.md`；`product-id` 必须在同一 Git 仓库内唯一、稳定并可安全作为单级目录名。事实册只保存当前终态仍成立、会改变后续 Android 工程决策且难以从局部代码重新得出的语义事实。产品旅程、内容、交互意图、视觉层级和无障碍目标归 `product-management`，安全授权政策归 `security-engineering`；本册只记 Android 生命周期、UI 与系统权限适配怎样兑现这些权威契约。

## 事实类型索引

1. 应用模块与入口边界
2. 生命周期、导航与恢复
3. UI 状态、组件与体验
4. 持久化、离线与网络
5. 后台、权限与安全
6. 性能、兼容与设备证据边界

## 通用入册门禁

- 候选事实必须在当前终态已经成立，并由代码、配置、调用链或权威契约直接支撑；计划、阶段、进度、历史任务、实施过程和推断不得入册。
- 候选事实必须稳定、非显然、决策相关，会改变后续实现或验证取舍，且跨模块或跨入口重查成本较高；可由单个局部实现直接看出的细节不入册。
- 必须唯一确认 Git 根、当前产品、`product-id`、事实的唯一 Owner 和主题合并键；归属不明时不得读取、创建或修改候选事实册，同一事实不得由多个 Owner 复制持有。
- 当前事实只写业务语义、成立条件、对消费者的保证和明确限制，不复制模块或组件树、完整导航、API 或存储定义、平台符号、文件清单及当前设备、系统版本或运行快照。
- 每项事实必须有可定位权威依据和风险相称的可重复复核入口，并通过秘密、个人数据与生产数据安全检查；证据不足时不得落册，终态处置只遵循公共终态协议。
- 长期兼容事实只写当前支持不变量与使其退出事实册的触发条件，不记录迁移阶段、完成比例、时间表或临时双轨进度。

## 主题表达规则

每个主题以稳定业务语义命名，不含路径、日期、任务号或动作前缀，并只容纳共同检索、共同变化的事实。根据事实类型、语义复杂度与检索需要，可使用段落、列表、表格或其组合，不强制 Markdown 标题层级、固定分栏、字段顺序或标签名称。

表达中仍须能够明确识别当前成立的事实及条件、权威依据、影响范围和复核方式：当前事实说明语义、保证与限制；权威依据收敛为一至三个可定位的仓库相对入口；影响范围说明消费者、环境与不得破坏关系；复核方式给出可重复命令或操作、关键断言、适用环境及证据盲区。各要素可自然分布，但不得缺失或依赖读者猜测。

## 动作语义

- `ADD`：稳定事实首次成立且通过全部门禁；同次创建产品目录和事实册。
- `UPDATE`：同一主题的当前语义、依据、影响或复核入口发生实质变化；原位合并，不追加历史段落。
- `DELETE`：事实已不再成立或不再由本 Owner 持有；移除主题，事实册无主题时删除本 Owner 文件。
- `NO_CHANGE`：实现可能变化，但当前事实、权威依据、影响范围与复核方式均无实质变化；不得因表达载体或排版偏好触碰事实文件。

## 事实类型

### 应用模块与入口边界

- **入册条件**：应用、功能或库边界已形成多个消费者依赖的稳定职责、依赖方向或启动保证，且会约束构建与交付取舍。
- **主题合并键**：以“应用或能力职责 + 消费关系 + 构建或启动边界”合并；共同演进的模块和入口同题，不按工程文件拆分。
- **当前事实写法**：只写职责语义、允许依赖、适用构建条件、启动保证、产物关系及明确不支持边界。
- **权威依据**：引用工程配置、入口实现、依赖约束和代表构建或启动测试中一至三个最强定位点；说明文档不能单独证明当前边界。
- **影响边界**：写明应用、能力消费者、构建配置、测试、自动化交付、设备能力及签名或发布边界。
- **复核入口**：构建并启动代表配置，验证入口、依赖隔离和关键消费者结果，同时注明未覆盖的签名、商店或外部交付环境。
- **变更规则**：职责、依赖方向、构建条件、入口保证、消费者、依据或复核边界实质变化时 `UPDATE`；工程组织调整但四项语义等价时 `NO_CHANGE`。
- **排除项**：不记录模块或依赖树、构建任务与配置全表、Manifest 或类符号、版本号、构建耗时、当前产物快照或未实施规划。

### 生命周期、导航与恢复

- **入册条件**：关键任务已对界面重建、进程回收、前后台、返回栈或外部入口形成稳定的状态权威、恢复和用户结果语义。
- **主题合并键**：以“用户任务 + 生命周期或导航所有者 + 恢复边界”合并；共同保存、进入、返回和重建的行为同题。
- **当前事实写法**：引用产品任务主题，只写 Android 生命周期、任务栈与外部入口如何兑现进入返回、重建恢复和副作用结束保证及其平台限制。
- **权威依据**：引用生命周期或导航协调实现、持久状态入口、外部入口配置和恢复测试中一至三个最强定位点；日志样本不能单独证明恢复成立。
- **影响边界**：写明任务、界面、任务栈、进程、账户、外部调用方、系统回收、数据源及服务端权限结果。
- **复核入口**：验证旋转或配置变化、后台回收、进程重建、冷暖外部入口、前进后退、非法输入、无权状态与恢复后的用户结果。
- **变更规则**：权威、进入、返回、恢复、副作用边界、适用范围、依据或复核入口变化时 `UPDATE`；导航或状态实现替换但语义等价时 `NO_CHANGE`。
- **排除项**：不记录完整导航图、Destination、Intent、回调或类清单，不保存返回栈、输入值、系统版本、设备或生命周期日志快照。

### UI 状态、组件与体验

- **入册条件**：关键任务或共享 UI 原语已形成跨消费者稳定的状态、事件、交互、视觉、本地化或无障碍保证。
- **主题合并键**：以“用户任务或共享原语 + UI 状态所有者 + 体验边界”合并；共同渲染与交互的状态和组件同题。
- **当前事实写法**：引用产品体验主题，只写 Android 状态与组件实现、输入和系统反馈、资源与布局适配、本地化及辅助技术结果和平台限制，不复述产品体验意图。
- **权威依据**：引用状态所有者、共享 UI 实现、资源或主题入口和单元、界面或无障碍测试中一至三个最强定位点；预览与截图只能补充。
- **影响边界**：写明页面或流程、输入方式、窗口与方向、字体和语言、主题、辅助技术、状态生产者与消费者。
- **复核入口**：在代表设备形态验证加载、空白、失败、成功、重建、滚动、输入、长文本、RTL、字体缩放、深浅色与辅助操作。
- **变更规则**：状态权威、事件语义、公共体验保证、适用范围、消费者、依据或复核边界变化时 `UPDATE`；内部 UI 重构等价时 `NO_CHANGE`。
- **排除项**：不记录组件树、Composable 或 View、资源、属性、颜色和字符串清单，不保存 Preview、截图、扫描、设备或当前界面快照。

### 持久化、离线与网络

- **入册条件**：业务数据的本地角色、离线能力、同步收敛或客户端通信结果已经稳定，且多个任务依赖同一权威与故障语义。
- **主题合并键**：以“业务数据或交互族 + 权威或适配角色 + 同步生命周期”合并；共同存取、通信和收敛的行为同题。
- **当前事实写法**：只写数据与交互语义、权威和副本关系、离线保证、同步与冲突结果、网络错误和恢复条件及明确限制。
- **权威依据**：引用数据访问或网络适配、同步协调、错误归一和迁移、离线或契约测试中一至三个最强定位点；存储或响应快照只能补充。
- **影响边界**：写明任务、账户、进程、网络状态、后台消费者、服务端权威、容量限制及跨版本数据关系。
- **复核入口**：验证迁移、事务结果、断网、重连、超时、取消、重复乱序、冲突、部分失败、账户切换、进程重建与最终收敛。
- **变更规则**：权威角色、离线保证、同步或错误语义、恢复条件、适用范围、依据或复核边界变化时 `UPDATE`；存储或传输实现替换且语义等价时 `NO_CHANGE`。
- **排除项**：不复制 Schema、实体、字段、查询、端点、DTO、错误码或协议清单，不保存用户数据、数据库、缓存、响应、队列或网络运行快照。

### 后台、权限与安全

- **入册条件**：关键后台任务、系统能力授权或客户端安全边界已形成跨入口稳定的触发、拒绝、恢复或数据保护语义。
- **主题合并键**：以“用户任务或受保护数据 + 后台或权限能力 + 完成、拒绝或清理边界”合并；共同授权和保护的路径同题。
- **当前事实写法**：引用产品用途与安全政策主题，只写 Android 后台执行、系统权限请求与状态适配、安全存储消费、拒绝后的平台行为、清理条件及系统限制，不定义主体资源授权政策。
- **权威依据**：引用后台协调、权限适配、安全存储或网络控制及相应测试中一至三个最强定位点；政策或服务端配置只能说明依赖。
- **影响边界**：写明任务、账户、设备能力、进程状态、网络和电量、敏感数据、外部入口、服务端幂等及安全政策边界。
- **复核入口**：验证重复触发、延迟或终止、到期、拒绝、撤销、受限状态、账户切换、凭据清理、不可信输入和安全失败结果。
- **变更规则**：后台保证、权限语义、安全边界、拒绝或恢复结果、适用范围、依据或复核边界变化时 `UPDATE`；内部机制替换且语义等价时 `NO_CHANGE`。
- **排除项**：不记录任务、权限、Intent、Service、Worker、密钥项或策略符号清单，不保存令牌、用户数据、推送载荷、调度记录或当前权限快照。

### 性能、兼容与设备证据边界

- **入册条件**：关键任务已形成稳定的资源保护、能力回退或支持不变量，且代表性设备证据会实质改变后续实现与验证取舍。
- **主题合并键**：以“用户任务或资源边界 + 性能或兼容保证 + 设备能力范围”合并；共同瓶颈和回退责任同题。
- **当前事实写法**：只写任务条件、资源或响应语义与保证、能力缺失时结果、当前支持不变量、证据适用限制与退出触发。
- **权威依据**：引用性能实现、兼容分支、构建配置和性能或设备测试中一至三个最强定位点；单次分数、截图或崩溃记录只能补充。
- **影响边界**：写明任务、数据与资源规模、设备能力、窗口形态、网络和电量、构建类型、第三方组件及用户结果。
- **复核入口**：在固定构建、数据和环境下验证启动、主线程、渲染、内存、资源受限与能力缺失结果，并注明模拟器、真实设备和生产证据边界。
- **变更规则**：资源保证、回退、支持不变量、证据边界、退出触发、依据或复核条件变化时 `UPDATE`；工具或实现位置变化但语义等价时 `NO_CHANGE`。
- **排除项**：不记录指标、机型、系统版本、依赖、崩溃或测试设备清单，不保存基准分数、设备信息、当前支持快照、运行记录或兼容进度。

## 全册安全与删除规则

- 禁止写入签名材料、密钥、凭据、完整令牌、个人数据、生产数据、原始请求响应、推送载荷、设备标识、任务摘要、过程记录、运行快照或原始差异。
- 事实依据失效、语义被替代、退出触发成立或所有权消失时必须 `UPDATE` 或 `DELETE`；历史由 Git 承担，不保留“曾经如此”的叙事。
- 只修改语义要素或证据确有实质变化的主题；仅有表达载体、排序或排版偏好变化时判定 `NO_CHANGE`，事实册必须保持字节不变。
- 删除主题前确认没有仍成立的合并语义；只可删除本 Owner 已无主题的事实册，禁止越界删除其他内容。

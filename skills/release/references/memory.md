# release 当前项目事实记忆

本文件是 `release` 记忆的唯一规则与实例格式，目标实例为 `<项目根>/docs/product-studio/release.md`。只由 `release` 维护；其他技能可读取相关主题，不复制正文。

该事实册是 `release` 对整个项目的累计专业事实视图，不是单轮任务摘要。单轮只增量同步实际核验范围，整册不以该范围、最近差异或最后一次修改为边界，也不要求每轮扫描全库。

## 收录门槛

- 只记后续发布仍会复用、当前已经证实的仓库发布基线、版本权威与政策、Tag 约定、制品生成与识别、环境契约、配置名称、部署迁移顺序、健康与业务信号、停止回滚入口及运行限制；事实须有权威依据、可复核入口和明确失效条件。
- 事实是否入册只由当前是否成立、是否属于 `release`、是否值得后续复用决定，与本次是否改变发布配置、制品或环境无关；本次未触及但经当前仓库或环境证据核验的既有事实同样可以收录。
- 当前环境的已部署制品或健康状态只有在目标环境、不可变制品、核验时点、直接证据和重新核验条件齐全时才可记录；没有当前取证时不得沿用旧结论。
- 每个主题只描述一个共同检索、共同变化的稳定语义，不按单次发布、命令、时间线、指标样本、事故或任务机械拆分。
- 授权只对当前对象、动作和时效成立，不写入记忆供后续复用；密钥、令牌、生产数据、秘密值和可直接复用的敏感凭据永不入册。

## 实例格式

首次确有事实时创建同名事实册；没有事实时不得创建文件。主题使用简短、可读且稳定的运行语义，不含 Owner、类型前缀、日期、任务号或变更动作。

```markdown
# release 当前项目事实

## <稳定事实主题>

- **当前事实**：<当前已证实的仓库发布基线、版本权威与政策、Tag 约定、制品、环境、部署迁移、健康信号、停止恢复入口或运行限制；用现在时写明条件和边界，易变状态须含核验时点与失效条件>
- **权威依据**：<一至三个 `仓库相对路径#精确位置`、流水线、制品摘要、环境查询、监控或运行手册入口；秘密只写安全引用名称>
- **影响边界**：<目标环境、实例、租户、区域、调用方、数据、任务、外部系统、不得破坏的当前关系及明确不适用处；无则写“无”>
- **复核入口**：<可重复使用的只读查询、健康检查、业务旅程、恢复检查或命令，以及关键阈值、观察窗、稳定未覆盖边界和重审触发>
```

## 终态同步

1. 获准写入的发布或明确记忆维护任务形成终态且适用验证完成后，以本次实际核验的当前仓库、制品和环境证据为本轮增量取材范围，对照现有主题重新判断仍成立的事实；本次差异与执行流水只用于定位变化、风险和证据，不构成事实边界。
2. 同一语义原位改写；权威实现或证据搬移只改“权威依据”，制品、环境、信号或入口变化时更新当前值与失效条件；事实或最后消费者消失时删除主题，不追加发布历史。
3. 只有需要新增主题、改写“当前事实、权威依据、影响边界、复核入口”之一或删除事实时才写文件；授权、执行流水、事故时间线和一次性结果留在当轮报告。完成当前范围核对后无增、改、删则报告 `memory: 0 facts changed`。
4. 只读发布审计未获事实册写入授权时，只报告候选增改删及证据，不修改文件。
5. 最后一个主题删除后移除整册；写后核对权威依据、影响边界、复核入口、时效与秘密边界，再运行适用项目校验。

## 禁止内容

- 发布计划、任务摘要、进度、待办、操作者、审批正文、命令流水、事故时间线、复盘过程、候选方案和历史版本。
- 可从流水线、制品库、配置系统或监控生成的完整清单，以及缺少目标环境、制品身份、核验时点或直接证据的“已上线”“健康”结论。
- 任何跨会话执行授权、密钥、令牌、用户数据、环境秘密、生产载荷，或其他 Owner 已保存的同一事实正文。

历史由 Git、流水线、制品库与事件系统承担。平台静态校验只能证明 Skill 结构合法，不能证明目标环境已执行、已恢复或健康；易变事实必须在当前任务中重新取证。

# 发布与运行专业准则

按发布风险加载适用能力卡；所有判断和动作绑定当前制品、目标环境、精确授权、发布范围、观察窗口与停止条件。

## 核心能力

### 发布策略

- **启用**：制定或调整直接、滚动、灰度、蓝绿、功能开关等发布方式、批次、顺序或扩大范围门禁时启用。
- **输入**：
  - 已验收且可追溯的制品、目标环境、发布范围、时间窗口和当前授权边界。
  - 用户与业务影响、持久状态变化、故障显现时间、可逆性、观测能力和用户容忍度。
  - 客户端缓存、旧版本调用方、前后端滚动窗口、队列消费者及第三方变更约束。
- **执行**：
  - 按影响半径、可逆性、故障可发现时间、状态变化、用户容忍度与观测能力选择发布方式，不沿用固定仪式。
  - 低风险、无持久状态且易回滚的变更可直接或滚动发布；高风险、难回滚或用户影响大的变更优先灰度、蓝绿或功能开关。
  - 为每批定义实例、租户、区域或用户比例，以及进入条件、观察窗口、成功阈值、停止条件与下一步。
  - 选择能代表关键用户、数据规模和依赖组合的灰度样本。
  - 为功能开关写明默认值、权限、目标群体、故障取值、观测方式、生命周期和清理责任。
  - 为人工步骤写明执行人、复核人、输入、精确动作、成功输出和失败分支。
- **裁决**：
  - 只有低风险、易回滚且故障可快速发现的范围才可直接扩大；其余范围通过可观察批次逐步放量。
  - 只选内部低流量用户不足以代表真实风险时，调整样本而非降低阈值。
  - 发布顺序必须保持旧调用方、新旧前后端、消息消费者和第三方依赖的兼容区间。
- **产出**：
  - 发布策略及选择依据，绑定实例、租户、区域或用户比例的批次计划。
  - 每批进入条件、观察窗口、技术与业务阈值、停止条件和下一门禁。
  - 兼容顺序、人工步骤、功能开关生命周期及清理责任。
- **验证**：
  - 用关键用户、真实数据规模、旧客户端、依赖组合和故障显现时间复核批次代表性。
  - 检查每批都有可查询信号、明确阈值、责任人和触发后的动作。
  - 检查人工步骤可由指定操作者按文档执行，功能开关默认值和故障值可验证。
- **完成**：
  - 发布方式与风险相称，所有依赖顺序和兼容窗口明确。
  - 每批范围可识别、样本有代表性，只在完整观察窗口内满足门禁后扩大。
  - 人工步骤和功能开关均可执行、可审计且有清理条件。
- **边界**：
  - 发布方案、代码修改许可、合并、历史许可或评审记录均不构成当前制品与环境的执行授权。
  - 没有代表性样本、观察窗口或停止阈值的“灰度”只是分批重复同一风险。
  - 不得让功能开关成为无默认值、无故障策略、无清理时间的永久双路径。

### 制品与配置治理

- **启用**：检查或改变构建制品、依赖、目标环境配置、密钥引用、镜像、运行时、基础设施或第三方前置条件时启用。
- **输入**：
  - 通过验收的提交或制品修订、构建记录、不可变版本、构建编号或制品摘要。
  - 依赖锁、生成时间、签名或校验和、存储位置和软件物料清单。
  - 必需配置名称、来源、默认值、敏感级别、生效方式、缺失行为和恢复值。
  - 目标与验收环境的容量、权限、网络、时区、区域、依赖版本和功能开关差异。
- **执行**：
  - 以不可变版本、提交、构建编号或摘要标识待发布对象，并与验收结果一一对应。
  - 核对构建来源、依赖锁定、生成时间、签名或校验和及安全存储位置。
  - 将环境配置与制品分离；只记录敏感配置的安全来源和引用，不复制秘密值。
  - 比较目标与验收环境的容量、权限、网络、时区、区域、依赖和功能开关，识别会使验收结论失效的差异。
  - 明确配置变更的生效、重启、滚动刷新或缓存失效顺序与影响。
  - 核对基础设施、镜像、运行时、数据库和第三方依赖满足制品要求。
- **裁决**：
  - “最新”“主分支”、可变标签和本地工作区均不是可追溯制品标识。
  - 软件物料、依赖风险和许可证证据只适用于其绑定的实际构建产物，不能从仓库扫描外推。
  - 身份不明、来源不可追溯、签名或校验异常的制品不得进入执行。
- **产出**：
  - 制品清单，包含不可变标识、提交、构建、验收结果、摘要和存储位置。
  - 配置清单，包含名称、安全来源、默认值、敏感级别、生效方式、缺失行为和恢复值。
  - 环境差异、前置条件、处置决定及会使结论失效的差异。
- **验证**：
  - 从制品反查提交、构建和验收结果，并重新计算或核对摘要、签名或校验和。
  - 在目标环境以只读方式核对配置存在性、依赖、容量、权限和网络前置条件；配置值只通过安全引用验证。
  - 对需重启、滚动刷新或缓存失效的配置验证顺序、影响和恢复值可用。
- **完成**：
  - 制品与当前验收结果一一对应且不可变，来源、依赖和存储可追溯。
  - 目标环境所有前置条件成立，差异均已处置或明确阻塞。
  - 配置变更可审计、可验证并具有经过核对的恢复值。
- **边界**：
  - 不得复制密钥、令牌或私密配置值到计划、日志和证据中，只保存安全引用。
  - 测试环境曾成功或 CI 绿色不能证明目标环境配置、权限、依赖和容量已就绪。
  - 不得把不同构建、分支或环境的扫描与验收结果冒充当前制品证据。

### 迁移编排

- **启用**：涉及数据库、Schema、缓存、消息、任务、回填、双写双读、数据收缩或任何不可逆状态变化时启用。
- **输入**：
  - 新旧代码和 Schema、读写路径、数据不变量、兼容调用方、消息消费者与收缩条件。
  - 数据量、锁范围、事务时长、日志增长、存储、复制延迟、缓存一致性和在线流量。
  - 迁移脚本、批次、重试、备份恢复目标、回滚、隔离和前向修复能力。
- **执行**：
  - 采用先扩展、再迁移、后收缩的顺序，使新旧代码在滚动窗口内均可运行。
  - 评估锁范围、事务时长、日志增长、存储、复制延迟、缓存一致性、回填批次和线上流量竞争。
  - 使迁移脚本可重入、可观测、可暂停；定义预检、每批数量、进度水位和失败重试边界。
  - 大规模回填使用限速、分片、检查点和暂停机制；每批核对数量、业务不变量和错误样本。
  - 双写或双读明确权威来源、冲突处理、对账方式、切换条件与最终清理点。
  - 运行前实际验证备份和恢复方案在目标恢复时间内可用。
  - 回滚方案覆盖代码、数据、配置、消息、缓存和外部副作用。
- **裁决**：
  - 不可逆迁移必须取得专门确认，并采用隔离、只读、流量切换或前向修复方案；不得伪称代码回退即可恢复。
  - 旧字段、旧接口或旧消费者只有在调用与数据证据证明兼容窗口结束后才能收缩。
  - 临时双写、双读或兼容路径必须有权威来源、切换和清理点，不能永久化。
- **产出**：
  - 扩展—迁移—收缩顺序及新旧代码兼容矩阵。
  - 预检、批次大小、限速、检查点、进度、重试、暂停、核对和错误样本处理方案。
  - 双写双读对账、备份恢复、回滚、隔离或前向修复方案及专门确认引用。
- **验证**：
  - 在代表性数据量和在线竞争条件下检查锁、日志、存储、复制延迟与缓存一致性。
  - 执行重入、暂停、失败重试和检查点恢复；逐批核对数量、业务不变量和错误样本。
  - 验证旧制品与新 Schema、新制品与扩展期 Schema 能共存。
  - 实际演练备份恢复或验证恢复能力，不以“存在备份”代替恢复证据。
- **完成**：
  - 新旧代码在滚动窗口共存，每批可观测、可核对、可暂停和可重入。
  - 权威数据来源、冲突处理、切换与清理条件明确。
  - 可逆迁移具有数据与代码恢复证据；不可逆迁移具有专门确认、隔离或前向修复路径。
- **边界**：
  - 单段 SQL、空库或小数据执行成功不能证明生产迁移可执行。
  - 不得遗漏消息、缓存、外部调用和异步任务中的数据副作用。
  - 兼容窗口结束前不得收缩旧字段、接口或消费者。

### 可观测与健康判断

- **启用**：建立发布门禁、读取健康状态、设置观察窗口、判断批次健康或执行发布后验证时启用。
- **输入**：
  - 当前制品、环境、批次、基础设施、运行时、应用、依赖、数据和异步任务拓扑。
  - 错误率、延迟、吞吐、资源、队列、依赖和核心业务成功率的基线与自然波动。
  - 指标查询、统计窗口、阈值、分群、责任人、对应动作和核心业务旅程。
- **执行**：
  - 为每个关键指标记录查询方式、统计窗口、基线、阈值、分群、责任人和触发动作。
  - 区分存活、就绪与业务可用，不以进程在线、健康端点或 HTTP 200 代替用户任务。
  - 同时观察基础设施、运行时、应用错误、依赖、数据、异步任务和业务漏斗。
  - 同时比较比例与绝对量、总体与分群、瞬时与趋势；低流量时识别样本不足。
  - 将日志、指标和追踪关联到制品、批次、环境、请求或任务。
  - 发布后走完核心业务旅程和一个重要失败或恢复路径，核对权限、数据、通知及异步完成状态。
  - 让观察窗口覆盖缓存刷新、队列处理、定时任务、用户峰值与依赖延迟等显现周期。
- **裁决**：
  - 没有对应动作的指标不能单独充当发布门禁。
  - 单层绿灯、零错误、无告警或单次健康检查不足以证明跨层健康。
  - 生产主动探针须有明确范围授权；会写入状态的探针须单独覆盖写入对象、清理和停止条件。
  - 失败或恢复探针只有在授权明确覆盖、可隔离、可清理且无真实用户副作用时执行；主动故障注入须另取独立授权。
- **产出**：
  - 技术和业务信号矩阵，包含查询、基线、阈值、窗口、分群、责任人与动作。
  - 核心旅程、失败或恢复路径结果，以及绑定制品、环境、批次和时间窗的日志、指标与追踪证据。
  - 观察窗口覆盖说明、样本充分性判断和未验证风险。
- **验证**：
  - 复查查询时间窗、环境、批次和分群，避免截图或结果错绑。
  - 将技术信号与核心旅程、数据结果、通知和异步完成状态相互核对。
  - 等待完整显现周期后再判定健康，确认低流量时绝对量和样本不足未被掩盖。
  - 对主动生产探针核对授权、隔离、清理、停止条件和真实用户副作用。
- **完成**：
  - 当前批次的基础设施、应用、依赖、数据、异步任务和核心业务旅程均有当前直接证据。
  - 观察窗口覆盖适用故障显现周期，指标越界有可执行动作，证据可定位到当前制品和批次。
  - 技术健康与业务结果分别记录，不以其中一项替代另一项。
- **边界**：
  - HTTP 200、进程存活、命令退出码为零、单次截图或无告警不能证明业务成功。
  - 不得把未执行的生产探针写成已验证；无授权时改用被动证据、只读检查或非生产演练，并缩小健康结论。

### 风险控制与回滚

- **启用**：存在用户、数据、权限、兼容、迁移、外部副作用风险，或需要停止、回滚、隔离和前向修复方案时启用。
- **输入**：
  - 最高影响和最可能失败模式、影响对象与允许影响上限。
  - 错误率、延迟、数据异常、业务转化、支持反馈等可观察信号和自然波动。
  - 部署与回滚工具、权限、旧制品、配置恢复值、数据处置、预计时长和事故升级路径。
- **执行**：
  - 为每项失败模式定义发现信号、影响上限、缓解动作和决策人。
  - 用可观察阈值写停止条件，不用“情况不对”等主观措辞。
  - 阈值触发后先停止扩大范围、冻结非必要变更并保存证据。
  - 编写包含负责人、工具或命令、顺序、预计时长、验证、数据处置和失败升级路径的回滚步骤。
  - 在可行环境演练回滚，至少验证命令、权限、旧制品和配置恢复值仍可取得。
  - 为不可回滚变化定义隔离、功能关闭、流量切换、只读模式或前向修复，并规划用户沟通与数据保护。
- **裁决**：
  - 停止阈值一旦满足，默认先止损；只有预先风险评估明确允许时才继续观察，不能为收集更多数据继续扩大影响。
  - 未经验证的文档步骤不算可执行回滚；代码回退不代表数据、配置、消息、缓存和外部副作用已经恢复。
  - 不可逆变化以补偿、隔离或前向修复闭环，不强求虚假的“原样回滚”。
- **产出**：
  - 失败模式、发现信号、影响上限、停止阈值、决策人和缓解动作表。
  - 可执行回滚手册，包含命令、权限、顺序、时长、验证、数据处置和升级路径。
  - 不可回滚变化的隔离、只读、流量切换、前向修复、用户沟通和数据保护方案。
- **验证**：
  - 演练或核对部署与回滚工具、权限、旧制品、配置恢复值和数据处置。
  - 模拟阈值触发后的停止、证据保存、回滚或隔离决策链。
  - 回滚后重新检查技术信号、核心业务旅程、数据不变量及完整稳定窗口。
- **完成**：
  - 每项高风险失败都有客观停止条件、明确决策人和可执行缓解路径。
  - 阈值触发时能先停止扩大范围并保存证据。
  - 回滚或隔离后，技术信号、核心旅程和数据不变量均恢复并经过稳定窗口。
- **边界**：
  - 回滚命令成功、服务重启完成或代码版本回退不能单独证明系统恢复。
  - 未获当前环境和动作授权时不得执行回滚、隔离或配置写入，只记录影响、阻塞和升级路径。

### 事故处置

- **启用**：发布期间或上线后出现持续影响、指标越界、数据异常、核心旅程中断，或影响仍在扩大时启用。
- **输入**：
  - 影响对象、开始时间、范围、严重度、扩大路径和用户、数据、业务连续性风险。
  - 当前制品、配置、环境、批次、最近动作，以及日志、指标、追踪和命令结果。
  - 已授权的停止、回滚、隔离、降级、限流措施和沟通渠道。
- **执行**：
  - 先确认影响对象、时间、范围、严重度和仍在扩大的路径，优先保护用户、数据与核心业务连续性。
  - 建立单一事件指挥和时间线，明确决策人、操作人和沟通渠道。
  - 保存日志、指标、追踪、配置、制品和关键命令结果，避免回滚或重启抹去线索。
  - 采用已评估且获授权的停止发布、回滚、隔离、降级或限流控制影响。
  - 对内外沟通区分已确认事实、当前影响、缓解动作和下次更新时间。
  - 恢复后复盘根因、促成条件、发现延迟、处置效果与防复发措施，并区分代码、配置、流程、容量和监控问题。
- **裁决**：
  - 先止损再诊断；事故中不混入无关重构或未经验证的新功能。
  - 同一环境由单一事件指挥协调，避免多人并发修改污染证据和扩大影响。
  - 猜测不得作为已确认根因发布；沟通必须区分事实、推断与待验证项。
- **产出**：
  - 事件时间线、角色分工、已确认事实、当前影响、缓解动作和沟通节奏。
  - 保存的日志、指标、追踪、配置、制品与命令证据。
  - 恢复判据、复盘结论、促成条件和带责任人及完成证据的防复发动作。
- **验证**：
  - 核对影响不再扩大，错误受控，核心旅程恢复，数据不变量成立。
  - 经过覆盖异步任务与延迟显现风险的稳定窗口后再确认恢复。
  - 复查时间线与证据能区分根因、促成条件和处置副作用。
- **完成**：
  - 用户、数据和核心业务影响已受控，核心旅程与数据不变量恢复并经过稳定窗口。
  - 根因和促成条件有证据支撑；防复发动作已有责任人、优先级和完成证据。
- **边界**：
  - 不得在事故中顺手重构、上线新功能或由多人无协调地修改同一环境。
  - 不得在无授权时扩大外部变更；紧急处置仍受已批准的事件权限和升级路径约束。

### 反馈闭环

- **启用**：发布完成、回滚、事故恢复、观察窗口结束或需要将运行证据交回产品迭代时启用。
- **输入**：
  - 业务指标、用户行为、客服或支持问题、错误样本、事故时间线和运维成本。
  - 临时功能开关、告警、双写、旁路、人工补偿及发布中发现的兼容、迁移、观测和回滚缺口。
  - 当前目标、适用分群、技术健康、业务结果和证据失效条件。
- **执行**：
  - 为反馈标明来源、频率、影响、适用分群和置信度。
  - 区分实现缺陷、体验摩擦、运行配置、支持流程和新产品需求，并交给对应责任领域。
  - 将兼容、迁移、观测和回滚缺口转为带责任人、优先级与完成证据的动作。
  - 为功能开关、临时告警、双写、旁路和人工补偿定义清理条件。
  - 让下一轮改动引用本次运行证据与失效条件，而非只引用复盘摘要。
- **裁决**：
  - 单个反馈可触发调查，但未经规模、频率和用户价值判断不得直接扩大产品范围。
  - 技术健康而业务信号未达预期时，保留真实结果并交回产品判断，不能把无故障误报为产品成功。
  - 缺陷、摩擦、配置、支持和新需求必须分流，不用一个“优化”标签混合处理。
- **产出**：
  - 带来源、频率、影响、分群、置信度、分类、责任人、优先级和完成证据的反馈清单。
  - 临时措施清理清单，以及兼容、迁移、观测和回滚改进项。
  - 技术健康与业务结果的分离结论及下一轮可引用的运行证据。
- **验证**：
  - 抽查每项反馈能追溯到指标、行为、支持记录、错误样本或事故证据。
  - 检查临时开关、告警、双写、旁路和人工补偿均有责任人、清理条件与验证方式。
  - 检查新需求已交回产品评估，而非直接进入发布补丁。
- **完成**：
  - 所有运行反馈均完成分类和责任交接，临时措施有明确清理条件。
  - 技术健康和业务目标分别评价，未达业务目标不会被无故障掩盖。
  - 下一轮改动可引用本次证据、剩余风险和失效条件。
- **边界**：
  - 单一反馈、无投诉或短时无告警不能证明价值目标成立，也不能直接扩大范围。
  - 不得让临时功能开关、双写、旁路、告警或人工补偿长期化而无清理责任。

## 能力组合

1. 先固定不可变制品、通过验收的修订、目标环境、发布范围、时间窗口和当前授权；组合制品与配置治理、发布策略、可观测与健康判断及风险控制与回滚，完成只读预检和门禁设计。
2. 识别前后端兼容、数据迁移、缓存、消息、任务、客户端与第三方依赖，画出必须串行和可以并行的顺序；存在持久状态变化时追加迁移编排。
3. 按影响半径、可逆性、故障显现时间和观测能力选择策略与批次；为技术和业务信号建立基线、成功阈值、停止条件、观察窗口和责任人。
4. 在执行前验证部署与回滚工具、权限、旧制品、配置恢复值、备份恢复和事故升级路径；只有授权精确覆盖当前制品、环境、范围、动作与时窗时才执行外部变更。
5. 执行期间逐批记录动作和结果，持续比较当前信号与基线；门禁满足才扩大范围，阈值触发则先停止、保存证据，再按授权执行回滚、隔离或缓解。
6. 发布后组合可观测与健康判断，验证基础设施、应用、依赖、数据、异步任务、核心业务旅程及重要失败或恢复路径；存在正在扩大的异常时切换事故处置。
7. 执行、回滚或观察窗口结束后组合反馈闭环，记录最终四轴状态、剩余风险、临时措施、事故和业务结果；把需要改变产品、架构或实现的事项交回对应责任领域。
8. 未获外部变更授权时，仍可用被动证据和只读检查闭合就绪轴并形成安全计划，但不得把就绪误写为已授权、已执行或健康。

## 完成判据

- 分轴记录状态，不把门禁混成单一“发布状态”：就绪轴为“未就绪／已就绪”，授权轴为“未授权／已授权”，执行轴为“未开始／执行中／已发布／已回滚／失败”，健康轴为“未验证／健康／异常”。
- 就绪轴只证明当前制品、配置、依赖、迁移、观测和回滚门禁满足；它可由范围内的被动证据与只读检查闭合为已就绪或未就绪，不依赖部署授权，也不证明任何外部变更已经发生。
- 授权轴只证明明确引用精确覆盖当前制品、目标环境、范围、动作、风险级别与有效时窗；代码修改、合并、评审、历史许可、发布方案和就绪结论均不能替代当前授权。
- 执行轴须记录时间、操作者、动作、制品、环境、批次、结果、证据位置和下一门禁；敏感信息仅保存安全引用。未获授权时保持“未开始”，并记录阻塞依据、重新适用条件和首个下一动作。
- 健康轴须绑定当前制品、环境、批次、查询、基线、阈值、窗口与分群；单次健康检查、命令零退出码、进程存活、HTTP 200、无告警或测试环境历史成功均不足。
- 执行已获授权须有绑定制品、环境、范围、动作与时窗的明确授权；制品可追溯须有不可变标识、提交、构建、验收结果与存储位置，不能使用“最新包”或本地工作区。
- 环境已就绪须有配置名称核对、依赖与容量检查、权限验证和差异处置；迁移可执行须有预检、批次、重入、进度、核对、暂停、恢复及数据回滚或前向修复证据，单段 SQL 或人工说明不足。
- 当前批次成功须同时有执行结果、技术指标、业务信号和完整观察窗口；回滚可用须验证旧制品、配置、权限、步骤、数据处置和恢复判据，文档写有“可回滚”不足。
- 系统恢复须同时满足错误受控、核心旅程成功、数据不变量成立及稳定窗口完成；服务重启或回滚命令成功不足。产品结果须按目标业务信号、用户旅程与适用分群判断，无告警或无投诉不足。
- 只有执行轴为“已发布”且健康轴在完整观察窗口内为“健康”时，才可宣告该范围发布成功；若业务目标未达标，另行记录真实结果并交回产品判断，不得宣告产品成功。
- 门禁失败或阈值越界时停止扩大范围并保存证据；只有相应授权存在时才执行回滚、隔离、配置写入或其他外部动作，无授权时记录影响、阻塞和升级路径。
- 被动观测和范围内的只读就绪检查不得写入生产状态。任何主动生产探针须有明确动作授权；会写入状态的探针还须绑定对象、影响上限、停止和清理条件。
- 生产失败或恢复探针必须同时满足授权精确覆盖、可隔离、可清理且无真实用户副作用；主动故障注入须取得独立于部署授权的单独授权，否则改用非生产演练或被动证据。
- 每项剩余风险和临时措施须记录用户或数据影响、触发条件、监测方式、责任人、清理条件和重新验证要求；最终记录应能区分缺陷、体验摩擦、配置问题、支持流程和新产品需求。

# 发布与运行

将已验收变更从精确仓库差异收束为可追溯版本与不可变制品，再安全带入指定环境，以当前技术与业务信号证明结果，并在门禁或阈值越界时停止推进。发布方案、代码修改许可、历史授权和准备就绪均不等于提交、打 Tag、推送或生产操作授权。

## 输入门禁

- 明确当前项目根与仓库根、仓库指令、任务属于版本准备、就绪审计、发布执行、事故处置、恢复验证还是复盘，以及用户要求的停止位置。
- 固定目标分支或引用、比较基线、目标提交或待发布变更、工作区状态、版本权威与政策、Tag 约定、目标远端、对应验收结论、待发布制品、目标环境、发布范围、时间窗口、现有流水线或运行工具、迁移方式、权限和责任边界。
- 读取适用的产品、架构、后端、前端与验证事实，存在时读取 `docs/product-studio/release.md` 中命中的发布事实，并核对仓库内 CI/CD、配置、迁移、健康检查、监控、回滚和运维入口。
- 产品结果或业务成功信号未定时交给 `$design`；系统边界、数据所有权、共享不变量或质量取舍未定时交给 `$architecture`；代码或迁移实现未完成时交给 `$backend` 或 `$frontend`；验收证据不足时交给 `$verification`；跨多个专业边界时由 `$router` 选择最小链。
- 将仓库准备、就绪、授权、执行和健康分别判定。相关变更未提交、版本来源冲突、候选 Tag 冲突或指向不明、缺少可追溯制品、适用验收、可执行恢复路径或明确操作授权时，可继续只读审计和方案整理，但不得提交、创建或推送 Tag、创建远端 Release 或执行外部变更。

## 专业能力

先查看 [发布与运行能力准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的能力段落；涉及实际生产操作、事故、不可逆迁移或总体发布裁决时，再读“常见误判”。

## 执行流程

1. 固定任务类型、仓库、待发布变更、验收修订、目标环境、范围和时间窗口，分别记录仓库准备、就绪、授权、执行与健康的当前状态；不得用一个“通过”覆盖五种状态。
2. 在精确仓库根读取分支与上游、`HEAD`、远端、本地与远端 Tag、工作区状态和最近可达发布基线，形成 `基线..目标提交` 的发布差异；相关未提交内容单列为阻塞，不擅自暂存、提交、隐藏、清理或回滚。
3. 按仓库既有政策识别唯一版本权威、发布模式和 Tag 格式，根据兼容性、持久状态、协议、通道与支持承诺裁定版本增量；只同步声明的版本镜像与生成文件，从精确差异和验收证据形成可追溯发布说明，并保证版本源、Tag 与制品元数据的映射一致。
4. 从目标提交与不可变制品双向核对源码、构建和验收证据，确认候选版本与 Tag 尚未冲突，并核对目标环境与验收环境的配置、容量、权限、网络、依赖、时区、区域和功能开关差异；秘密只保留名称与安全引用。
5. 沿前后端、数据库、缓存、消息、任务和第三方依赖梳理兼容顺序；迁移采用扩展、兼容运行、分批处理、校验、切换与收缩，明确不可逆部分及其专门确认。
6. 依据影响半径、可逆性、故障显现时间和观测能力选择发布策略，定义每批范围、进入条件、观察窗口、技术与业务阈值、停止条件和下一动作。
7. 在执行前核对提交、Tag、远端 Release、部署与回滚入口及权限，确认 Tag 推送的流水线触发范围，并核验旧制品、配置恢复值、备份恢复或前向修复路径；无法证明恢复能力时不得把发布判为就绪。
8. 未获绑定仓库、远端、引用、目标提交、版本号、Tag 名、制品、环境、范围、具体动作与有效时窗的明确授权时，停在只读结论，列明已就绪项、阻塞、首个下一动作和所需授权，不执行分支切换或创建、合并、变基、挑拣、修订或重置提交、提交、Tag 创建或签名、分支或 Tag 推送、远端 Release、部署、迁移、切流、配置写入、回滚或故障注入。
9. 获得相应授权后再次确认目标提交、版本与 Tag 未漂移，再按项目既有工具执行获准的最小动作；Tag 精确指向已验收提交，已发布 Tag 不移动、复用或强制覆盖，每步绑定动作、操作者、仓库或制品、环境、时间、退出状态、直接证据和下一门禁。
10. 若 Tag 推送触发流水线、制品发布或部署，将该推送纳入对应批次与观测门禁；其余环境操作也只使用目标项目既有、已核验的运行工具，按最小影响顺序逐批执行。
11. 每批完成后分别核对远端引用、制品构建、基础设施、应用、依赖、数据、异步任务和核心业务信号；会写生产数据、触发外部副作用或影响真实用户的探针必须另在授权范围内，并具有隔离与清理方案。
12. 门禁失败或指标越界时先停止扩大范围、保存证据并控制影响，再执行已批准的回滚、隔离、降级或前向修复；已发布版本与 Tag 保持可复现，恢复后重新验证业务旅程、数据不变量与完整稳定窗口。
13. 活跃事故先确认影响、建立单一操作序列并止损；恢复验证与事后复盘分开处理，不以计划中的回滚步骤冒充已执行结果，也不以暂时无告警冒充根因闭合。
14. 汇总仓库差异、版本、Tag、发布说明、发布结论、偏差、事故、临时措施及反馈。产品目标需改变时交回 `$design`，架构或实现需改变时交回对应 Owner，并重新经过 `$verification` 后方可形成新制品。

## 当前发布事实记忆

开始工作时，若 `<当前项目根>/docs/product-studio/release.md` 存在，只读取命中的事实主题及直接关联。任务收口前完整读取 [release 记忆规则与实例格式](references/memory.md)，仅在形成值得后续发布复用、具有当前证据和明确失效条件的最终事实时同步；授权、命令流水、事故时间线和一次性指标不入册。没有总结性事实变化时报告 `memory: 0 facts changed`。

## 输出与交接

- 分轴结论：仓库准备为未准备或已准备；就绪为未就绪或已就绪；授权为未授权或已授权；执行为未开始、执行中、已发布、已回滚或失败；健康为未验证、健康或异常。
- 仓库根、比较区间、目标提交、工作区状态、版本权威与版本号、Tag、发布说明、制品、目标环境、配置与依赖差异、门禁、迁移、批次、观察窗、停止与恢复条件，以及实际执行和运行信号的可追溯证据。
- 未执行项、首个可行动缺口、剩余风险、证据失效条件，以及应退回 `$design`、`$architecture`、`$backend`、`$frontend` 或 `$verification` 的事项。
- 只读就绪审计在门禁、授权状态、缺口和下一动作明确后即可闭合；只有宣告已发布或健康时才要求对应环境的当前执行与观察证据。

## 边界

- 可审计仓库差异、准备版本与发布说明、制定发布方案、判定就绪、设置批次门禁与停止条件，并在当前授权覆盖的范围内执行指定提交、Tag、推送、远端 Release、部署、迁移、切流、配置、回滚或环境操作。
- 不擅自暂存、提交、隐藏、清理或回滚用户改动，不擅自切换或创建分支、合并、变基、挑拣、修订或重写历史；不在相关变更未提交、版本来源冲突或 Tag 目标不明时继续发布，也不移动、复用、删除或强制覆盖已发布 Tag。
- 仓库状态变更与远端操作须分别取得绑定仓库、远端、引用、目标提交、版本号、Tag 名和动作的明确授权；本地提交或 Tag、远端 Tag、制品发布与环境部署分别取证，不互相替代。
- 不把代码权限、合并、CI 绿色、旧授权、运行手册或其他环境成功外推为当前生产授权与结果；任一制品、环境、范围、动作或时窗变化都重新核对授权。
- 不自行改变产品范围、系统不变量或实现契约，不在事故中夹带无关重构；发现上游缺口即保留证据并退回其 Owner。
- 发布证据只保存脱敏结果与安全引用，密钥、令牌、生产数据和可直接复用的敏感凭据不得写入输出、日志或记忆。

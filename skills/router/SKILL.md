# 编码任务路由网关

本技能只作任务路由与跨技能编排，不代替 `design`、`architecture`、`backend`、`frontend`、`verification`、`release` 作专业裁决；不创建或更新网关专属事实文件，也不代写专项记忆。

## 输入

- 用户期望的可观察结果、显式非目标、允许修改的范围、执行阶段与停止位置。
- 当前仓库结构、项目指令、已有改动、受影响模块、现行契约与可用验证命令。

## 专业能力

先读 [交付编排能力准则](references/principles.md) 的“目录”与“核心能力”，完整读取与任务匹配的能力段落；涉及多个技能、共享契约、并行分支或风险门禁时，再读“常见误判”。

## 直达与触发

目标和边界明确时，绕过本技能：

- **明确产品设计**：用户、任务、业务闭环、交互体验、产品规则、范围或验收直接调用 `design`。
- **明确架构设计**：模块与服务边界、数据所有权、共享不变量、跨边界交互语义、质量属性、信任边界、故障或演进方案直接调用 `architecture`。
- **明确后端编码**：领域逻辑、具体 API、Schema、权限、事务、缓存、消息、任务或外部集成直接调用 `backend`，代码变化后调用 `verification`。
- **明确前端编码**：页面、组件、交互、视觉、响应式、可访问性或浏览器状态直接调用 `frontend`，代码变化后调用 `verification`。
- **明确测试验收**：测试用例、缺陷复现、回归、联调、证据审计或完成判定直接调用 `verification`。
- **明确发布运行**：已验收制品的发布准备、生产就绪、部署迁移、观测、回滚、事故恢复或复盘直接调用 `release`；实际外部变更仍须精确授权。

出现以下任一情形才启用本技能：

- 请求只有愿景或结果描述，尚不能确定产品行为、改动边界或验收口径。
- 同一结果同时跨越 `design`、`architecture`、`backend`、`frontend` 中两个以上专业领域，且存在共享契约或先后依赖。单一实现技能后的常规 `verification` 只是终端门禁，不计作跨领域触发条件。
- 用户要求“完整功能”“端到端”“从零实现”，需要建立最小可运行纵向切片。
- 变更可能影响多个模块、数据所有权、公共 API、权限边界、异步一致性或多个并发写入者。
- 同一请求既要求实现代码又要求将验收制品带入目标环境，需要明确验收与发布的串行门禁。

## 最小调用链

跨端任务按产物缺口选链：

```text
契约清晰的全栈改动     backend + frontend -> verification
产品语义尚未确定       router -> design -> [architecture 按风险启用] -> backend + frontend -> verification
系统或技术边界未定     router -> architecture -> backend + frontend -> verification
实现并发布             router -> [design / architecture 按需] -> backend + frontend -> verification -> release
```

只读分析停在产生所需结论的技能，不得擅自进入实现。`design` 只在产品语义尚未确定时加入；`architecture` 只在跨边界不变量、所有权或质量风险真实存在时加入；普通局部实现不得为了流程完整强制经过二者。

## 编排规则

1. 归一原始请求与仓库事实，依据“直达与触发”判定是否需要编排；直接任务立即交给对应专业技能，编排任务说明触发依据和停止位置。
2. 完整读取命中的能力准则，建立只含必要节点的依赖图，为每个节点标明 Owner、输入版本、预期输出、消费者、写集合、门禁和失败返回点。
3. 先从仓库和现有契约消除不确定性，只对会改变目标、共享契约、安全数据边界或不可逆结果的未决事项请求裁决，并由相应专业 Owner 形成结论。
4. 将目标切为可观察、可验证且有恢复点的纵向里程碑，固定共享契约的 Owner 与版本，再按依赖图安排顺序、风险探针和消费者解锁。
5. 按能力准则执行并行、归并、失败隔离与局部重排，每个里程碑取得对应 Owner 的聚焦证据后再解锁消费者。
6. 代码结果由 `verification` 独立裁决；原始范围包含发布时，仅将可追溯且通过适用验收的制品交给 `release`，实际仓库或环境动作仍由 `release` 另行核对精确授权。
7. 节点均产生承诺产物或硬依赖使消费者无法继续时停止编排，交付当前链路、状态、证据、阻塞和下一动作；Router 不代作终态裁决，也不创建或同步任何专业事实记忆。

## 裁决边界

- 本技能可裁决技能选择、依赖顺序、切片粒度、并行条件、里程碑解锁条件与失败隔离范围。
- 专业裁决归对应技能：产品范围、业务闭环与用户体验目标归 `design`；系统边界、数据所有权、共享不变量与质量取舍归 `architecture`；具体 API、Schema 与服务端实现归 `backend`；界面与浏览器实现归 `frontend`；测试策略、证据和是否通过归 `verification`；发布就绪、操作授权、环境执行与运行健康归 `release`。
- 代码权限不等于生产操作授权；只有 `$release` 可在绑定当前制品、环境、范围、动作与时窗的明确授权内执行生产操作。
- 不得因调用本技能扩大用户范围、改写无关文件或引入无证据的新架构。

# 后端工程能力准则

## 领域模型与业务规则

- 从业务动作、状态变化和不变量建模，不把数据库实体直接当作全部领域模型。
- 明确实体标识、值对象、生命周期、状态转换、允许操作与拒绝原因。
- 让业务规则集中在拥有该状态的模块，避免控制器、任务、消息消费者各自复制一套判断。
- 对金额、时间、精度、时区、空值和枚举使用明确类型与边界，避免魔法字符串和隐式转换。
- 产品范围或架构不变量改变时退回责任角色，不在实现中形成隐含新规则。

## API 与错误设计

- 操作名称表达业务目的，HTTP、RPC 或事件语义与实际副作用一致；查询不得暗中改变状态。
- 请求只暴露调用方需要控制的字段，服务端生成的身份、权限和审计字段不得由客户端伪造。
- 响应稳定、最小且可扩展；分页、排序、筛选、时间和金额格式遵循仓库统一约定。
- 错误区分参数、业务冲突、认证、授权、资源不存在、限流、依赖失败和系统故障，并提供可行动信息。
- 契约变更识别所有调用方，优先向后兼容；必须破坏兼容时给出版本、迁移窗口和退役计划。

## 数据建模与迁移

- 用数据库约束表达真正不可违反的不变量，应用校验不能替代唯一、外键、非空或范围约束。
- 根据查询与写入模式设计索引，检查组合顺序、选择性、写放大、重复索引和执行计划。
- 明确数据所有者、生命周期、归档、删除、审计和备份恢复，不让临时字段永久成为事实源。
- 迁移区分结构、回填和清理阶段，采用可重入、可观察、可暂停和可回滚的步骤。
- 大表迁移评估锁、事务时长、日志增长、批次和新旧代码共存；禁止假设迁移瞬时完成。

## 权限与安全

- 在服务端完成认证、角色或属性授权、资源所有权和数据范围校验；列表与详情使用一致权限。
- 对所有外部输入进行类型、长度、格式、业务和文件校验，使用结构化解析与参数化查询。
- 保护密码、令牌、密钥和个人数据；日志、异常和响应不得泄露敏感字段或内部堆栈。
- 对导出、批量操作、管理能力和高价值状态变更记录审计主体、对象、动作、结果与时间。
- 防范越权、注入、重放、批量枚举、资源耗尽和不安全反序列化等与当前入口有关的风险。

## 事务、并发与幂等

- 为每次状态变化说明原子边界；跨资源操作明确最终一致、补偿或人工恢复策略。
- 选择乐观锁、悲观锁、唯一约束或串行化时说明冲突概率、等待代价和失败反馈。
- 写操作定义幂等键作用域、有效期、重复响应和并发竞争行为；消息消费同时考虑重复与乱序。
- 重试只用于可恢复错误，设置超时、次数、退避和抖动，并避免多层重试造成放大。
- 部分失败必须可观察，已完成与未完成项可区分，恢复操作不会重复造成副作用。

## 集成、缓存与异步处理

- 外部依赖设置连接与请求超时、故障隔离、限流、降级和可测试替身。
- 缓存说明键、权威来源、TTL、失效、穿透、击穿、雪崩和陈旧容忍；不缓存未经授权的数据范围。
- 消息定义生产条件、Schema、顺序、重复、死信、重放和消费者幂等；不要把队列当作自动可靠。
- 批处理和定时任务支持分页、断点、并发限制、重复执行和失败项重试，不一次加载全部数据。

## 性能与可观测性

- 从关键路径测量数据库查询、外部调用、序列化、锁、队列和内存开销，避免无证据优化。
- 检查 N+1、全表扫描、无界分页、过大事务、同步串行调用和热点资源。
- 日志使用可关联标识并记录业务阶段与结果；指标覆盖成功率、错误类型、延迟、吞吐和积压。
- 告警必须对应用户影响和处置动作；健康检查区分进程存活、依赖就绪和业务可用。

## 测试策略

- 领域测试覆盖状态转换、边界值与拒绝路径；契约测试覆盖请求响应、错误和兼容行为。
- 权限测试至少覆盖匿名、无权、资源所有者、跨租户或跨数据范围访问。
- 持久化与迁移测试使用真实约束验证索引、事务和旧数据兼容，不只模拟仓储。
- 并发和幂等测试制造竞态、重复请求、重试和部分失败，验证最终状态与副作用次数。
- 每项高风险行为至少有一个失败或恢复用例，且证据可映射到产品或架构契约。

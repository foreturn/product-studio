## 专业约束

### 前端框架与应用结构

- 实现必须先完整满足已确认的用户任务、业务状态与失败边界，并延续仓库已经采用的组件框架、路由、状态、样式和构建约定，不得为局部需求并行引入另一套同类体系。
- 框架响应式状态、生命周期和副作用模型必须保持一致，组件不得绕过框架数据流直接维持另一份界面真相。
- 渲染边界应依据首屏完整度、交互密度、个性化、缓存和运行约束选择，不得以框架能力存在为由让整站采用同一种模式。
- 模块、目录与文件应按业务内聚性、职责和变化原因组织并沿用仓库命名惯例；组件、类型、函数与方法名称应表达业务对象或具体行为，页面只负责组合，领域规则与数据转换不得沉入无边界工具集或依赖具体视图组件才能成立。
- 依赖应从页面和功能指向稳定的领域及基础能力，禁止循环依赖、跨模块读取内部实现和无边界全局工具集合。
- 新抽象、新依赖和新状态层必须解决当前已经存在的复杂度，不能为了形式统一或未来猜测增加平行机制。
- 存在服务端或构建期预渲染时，服务端输出与客户端首次渲染必须由同一份确定性数据产生；浏览器专属能力、随机值、时间值和客户端偏好不得造成水合错配、重复请求或首屏闪变。

### URL、路由、导航与状态分层

- URL 应表达可分享、可刷新、可书签和可恢复的稳定任务状态；短暂交互、未提交编辑和纯视觉状态不应污染地址语义。
- 路径、查询参数和片段应保持一致的资源含义，参数必须可校验和规范化；敏感数据、瞬时授权结果和大型状态不得进入 URL。
- 地址栏直达、站内导航、刷新、前进后退和外部深链应得到一致结果；未知资源、无权访问、失效链接和系统故障应有不同去向。
- 路由层级应与应用壳、导航和页面边界一致；共享布局保持稳定，页面切换不得重建无关全局区域或丢失仍有效上下文。
- 远端事实、查询副本、表单编辑、局部交互和跨页面状态应分层保存，每项状态只有一个权威来源、明确存活期和重置条件。
- 客户端路由守卫和界面隐藏只改善交互，不能替代服务端授权、对象级校验和租户隔离。
- 主导航、当前位置、返回路径和页面标题必须共同表达用户身处何处；高频任务应有稳定且直接的入口，核心动作不得藏在仅悬停可见或难以发现的层级中。
- 从列表进入详情再返回时，筛选、排序、分页、展开与滚动等任务上下文应按用户预期恢复；离开未提交编辑或进行中操作时必须明确保留、舍弃与继续的后果。

### 远端数据、缓存与并发

- 远端事实、缓存副本和界面派生结果必须明确区分；缓存键应覆盖所有影响结果的参数、身份和作用域，失效范围应与写入影响相称。
- 初次加载、后台刷新、分页追加和局部更新是不同状态，不应以单一加载标记遮蔽已有内容或误报空状态。
- 并发策略应匹配用户意图和业务语义；过期读取不得覆盖较新状态，不可并发写入应保持顺序，批量工作必须有资源上限。
- 自动重试只适用于瞬态且可安全重放的操作，并受次数、总时限和服务端节流约束；取消与业务拒绝不应被当作网络故障重试。
- 乐观更新仅用于结果可预测、失败可回滚且冲突可解释的操作；资格、金额、库存和不可逆副作用必须以服务端确认结果为准。
- 传输模型应在系统边界转换为业务可用模型；界面不得依赖错误文案、偶然字段、传输库对象或某次样本响应推导规则。

### 实时数据、本地持久化与离线边界

- 实时连接只代表传输通道可用，不代表数据完整；消息必须具备可识别身份，并对重复、乱序、缺口、断线和重连后的状态收敛作出设计。
- 实时程度应与业务时效、设备资源和失败成本相称；低频变化不应为了表面即时性维持昂贵长连接或高频轮询。
- 浏览器本地数据应明确是设置、缓存、草稿还是离线副本；不得把可被清除、驱逐或篡改的数据提升为授权依据和跨设备权威。
- 本地结构变化必须具有版本语义和可验证升级路径；多标签并发、身份切换、容量不足、浏览器驱逐和升级中断均不得产生静默损坏。
- 离线能力应明确哪些读取和写入可继续、哪些必须阻断；排队写入需要稳定身份、顺序、幂等、冲突和失败可见性。
- 缓存与离线数据必须按账户和租户隔离，注销时清除敏感副本；恢复联网后以权威数据校准，不以本地时间和到达顺序武断覆盖。

### 组件框架、组件体系与语义

- 组件应分为基础原语、通用交互、业务组件和页面组合；跨层复用必须通过稳定公共接口，不得依赖内部节点、样式和私有状态。
- 只有语义、行为和变化方向一致的真实消费者才能共享组件；相似外观不足以抽象，单一消费者也不需要预造万能组件。
- 公共属性和事件必须表达业务或交互语义，并限制非法组合；大量布尔开关、隐式全局依赖和双重受控状态会使组件失去边界。
- 组件应优先复用项目已有设计系统和交互原语，新组件必须与既有尺寸、状态、焦点、错误和主题约定保持一致。
- 框架组件最终输出仍须保持正确内容与交互语义，阅读顺序、键盘顺序和视觉顺序不得互相矛盾。
- 用户可见文字必须忠实落实已确认的产品内容语义，从用户所处情境、业务对象、任务、结果和下一步呈现；不得以实现者或生成者视角讲解界面、罗列功能或填充无证据的价值宣称，AI 或系统只有在其身份影响用户判断时才作为叙述主体。
- 组件创建的请求、监听、订阅、计时和临时资源必须服从框架生命周期，卸载或依赖变化后不得继续写入陈旧状态。
- 组件实例和列表项身份必须来自稳定的数据身份；筛选、重排、分页与条件切换不得错误复用局部状态、输入值、焦点或仍在进行的副作用。

### CSS 级联、令牌与主题

- 级联顺序、来源、作用域和特异性应可解释且稳定；全局样式只承载基础规则，组件不得依赖偶然加载顺序和不断提高权重覆盖。
- 选择器应保持低耦合，不绑定无关 DOM 层级；交互状态应由真实语义状态驱动，禁止脚本同时改写多处行内样式维持一致。
- 设计令牌应区分原始值、语义角色和必要的组件约束；业务组件消费用途语义，不直接散布品牌色、临时尺寸和外观命名。
- 主题必须完整覆盖内容、表面、边界、动作、焦点、禁用和反馈状态；深浅模式不能依靠机械反转，也不能在首屏出现错误主题闪变。
- 第三方样式覆盖必须限定影响范围并保持升级可诊断；无说明的高特异性和强制覆盖不应成为日常修复机制。
- 可由 CSS 内在布局、容器状态和用户偏好表达的呈现，不应转交脚本测量和重复计算。
- 既有样式互相冲突时，应以正式设计系统、共享原语和被多个成熟流程验证的模式确定权威；不得机械平均矛盾规则，也不得把孤立页面的偶然外观扩散为新标准。

### 页面容器、布局与响应式

- 应建立统一页面容器体系，明确全宽区域、受限内容宽度、高密度工作区和阅读区的用途；同类页面共享最大宽度、边距与对齐基线。
- 布局应由内容关系和任务顺序决定，不能用绝对定位、空白占位或任意固定高度拼出只在单一视口成立的页面。
- 间距、栅格、控件高度和固定格式元素必须来自有限尺度体系，同类元素不得因页面作者不同出现随机大小与对齐偏差。
- 响应式变化应由内容与能力开始失效的位置驱动；小屏、缩放、字体放大、方向变化和虚拟键盘下仍须保留核心信息与操作。
- 组件应在所属容器内自适应，页面不得依赖少数设备宽度的截图效果；动态文本、极值数据和加载状态不能造成重叠或无意义跳动。
- 每个区域应有明确滚动主体；粘性区域、固定工具栏和浮层必须统一处理层叠、碰撞、背景滚动、关闭与焦点恢复。

### 视觉层级、节奏、颜色与尺寸

- 页面必须沿用统一的字号、字重、行高、控件高度、图标尺寸、圆角和间距阶梯，同一层级不得出现近似却不一致的数值。
- 视觉优先级应主要由结构、位置、尺寸、排版和留白形成；每个工作区域只保留清晰主动作，装饰不得压过业务信息。
- 颜色必须通过语义角色统一管理，内容、表面、边界、动作、焦点和状态在所有主题下保持协调与足够对比。
- 状态不得只依靠颜色表达，文本、图标、形状或位置必须提供等价线索；单一色系也不得吞没层级和状态辨识。
- 同类按钮、输入、标签、表格和反馈必须共享视觉状态集合，悬停、焦点、按下、禁用、错误和加载不可由页面各自发挥。
- 图标与媒体必须复用一致视觉系统并保持稳定尺寸；用户需要检查主体时，不得用模糊、过暗、过度裁剪或仅具氛围的素材代替。
- 同类页面应保持一致的信息密度、分区方式和动作位置；卡片、边框、阴影与强调色只用于表达真实分组和层级，不得把每个区块都装饰成彼此争夺注意力的容器。
- 视觉变化必须服务于内容关系和任务状态；新增页面应先复用既有版式与令牌，再以充分理由引入新变体，不能因局部审美偏好破坏产品整体节奏。

### 表单、工作流与数据密集界面

- 表单应使用与数据含义匹配的原生控件、持久标签和分组；占位文字不能代替名称，错误必须与相关字段及整体摘要建立关联。
- 可在客户端确定的格式问题可以即时反馈，资格、唯一性、权限和业务冲突必须由服务端裁定；客户端通过不等于操作成功。
- 提交过程应防止重复副作用，失败后保留可继续编辑的内容；成功反馈必须绑定真实业务完成状态，不依赖动画或本地推断。
- 需要跨行比较的数据应采用利于扫描的结构，独立对象才适合卡片；列、数值、空值、排序和展开行为应保持一致。
- 大数据的筛选、排序、分页和虚拟呈现不得改变数据语义；选择范围、跨页行为和批量影响必须对用户明确。
- 空状态应区分尚无数据、筛选无结果、无权限、加载失败和离线副本；部分失败应可定位并仅重试失败项。

### 操作效率、交互反馈与页面状态

- 每个异步区域必须区分初次加载、保留旧内容的刷新、空结果、部分成功、业务拒绝、系统失败和恢复中状态。
- 反馈应出现在动作或问题附近并持续到用户能够理解结果；短暂提示不得承载字段错误、权限变化或需要后续处理的重要信息。
- 可逆的低风险动作应优先允许直接执行并提供恢复，高风险或不可逆动作必须在执行前明确对象、范围和后果。
- 加载占位、错误内容、标签和动态数值不得改变工具栏、按钮、网格和固定格式组件的基本尺寸，避免反馈引发布局跳动。
- 动效只能强化状态变化、空间连续性和操作因果，不能拖延任务、抢夺焦点或成为业务完成的必要条件。
- 减少动画、弱网、重复点击、取消和结果迟到时，界面仍必须保持唯一可解释状态，不得同时呈现互相冲突的成功与失败。
- 常用动作应在使用位置直接可见，并在同类页面保持名称、图标、位置和顺序一致；低频动作可以收纳，但不能牺牲可发现性或让用户猜测同一命令的不同表达。
- 点击、触控和键盘操作都应有足够目标、明确焦点与即时状态响应；主次动作不得获得相同视觉重量，也不得在同一区域散布多个相互竞争的主动作。

### 无障碍、国际化与双向文本

- 核心任务必须支持键盘、触控和辅助技术；名称、角色、值、状态、焦点顺序与错误关系应在语义树中准确呈现。
- 焦点只在上下文显著改变时主动移动，并在浮层关闭后回到合理位置；动态播报应传达必要结果而不过度打断。
- 字体放大、页面缩放、高对比、减少动画和不同指针能力下不得丢失功能；自动扫描只能发现部分问题，不能替代真实任务验证。
- 可翻译内容应保持完整语句，复数、选择、日期、数字、货币和时区按目标地区规则处理，不拼接词片段或依赖机器默认环境。
- 服务端与浏览器首次呈现应共享语言、时区和资源版本；语言切换需要同步刷新相关格式、缓存与文档属性。
- 双向界面使用逻辑方向和文本隔离；布局、图标和动效只在语义方向相关时镜像，不能对所有视觉元素机械翻转。

### 浏览器安全、错误与恢复

- 不可信内容必须按最终解释上下文处理；普通内容使用文本语义，富内容采用受控允许范围，危险协议、跨窗口消息和嵌入内容均需校验来源。
- 客户端不得保存真正的服务秘密，也不得把界面隐藏、路由判断和本地状态当作授权；身份切换后必须隔离并清理相应缓存与连接。
- 浏览器安全策略应遵循最小来源、最小能力和最小持久化；第三方脚本及嵌入内容只能接触完成其功能所需的数据和接口。
- 加载失败、业务拒绝、认证失效、无权访问、冲突、限流、离线、超时和程序异常应保持不同语义，不得统一降级为空数据或短暂提示。
- 错误隔离范围应与故障影响相称；局部失败保留已有内容，页面级前提破坏才进入整体恢复，程序异常不能拖垮无关应用区域。
- 恢复动作应明确且有限，保留未提交工作并避免重复副作用；不可恢复或结果不确定时必须如实呈现，不得伪装成功。

### 性能与资源生命周期

- 性能优化必须基于代表设备、网络、数据和生产型构建的可重复测量；采用的机制必须对应已确认的传输、执行、布局、绘制或内存瓶颈。
- 优先保障可见内容、交互响应和视觉稳定；资源体积、请求数量和单次实验室得分不能替代用户完成任务的实际表现。
- 代码拆分、预取、记忆化、虚拟呈现和后台线程只在测量证明收益时采用；优化不得扩大一致性风险、缓存错误或交互复杂度。
- 监听、观察、计时、连接、后台工作、媒体和临时资源必须随最小生命周期释放；共享昂贵资源应具有明确的消费者与停止条件。
- 缓存同时具有有效期、容量和身份作用域；页面隐藏、前进后退缓存与内存压力下，应暂停或释放可重建资源而不破坏恢复。
- 验证应比较同条件前后数据，并关注低端设备与长尾；性能改善不能以无障碍、内容完整和错误恢复退化为代价。

### 兼容性、构建与依赖治理

- 支持范围应依据产品承诺和真实用户环境形成明确矩阵；语法转换与运行能力分别评估，浏览器能力使用特性检测而非身份猜测。
- 核心任务在受支持环境中始终可用；增强能力失败应有基础路径，兼容填补只覆盖真实缺口，不为未知未来加载普遍复杂度。
- 构建应在干净环境中可重复，环境差异不得形成未经验证的业务分支；任何交付给浏览器的配置都不能视为秘密。
- 拆包应围绕路由、低频重型能力和缓存稳定性，避免过多碎片、重复依赖和首屏请求链；产物预算应由实际体验目标驱动。
- 通用交互、数据处理、格式解析、编辑、图表与浏览器适配应优先复用项目现有能力、Web 平台标准和维护成熟的开源组件；新增依赖须同时权衡契约匹配、体积、维护、安全、许可、传递依赖和退出成本。
- 只有候选组件无法满足关键交互、无障碍、兼容或性能要求，或其总引入成本明确更高时才有限自研；不得复制依赖源码、重造通用组件体系或为单一缺口预建平台。
- 调试映射必须与交付版本准确对应并受控保存；开发便利配置、测试后门和未授权源码信息不得进入生产产物。

### 测试与前端可观测性

- 测试层级应由风险只能在哪一层暴露决定：纯规则、组件行为、跨模块集成、浏览器语义和真实用户路径分别使用最低充分证据。
- 断言应面向用户可见结果、语义和稳定契约，不依赖私有调用、临时节点层级和脆弱选择器；替身数据必须遵循真实边界。
- 布局、焦点、导航历史、浏览器存储、多上下文并发和资源生命周期需要真实浏览器验证；截图只能补充视觉差异。
- 测试应覆盖成功、取消、乱序、重复、离线、错误和恢复，保持数据隔离与可重复性，并明确模拟环境不能证明的外部行为。
- 运行观测只采集能定位版本、页面、操作和故障影响的信号；错误、性能和网络事件应可关联，同时限制数量和噪声。
- 遥测在采集前脱敏并尊重用户选择；完整地址参数、凭据、正文和用户内容不得进入日志，观测失败不能阻塞业务。

### SEO 与页面元数据

- 只有公开、无需认证且具有独立搜索价值的页面进入索引；筛选组合、分页和重复变体是否收录应依据内容独立性决定。
- 可索引页面的主体与关键元数据应存在于抓取时的文档中；客户端后置修改不能成为搜索引擎获得唯一内容语义的前提。
- 每个规范资源保持唯一地址，语言变体、站点地图、重定向和规范声明相互一致；结构化数据只能描述页面真实可见内容。
- 创建、重命名、临时缺失、永久删除和未知路径应返回符合资源生命周期的状态，不得全部用成功应用壳掩盖。
- 分享预览使用公开、稳定且能真实呈现对象的标题、说明和媒体；私有内容、账户状态和内部标识不得泄漏到页面源码。

# Web 工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/web-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始相关工作前读取已有事实；仓库中的当前权威实现与契约优先于旧事实。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程和一次性结果。

## 核心记忆

### 应用与渲染边界

- 记住各浏览器入口的渲染方式、服务端与客户端职责，以及水合、流式渲染或纯客户端运行之间不可混淆的边界。
- 记住部署基路径、静态资源、运行时配置与浏览器能力由谁提供，哪些入口必须在无脚本、弱网或初始化失败时仍可使用。

### 路由与恢复

- 记住核心用户任务对应的稳定 URL、路由所有者、进入与返回关系，以及刷新、前进后退和部署回退必须保留的任务上下文。
- 记住深链、非法地址、无权访问和未完成流程的统一落点，避免导航实现改变用户原有恢复路径。

### 状态权威与身份隔离

- 记住关键业务状态的唯一权威、浏览器副本与派生状态的关系，以及刷新、跨标签页和会话重建时如何恢复或失效。
- 记住账户、租户与匿名状态的隔离边界，以及身份切换、退出登录和权限变化时必须清理的客户端数据。

### 网络并发与错误恢复

- 记住共享请求、缓存与实时连接的所有者，以及取消、去重、乱序、重复消息和陈旧响应的统一处理原则。
- 记住离线、超时、会话失效、业务拒绝和服务不可用时哪些操作可以重试、继续或回滚，以及用户输入是否必须保留。

### 共享组件与无障碍

- 记住跨页面共享原语的交互契约、状态组合与设计令牌关系，避免局部实现改写公共行为。
- 记住键盘顺序、焦点归属、辅助名称、状态播报和高对比支持等必须由所有消费场景共同维持的无障碍约束。

### 响应式能力保留

- 记住从窄屏到宽屏、触控到键鼠、常规缩放到大字号时必须保留的信息、操作与阅读顺序。
- 记住哪些区域允许重排、折叠、滚动或切换呈现形式，以及多栏、浮层和固定操作之间不可破坏的可达关系。

### 本地化与时间

- 记住语言、消息与格式化资源的权威来源，以及缺失翻译、长文本、复数、RTL 和双向文本的统一处理边界。
- 记住业务时间的时区、日界线与服务端时间关系，区分绝对时刻、当地日期和相对时长，避免浏览器默认值改变业务含义。

### 浏览器信任与兼容退化

- 记住富文本、文件、跳转、跨窗口通信和第三方内容的信任边界，以及身份凭据在存储、请求和日志中的保护约束。
- 记住受支持浏览器能力、检测方式与缺失能力时的退化路径，确保兼容处理仍保留核心任务并守住资源上限。

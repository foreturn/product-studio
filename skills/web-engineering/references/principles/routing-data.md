# Web 工程 · 路由、状态与数据

### URL、路由、导航与状态分层

- URL 应表达可分享、可刷新、可书签和可恢复的稳定任务状态；短暂交互、未提交编辑和纯视觉状态不应污染地址语义。
- 路径、查询参数和片段应保持一致的资源含义，参数必须可校验和规范化；敏感数据、瞬时授权结果和大型状态不得进入 URL。
- 地址栏直达、站内导航、刷新、前进后退和外部深链应得到一致结果；未知资源、无权访问、失效链接和系统故障应有不同去向。
- 路由层级应与应用壳、导航和页面边界一致；共享布局保持稳定，页面切换不得重建无关全局区域或丢失仍有效上下文。
- 远端事实、查询副本、表单编辑、局部交互和跨页面状态应分层保存，每项状态只有一个权威来源、明确存活期和重置条件。
- 客户端路由守卫和界面隐藏只改善交互，不能替代服务端授权、对象级校验和租户隔离。
- 主导航、当前位置、返回路径和页面标题必须共同表达用户身处何处；高频任务应有稳定且直接的入口，核心动作不得藏在仅悬停可见或难以发现的层级中。
- 从列表进入详情再返回时，筛选、排序、分页、展开与滚动等任务上下文应按用户预期恢复；离开未提交编辑或进行中操作时必须明确保留、舍弃与继续的后果。

### 远端数据、缓存与并发

- 远端事实、缓存副本和界面派生结果必须明确区分；缓存键应覆盖所有影响结果的参数、身份和作用域，失效范围应与写入影响相称。
- 初次加载、后台刷新、分页追加和局部更新是不同状态，不应以单一加载标记遮蔽已有内容或误报空状态。
- 并发策略应匹配用户意图和业务语义；过期读取不得覆盖较新状态，不可并发写入应保持顺序，批量工作必须有资源上限。
- 自动重试只适用于瞬态且可安全重放的操作，并受次数、总时限和服务端节流约束；取消与业务拒绝不应被当作网络故障重试。
- 乐观更新仅用于结果可预测、失败可回滚且冲突可解释的操作；资格、金额、库存和不可逆副作用必须以服务端确认结果为准。
- 传输模型应在系统边界转换为业务可用模型；界面不得依赖错误文案、偶然字段、传输库对象或某次样本响应推导规则。

### 实时数据、本地持久化与离线边界

- 实时连接只代表传输通道可用，不代表数据完整；消息必须具备可识别身份，并对重复、乱序、缺口、断线和重连后的状态收敛作出设计。
- 实时程度应与业务时效、设备资源和失败成本相称；低频变化不应为了表面即时性维持昂贵长连接或高频轮询。
- 浏览器本地数据应明确是设置、缓存、草稿还是离线副本；不得把可被清除、驱逐或篡改的数据提升为授权依据和跨设备权威。
- 本地结构变化必须具有版本语义和可验证升级路径；多标签并发、身份切换、容量不足、浏览器驱逐和升级中断均不得产生静默损坏。
- 离线能力应明确哪些读取和写入可继续、哪些必须阻断；排队写入需要稳定身份、顺序、幂等、冲突和失败可见性。
- 缓存与离线数据必须按账户和租户隔离，注销时清除敏感副本；恢复联网后以权威数据校准，不以本地时间和到达顺序武断覆盖。

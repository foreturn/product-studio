# Web 工程 · 表单、交互反馈与可达性

### 表单、工作流与数据密集界面

- 表单应使用与数据含义匹配的原生控件、持久标签和分组；占位文字不能代替名称，错误必须与相关字段及整体摘要建立关联。
- 可在客户端确定的格式问题可以即时反馈，资格、唯一性、权限和业务冲突必须由服务端裁定；客户端通过不等于操作成功。
- 提交过程应防止重复副作用，失败后保留可继续编辑的内容；成功反馈必须绑定真实业务完成状态，不依赖动画或本地推断。
- 需要跨行比较的数据应采用利于扫描的结构，独立对象才适合卡片；列、数值、空值、排序和展开行为应保持一致。
- 大数据的筛选、排序、分页和虚拟呈现不得改变数据语义；选择范围、跨页行为和批量影响必须对用户明确。
- 空状态应区分尚无数据、筛选无结果、无权限、加载失败和离线副本；部分失败应可定位并仅重试失败项。

### 操作效率、交互反馈与页面状态

- 每个异步区域必须区分初次加载、保留旧内容的刷新、空结果、部分成功、业务拒绝、系统失败和恢复中状态。
- 反馈应出现在动作或问题附近并持续到用户能够理解结果；短暂提示不得承载字段错误、权限变化或需要后续处理的重要信息。
- 可逆的低风险动作应优先允许直接执行并提供恢复，高风险或不可逆动作必须在执行前明确对象、范围和后果。
- 加载占位、错误内容、标签和动态数值不得改变工具栏、按钮、网格和固定格式组件的基本尺寸，避免反馈引发布局跳动。
- 动效只能强化状态变化、空间连续性和操作因果，不能拖延任务、抢夺焦点或成为业务完成的必要条件。
- 减少动画、弱网、重复点击、取消和结果迟到时，界面仍必须保持唯一可解释状态，不得同时呈现互相冲突的成功与失败。
- 常用动作应在使用位置直接可见，并在同类页面保持名称、图标、位置和顺序一致；低频动作可以收纳，但不能牺牲可发现性或让用户猜测同一命令的不同表达。
- 点击、触控和键盘操作都应有足够目标、明确焦点与即时状态响应；主次动作不得获得相同视觉重量，也不得在同一区域散布多个相互竞争的主动作。

### 无障碍、国际化与双向文本

- 核心任务必须支持键盘、触控和辅助技术；名称、角色、值、状态、焦点顺序与错误关系应在语义树中准确呈现。
- 焦点只在上下文显著改变时主动移动，并在浮层关闭后回到合理位置；动态播报应传达必要结果而不过度打断。
- 字体放大、页面缩放、高对比、减少动画和不同指针能力下不得丢失功能；自动扫描只能发现部分问题，不能替代真实任务验证。
- 可翻译内容应保持完整语句，复数、选择、日期、数字、货币和时区按目标地区规则处理，不拼接词片段或依赖机器默认环境。
- 服务端与浏览器首次呈现应共享语言、时区和资源版本；语言切换需要同步刷新相关格式、缓存与文档属性。
- 双向界面使用逻辑方向和文本隔离；布局、图标和动效只在语义方向相关时镜像，不能对所有视觉元素机械翻转。

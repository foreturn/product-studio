# 产品管理项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/product-management.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始相关工作前读取已有事实。
- 当前代码、配置和正式契约等权威信息与旧事实冲突时，以当前权威为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程和一次性结果。

## 核心记忆

### 角色、问题与价值

- 记住产品实际服务的角色、适用资格、关键使用情境，以及产品必须解决的核心问题。
- 记住各角色依赖产品获得的长期价值，以及明确不服务的角色、情境和诉求。

### 产品政策与业务状态

- 记住业务对象的资格、前置条件、允许与拒绝规则、关键状态含义和不可逆变化。
- 记住跨入口必须一致的政策、有效例外，以及需要人工介入的边界。

### 范围、非目标与兼容承诺

- 记住产品当前包含的完整能力边界、必要组成和明确非目标。
- 记住仍被真实消费者依赖的兼容承诺，以及停止兼容所需满足的明确前提。

### 成功指标与质量护栏

- 记住用于产品判断的稳定指标口径、观察范围、分群方式和决策阈值。
- 记住必须同时守住的质量护栏、数据限制和不可归因边界，而非某次观测数值。

### 产品验收与不回归契约

- 记住核心场景的前置条件、必须可观察到的行为，以及绝不能出现的行为。
- 记住重复操作、中断恢复和兼容路径中不得退化的产品承诺。

### 用户旅程与信息架构

- 记住核心任务的主入口、关键阶段、决策点、完成方式、退出方式和中断恢复方式。
- 记住信息对象的分类、归属、查找关系，以及跨角色或跨平台的衔接规则。

### 内容、交互、视觉与无障碍

- 记住跨触点统一的术语、动作含义、关键反馈、信息层级和风险层级。
- 记住响应式布局、不同输入方式和辅助技术下必须保持等价的任务能力，以及允许的平台差异。

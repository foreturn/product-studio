# 平台工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/platform-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始平台相关工作前，读取已有事实。
- 当前权威优先于旧事实；两者冲突时，以当前仓库、运行声明和受控平台所共同确认的认知为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程或一次性结果。

## 核心记忆

### 环境、账户与运行身份

- 记住产品在各环境和账户中的归属，以及生产与非生产、共享与专属资源之间不可跨越的隔离边界。
- 记住各类工作负载取得运行身份的机制、身份作用域和缺失身份时的既定行为。

### 基础设施权威与生命周期

- 记住各资源域由哪套声明和状态管理，何处允许人工管理，以及并发变更、导入、替换和销毁必须遵守的不变量。
- 记住有状态资产的保护关系，以及基础设施声明与运行实态冲突时采用的权威来源。

### 网络、运行时与配置

- 记住工作负载的入口、出口、名称解析、运行承载和持久状态边界，以及跨边界通信的允许与拒绝语义。
- 记住运行配置的来源优先级、注入与刷新机制，以及关键配置缺失或失效时的启动和降级行为。

### CI 与制品通道

- 记住 CI 任务的执行信任域、隔离方式和凭据作用域，以及制品上传、下载、保存和缓存各自承担的角色。
- 记住平台只拥有执行域与传输存储通道；制品身份和晋级关系由发布工程维护，来源准入和完整性政策由安全工程维护。

### 观测、SLO 与容量

- 记住关键用户路径和平台能力采用的权威信号、关联方式、服务目标语义及已知观测盲区。
- 记住容量不足或依赖饱和时的限流、排队、降级和恢复行为，以及影响容量判断的主要共享瓶颈。

### 韧性、灾难恢复与事故处置

- 记住主要故障域、传播边界、自动恢复与人工接管的分界，以及各类持久数据依赖的恢复顺序和恢复保证。
- 记住事故处置的权限边界、隔离与恢复机制，以及无法由代码回滚撤销的基础设施或数据影响。

### 成本、兼容与漂移

- 记住产品成本的稳定归属方式、主要成本驱动和会改变架构取舍的资源约束。
- 记住受支持的平台与基础设施兼容边界、漂移判定来源，以及发现声明外变更后的处置责任。

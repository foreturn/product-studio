# 平台工程项目记忆

## 核心记忆

### 环境、账户、区域与运行身份

- 记住产品在开发、测试、预发布、生产与灾备环境中的账户、区域、网络和资源归属，生产与非生产、共享与专属、长期与临时环境之间不可跨越的数据、权限和费用边界。
- 记住每类工作负载、CI 任务、运维人员和外部集成取得身份的来源、信任链、作用域、有效期与环境绑定，缺失、过期或身份服务不可用时的启动、拒绝和恢复行为。
- 记住环境差异中允许变化的容量、配置和依赖，必须保持一致的信任、传输、存储与故障机制，以及临时环境的数据隔离、域名、凭据、资源上限和自动回收责任。

### IaC 权威、状态与资源生命周期

- 记住网络、计算、存储、身份、观测和外部平台资源分别由哪套声明、模块与状态管理，状态后端的并发保护、版本恢复、访问隔离和敏感信息边界，以及允许人工管理的明确例外。
- 记住资源创建、导入、更新、重命名、替换、迁移和销毁时必须保持的稳定身份、依赖与有状态资产保护关系，哪些计划动作因级联删除、不可逆替换或解释不清必须停止。
- 记住声明态与运行实态冲突时采用的权威和处置责任，漂移如何发现、分类、保留紧急修复并回归声明，以及重复执行、恢复状态和销毁后不遗留资源或权限的验证入口。

### 工作负载、运行时与调度边界

- 记住各服务、长时进程、计划任务、一次性作业和节点级组件采用的运行形态、部署单元、状态依赖与宿主边界，以及不可变制品、入口命令和本地临时状态的关系。
- 记住启动、存活、就绪、停止接收新工作、排空和终止的实际语义，更新与缩容期间必须保护的副本、在途请求、租约和任务，以及计划任务的唯一性、幂等、重叠和过期规则。
- 记住资源请求、限制、调度约束、故障域分散和维护保护的依据，运行身份、可写范围与宿主访问的最小权限，以及启动失败、资源不足和节点维护时的确定落点。

### 网络、命名、传输与流量治理

- 记住网络分区、地址与路由域、南北向和东西向入口出口、名称解析与服务发现的所有者，跨区访问允许的来源、目标、协议和业务依据，以及默认拒绝与返回路径的实际控制点。
- 记住稳定服务名称、解析缓存、切换延迟、证书与信任材料的签发、续期、轮换和撤销关系，传输加密在哪些边界同时验证通信对端，哪些内部位置仍不构成可信身份。
- 记住入口与应用路由、请求和连接上限、超时、重试、排空、负载均衡与健康摘流的端到端预算，拒绝点和路径选择的观测入口，以及网络隔离能够限制但不能替代的应用授权边界。

### 配置、秘密与工作负载凭据

- 记住普通配置的 Schema、来源、优先级、作用域、默认值、兼容规则、注入与刷新方式，以及缺失、非法组合或部分更新时应用在接收流量前的失败与降级行为。
- 记住秘密和密钥所在的受保护存储、引用与注入机制，哪些工作负载可取得何种用途和环境的秘密，轮换期间的新旧值兼容、消费者定位、最终拒绝和泄露撤销路径。
- 记住短期工作负载身份与不得复用的静态凭据边界，源码、制品、IaC 状态、环境变量、子进程、崩溃与诊断中的暴露面，以及配置或秘密更新必须保持的原子性和审计关系。

### 存储、耐久性与数据生命周期

- 记住块、文件、对象、临时卷和托管数据服务分别承载的访问、一致性、共享、延迟与吞吐语义，哪些状态可随实例消失，哪些持久事实必须跨重建和调度保留。
- 记住存储创建、扩容、迁移、快照、保留和销毁同数据生命周期的绑定，内容完整性、版本与写入完成如何独立校验，以及工作负载删除、自动清理和冷热分层不得破坏的引用与恢复链。
- 记住多副本耐久、在线可用和可恢复备份各自不同的保证，主要故障域、访问权限和恢复依赖，以及存储或数据专业拥有而平台不得越权重定义的内容语义。

### CI 执行域、缓存与制品通道

- 记住各 CI 任务的触发来源、执行信任域、隔离方式、运行身份、网络与秘密作用域，以及不受信变更、受信构建和高权限发布步骤之间不可跨越的边界。
- 记住依赖缓存、构建缓存、工作区、日志和临时制品的身份键、共享范围、保存期限和污染清理规则，哪些输入变化必须使复用失效，哪些数据不得跨仓库、分支、租户或环境泄漏。
- 记住平台只拥有执行域与上传、下载、保存通道的边界，制品不可变身份和晋级关系由发布工程维护、来源与完整性政策由安全工程维护，以及通道不可用、上传不完整和重复执行时的确定行为。

### 观测、SLO、容量与成本约束

- 记住关键用户路径和平台能力使用的指标、日志与追踪语义，服务、版本、环境、租户和关联标识如何贯通同步与异步边界，遥测的采样、保留、脱敏、访问、成本和已知盲区。
- 记住各 SLI 的好事件、总事件、排除项和数据源，SLO 与错误预算的适用窗口，快速与缓慢退化的告警阈值、聚合抑制、分页条件和可执行处置入口。
- 记住容量模型采用的代表负载、单实例安全能力、启动延迟、下游与配额上限，排队、限流、负载削减和伸缩边界，以及成本按产品、服务、环境和业务单位的归属与会改变可靠性取舍的主要驱动。

### 韧性、灾难恢复、事故与环境证据

- 记住节点、区域、账户、网络、存储和第三方的真实故障域与传播路径，隔舱、断路、降级和有限重试所保护的业务语义，以及恢复点、恢复时间和最大影响范围对应的产品过程。
- 记住主环境失效时应用、数据、身份、命名、证书、制品、IaC 状态和外部依赖的恢复顺序、备用入口、人工接管与回切条件，哪些基础设施或数据影响不能靠代码回滚撤销。
- 记住事故分级、指挥、操作、调查和沟通权限，恢复必须观察的关键旅程、积压、副作用与稳定窗口，以及静态检查、计划模拟、预发布、故障注入和真实恢复演练各自能够与不能证明的范围。

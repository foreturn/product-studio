# 当前项目事实同步

在可写任务形成可交付终态并取得当前、独立、风险相称的验证后，核对专业事实裁决包并作最小写入。`fact-sync` 不拥有事实正文，不从差异自行发明语义，也不建立 `fact-sync` 事实册。

## 不可绕过的规则

```text
没有终态，不写事实。
没有相称验证，不写事实。
没有唯一 product-id，不读候选册、不写事实、不建目录。
没有专业 Owner 的明确裁决，不替其猜测事实。
```

实现代码已经写完、测试大多通过、文档顺手可改、任务时间紧迫或“事实显而易见”均不构成例外。事实同步失败不反向改变代码验证结论，但任务不得宣称事实闭环已经完成。

## 输入门禁

- 明确 Git 仓库根、仓库指令、用户授权范围、任务类型、请求范围、最终差异、当前修订或不可变制品、实际验证、未执行项、已知失败和专业事实裁决包。
- 从用户范围、仓库原生产品身份、产品入口与元数据、相关项目根、代码调用链或发布链确定仓库内唯一、稳定且可安全作为单级目录名的 `product-id`；不得从项目目录名机械推导。
- 所有写入必须具备当前、独立、风险相称的终态验证；发布或运行事实还须具备当前制品或修订、目标环境和时效证据。失败、阻塞、进行中、待确认、临时双轨或恢复未验证状态不得进入写入阶段。
- 只读任务未获事实册写入授权时，只输出候选核对结果；显式事实维护任务仍须核验权威来源与复核入口，不因“只改文档”降低证据门槛。
- 每个受影响专业边界必须提供符合对应事实规则的 `ADD`、`UPDATE`、`DELETE` 或 `NO_CHANGE` 裁决包。缺失语义所有权、locator、主题、四字段、删除依据或直接证据时阻塞，不由本技能补写语义。

## 专业能力

先查看 [事实同步能力准则](references/principles.md) 的“目录”与“核心能力”，完整读取本次命中的段落；存在多个产品、多个 Owner、旧册、所有权冲突、删除或易变运行事实时，再读“常见误判”。

## 四态裁决契约

专业 Owner 的每项裁决只能为：

- `ADD`：当前已证实且值得后续复用，目标册没有同义主题；必须提供新主题和四字段完整当前值。
- `UPDATE`：同一当前语义仍存在，但“当前事实、权威依据、影响边界、复核入口”至少一项改变；必须提供原主题定位与更新后的四字段。
- `DELETE`：事实、适用条件或最后消费者已消失；必须提供现有主题、消失证据和影响核对，不能用“已废弃”主题保留历史。
- `NO_CHANGE`：本次实际核验范围内没有任何现有或应新增事实字段变化；不触碰目标文件。

同一 Owner 可对不同主题给出多个动作；若任何主题发生 `ADD`、`UPDATE` 或 `DELETE`，该 Owner 的汇总状态不得同时写作 `NO_CHANGE`。

## 同步流程

1. 固定任务终态、当前修订或制品、验证结论、证据环境、用户授权与失效条件；任一前提不成立时返回 `DEFERRED` 或 `BLOCKED`，不修改事实文件。
2. 确定本轮命中的 `product-id` 集合；多产品逐一隔离处理，产品归属不唯一时只阻塞歧义产品，不把事实强塞进候选目录。
3. 从最终实现、契约、Schema、配置、调用链、验证与发布证据识别可能受影响的专业边界，并读取对应事实规则与稳定 locator。最终差异用于定位，不构成事实边界。
4. 读取每个专业边界稳定 locator 中命中的现有主题及直接关联，收集四态裁决包；未命中且裁决包明确 `NO_CHANGE` 时不扩成全库事实盘点。
5. 核对事实语义只归一个专业所有权边界。跨边界主题相似时比较权威实现、变化原因和直接消费者；无法唯一归属便阻塞并列明冲突与证据缺口，不复制正文或自行拆词。
6. 形成写前计划，逐项列出 `product-id`、Owner、locator、主题、动作、证据和预期文件变化；检查旧值与当前文件仍一致，防止覆盖用户或并行任务的新改动。
7. 只机械应用已通过门禁的最小变更：同义主题原位更新，新增主题只写当前四字段，删除主题不留历史；没有事实时不创建目录或空册。
8. 写后检查标题、主题唯一性、四字段完整性、权威依据、影响边界、复核入口、产品隔离、秘密边界和 Owner 重复；再运行仓库适用的事实结构或插件校验。
9. 输出逐产品、逐专业边界回执与写后校验证据；任何写入或校验失败均停止，说明哪些动作已应用、哪些未应用及所缺裁决，不把部分写入报告成完整闭环。

## 专业事实裁决包

每个受影响专业边界必须具备足以机械执行的结构：

```text
product-id: <稳定产品标识>
owner: <唯一专业语义所有权标识>
locator: docs/product-studio/<product-id>/<稳定文件名>.md
terminal-evidence: <当前终态与验证证据>
actions:
  - action: ADD | UPDATE | DELETE | NO_CHANGE
    topic: <稳定事实主题；NO_CHANGE 可为命中范围说明>
    current-fact: <ADD/UPDATE 必填>
    authoritative-evidence: <ADD/UPDATE 必填；DELETE 提供消失证据>
    impact-boundary: <ADD/UPDATE 必填；DELETE 提供影响核对>
    revalidation-entry: <ADD/UPDATE 必填>
```

自然语言输入可用，但必须无歧义地包含同等字段。字段不全时返回 `BLOCKED`，`fact-sync` 不可代写专业语义。

## 输出

- `SYNCED`：列出实际应用的 `ADD`、`UPDATE`、`DELETE`，目标文件及写后校验；只表示事实册与当前证据同步，不扩大代码、发布或健康结论。
- `NO_CHANGE`：逐 Owner 报告 `facts: <owner> NO_CHANGE`，并确认未触碰事实文件。
- `DEFERRED`：终态、验证、授权或时效尚未满足，列明继续所需条件；不写文件。
- `BLOCKED`：`product-id`、语义所有权、语义、现有文件、证据或写入发生冲突，列明冲突、证据缺口与所需裁决；不猜测解决。
- 对混合结果逐产品、逐 Owner 分列，不能用一个成功汇总掩盖其他阻塞或未执行项。

## 边界

- 可核验终态与证据门禁、定位事实册、检查裁决包、检测重复所有权、机械应用四态动作、删除空册空目录并验证结构。
- 不裁定产品、体验、架构、后端、前端、数据库、安全、质量或发布事实的专业语义，不修改 Owner 给出的当前事实、影响边界和复核入口来“润色”。
- 不把 Git diff、提交信息、任务描述、测试名称、旧报告或其他项目事实直接转换为当前事实；这些只能帮助定位待核验边界。
- 不记录历史、过程、计划、授权、秘密或一次性结果，不创建共享总览、事实注册表、格式版本文件或 `fact-sync.md`。
- 不为完成闭环而补写未取得相称验证的事实，也不以事实同步结果代替独立验收结论、实际发布状态或环境健康结论。

## 红线

- “代码已经合并，事实以后再核对”意味着返回 `DEFERRED`，不得先写猜测内容。
- “只有文档，不会影响运行”不能绕过唯一 Owner、权威依据和复核入口。
- “几个 Owner 都能解释”意味着所有权尚未确定，应 `BLOCKED`，不得复制到多册。
- “路径变了但语义没变”仍是 `UPDATE`，只改权威依据；“功能删除了”是 `DELETE`，不得保留历史墓碑。
- “本次代码没改到该事实”不等于 `NO_CHANGE`；只要本次实际核验证明其当前值、依据、边界或复核入口发生变化，就须由 Owner 裁决相应动作。

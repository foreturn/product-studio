## 核心能力

### 终态与验证门禁

- 实现终态要求请求范围内的代码、权威契约、消费者和必要生成物已一致，临时探针、待补分支和未解释失败已经清理或明确排除；“停止编码”不等于终态。
- 相称验证由变更风险决定。局部纯逻辑可由聚焦测试和静态检查证明；数据库、安全、浏览器、外部协议或发布状态必须取得对应层级证据，低层模拟不得外推。
- 代码实现必须具备对当前修订的独立通过结论，且未覆盖项不会否定候选事实；验证失败、阻塞或证据过期时返回 `DEFERRED`。
- 发布事实要求操作状态稳定且恢复已验证。准备中、执行中、回滚中、事故未恢复和观察窗未结束不写成稳定状态。
- 事实维护任务虽可不改代码，仍须由权威来源证明当前语义，并满足 Owner、产品身份和写入授权门禁。
- 同步前记录证据的修订、制品、环境和失效条件；对象漂移后重新门禁，不沿用旧绿灯。

### 产品身份与事实定位

- 由用户范围、产品入口、仓库原生身份、元数据、调用链和发布链共同确定 `product-id`，优先复用已确认属于同一产品的事实目录，不从 Git 根、工作区名或项目文件夹名机械推导。
- `product-id` 必须在仓库内唯一、稳定且可安全作为单级目录名；包含路径分隔、父目录跳转、空白歧义或可变版本号时阻塞。
- 同一仓库多个产品逐产品处理，每个裁决包绑定一个 `product-id`；共享代码并不自动属于所有产品，须按权威实现和真实消费者判定正文归属。
- locator 由对应专业事实规则定义。目录名或技能名变化不得擅自改写稳定 locator；找不到规则时返回 `BLOCKED` 并列明所缺规则。
- 产品归属不唯一时，不读取任一候选产品事实作为当前输入，不创建目录，也不通过选择“最像”的名称推进。

### 影响面与 Owner 发现

- 从最终行为、权威契约、数据流、信任边界、验证能力和运行方式识别专业边界；Git diff、提交标题和改动文件只用于定位，不构成事实边界。
- 只纳入本次实际核验范围中可能新增、变化或消失的 Owner；不为流程完整强制所有技能扫描全库，也不漏掉未改文件但被消费者变化推翻的事实。
- API 行为、数据库物理设计、安全策略、验证能力和发布状态分别归其专业 Owner；一个实现可能产生多个 Owner 的候选，但同一事实正文只归一个 Owner。
- 删除调用方、改动共享契约、移动权威实现、改变重验入口或移除最后消费者，都可能触发事实核对，即使产品可见行为看似不变。
- 若无法判断某项候选的唯一语义所有权，只能列出冲突边界和证据缺口，不能由 `fact-sync` 选一个方便的文件写入。

### 四态裁决核验

- `ADD` 前搜索目标册中的同义主题和直接关联，避免仅因标题不同重复记录；新主题必须同时具备四字段且使用现在时。
- `UPDATE` 必须指向现有主题并提供完整更新后值；只改路径也是更新，不能因为业务语义没变而留下失效依据。
- `DELETE` 必须证明事实本身、适用条件或最后消费者已消失，并核对是否存在替代权威来源；删除不保留“曾经存在”“已迁移”或弃用墓碑。
- `NO_CHANGE` 只表示实际核验范围内没有字段变化，不等于未检查，也不允许与该 Owner 的其他写动作并列为汇总状态。
- 专业事实裁决包与当前文件、权威来源或验证证据不一致时阻塞；`fact-sync` 不采用看起来更新的一方，也不合并折中措辞。
- 四字段必须共同描述一个稳定语义。若字段涵盖不同变化周期、不同专业所有权或无法由同一复核入口验证，返回 `BLOCKED` 并说明主题需拆分。

### 唯一所有权与跨产品边界

- Owner 由权威实现或契约、专业决定权和主要变化原因共同确定，不由最先发现者、改动者或目标文件名决定。
- 其他 Owner 可记录自身对权威事实的依赖与兼容边界，但不得复制原事实正文；依赖主题必须以本 Owner 的可执行行为为中心。
- 跨产品共享事实正文只进入拥有权威实现或契约的产品事实册，消费者产品只记录自身依赖。权威归属无法确认时继续以源码或正式契约为准，不强塞入产品事实目录。
- 主题相似不自动等于重复；比较必要条件、当前结果、变化原因、消费者和复核入口。实为同义时只保留唯一 Owner，实为依赖时明确边界。
- `fact-sync` 自身没有事实所有权、memory 规则或目标 locator，也不维护中央事实索引；否则会成为第二事实源。

### 最小写入与并发保护

- 写前读取目标文件当前内容并固定命中主题旧值；应用补丁前再次确认旧值未漂移，避免覆盖用户、其他代理或并行分支的新修改。
- 每次只应用已裁决的主题级增改删，不排序无关主题、不改写风格、不全文件格式化，也不修正其他 Owner 的旧问题。
- 同义主题原位更新；新增主题放在现有语义邻近位置或文件末尾，保持项目既有 Markdown 风格；删除只移除命中主题及其直属内容。
- `NO_CHANGE` 不写时间戳、状态、检查记录或换行，不触碰文件系统元数据可见内容。
- 多 Owner 写入可先完成独立目标文件，但任一共享语义冲突须在写前解决；同一文件不得由多个 Owner 同时写。
- 部分写入后校验失败时保存精确差异和已应用动作，不用破坏性回滚覆盖用户并行修改；在可安全精确撤销本轮补丁时才恢复，否则报告阻塞供人工裁决。

### 结构、证据与秘密校验

- 每册标题使用 Owner 当前技能名，主题为稳定人类语义，不含日期、任务号、动作、路径或 Owner 前缀；不使用 frontmatter、格式版本、状态和更新时间。
- 每个主题恰有“当前事实、权威依据、影响边界、复核入口”四项；缺失、重复、空值或自由增添第五字段均阻塞。
- 权威依据优先使用一至三个仓库相对路径和精确 Symbol、Route、Schema、配置键、流水线或可定位环境查询；模糊目录、搜索词和外部文章不能独自支撑当前事实。
- 复核入口必须可重复，并说明关键断言、适用环境和证据边界；“看代码”“跑测试”“人工确认”不够精确。
- 影响边界写明直接消费者、环境、数据、权限、外部系统和明确不适用处，不用“全局”“所有地方”等无证据表述。
- 禁止密钥、令牌、密码、个人数据、生产载荷、可复用授权和环境秘密；安全引用只保留名称与受控入口，不保存值。
- 写后核验所有新增或更新依据仍存在且指向当前语义；静态路径存在只能证明可定位，不能替代语义与运行证据。

### 删除、空册与旧册处理

- 删除最后一个主题后移除整册；产品目录没有任何专业事实册时才移除空目录，不删除其中其他项目文档或未知文件。
- 只因技能、目录或 Owner 改名，不得机械改动稳定 locator；locator 是否迁移由 Owner 规则显式裁定，并需要消费者与兼容核对。
- 旧册与新册同时存在时，先由专业 Owner 判断是同一 locator 的迁移、不同语义册还是重复冲突；未裁定前不得合并、删除或选择较新的文件。
- 删除事实不等于删除权威源码、测试或正式文档；`fact-sync` 的删除授权只覆盖已确认的事实主题、空册和空事实目录。
- 目标册不存在时，`DELETE` 通常说明裁决或输入已漂移，应阻塞复核；不得把“不存在”默认为删除成功而掩盖定位错误。

### 回执、失败与恢复

- 回执逐产品、逐 Owner、逐主题列出动作、目标 locator 和结果，`NO_CHANGE` 明确说明未触碰文件；总数只作摘要，不代替明细。
- `DEFERRED` 用于终态、验证、授权、时效尚未满足；`BLOCKED` 用于产品、Owner、语义、文件、证据或写入冲突。两者都不伪装成 `NO_CHANGE`。
- 写后校验绑定实际差异、当前文件和命令退出状态；插件格式校验只能证明结构合法，不能证明事实语义新鲜。
- 事实同步失败不得反向改变既有实现验收结论，但完成汇报必须明确“实现结论”与“事实同步状态”彼此独立，并列出未应用动作与所缺裁决。
- 重试前重新读取当前文件、终态和验证证据，确认没有并行漂移；不重复应用上次 ADD，不用“最后写入者获胜”处理冲突。

## 常见误判

- 把事实同步当作任务日志，将改了哪些文件、跑了什么命令、谁负责后续写入事实册。
- 仅查看 Git diff，漏掉调用方消失、权威路径搬移、复核入口变化和未改文件中的失效事实。
- 代码写完便更新事实，稍后测试失败后又留下并不存在或不稳定的项目语义。
- 让 `fact-sync` 根据代码自行撰写专业事实，会夺走专业语义裁决并形成第二套中央事实源。
- 所有技能都返回 `NO_CHANGE` 但没有说明实际核验范围、现有主题或直接证据，把未检查伪装成无变化。
- 同一 API、安全规则或数据约束复制到多个册，只因多个角色都会消费它；消费者应记录依赖，不复制权威正文。
- 为保持“完整历史”保留已删除主题、追加迁移说明或状态字段；历史应由 Git、ADR、流水线和事件系统承担。
- 新技能名出现后机械重命名所有事实文件，令外部项目既有 locator 和消费者静默断链。
- 把测试通过写进事实册，混淆可重复验证能力与一次性验证结果；只有持续存在的检查能力归质量事实。
- 把发布授权、事故时间线、实时指标或秘密写入事实册，制造跨会话越权和陈旧运行结论。
- 写后只验证 Markdown 能解析，未核对依据仍存在、语义归属唯一、复核入口可执行及证据边界相称。
- 因同步失败而破坏性回滚整个工作区，覆盖用户或其他代理的并行改动；恢复只能精确针对本轮可证明的事实补丁。

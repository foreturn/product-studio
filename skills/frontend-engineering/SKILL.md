# 前端工程

以已确认的产品目标、体验契约、接口契约与安全策略为准，将用户可见行为落实为可维护代码和真实渲染证据。不得以视觉偏好重写产品范围、业务规则、交互意图或服务端语义。

## 专业所有权

`frontend-engineering` 唯一裁定前端代码层的路由与页面结构、组件边界、请求适配、客户端状态、表单实现、设计令牌与视觉实现、响应式布局、浏览器安全控制、性能策略和开发级真实渲染自检。

以下语义是本技能的输入边界，不在前端实现中重新定义：产品范围与验收目标、用户旅程与信息架构、跨系统边界、API 与权限语义、安全与隐私政策、总体验收结论、生产执行与运行健康。

## 输入与证据门槛

- 明确 Git 仓库根、当前产品与稳定 `product-id`、相关项目根、仓库指令、授权范围、真实入口、目标角色、核心任务、成功结果、支持环境、现有设计系统和不得破坏能力。
- 从路由、页面、组件、样式、请求层、状态容器、类型、测试和真实浏览器核验当前行为；静态稿、样例响应和单张截图只作线索，不能替代实际交互与契约证据。
- 将产品、体验、架构、API 和安全输入标为已确认契约、当前实现事实、运行证据、假设或未知。缺少会改变用户任务、接口结果、权限或安全行为的前提时，停止依赖该前提的实现并列出所缺契约与证据。
- 不从偶然响应、错误文案、现有 UI 或客户端缓存猜造服务端规则；共享 API、用户体验和安全政策只消费已确认版本。

## 专业能力

先查看 [前端工程能力准则](references/principles.md) 的目录与核心能力，完整读取本次命中的能力段落。涉及整体界面、交付收口或风险复核时，再读“常见误判”；局部修复不机械扩成全产品重设计。

## 实施方法

### 1. 追踪任务与界面调用链

1. 从真实入口完成当前任务，沿路由、页面、组件、样式、请求和状态调用链追踪用户看到的信息、作出的决定、动作、等待、失败、恢复与完成去向。
2. 列出受影响角色、身份、设备、输入方式、数据状态和消费者，固定必须改变与必须保持的体验结果。
3. 对每个页面或流程建立状态矩阵：初始、加载、刷新、空白、权限、禁用、编辑、提交、部分成功、失败、成功、过期、取消和恢复；不适用状态须有明确理由。

### 2. 固定信息、动作与状态模型

1. 将入口、标题、信息层级、主次动作、内容、反馈和恢复契约映射到路由、页面与组件；技术结构不得改变既定任务顺序或业务含义。
2. 将服务端数据、缓存、表单草稿、导航和瞬时交互分开建模，用枚举状态或状态机消除互斥状态同时成立的可能。
3. 为异步动作明确即时反馈、重复提交防护、取消、竞态、旧响应覆盖、乐观更新与回滚；刷新、返回、深链、会话过期和卸载后结果均有确定行为。
4. 接口适配明确缺失与空值、时间、金额、枚举、错误码、分页、排序、幂等和兼容表达，不解析易变文案或扩大服务端数据范围。

### 3. 设计组件、视觉与响应式实现

1. 沿用现有技术栈、组件、图标、令牌、容器、网格和间距；仅当现有方案无法表达当前需求且存在真实消费者时增加变体、公共组件或令牌。
2. 组件围绕稳定业务表达、数据所有权和交互职责划分，避免巨型页面与仅转发属性的碎片化；公共 API 显式限制属性、变体、状态和内容边界。
3. 先确定内容优先级、最小可用宽度和重排规则，再实现桌面与移动布局；表格、工具栏、图表、编辑器和媒体须有稳定尺寸、溢出、滚动和触控策略。
4. 用长标题、长单词、国际化文案、极值数字、延迟资源和动态计数检验换行、截断、预留空间与布局稳定，确保控件、文本和动态内容不重叠或遮挡。

### 4. 落实可访问性、安全与性能

1. 使用语义元素；键盘可完成核心任务，焦点顺序、弹层焦点圈、错误定位和操作后焦点去向明确。标签、说明、错误、辅助名称和动态通知不只依赖颜色或占位符。
2. 将服务端内容、富文本、URL、文件和第三方嵌入视为不可信输入，使用项目既有转义、净化和协议限制；客户端隐藏不得冒充授权。
3. 密钥、完整令牌、个人数据和敏感载荷不得进入源码、URL、无保护存储、日志、错误或埋点；退出、会话过期与跨用户切换须清理受保护状态。
4. 先测量首屏、交互延迟、布局稳定、长任务、列表滚动与输入响应，再选择拆包、延迟加载、虚拟化或记忆化；请求、缓存、监听器和后台任务均有边界与清理路径。

### 5. 最小实现与真实渲染验证

1. 同步必要的路由、类型、适配器、状态、组件、令牌、样式和测试，只实现已确认契约要求的最小完整改动。
2. 先用能失败的聚焦测试固定新增或修复行为，再写最小实现；自动化断言用户可观察结果，不依赖脆弱 DOM、样式类名或内部调用次数。
3. 运行项目既有格式、静态、类型、测试和构建检查，再在目标浏览器、视口、身份、数据和输入方式中从真实入口完成核心任务及高价值失败或恢复路径。
4. 检查控制台、网络、资源、文本溢出、布局、滚动、焦点、辅助名称、缩放、触控和性能；截图只证明所示帧，自动扫描只证明其规则范围。
5. 复核最终差异与所有消费者，记录无法取得的浏览器、设备、辅助技术、真实后端或性能证据及其影响，不以静态绿色外推。

## 输出

- 符合现有技术栈和已确认契约的路由、页面、组件、样式、状态、请求适配与聚焦测试。
- 任务调用链、状态矩阵、接口映射、组件边界、响应式、可访问性、安全和性能实现决定。
- 真实入口、身份、数据、浏览器、视口、输入方式、控制台、网络与关键断言，以及自动化、模拟、截图和真实操作各自的证据边界。
- 尚缺契约、未执行验证、剩余风险、影响范围与重验入口；契约冲突须保留当前复现，不在前端建立临时第二套语义。

## 完成门槛

- 从真实入口完成已确认核心任务，产品、体验、API 与安全契约均有对应实现，没有猜造或静默改写输入语义。
- 项目既有静态、类型、测试和构建检查通过，目标浏览器、视口、身份、数据状态及高价值恢复路径取得风险相称的真实操作证据。
- 最终差异只含授权范围，没有非法状态、无消费者抽象、内容遮挡、不可达操作、敏感数据泄露或未说明的性能与兼容风险。
- 未取得的真实设备、辅助技术、外部服务或生产环境证据被明确标为缺口，没有被截图、模拟或本地结果替代。

## 禁区

- 不发明产品范围、业务规则、验收目标、用户旅程、信息架构、内容层级或交互意图。
- 不重新裁定系统边界、API、权限、一致性、安全政策、隐私例外、会话或凭据策略。
- 不为未来预留无消费者公共组件、状态容器、设计令牌或依赖，也不以视觉装饰取代信息结构。
- 不宣告总体验收、生产执行或环境健康，也不把事实候选直接写成已同步事实。

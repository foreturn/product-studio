# 发布工程与运行

将已验收变更从精确仓库差异收束为可追溯版本与不可变制品，再在当前授权内安全带入指定环境，以技术和业务信号证明结果，并在门禁或阈值越界时停止推进。方案、代码修改许可、历史授权和准备就绪均不等于提交、Tag、推送或生产操作授权。

## 唯一决策权

`release-engineering` 唯一裁定仓库与版本准备、Tag 和发布说明、制品追溯、环境就绪、发布批次与观察门禁、当前操作授权、实际生产执行、运行健康、停止回滚和事故恢复。它只消费已确认的产品、架构、实现、数据库、安全与质量契约，不在发布现场重写这些专业决定。

## 输入门禁

- 明确 Git 仓库根、当前产品与稳定的 `product-id`、相关项目根、仓库指令、任务属于版本准备、就绪审计、发布执行、事故处置、恢复验证还是复盘，以及用户要求的停止位置。
- 固定目标分支或引用、比较基线、目标提交或待发布变更、工作区状态、版本权威与政策、Tag 约定、目标远端、当前验收结论、待发布制品、目标环境、范围、时间窗口、运行工具、权限和责任边界。
- 读取命中的产品、体验、架构、后端、前端、数据库、安全和质量事实，存在时读取稳定 locator `docs/product-studio/<product-id>/release.md` 中的发布主题，并核对 CI/CD、配置、迁移执行入口、健康检查、监控、回滚和运维入口。
- 产品成功信号、系统不变量、代码契约、物理数据库方案、安全控制或验收证据不足时，停止依赖该前提的发布动作，列明缺口、影响与所需专业决定；发布技能只编排并执行已确认制品、数据库方案和安全门禁，不重新设计它们。
- 将仓库准备、发布就绪、操作授权、实际执行和运行健康分别判定。变更未提交、版本来源冲突、Tag 指向不明、缺少可追溯制品、适用验收、数据库预检、安全门禁、恢复路径或当前操作授权时，只作只读审计与方案整理。

## 执行流程

1. 固定任务类型、停止位置、仓库、目标提交、验收修订、制品、目标环境、范围和时间窗口，分别记录仓库准备、就绪、授权、执行与健康状态。
2. 追踪仓库、版本、Tag、流水线、制品、配置、依赖、迁移执行入口、安全门禁、健康与恢复入口；专业前提不足时停止依赖它的动作并报告所缺契约，不以发布脚本补写策略。
3. 形成精确发布对象、版本裁定、Tag 方案、发布说明、制品映射和环境差异；未提交内容、版本或 Tag 冲突及证据漂移单列为阻塞，不以准备工作夹带仓库状态变化。
4. 依据已验证的数据库兼容矩阵、迁移与回填方案、预检、批次、停止恢复条件，以及已确认的秘密、权限、供应链和运行控制，组合发布批次与观测门禁。
5. 任何状态变化前，核对明确授权是否绑定当前仓库或远端、引用与目标提交、版本与 Tag、制品或环境、范围、动作和有效时窗；缺少当前授权时停在只读结论。
6. 获得相应授权后重核对象未漂移，使用项目既有工具执行获准的最小动作，将自动触发影响纳入同一批次；每步记录退出状态、直接证据和下一门禁，不超出授权范围。
7. 每批按当前信号判断健康；门禁失败或指标越界时停止扩大范围、保存证据并执行已批准的恢复动作，恢复后重新验证业务旅程、数据不变量与稳定窗口。
8. 汇总五轴结论、实际执行与未执行项、证据、偏差、风险和失效条件；发布范围形成终态且取得相称验证后，只形成事实候选，不直接写事实册。

## 当前产品事实

开始工作时，从用户范围、仓库原生产品身份、产品入口与元数据、相关项目根、目标制品和发布链确定 Git 仓库根及仓库内唯一、稳定且可安全作为单级目录名的 `product-id`；优先复用已确认属于同一产品的既有事实目录，不从项目目录名机械推导。若稳定 locator `<Git仓库根>/docs/product-studio/<product-id>/release.md` 存在，只读取命中主题及直接关联。

`release-engineering` 是该册发布与运行事实的唯一语义 Owner。仅依据 [release-engineering 事实规则与实例格式](references/memory.md) 形成 `ADD`、`UPDATE`、`DELETE` 或 `NO_CHANGE` 候选，不自行写册。授权、命令流水、事故时间线和一次性指标不入册；易变环境事实必须绑定不可变制品、目标环境、核验时点和失效条件。

## 输出

- 分轴结论：仓库准备为未准备或已准备；就绪为未就绪或已就绪；授权为未授权或已授权；执行为未开始、执行中、已发布、已回滚或失败；健康为未验证、健康或异常。
- 交付仓库根、比较区间、目标提交、工作区状态、版本权威与版本号、Tag、发布说明、制品、目标环境、配置与依赖差异、门禁、迁移批次、观察窗、停止与恢复条件，以及实际执行和运行信号的可追溯证据。
- 未执行项、首个可行动缺口、剩余风险、证据失效条件，以及尚缺的产品、体验、架构、实现、数据库、安全或质量契约。
- 只读就绪审计在门禁、授权状态、缺口和下一动作明确后即可闭合；只有宣告已发布或健康时才要求对应环境的当前执行与观察证据。
- 发布事实候选只在发布范围形成终态并取得当前、风险相称的验证后产生；准备中、执行中、失败、回滚未验证或健康未定状态不得写成稳定事实。事实候选是否写入取决于当前授权和事实规则，不构成固定后续步骤。

## 边界

- 可只读审计差异、准备版本与发布说明、制定发布批次、判定就绪并设置门禁；只有当前授权覆盖的仓库或环境对象、范围、动作和时窗才可执行对应状态变化。
- 可编排并执行已确认的迁移与回填方案，不裁定表列、DDL、索引、锁、批次算法、数据校验或数据库恢复策略；方案或真实证据缺失时停止相应环境动作并报告缺口。
- 可落实已确认的制品、秘密引用、环境权限、供应链和安全监控门禁，不自行批准安全例外或降低控制。
- 不擅自暂存、提交、隐藏、清理或回滚用户改动，也不擅自改变分支或历史；任何此类动作都须由当前精确授权单独覆盖。
- 仓库、制品、环境与健康结论只绑定各自直接证据；代码权限、CI、旧授权、运行手册和其他环境结果均不得外推。
- 不自行改变产品范围、体验、系统不变量或实现契约，不以发布检查代替独立验收，也不把事实候选直接写成已同步事实。

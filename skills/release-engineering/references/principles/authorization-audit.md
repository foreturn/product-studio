# 发布工程 · 授权、隔离与审计

### 授权、隔离与审计

- 提交、推送、标记、上传、部署、迁移、切流和恢复等写动作须逐项核对授权是否覆盖对象、环境与影响；同一会话中范围与条件仍成立的已有授权继续有效，只有超出其范围或条件失效时才补足授权。
- 代码完成、测试通过、具备凭据或其他范围的批准都不能扩大外部写入权限；授权可以覆盖一组明确动作，不应把逐项核对变成对已授权动作反复请求确认。
- 高风险环境必须具备身份校验、并发隔离、最小权限和防重复机制，避免错误目标或会话交叉覆盖。
- 操作前必须能明确显示目标环境、对象身份和影响范围，作用域不一致时应停止而非依赖人工猜测。
- 审计记录必须足以追溯动作与结果，同时不得包含秘密、令牌、私钥或未脱敏生产载荷。

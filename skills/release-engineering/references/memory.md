# 发布工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/release-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始发布相关工作前，读取已有事实。
- 当前权威优先于旧事实；两者冲突时，以当前清单、发布配置、制品系统和分发渠道所共同确认的认知为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程或一次性结果。

## 核心记忆

### 发布单元与版本权威

- 记住哪些组件共享发布生命周期，哪些组件独立发布，以及每个发布单元的版本权威载体和同步关系。
- 记住正式 Tag 的指向语义、可变开发身份的边界，以及渠道和消费者据以识别发布对象的稳定规则。

### 不可变制品与来源关系

- 记住源快照、构建、制品身份和证明材料之间必须保持的绑定，以及制品跨环境流转时不得重新构建的不变量。
- 记住可变别名和缓存不承担权威身份，以及平台工程、安全工程分别拥有的通道和来源政策边界。

### 环境、配置与依赖映射

- 记住环境类别、部署单元、配置来源、秘密引用和外部依赖之间的稳定映射，以及部署对象的身份确认方式。
- 记住临时环境与正式环境不可等同之处，以及配置或依赖不一致时必须停止推进的边界。

### 渐进发布与健康观察

- 记住发布顺序、风险分区、最大影响范围，以及扩大、暂停和完成所依赖的稳定技术信号与业务行为。
- 记住后台任务、数据写入和外部副作用中不受流量控制覆盖的路径，避免低估实际影响范围。

### 兼容迁移、停止与恢复

- 记住协议、数据和组件演进期间必须维持的兼容组合、执行顺序和退出条件。
- 记住触发停止的条件、可回滚对象、恢复入口和不可逆副作用，以及代码回滚无法恢复的数据边界。

### 分发渠道与消费者兼容

- 记住各分发渠道的身份关系、同步方式、发现或安装契约，以及消费者依赖的稳定兼容边界。
- 记住一个渠道上的验证不能证明其他渠道，独立生命周期的渠道也不能共享发布判断。

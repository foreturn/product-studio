`release-engineering` 是发布与运行事实的唯一语义 Owner。事实实例固定为 `<Git仓库根>/docs/product-studio/<product-id>/release.md`；稳定 locator 不因 Skill 名称变化而迁移。

本册保存后续发布仍需重复使用的版本、制品、环境、执行和恢复语义，以及具备严格时效边界的当前部署身份；不保存某次发布过程。Git、流水线、制品库、配置系统、环境查询和监控始终是权威来源；命中主题时必须重新核验。

## 事实册定位与共同约束

- `product-id` 必须在同一 Git 仓库内唯一、稳定且可安全作为单级目录名。结合用户范围、仓库原生产品身份、入口与元数据、相关项目根、目标制品及分发关系确认，不从目录名机械推导。
- 多产品仓库逐产品隔离。产品归属不能唯一确认时，不读取候选册、不创建目录、不写入；跨产品正文只保存在拥有权威制品或运行契约的产品事实册。
- 每个主题描述一组共同检索、共同变化的稳定发布语义，或以稳定环境与工作负载为键的当前部署身份；不按某次提交、digest、批次、命令、事故、审批或指标样本机械拆分。
- 写入前必须具备当前权威来源、风险相称的直接证据和事实册写入授权。易变运行事实还必须绑定目标环境、不可变制品、核验时点与失效条件。
- `ADD` 新增册内尚无同义主题的稳定事实；`UPDATE` 原位修改同一主题发生变化的字段；`DELETE` 删除已失效且无真实消费者的主题；`NO_CHANGE` 表示实际核验范围内四栏均无变化并且不得触碰文件。
- `DEFERRED` 不是第五种事实动作，而是无法作出四态裁决的停止结果：终态未形成、写权限缺失、证据不足、权威来源冲突或秘密无法安全分离时，报告缺口并保持事实文件字节不变；不得用 `NO_CHANGE` 掩盖未完成核验。
- 只对实际核验的制品、环境和范围负责，不把一个环境或观察窗口外推至其他环境。最后主题删除后移除 `release.md`；产品目录没有其他事实册时再移除空目录。

统一实例格式：

```markdown
# release-engineering 当前产品事实

## <稳定发布事实主题>

- **当前事实**：<当前发布、制品、环境、执行、健康或恢复语义；易变事实包含环境、制品、核验时点和失效条件>
- **权威依据**：<一至三个仓库相对路径、流水线、制品摘要、配置、环境查询、监控或运行手册入口>
- **影响边界**：<渠道、目标环境、区域、租户、实例、数据、外部系统、不得破坏关系及明确不适用处>
- **复核入口**：<可重复只读查询、校验、健康检查、业务旅程或恢复演练，含阈值、观察窗、未覆盖边界和重审触发>
```

## 事实类型：版本权威与 Tag 政策

- **入册条件**：版本号的唯一权威位置、计算规则、发布分支约束或 Tag 命名和指向政策不显然，且后续发布必须复用；某次准备发布的临时版本号不作为稳定政策入册。
- **主题合并键**：以“发布单元 + 版本权威或 Tag 政策”为合并键；同一发布单元的版本来源、格式和 Tag 关系合并记录，不按版本号或某个 Tag 建题。
- **当前事实写法**：写明发布单元、版本权威文件或生成来源、版本格式、递增条件、Tag 命名、Tag 必须指向的对象、分支或工作区前置及冲突处理原则。
- **权威依据**：指向版本文件、构建配置、发布脚本、流水线规则和实际 Tag 校验入口；README 或历史 Tag 只能辅助，不能替代当前权威定义。
- **影响边界**：列出共享该版本的包、插件、服务、渠道和自动触发动作，并明确独立版本单元或不受该 Tag 约束的分发面。
- **复核入口**：给出读取版本权威、比较清单一致性、验证 Tag 格式和目标提交的只读方法；发布单元拆分、版本源改变或流水线触发条件变化时重审。
- **变更规则**：首次识别稳定非显然政策为 `ADD`；权威位置、格式、同步范围、Tag 规则或触发边界改变为 `UPDATE`；发布单元退役为 `DELETE`；只产生一个新版本或 Tag 而政策未变为 `NO_CHANGE`。
- **专属禁项**：不记录待发布版本草案、单个历史 Tag 清单、某次 bump 过程、提交号流水、个人分支约定或未写入权威配置的口头规则。

## 事实类型：不可变制品与供应链追溯

- **入册条件**：制品的生成、命名、摘要、签名、来源提交、依赖清单或晋级关系构成后续发布必须遵守的稳定追溯契约，并由当前流水线或制品系统证实。
- **主题合并键**：以“制品类型 + 生成或晋级链”为合并键；同一制品在不同环境的晋级关系合并记录，具体某个 digest 不单独成为永久主题。
- **当前事实写法**：写明制品类型、构建来源、不可变身份、摘要或签名机制、来源提交映射、SBOM 或依赖证明、存储位置类别、晋级条件和禁止重建替换的规则。
- **权威依据**：指向构建和签名流水线、制品清单、registry/repository 配置、校验脚本及受控制品元数据查询；事实册只写入口与规则，不复制秘密或完整依赖表。
- **影响边界**：列出消费该制品的环境、平台、架构、发布渠道和下游部署，并明确开发构建、可变标签或未经签名制品不具备的保证。
- **复核入口**：给出从目标提交定位制品、校验摘要或签名、检查来源与晋级状态的方法；构建器、签名机制、存储、命名或晋级政策变化时重审。
- **变更规则**：稳定追溯链首次成立为 `ADD`；生成、标识、签名、来源映射、存储或晋级规则改变为 `UPDATE`；制品类型及其消费者全部退役为 `DELETE`；仅生成新 digest 而契约不变为 `NO_CHANGE`。
- **专属禁项**：不记录私钥、访问令牌、某次构建完整日志、所有制品清单、临时标签、可变 latest 状态或缺少来源证明的“已签名”结论。

## 事实类型：当前部署身份与环境归属

- **入册条件**：命名环境中的部署单元或工作负载已由当前只读环境证据确认正在运行某一不可变制品，且该环境到制品的现行映射对后续诊断、兼容、回滚或发布判断具有复用价值；必须同时取得环境、部署单元、不可变制品身份、核验时点和明确失效条件。
- **主题合并键**：以“目标环境 + 区域或集群边界 + 部署单元或工作负载”为合并键；同一工作负载的新版本、digest、核验时点和回滚状态原位更新，不能以 digest、Tag、发布日期或某次 rollout 另建主题。
- **当前事实写法**：写明截至 `<核验时点>`，`<环境／区域／集群>` 的 `<部署单元或工作负载>` 实际运行 `<制品类型、版本与完整不可变摘要>`，该观察覆盖 `<实例或流量范围>`，并在下一次部署、回滚、调度重建、制品漂移或超过约定新鲜度窗口时失效；期望状态与实际状态不一致时分别标明，不能择一冒充。滚动或漂移期间只写查询范围内各摘要对应的实例集合、实例数或流量分区，用于界定实际身份覆盖，不写“完成百分比”、阶段进度或过程时间线。
- **权威依据**：指向当前编排器或平台的只读工作负载查询、部署状态、制品 registry 元数据和来源映射；配置中的期望版本、可变 Tag、终端缓存或旧发布记录不能脱离实际运行身份独立证明本事实。原始查询含秘密时，只能引用安全查询入口和经核对的非敏感字段，不得复制原始输出；若无法安全分离证据则不得入册。
- **影响边界**：列出环境、区域、集群、实例组、流量范围、租户或渠道及消费该身份的诊断、兼容和回滚判断，并明确未查询的副本、异步任务、边缘节点和其他环境不得外推。
- **复核入口**：重新查询目标工作负载的期望与实际不可变摘要、实例一致性、来源制品及观察时点，断言覆盖范围内无混合或漂移；下一次部署、回滚、扩缩容重建、调度迁移、查询入口变化或新鲜度窗口届满时立即重审。工作负载退役须以权威运行清单中稳定键消失，并结合仓库部署声明或等价控制面证据复核，不以一次查询失败推断退役。
- **变更规则**：首次取得完整现行映射且册中无同义主题为 `ADD`；实际摘要、版本、期望／实际关系、身份分布、环境归属、覆盖范围、核验时点、失效条件或证据入口改变为 `UPDATE`，因此新一次有效查询即使摘要未变，只要延长事实有效期也须原位更新；环境或工作负载已证实退役，或者既有快照已触发自身失效条件且没有新的当前映射可替代时为 `DELETE`，删除后不留过期墓碑；`NO_CHANGE` 只适用于候选仍引用同一权威观察且不刷新核验时点、失效条件或任一栏；证据不足、权威来源冲突或秘密无法安全分离时为 `DEFERRED` 并保持文件字节不变，不得借旧记录刷新时间，也不得提前删除尚未失效的主题。
- **专属禁项**：不记录部署计划、rollout 进度、当前授权、操作者、临时命令流水、可变 Tag 单独值、未查询的期望状态、健康或成功外推、私钥、令牌、签名材料、环境秘密、用户数据或完整生产载荷；不可变 digest 可以作为事实值，但不得充当主题键。

## 事实类型：环境、配置与依赖契约

- **入册条件**：目标环境的部署单元、配置名称、秘密引用、外部依赖、资源或网络前置是发布可重复执行的稳定条件，且缺失会导致错误发布或不可诊断故障。
- **主题合并键**：以“目标环境类别 + 部署单元 + 契约簇”为合并键；同一环境中共同变化的配置和依赖合并，权限、网络或数据域显著不同的环境分别建题。
- **当前事实写法**：写明环境标识、部署单元、配置和秘密引用名称、必需依赖及版本范围、资源和网络前置、默认安全状态、差异边界和就绪判据。
- **权威依据**：指向 IaC、部署清单、配置 Schema、受控秘密引用、环境模板、依赖检查和只读环境查询；实际秘密值永不写入。
- **影响边界**：列出区域、租户、实例组、外部服务、数据存储和消费制品，并明确其他环境、临时沙箱或个人配置不受何种约束。
- **复核入口**：给出渲染或解析配置、对比目标环境、检查依赖和只读确认资源的方法；配置 Schema、依赖版本、区域拓扑或秘密引用变化时重审。
- **变更规则**：稳定环境契约首次明确为 `ADD`；部署单元、配置名、依赖、资源、网络、就绪条件或适用环境改变为 `UPDATE`；环境或部署单元退役为 `DELETE`；仅轮换秘密值而引用契约不变为 `NO_CHANGE`。
- **专属禁项**：不记录秘密值、临时环境变量、个人机器配置、完整生产拓扑清单、一次性容量快照、当前授权或未由配置系统证实的环境差异。

## 事实类型：部署批次、切流与观察门禁

- **入册条件**：部署顺序、批次切分、灰度或蓝绿策略、流量切换和扩大范围的门禁是稳定且后续发布会复用的运行契约，并有项目工具或运行手册支撑。
- **主题合并键**：以“部署单元 + 发布策略 + 风险边界”为合并键；同一策略的批次比例和门禁合并记录，不按某次 rollout 批次建题。
- **当前事实写法**：写明部署对象、顺序、批次或流量单位、进入条件、每批观察信号和窗口、扩大范围条件、暂停点、最大影响范围及完成判据。
- **权威依据**：指向部署流水线、编排配置、流量管理规则、门禁查询、运行手册和稳定指标定义；某次人工命令不能独立成为政策依据。
- **影响边界**：列出目标环境、区域、租户、实例、入口流量、后台任务和外部副作用，并明确不适用的部署单元或不受切流控制的路径。
- **复核入口**：给出只读确认当前策略、模拟或测试批次、检查门禁和观察窗口的方法；拓扑、流量工具、风险分区或健康阈值改变时重审。
- **变更规则**：稳定部署策略首次形成为 `ADD`；顺序、批次单位、门禁、观察窗、暂停点或最大影响范围改变为 `UPDATE`；策略及最后消费者退役为 `DELETE`；某次发布停在不同批次但规则未变为 `NO_CHANGE`。
- **专属禁项**：不记录某次 rollout 进度、操作者、当前审批、命令流水、临时灰度比例、未绑定制品的“已部署”状态或缺少观察证据的完成声明。

## 事实类型：数据库迁移执行契约

- **入册条件**：已确认数据库变更具有后续部署必须遵循的稳定执行入口、兼容阶段、预检、批次、暂停、验证或清理顺序；物理 DDL 和迁移算法本身不在本册重复。
- **主题合并键**：以“数据存储 + 迁移族 + 兼容窗口”为合并键；同一演进的扩展、回填、切换和收缩阶段合并记录，不按迁移文件逐个建题。
- **当前事实写法**：写明目标存储和版本、迁移执行入口、前置备份或预检、兼容版本组合、阶段顺序、回填或切换批次、每阶段验证、暂停与恢复入口、收缩条件和不可逆边界。
- **权威依据**：指向已确认迁移文件、执行脚本、部署流水线、兼容矩阵、预检和恢复手册；不得由发布现场临时推导 Schema 策略。
- **影响边界**：列出读写应用版本、数据表或分区、后台任务、复制拓扑、锁或容量风险、目标环境和允许的兼容窗口，并明确未验证数据库版本。
- **复核入口**：给出测试或影子环境的迁移往返、预检、分批执行、数据校验和恢复演练入口；Schema、数据规模、应用版本组合或恢复能力变化时重审。
- **变更规则**：稳定执行契约首次确认并会复用时为 `ADD`；入口、版本组合、阶段、批次、验证、暂停恢复或不可逆边界改变为 `UPDATE`；迁移完成且所有临时兼容与未来消费者均消失时为 `DELETE`；某次执行进度变化而稳定契约未变为 `NO_CHANGE`。
- **专属禁项**：不记录迁移进度、一次性回填游标、生产数据、连接秘密、未确认 DDL、锁策略设计过程、单次执行日志或把代码回滚写成数据回滚保证。

## 事实类型：健康信号、业务验证与观察窗口

- **入册条件**：技术健康、业务旅程、数据不变量或外部副作用具有稳定信号、阈值和观察方法，可用于后续发布判断；单次指标值或没有处置动作的告警不入册。
- **主题合并键**：以“发布对象 + 健康或业务结果”为合并键；共同决定同一门禁的指标合并记录，信号作用和处置不同则分别建题。
- **当前事实写法**：写明信号定义、数据来源、适用制品与环境、基线或阈值、聚合和观察窗口、业务验证步骤、异常判据、失效条件及信号缺失时的处理原则。
- **权威依据**：指向指标和告警定义、健康端点、业务探针、监控面板查询、数据校验及当前环境只读证据；面板截图不能替代查询定义。
- **影响边界**：列出环境、区域、租户、流量、服务、数据和外部依赖，并说明信号覆盖的故障类型、观测延迟及不能证明的长期健康。
- **复核入口**：给出查询信号、执行代表性业务旅程、核对数据不变量和等待稳定窗口的方法；指标定义、阈值来源、业务路径或观测链变化时重审。
- **变更规则**：稳定健康契约首次建立为 `ADD`；信号、来源、阈值、窗口、业务旅程、环境或证明边界改变为 `UPDATE`；信号或发布对象退役为 `DELETE`；仅当前数值改变而契约未变为 `NO_CHANGE`。
- **专属禁项**：不记录一次指标截图、临时告警、无环境和制品身份的“健康”结论、事故时间线、个人观察、任意降低阈值或把短窗口外推为长期稳定。

## 事实类型：停止、回滚与恢复入口

- **入册条件**：发布存在稳定的停止条件、代码或配置回滚、数据恢复、流量回切、任务暂停或人工恢复入口，且后续操作需要提前知道其能力和限制。
- **主题合并键**：以“故障边界 + 恢复能力”为合并键；共同收敛同一故障的停止、回滚和验证合并记录，不按事故或命令分别建题。
- **当前事实写法**：写明触发条件、停止扩大范围的时点、可逆对象、恢复入口、必要权限类别、数据和外部副作用处理、预计恢复目标、完成判据、不可恢复部分及升级边界。
- **权威依据**：指向回滚或恢复脚本、流量配置、备份恢复手册、任务控制入口、演练测试和监控门禁；历史成功不能替代当前入口可用性。
- **影响边界**：列出制品、环境、数据存储、队列、缓存、外部系统、租户和最大影响范围，并明确代码回滚不能自动撤销的数据或外部副作用。
- **复核入口**：给出非生产演练、只读入口检查、恢复后业务和数据验证及稳定观察方法；工具、权限模型、备份策略、拓扑或副作用变化时重审。
- **变更规则**：稳定恢复能力首次证实时为 `ADD`；触发、入口、权限类别、恢复范围、完成判据或不可逆边界改变为 `UPDATE`；能力退役或故障边界消失为 `DELETE`；一次演练结果改变但能力契约未变为 `NO_CHANGE`。
- **专属禁项**：不记录当前操作授权、真实凭据、事故指挥流水、责任人、未经演练的恢复承诺、生产载荷、临时人工命令或把回滚入口存在等同于完整恢复。

## 事实类型：分发渠道与兼容身份

- **入册条件**：同一产品通过多个 marketplace、包仓、应用商店、镜像仓或客户渠道分发，且清单身份、版本同步、安装发现或渠道兼容关系是后续发布需要重复核验的稳定事实。
- **主题合并键**：以“产品发布单元 + 分发渠道集合”为合并键；同一身份在多个渠道的映射合并记录，独立版本和生命周期的渠道分别建题。
- **当前事实写法**：写明各渠道的清单或包身份、版本权威关系、入口文件、兼容范围、安装或发现边界、同步要求以及一个渠道的证据为何不能证明其他渠道。
- **权威依据**：指向各渠道清单、marketplace 配置、包元数据、发布流水线和安装校验入口；宣传页面或一个渠道的安装结果不能替代其他渠道证据。
- **影响边界**：列出消费平台、客户端版本、渠道、包名、插件名和共享制品，并明确尚未安装、未发布或未在新上下文验证的分发面。
- **复核入口**：给出解析并比较各渠道身份、版本和入口，分别校验清单和实际安装发现的方法；渠道清单、版本政策、客户端格式或共享制品关系变化时重审。
- **变更规则**：多渠道稳定映射首次形成时为 `ADD`；身份、版本关系、入口、兼容范围或验证边界变化为 `UPDATE`；渠道永久退役为 `DELETE`；仅发布新版本且映射规则不变为 `NO_CHANGE`。
- **专属禁项**：不记录某次安装日志、个人缓存路径、尚未发布即宣称远端可用、一个渠道的结果外推、完整用户安装清单或市场宣传文案。

## 全局禁止内容

- 发布计划、任务摘要、进度、操作者、审批正文、命令流水、事故时间线、复盘过程、候选方案、前后对比和历史版本。
- 缺少环境、不可变制品、核验时点或直接证据的“已上线”“健康”结论，以及可由流水线、制品库、配置或监控生成的完整清单。
- 跨会话操作授权、密钥、令牌、用户数据、环境秘密、生产载荷和其他专业事实正文。

Git、流水线、制品库与事件系统承担历史；本册只索引当前仍成立、可重新核验且属于发布工程的事实。

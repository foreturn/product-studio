# 质量工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/quality-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始质量相关工作前，读取已有事实。
- 当前权威优先于旧事实；两者冲突时，以当前产品契约、实现和可重复验证能力所共同确认的认知为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程或一次性结果。

## 核心记忆

### 关键用户行为与业务不变量

- 记住最重要的用户任务、业务不变量和失败行为，以及必须跨越界面、接口、持久化或异步处理观察的副作用。
- 记住一旦失效便会造成高损失、越权或不可逆数据影响的路径。

### 风险与验证重点

- 记住各模块最主要的失效模式、影响范围和容易复发的边界条件。
- 记住哪些变化会扩大验证范围，例如共享契约、身份权限、数据演进、并发、外部依赖或恢复行为的变化。

### 测试层级与替身边界

- 记住单元、集成、契约、端到端和真实环境验证各自覆盖的行为，以及它们不能彼此替代的边界。
- 记住哪些依赖允许使用替身，哪些判断必须经过真实引擎、浏览器、设备或外部提供方。

### 验证入口与发现范围

- 记住稳定验证入口所涵盖的模块、平台和测试发现范围，以及必要的运行时、配置和依赖前置。
- 记住缓存、跳过、分片和局部执行会遗漏的范围，避免把局部证据外推到未覆盖表面。

### 环境、夹具与数据语义

- 记住验证环境与目标环境之间会影响判断的差异，以及身份类别、数据形态、时钟、随机性和并发所需的确定性约束。
- 记住共享状态、构造、隔离和清理的不变量，确保重复执行不会相互污染。

### 跨边界证据关系

- 记住关键行为必须由哪些证据层共同支撑，以及接口响应、持久副作用、消息处理、审计和用户可见行为之间如何关联同一对象。
- 记住模拟环境与真实环境、静态检查与运行行为之间不可外推的界线。

### 非功能预算与兼容边界

- 记住性能、容量、可靠性、恢复和兼容要求所采用的工作负载、测量口径与适用环境。
- 记住受支持的平台、运行时、浏览器和设备类别，以及超出支持范围时不能沿用的质量判断。

### 回归守卫

- 记住高价值不变量由哪些持久测试或检查保护，以及守卫应当能够捕获的目标错误。
- 记住曾反复暴露系统性缺陷的交互边界和对应守卫，避免只在局部层级重复覆盖。

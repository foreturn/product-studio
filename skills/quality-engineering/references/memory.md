# 质量工程项目记忆

## 核心记忆

### 验收对象、质量判据与可证伪边界

- 记住产品、模块、契约、制品或发布候选中实际被验收的稳定对象，其权威基线、适用角色、环境、身份、数据和消费者，以及对象身份变化后哪些既有证据必须失效。
- 记住关键用户行为和业务不变量的前置条件、可观察结果、禁止结果与失效条件，接口、持久化、消息、审计和用户界面中需要共同观察的副作用，以及不能由实现存在或测试绿色替代的判据。
- 记住高损失、越权、不可逆数据影响和结果未知路径的明确完成标准，哪些主张当前可直接验证，哪些必须保持为阻塞、未覆盖或不适用而不能包装为通过。

### 风险模型、影响扩散与回归范围

- 记住各模块和关键旅程最主要的失效模式、发生前提、影响范围、可发现性、可逆性、数据敏感度和真实消费者，以及风险排序中不可被低价值检查淹没的路径。
- 记住变更从直接文件沿共享契约、依赖、调用方、权限、租户、数据、副作用和外部系统扩散的关系，哪些公共组件、状态权威或运行边界一变便必须扩大回归范围。
- 记住允许、拒绝、边界、重复、乱序、超时、取消、部分成功、结果未知与恢复中容易复发的条件，以及未覆盖风险的触发后果和重新验证入口。

### 状态空间、用例设计与副作用断言

- 记住测试应覆盖的业务状态、合法转换、决策条件、输入边界、事件顺序和相互作用维度，以及哪些组合代表独立风险、哪些重复样本可以合并而不损失判别力。
- 记住每类拒绝、取消、超时、冲突和重试除返回结果外还必须确认未发生的持久化、扣减、消息、通知和外部调用，以及最终状态、恢复入口和幂等结果。
- 记住适合用示例、决策表、状态模型、性质或生成数据表达的不变量，独立判定依据、最小失败样本、随机种子和可重放条件，以及不得复制被测核心规则的边界。

### 测试层级、替身与真实边界

- 记住单元、组件、集成、契约、端到端和真实环境验证分别覆盖的规则、进程、协议、用户旅程和失败面，哪一层是最低充分证据，以及多层测试各自证明的不同不变量。
- 记住哪些依赖允许以替身控制时间、故障与边界，哪些数据库约束与锁、浏览器语义、设备能力、网络、消息系统或外部提供方行为必须由具备真实语义的环境验证。
- 记住静态检查、Mock、截图、模拟器、预发布和生产观察各自不能外推的范围，替身数据必须遵循的真实契约，以及高成本真实验证只用于哪些低层证据无法证明的风险。

### 验证入口、环境、夹具与可诊断性

- 记住各稳定验证命令、任务和流水线实际发现的模块、平台、测试类型与生成资产，其运行时、工具链、配置、依赖和工作目录前提，以及缓存、跳过、分片和局部筛选会遗漏的范围。
- 记住身份类别、租户、数据形态、时间、随机、并发和外部响应的控制与隔离方式，共享状态、构造、清理和重复执行的不变量，以及目标环境与测试环境中会改变结论的差异。
- 记住自动化失败必须保留的关键输入、对象身份、预期、实际、时序和首个错误状态，异步等待的完成条件与总时限，以及快照、生成数据、公共助手和不稳定基础设施的诊断边界。

### 契约、数据、消息与并发完整性

- 记住关键 API、事件和消费者契约需要验证的结构、业务语义、错误、版本与兼容组合，以及请求成功、消息投递和消费者收敛如何关联到同一业务对象。
- 记住数据约束、事务提交与回滚、幂等、迁移起点、中断重入和持久副作用必须由哪个目标引擎或集成环境证明，空库、替代引擎和脚本退出不能证明的边界。
- 记住并发测试需要控制的关键交错、唯一结果、冲突和最终状态，消息重复、乱序、延迟与缺失的恢复语义，以及顺序多跑、任意等待或统一重试不能替代的直接证据。

### 用户旅程、视觉系统与无障碍证据

- 记住核心旅程的真实入口、当前位置、主动作、返回上下文和失败恢复，支持范围内的视口、窗口、方向、缩放、输入方式、内容极值和生命周期变化中必须保持的任务能力。
- 记住语义名称与角色、键盘和焦点顺序、错误关联、动态播报、触控目标和非颜色传意的行为约束，以及哪些任务必须使用真实渲染、辅助技术、浏览器或代表设备验证。
- 记住同类页面的容器、对齐、间距、排版、颜色语义、控件尺寸和动作层级，加载、刷新、空、部分成功、业务拒绝、系统失败与结果未知的视觉和恢复契约，以及截图只能补充而不能独立证明的行为。

### 性能、可靠性、安全与运行证据

- 记住性能和容量判断采用的工作负载、数据规模、环境、构建、基线、统计口径与时间窗口，尾延迟、错误、资源饱和、系统拐点和保护行为中哪些用户可见结果必须同时成立。
- 记住可靠性试验覆盖的故障域、降级、积压、数据不变量、恢复与稳定窗口，安全验证中的主体、动作、对象、租户、允许与拒绝对照，以及故障和对抗测试允许的爆炸半径与恢复条件。
- 记住运行信号如何绑定候选版本、环境、身份、区域、流量和用户结果，缺少告警、总体成功率或局部健康不能证明的范围，以及线上缺陷怎样转化为脱敏、最小且能识别原错误语义的稳定守卫。

### 缺陷归因、不稳定测试与结论守卫

- 记住实现偏离已确认决定、决定前提被证伪、适用条件变化、产品缺陷、测试缺陷、环境故障、契约冲突和证据不足的判别依据，基线与目标比较必须固定的输入、环境和观察方式，以及首个错误状态、最小复现、待重审决定和仍有效边界的定位入口。
- 记住反复暴露系统性问题的交互边界、对应回归守卫及其应捕获的错误语义，不稳定测试的复现率、临时隔离、门禁影响和修复条件，以及不得以重跑通过、永久跳过或放宽超时掩盖的失败。
- 记住 `PASS`、`FAIL`、`INCONCLUSIVE` 与 `NOT_APPLICABLE` 各自需要的直接证据和阻塞语义，结论只能覆盖的修订、制品、环境、身份、数据规模与时间窗口，以及对象漂移后的重新取证条件。

# quality-engineering 当前产品事实规则

## 所有权与稳定位置

`quality-engineering` 只拥有稳定质量门禁、权威契约到证据的覆盖映射、验证环境契约、非功能测量契约和回归守卫事实。它不拥有被验证的产品政策、接口语义、数据规则、安全策略或发布状态正文。

稳定事实册为 `docs/product-studio/<product-id>/quality-engineering.md`。`product-id` 必须由产品入口、元数据、项目根、目标代码和调用链共同确认；归属不唯一时不得读取、创建或修改候选事实册。

## 事实类型索引

1. 权威契约与风险覆盖映射
2. 稳定验证门禁与入口
3. 验证环境、夹具与数据边界
4. 跨边界证据组合
5. 非功能预算与测量契约
6. 回归守卫、证据有效性与退出边界

## 通用入册门禁

- 候选事实必须是可交付终态中当前已经成立的受支持语义，不得是计划、目标、进度、缺陷状态或一次验收结论。
- 候选事实必须跨局部重构、发布或人员交接仍稳定且有意义，且不能由单个文件、清单或普通查询低成本直接生成。
- 候选事实必须会改变后续验证范围、证据选择、风险判断或退出结论，重新发现其完整语义具有明显成本。
- 候选事实必须具有唯一 Owner；质量册只引用权威契约并记录覆盖关系，不复制其他专业的事实正文。
- 候选事实必须由当前权威代码、测试、配置、契约或受控环境直接支撑，并能够沿权威入口重复复核；事实册不能自证。
- 单次绿红、覆盖率、运行耗时、当前版本、制品、环境状态、指标值和核验时点只用于本轮报告，不进入事实册。
- 秘密、令牌、用户或生产数据、原始载荷、授权、任务历史和可利用细节永不入册。

## 主题表达规则

主题以稳定质量语义命名，不含日期、版本、任务号、缺陷号或动作前缀。正文不绑定统一 Markdown 标题、栏位、顺序或句数；可依事实类型与检索需要使用段落、列表、表格或局部小节。无论表达形式如何，都必须能够辨认当前成立的语义、权威依据、适用或影响边界、复核方式与失效触发；由命中的事实类型决定具体内容，不用空栏或占位符凑格式。

一个主题只容纳共同检索、共同变化的语义。测试清单、日志、报告、截图和证据叙事不得复制进正文。

## 动作语义

- `ADD`：候选通过全部入册门禁，且同一合并键尚无主题。
- `UPDATE`：同一主题的当前语义、依据、影响边界或复核入口发生实质变化；原位保留唯一当前版本。
- `DELETE`：当前权威证明确认事实或最后消费者已经消失；直接删除，不留墓碑。
- `NO_CHANGE`：已沿权威入口复核，但稳定语义没有新增、改变或消失；事实册字节保持不变。

任一动作的归属、证据或写权限不足时不得写入事实册，具体收束结果只依公共终态协议判定。

## 事实类型

### 权威契约与风险覆盖映射

- **入册条件**：其他 Owner 的稳定契约或不变量具有反复出现的高风险失败面，并已形成可复用的证据覆盖关系。
- **主题合并键**：`权威契约主题 + 风险边界 + 证据覆盖单元`；共同由同一证据组合保护的风险合并。
- **当前事实写法**：引用权威主题或契约入口，写明受保护风险、证据层级、覆盖保证、已知空白和结论限制，不复述契约正文。
- **权威依据**：引用契约 Owner 的稳定入口、验证配置、断言入口和真实消费者；事实册自身与旧报告不能续证。
- **影响边界**：列出适用交付单元、消费者、身份、数据、平台和环境，并说明替身或局部证据不能证明的范围。
- **复核入口**：从权威契约追溯到证据并证明断言能因目标缺陷失败；契约、消费者、风险或证据层级变化时重审。
- **变更规则**：覆盖关系首次稳定成立为 `ADD`；权威引用、风险、证据或边界变化为 `UPDATE`；契约与最后消费者或有效证据消失为 `DELETE`。
- **排除项**：不复制产品验收、API 结果、权限矩阵、数据规则、用户旅程正文、测试清单、覆盖率或临时风险排序。

### 稳定验证门禁与入口

- **入册条件**：后续交付会反复使用同一可执行入口、前置条件、失败语义和质量门槛，且这些关系不能从单个脚本名完整推导。
- **主题合并键**：`交付单元 + 门禁目的 + 证据层级`；共同决定一个退出判断的入口合并。
- **当前事实写法**：写明规范入口、必要前置、覆盖目的、关键失败含义、门槛来源、跳过限制及不能证明的边界。
- **权威依据**：引用包脚本、构建或测试配置、流水线任务和稳定断言入口，不复制命令输出。
- **影响边界**：列出适用模块、平台、运行时、配置和依赖，并明确缓存、跳过、局部运行和未运行环境的限制。
- **复核入口**：在可说明的干净状态执行入口，核对发现范围、退出语义和关键断言；入口、门槛或交付边界变化时重审。
- **变更规则**：稳定门禁首次成立为 `ADD`；入口、前置、覆盖目的、门槛或失败语义变化为 `UPDATE`；门禁与最后消费者退役为 `DELETE`。
- **排除项**：不记录一次输出、耗时、流水线 URL、个人别名、临时过滤参数、当前绿红或可自动生成的测试清单。

### 验证环境、夹具与数据边界

- **入册条件**：验证正确性依赖稳定的环境语义、身份类别、最小数据形态、确定性控制、隔离或清理契约，缺失会反复造成误判。
- **主题合并键**：`验证边界 + 环境或夹具语义 + 隔离范围`；共同构成同一前置的资源合并。
- **当前事实写法**：写明环境等价性、身份与数据语义、构造和清理保证、共享状态边界、确定性条件及与目标环境的已知差异。
- **权威依据**：引用环境定义、测试配置、夹具入口、数据 Schema、时钟或随机控制和清理实现，不引用实例值。
- **影响边界**：列出适用测试层级、模块、并发范围、数据库或外部依赖，并明确替代引擎与本机残留不适用。
- **复核入口**：从空状态构造、重复执行并验证清理和隔离；环境语义、Schema、身份、时钟或并发机制变化时重审。
- **变更规则**：稳定前置首次成立为 `ADD`；环境语义、身份、数据、隔离或清理保证变化为 `UPDATE`；环境与最后消费者退役为 `DELETE`。
- **排除项**：不记录真实凭据、用户或生产数据、实例 ID、随机运行值、临时地址、个人路径、完整夹具字段或生成数据清单。

### 跨边界证据组合

- **入册条件**：单一证据层无法证明关键用户结果、接口交互、持久副作用、安全边界或恢复行为，后续验收必须复用稳定证据组合。
- **主题合并键**：`受保护结果 + 跨越边界 + 证据组合`；共同决定同一结论的证据合并。
- **当前事实写法**：写明所引用的权威结果、必须观察的边界、各证据层分别证明什么、组合后的保证和仍未覆盖之处。
- **权威依据**：引用权威契约、稳定测试入口、目标引擎或设备配置和断言，不复制业务或安全策略正文。
- **影响边界**：列出用户任务、接口、身份、数据、平台、设备和外部依赖，明确模拟、替身和静态检查的外推限制。
- **复核入口**：按同一对象身份执行证据组合并核对跨边界结果；契约、边界、平台支持或证据能力变化时重审。
- **变更规则**：稳定组合首次必需且成立为 `ADD`；引用、边界、证据分工或证明限制变化为 `UPDATE`；结果与最后消费者或组合退役为 `DELETE`。
- **排除项**：不复述业务行为、页面步骤、接口字段、授权政策或数据 Schema，不记录截图集、设备快照和一次验收报告。

### 非功能预算与测量契约

- **入册条件**：产品具有会约束后续交付的稳定性能、容量、可靠性、恢复或兼容预算，并有可重复测量语义。
- **主题合并键**：`质量属性 + 工作负载或兼容边界 + 测量语义`；环境和失效条件相同的预算合并。
- **当前事实写法**：写明预算来源、工作负载和数据规模、统计口径、环境等价性、通过语义、故障或版本边界及禁止外推范围。
- **权威依据**：引用批准的预算、负载或故障脚本、基准配置、兼容矩阵和结构化查询入口，不复制即时数值。
- **影响边界**：列出服务、接口、设备、版本、区域、数据规模和依赖，明确未取证环境与超出负载不适用。
- **复核入口**：按固定测量语义重新执行并核对分布、错误、资源和恢复；预算、工作负载、环境或支持范围变化时重审。
- **变更规则**：稳定预算和方法首次成立为 `ADD`；预算语义、负载、统计、环境或兼容边界变化为 `UPDATE`；预算与最后消费者退役为 `DELETE`。
- **排除项**：不记录一次基准结果、生产即时指标、当前容量、事故数字、未经批准目标、平均值排名或无工作负载身份的结论。

### 回归守卫、证据有效性与退出边界

- **入册条件**：高价值不变量具有持久回归守卫，或一类交付对象具有稳定证据绑定、失效条件和退出门槛，后续维护必须持续遵守。
- **主题合并键**：`受保护不变量或交付对象 + 守卫或退出边界`；共同决定一个质量结论的规则合并。
- **当前事实写法**：写明权威不变量引用、守卫目的、必要证据、对象与环境绑定、失效条件、退出语义和不能替代的判断。
- **权威依据**：引用持久测试、质量配置、流水线门禁、真实环境入口和证据绑定实现，不引用缺陷工单或旧报告正文。
- **影响边界**：列出修订、制品、平台、环境、风险等级和消费门禁，并说明旧证据、缓存、跳过和未运行不受证明。
- **复核入口**：证明守卫能因目标错误失败，并以新对象重新取得完整证据；不变量、门禁、环境或证据层级变化时重审。
- **变更规则**：稳定守卫或退出规则首次成立为 `ADD`；目的、证据、绑定、失效条件或边界变化为 `UPDATE`；不变量与最后消费者或规则消失为 `DELETE`。
- **排除项**：不记录缺陷时间线、责任人、提交摘要、当前 PASS/FAIL、测试进度、审批、临时豁免、一次堆栈或旧证据摘要。

## 全册安全与删除规则

- 禁止写入秘密、凭据、密钥、令牌、个人或用户数据、生产数据、原始载荷、授权、任务历史、原始差异、长日志和可利用细节。
- 同一正文只属于一个 Owner；质量册只保存证据关系，跨边界通过主题和权威入口引用，不复制其他事实正文。
- 删除必须由当前权威证明确认事实或最后消费者消失，不以一次失败、测试未运行、文件移动或工具不可用推断失效。
- 删除最后主题时删除空事实册；产品目录没有其他事实册时才删除空目录。历史由 Git 和权威证据系统承担。

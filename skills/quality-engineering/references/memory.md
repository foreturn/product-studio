`quality-engineering` 是持续验证事实的唯一语义 Owner。事实实例固定为 `<Git仓库根>/docs/product-studio/<product-id>/verification.md`；文件名 `verification.md` 是兼容既有项目的稳定 locator，不因 Skill 名称变化而迁移。

本册保存可供后续工作重复使用的验证能力、覆盖关系与证据边界，不保存某一轮验收结果。源码、测试、夹具、配置和当前运行证据始终比事实册权威；命中主题时必须回到这些来源复核。

## 事实册定位与共同约束

- `product-id` 必须在同一 Git 仓库内唯一、稳定且可安全作为单级目录名。结合用户范围、仓库原生产品身份、产品入口与元数据、相关项目根、目标代码、制品及验证消费关系确认，不从目录名机械推导。
- 多产品仓库逐产品隔离。产品归属不能唯一确认时，不把候选事实册作为当前事实读取，不创建目录，也不写入。
- 每个主题描述一组共同检索、共同变化的持续验证语义，不按任务、提交、单个测试文件、单次命令、某次制品或一次结果机械拆分。
- 写入前必须具备当前实现或验证资产、权威要求和与风险相称的直接证据。只读任务或未获事实册写入授权时，只报告候选动作与证据。
- `ADD` 新增册内尚无同义主题的稳定事实；`UPDATE` 原位修改同一主题发生变化的字段；`DELETE` 删除已经失效且没有真实消费者的主题；`NO_CHANGE` 表示实际核验范围内四栏均无变化并且不得触碰文件。
- 只对本次实际核验范围负责，不因局部检查宣称全产品验证事实已经刷新。最后一个主题删除后移除 `verification.md`；产品目录没有其他事实册时再移除空目录。

统一实例格式：

```markdown
# quality-engineering 当前产品事实

## <稳定验证事实主题>

- **当前事实**：<当前可重复使用的验证能力、适用条件、关键断言和证明边界>
- **权威依据**：<一至三个仓库相对路径及精确测试、夹具、脚本、配置、契约或被测 Symbol>
- **影响边界**：<所覆盖的要求、风险、实现、环境、消费者、不得破坏关系及明确不适用处>
- **复核入口**：<可重复测试、脚本、命令或操作旅程，包含环境、输入、关键断言、未覆盖边界和重审触发>
```

## 事实类型：要求追溯与风险覆盖关系

- **入册条件**：某项稳定产品要求、业务不变量、安全控制、兼容约束或高价值风险已经由可重复验证资产持续覆盖，且后续改动仍需据此选择回归范围；只有需求文字而没有可执行检查，或只有孤立测试而无法说明其证明对象时不入册。
- **主题合并键**：以“稳定要求或风险簇 + 被保护结果”为合并键；同一风险由多个测试层共同证明时合并为一个主题，不按 `AC-ID`、测试文件或测试层分别建题。
- **当前事实写法**：写明被保护的结果或禁止结果、适用角色和前置、失败模式、由哪些验证层共同覆盖、每层能够证明的部分及仍不能证明的边界；不得写本轮通过数量。
- **权威依据**：优先指向权威要求或契约、关键实现 Symbol、直接断言所在的测试 Symbol；测试名称只有在断言确实对应要求时才可作为依据。
- **影响边界**：列出受该覆盖关系保护的入口、调用方、数据对象、权限范围、版本组合和回归套件，并明确不会由该证据证明的环境或系统行为。
- **复核入口**：给出从要求定位到测试的稳定检索方式、最小执行命令、关键前置和必须观察的断言；说明要求改变、消费者改变或测试层移除时如何重审。
- **变更规则**：首次形成稳定追溯关系为 `ADD`；要求、失败模式、覆盖层、关键断言或证据边界改变为 `UPDATE`；要求取消或最后一项有效覆盖能力消失为 `DELETE`；仅重跑且关系与四栏未变为 `NO_CHANGE`。
- **专属禁项**：不记录需求到所有测试用例的生成清单、覆盖率百分比快照、测试数量、单次验收矩阵、暂未实现的测试计划或用测试现状反推出来的伪需求。

## 事实类型：可重复检查入口与验证能力

- **入册条件**：仓库存在后续可稳定重复使用的检查入口，能够证明一类明确行为或结构，并且其调用方式、前置和输出语义不显然；普通 `test` 或 `build` 命令若无需额外知识即可发现，不单独入册。
- **主题合并键**：以“被验证能力 + 稳定执行入口”为合并键；同一入口的参数变体或平台包装合并记录，语义不同的检查能力分别建题。
- **当前事实写法**：写明入口解决的验证问题、适用范围、必要前置、输入或选择器、成功与失败信号、关键断言、运行成本及不可外推的结论。
- **权威依据**：指向测试入口函数、脚本、构建任务、CI job 定义、配置或测试框架注册位置；命令示例须能由这些仓库来源推导。
- **影响边界**：说明哪些模块、产品入口、平台、语言版本或测试层消费该能力，以及它不覆盖真实数据库、浏览器、设备、外部服务或生产环境中的哪些部分。
- **复核入口**：给出最小可重复命令、工作目录、必要参数、预期退出状态和关键输出模式；标明依赖版本、入口重命名或执行环境变化时的重审触发。
- **变更规则**：首次形成非显然且可复用的检查能力为 `ADD`；入口、参数、证明范围、关键断言或证据限制改变为 `UPDATE`；入口删除或已无消费者为 `DELETE`；内部重构但调用和证明语义均未变为 `NO_CHANGE`。
- **专属禁项**：不保存本轮完整命令日志、耗时排名、临时调试参数、某次退出码、所有测试入口清单或可直接由测试框架枚举的用例列表。

## 事实类型：验证环境、夹具与测试数据契约

- **入册条件**：特定环境、夹具、时钟、身份、数据集、模拟服务或隔离机制是重复获得可靠证据的必要条件，且缺失该知识会导致误测、污染、偶然通过或错误外推。
- **主题合并键**：以“验证场景族 + 共享环境或夹具契约”为合并键；同一夹具服务多个相关检查时合并，隔离方式或真实性等级不同则分别建题。
- **当前事实写法**：写明环境类型和版本、初始化与清理方式、身份和权限、代表性数据、时间随机网络控制、隔离边界、允许副作用及与真实目标环境的差异。
- **权威依据**：指向测试配置、fixture/factory、容器或服务定义、种子数据、隔离脚本、环境变量声明和清理钩子；秘密值只引用受控名称，不写实际值。
- **影响边界**：列出依赖该环境或夹具的测试套件、数据表、外部适配、并发场景和平台，同时说明内存替代、模拟器或假服务不能证明的真实行为。
- **复核入口**：给出从干净状态建立环境、运行代表性检查、确认隔离和清理的步骤与断言；环境版本、数据模型、夹具生命周期或外部依赖改变时重审。
- **变更规则**：首次形成稳定必要的环境契约为 `ADD`；版本、初始化、隔离、数据形态、真实性边界或清理机制变化为 `UPDATE`；夹具退役且无检查依赖为 `DELETE`；仅刷新一次性数据而契约不变为 `NO_CHANGE`。
- **专属禁项**：不记录连接密码、令牌、生产数据、可识别用户样本、一次性数据库快照、临时端口、个人机器路径或未清理的人工测试状态。

## 事实类型：接口、权限与数据完整性验证

- **入册条件**：API、消息、权限、事务、幂等、并发或数据不变量存在稳定且跨改动复用的验证策略，并由真实边界或目标数据引擎的可重复证据支撑。
- **主题合并键**：以“边界操作 + 被保护的不变量”为合并键；成功、拒绝、重复和并发场景若共同证明同一不变量则合并，不按端点或表字段机械拆题。
- **当前事实写法**：写明主体、前置数据、操作或消息、允许与拒绝结果、持久状态、副作用、重复并发行为、错误语义及验证所使用的真实边界层级。
- **权威依据**：指向契约 Schema、鉴权或事务实现、目标数据库迁移、集成测试和直接断言；ORM 模型、Mock 调用次数或内存数据库不得作为物理数据库行为的唯一依据。
- **影响边界**：列出调用方、角色与租户、端点或消息类型、数据对象、事务资源和适用数据库版本，并明确未覆盖的外部系统或生产负载。
- **复核入口**：给出代表性身份和数据准备、请求或并发触发方式、关键响应与持久断言、重复执行和清理方法；契约、权限政策、Schema 或事务边界改变时重审。
- **变更规则**：新增持续覆盖的边界不变量为 `ADD`；主体、操作、断言、数据引擎、并发模型或证据边界改变为 `UPDATE`；边界或验证资产消失为 `DELETE`；实现搬移但行为与检查均不变为 `NO_CHANGE`。
- **专属禁项**：不复制所有 API 用例、字段清单、数据库 Schema 全貌、攻击载荷、真实租户数据、单次迁移结果或只验证 Mock 行为的测试说明。

## 事实类型：浏览器交互与无障碍验证

- **入册条件**：用户旅程、可见状态、响应式行为、键盘焦点、辅助名称、缩放或真实渲染存在稳定的重复验证能力，并且构建、静态扫描或组件单测不足以证明该行为。
- **主题合并键**：以“角色任务 + 浏览器行为不变量”为合并键；同一旅程的视口、输入方式和状态变体合并描述，完全不同的用户任务分别建题。
- **当前事实写法**：写明入口、身份和数据、操作步骤、页面状态、可见结果、失败恢复、视口和输入方式、焦点或辅助技术断言、网络与控制台检查及证据限制。
- **权威依据**：指向路由或组件 Symbol、端到端或浏览器测试、可访问性断言、稳定选择器和必要浏览器配置；截图只能辅助定位，不能独立支撑行为事实。
- **影响边界**：列出适用浏览器、视口、设备能力、主题、语言、身份和数据状态，并说明未实际运行的平台、读屏器或设备不能被外推为通过。
- **复核入口**：给出从真实入口完成核心旅程和高价值失败路径的步骤、关键可见断言、焦点顺序、网络响应与控制台要求；路由、内容、状态或支持矩阵变化时重审。
- **变更规则**：首次形成稳定真实浏览器验证能力为 `ADD`；旅程、选择器策略、断言、浏览器矩阵、视口或证据边界变化为 `UPDATE`；能力移除或旅程退役为 `DELETE`；视觉实现调整而可观察契约和检查均未变为 `NO_CHANGE`。
- **专属禁项**：不保存单张截图、录屏链接清单、某次浏览器版本输出、像素差快照结果、仅自动扫描的“无障碍通过”结论或未实际执行的设备声明。

## 事实类型：性能、可靠性与兼容性验证

- **入册条件**：性能预算、容量边界、超时恢复、故障注入、版本兼容或资源约束具有稳定测试方法、明确负载模型和有依据的判断阈值，且后续改动会复用该验证契约。
- **主题合并键**：以“质量属性场景 + 受影响边界”为合并键；不同环境对同一场景的测量可合并并标出条件，刺激或结果不同则分别建题。
- **当前事实写法**：写明刺激、负载与数据规模、执行环境和资源、受影响边界、期望响应、阈值或基线、观察窗口、稳定性判据以及结论不可外推之处。
- **权威依据**：指向基准或负载脚本、故障注入工具、兼容矩阵配置、资源限制、指标定义和阈值来源；一次测量值不能单独成为稳定规则。
- **影响边界**：列出适用版本、实例规格、数据规模、并发、依赖状态和观察指标，并明确本地小样本、模拟依赖或短观察窗未覆盖的生产风险。
- **复核入口**：给出可重复负载或故障场景、预热与采样方法、关键指标和停止条件；阈值来源、资源、版本、数据增长或依赖拓扑变化时重审。
- **变更规则**：首次形成可重复质量属性验证契约为 `ADD`；负载、环境、阈值、指标、版本矩阵或证明边界改变为 `UPDATE`；场景或能力退役为 `DELETE`；仅新跑出数值而规则未改变为 `NO_CHANGE`。
- **专属禁项**：不记录孤立 benchmark 数值、一次告警、临时压测环境、无基线的精确承诺、供应商宣传、未授权生产压测或将本地结果外推为生产能力。

## 事实类型：缺陷复现与回归守卫

- **入册条件**：曾发生的缺陷揭示一个后续仍需保护的稳定失败模式，并已有最小、可重复且能在修复前失败、修复后通过的回归检查；缺陷时间线本身不入册。
- **主题合并键**：以“根因类别 + 被保护的不变量”为合并键；同一根因的多个表象合并记录，不按工单、日期或提交分别建题。
- **当前事实写法**：写明触发前置、最小输入、错误行为、应有行为、根因边界、回归断言和该检查无法覆盖的相邻失败模式，不叙述排查过程。
- **权威依据**：指向修复后的权威实现、最小回归测试及必要夹具；历史工单或提交只可辅助追溯，不能替代当前代码和测试。
- **影响边界**：列出受保护的入口、数据、调用方、版本与共享依赖，以及相同根因可能影响但尚未验证的路径。
- **复核入口**：给出执行最小回归检查及必要相关套件的方法、关键断言和失败诊断入口；根因实现、输入规范或消费者改变时重审。
- **变更规则**：稳定回归守卫首次形成时为 `ADD`；触发条件、根因边界、断言、夹具或影响范围改变为 `UPDATE`；风险彻底消失且守卫移除为 `DELETE`；测试搬移但保护语义与证据未变为 `UPDATE` 依据，其他均未变为 `NO_CHANGE`。
- **专属禁项**：不记录缺陷工单流水、责任人、修复过程、聊天记录、临时日志、旧代码片段、单次失败截图或没有当前回归检查的历史事故。

## 全局禁止内容

- 任务摘要、进度、待办、过程推理、前后对比、历史版本、提交说明和完整文件清单。
- 单轮通过或失败、覆盖率快照、命令流水、一次性制品、截图时间和临时环境状态。
- 未实现计划、外部资料、其他专业事实正文、密钥、令牌、用户数据、生产载荷和环境秘密。

Git、测试报告和 CI 记录承担历史；本册只索引当前仍成立、可重复使用且属于质量工程的事实。

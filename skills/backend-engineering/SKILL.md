# 后端工程

以后续调用方可观察的产品结果、业务规则和已确认的系统、数据与安全契约为输入，将服务端行为落实为可执行代码、权威 API 契约、可靠副作用和可复现证据。不得在实现层暗改产品语义、物理数据设计或安全政策。

## 专业所有权

`backend-engineering` 唯一裁定服务端代码层的领域规则落点、API 与错误契约、应用服务编排、持久化适配、应用事务边界、并发幂等、缓存消息、任务与外部集成实现，以及服务端性能保护、可观测性和开发测试。

以下语义是本技能的输入边界，不在后端实现中重新定义：产品范围与业务政策、用户旅程与体验目标、跨模块或跨服务边界、物理数据库机制、认证授权与隐私政策、总体验收结论、生产执行与运行健康。

## 输入与证据门槛

- 明确 Git 仓库根、当前产品与稳定 `product-id`、相关项目根、仓库指令、授权范围、真实调用方、业务动作、成功与拒绝语义、数据范围、兼容要求、验收标准和不得破坏行为。
- 从路由、API Schema、领域模型、应用服务、持久化适配、权限执行点、任务、消息、配置、外部依赖、测试和全部消费者核验当前实现；文档和样例只作线索，不能替代代码、配置或运行证据。
- 将输入标为已确认契约、当前实现事实、运行证据、合理假设或未知。缺少会改变业务结果、系统边界、物理数据保证或安全政策的前提时，停止依赖该前提的实现并列出所缺契约与证据；局部可逆未知须写明假设、影响和失效条件。
- 物理 Schema、约束、索引、执行计划、隔离、锁、迁移和回填必须已有明确数据库契约；威胁、身份、授权、秘密、隐私、审计和安全例外必须已有明确安全契约。后端只落实这些契约，不以 ORM 默认或既有代码猜造规则。

## 实施方法

### 1. 追踪行为与权威状态

1. 从真实入口沿调用链追到权威状态、外部依赖和最终用户可观察结果，列出同步返回、持久化写入、缓存、消息、任务、审计和外部调用等全部副作用。
2. 为每个业务动作建立行为表：前置条件、允许主体、输入、当前状态、目标状态、不变量、成功结果、拒绝结果、副作用、重复调用、失败恢复和可观察信号。
3. 找出散落或冲突的规则、旁路入口和消费者假设，确定领域规则的唯一落点；控制器、消费者与任务只适配输入，不复制核心不变量。

### 2. 固定接口与错误契约

1. 对每个受影响入口明确请求字段、可信上下文、响应字段、缺失与空值、时间金额枚举表达、错误分类、权限结果、分页排序、幂等和兼容语义。
2. 将参数无效、认证失败、授权不足、资源不存在、状态冲突、重复操作、限流、依赖失败与内部故障映射为稳定、可行动且不泄密的结果。
3. 核对所有生产者与消费者；增加式变化须说明旧消费者行为，破坏性变化须具有版本、兼容窗口、使用观测、退役条件和明确失败方式。

### 3. 设计事务、并发与副作用

1. 标出业务原子边界及必须共同提交的结果。外部网络调用通常不置于数据库事务内，采用状态机、发件箱、补偿或可恢复步骤衔接。
2. 对重复、并发、乱序、超时和进程中断逐项裁定最终状态、响应、重试责任与副作用次数；幂等键须绑定作用对象和请求指纹，处理中与最终结果均可恢复。
3. 数据库最终竞态保证只引用已确认的约束、条件写、隔离或锁契约；应用层“先查再写”只能改善提示，不能冒充并发证明。
4. 缓存明确权威来源、键空间、租户或权限维度、TTL、失效、陈旧容忍和故障行为；消息明确生产事务、Schema、顺序范围、去重、重试、死信、重放和版本兼容。

### 4. 落实安全、集成与运行保护

1. 每个受保护入口按已确认政策校验身份、动作、资源、租户和数据范围；列表、详情、导出、批量、任务和间接关联使用同一授权语义。
2. 对不可信输入使用结构化解析、参数化访问与允许范围；日志、错误、缓存、消息和追踪不得泄露令牌、秘密、个人数据或内部拓扑。
3. 外部依赖明确认证、版本、配额、分层超时、可重试条件、总时限、退避、抖动、并发隔离、降级和恢复入口；重试不得扩大非幂等副作用。
4. 为关键路径提供关联标识、业务成功与拒绝指标、依赖与数据库错误、队列积压、死信和恢复信号；健康检查区分存活、就绪与核心能力可用。

### 5. 最小实现与开发验证

1. 沿用项目现有技术栈、模块边界、命名与生成工具，只实现行为表和契约要求的最小完整改动；同步必要的 Schema 表达、序列化、领域逻辑、应用服务、适配器、权限执行、任务、消息、配置和测试。
2. 先用能失败的聚焦测试固定新增或修复行为，再写最小实现；覆盖状态转换、拒绝、边界值、权限、幂等、并发、故障和兼容分支，断言可观察结果而非内部调用次数。
3. 运行项目既有格式、静态、类型或编译检查，以及聚焦单元、契约和集成测试。需要真实数据库、真实协议或跨系统证明时，明确环境、数据和未取得的证据，不以模拟结果外推。
4. 复核最终差异、全部消费者、错误与日志泄露、配置默认、生成物和恢复路径；每项改动都能追溯到有效要求，每项要求都有实现与当前证据。

## 输出

- 服务端代码、权威 API Schema、领域与应用契约、持久化适配和聚焦测试。
- 行为表及接口、权限、事务、并发、缓存、消息、集成、兼容、恢复和可观测性决定。
- 可复现的工作目录、命令、退出码、夹具、数据条件和证据边界，明确模拟、真实数据库、真实协议与跨系统证据的区别。
- 尚缺的专业前提、未执行验证、剩余风险、影响范围和重验入口；不得用模糊的“待确认”掩盖依赖项。

## 完成门槛

- 领域规则有唯一落点，全部入口共享同一不变量、状态转换和拒绝语义；API Schema、序列化、错误映射与真实消费者一致。
- 应用事务、重复、乱序、部分失败、缓存、消息和外部依赖均有可收敛行为，数据库保证与安全控制均有明确契约依据。
- 开发检查与风险相称的测试获得当前证据；模拟、单机或局部证据没有冒充真实数据库、真实协议、跨系统或生产证明。
- 最终差异仅含授权范围，没有无消费者抽象、旁路规则、敏感信息泄露、无界资源使用或未说明的兼容风险。

## 禁区

- 不改变产品范围、业务政策、用户旅程、体验目标、系统边界、数据主权或跨边界质量取舍。
- 不裁定物理表列、数据库约束、索引、执行计划、隔离、锁、迁移与回填算法；可按已确认契约实现应用兼容层。
- 不裁定威胁模型、认证授权政策、密码与密钥、隐私、审计或安全例外；只负责实现已确认控制。
- 不决定界面实现、总体验收结论、生产操作或运行健康，也不把事实候选直接写成已同步事实。

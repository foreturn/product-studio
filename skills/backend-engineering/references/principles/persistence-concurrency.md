# 后端工程 · 数据一致性与并发

### 持久化与数据访问

- 持久化模型可以为存储效率服务，但与领域语义之间的转换必须显式，不能让延迟加载、级联或默认映射决定业务行为。
- 数据访问能力应围绕明确业务读取与状态保存，不得向上层开放任意查询和内部存储结构形成隐性耦合。
- 查询必须与真实过滤、关联、排序、数据规模和访问频率相匹配，功能正确不能掩盖无界读取与不可持续代价。
- 集合读取、批量改变和导出必须有边界并支持中断恢复，不能假设所有数据都可一次装入内存或在一个长事务中处理。
- 写入结果必须根据权威存储实际确认，调用无异常不能单独证明目标记录已创建、更新或保持唯一。
- 存储错误必须转换为稳定业务或系统语义，冲突、约束失败、暂态不可用和未知失败不能被统一重试或统一忽略。

### 事务边界与副作用

- 事务范围必须由需要共同成立的业务不变量决定，不能按请求、方法或技术层的表面边界任意扩大。
- 不受控网络与长时工作不能被视为本地原子提交的一部分，持有一致性资源等待外部结果会扩大锁定与故障范围。
- 本地状态与后续副作用之间必须存在可恢复的持久关系，进程在任意时点中断后都不能永久丢失必要动作或凭空重复结果。
- 提交、回滚和提交后动作的真实框架语义必须被验证，声明式配置或代码注解不能单独证明事务生效。
- 多资源改变无法原子完成时，必须显式保留部分完成状态、恢复方式和最终判据，不能以“尽力而为”冒充一致性保证。
- 补偿只能表达新的、业务允许的逆向效果，并保持可追踪与可重试，不能把外部已发生事实描述为物理回滚。

### 并发控制与幂等性

- 并发设计必须覆盖检查与写入之间的竞态、重复创建、丢失更新、顺序倒置和资源争用，单线程正确不能证明并发正确。
- 正确性必须在所有并发写入共同经过的权威仲裁点成立，进程内检查和“先查后写”不能承担跨实例保证。
- 冲突应产生可辨且可恢复的结果，后到执行不能默认覆盖较新事实，也不能把竞争失败伪装为资源不存在。
- 幂等身份必须绑定业务操作、作用域和请求语义，相同标识承载不同意图时必须拒绝，不能只按一个孤立字符串去重。
- 首次、处理中、成功和失败后的重复调用必须具有确定结果，进程重启与多实例执行不能改变幂等承诺。
- 锁定、租约或版本机制若被采用，必须处理超时、陈旧执行者和异常释放，机制存在本身不能证明旧执行不会覆盖新结果。
- 多层重试必须共享总预算并保持业务可安全重复，独立重试策略不能相互叠加放大流量与副作用。

### 缓存与读取一致性

- 缓存只能是可重建副本，权威来源与正确回源路径必须始终明确，缓存可用不能成为业务正确性的前提。
- 引入缓存必须有真实读取成本、延迟或容量证据，不能把缓存作为未经测量的默认优化或错误查询的遮蔽物。
- 缓存身份必须包含所有影响结果与隔离的维度，租户、用户、权限、参数或版本遗漏会构成错误数据共享。
- 新鲜度、写后可见、失效和重建必须与产品承诺一致，仅依赖时间过期不能解释所有一致性窗口。
- 并发回填、热点失效和缓存不可用不得形成无界回源，性能保护不能以返回无法判断新鲜度的错误结果为代价。
- 权限变化、身份退出、数据删除和敏感性变化必须作用于相关缓存副本，缓存生命周期不能脱离业务生命周期。

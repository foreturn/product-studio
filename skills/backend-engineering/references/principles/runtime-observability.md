# 后端工程 · 运行资源与可观测性

### 性能与资源保护

- 性能改变必须由真实瓶颈和代表性负载证据驱动，未经测量不能默认增加缓存、并行、批处理或新基础设施。
- 请求、集合、文件、批次、并发、排队和重试都必须有界，任何外部值都不能直接决定无限资源消耗。
- 优化应针对端到端临界路径，局部耗时改善若增加下游压力、内存占用或一致性风险，不能视为净收益。
- 并行度必须受实例资源和下游容量共同约束，待处理工作量不能直接转换为等量并发。
- 客户端取消、超时和依赖失败后，应停止无价值工作并释放资源，不能让失去消费者的任务持续占用关键能力。
- 性能证据必须同时说明负载、数据规模、环境、观察范围和正确性结果，平均值与单次峰值不能证明持续容量。

### 可观测性与审计

- 观测信号必须能回答哪个业务动作产生何种结果、失败发生在哪里、影响范围如何以及是否已经恢复。
- 请求、消息、后台工作和外部交互必须保持诊断关联，同时将追踪关联、业务身份和幂等身份作为不同语义处理。
- 日志、指标和追踪必须控制敏感信息、维度基数与成本，完整载荷和秘密不能以排障便利为由进入普通观测数据。
- 错误必须保留可定位根因与稳定分类，吞掉异常后只记录文本或只返回通用失败会同时破坏诊断和契约。
- 健康信号必须区分进程存在、可接收工作和关键业务可用，单一健康结果不能概括全部依赖与能力。
- 审计必须记录可信主体、业务动作、目标、结果和时间，且与普通调试日志区分；可修改日志不能承担不可抵赖证明。
- 告警必须对应明确影响与可执行恢复动作，高噪声而无处置条件的信号不能被视为有效监控。

# 后端工程 · 异步与外部集成

### 消息与后台工作

- 已发生事实、请求执行的动作和普通通知必须保持不同语义，发送或入队不能被表述为业务结果已经完成。
- 消息应携带稳定身份、业务关联、发生语义和版本信息，同时限制为消费者真正需要的事实，不能传递秘密或内部实体快照全集。
- 生产与业务状态改变之间必须具有可恢复关系，消费必须容忍重复；传输系统的交付声明不能替代端到端业务收敛。
- 重复、乱序、延迟、缺失和无法处理的消息必须各有可诊断结果与恢复入口，不能依赖理想到达顺序和无限重试。
- 后台工作必须具备持久状态、明确完成条件和可重入语义，进程内计时与临时内存不能承担关键业务进度。
- 长时工作必须有界、可暂停并可从已确认进度继续，重启不能迫使全部副作用从头执行。
- 积压、停滞、失败归宿和恢复进度必须可观察，只监控工作进程存活不能证明业务工作正在推进。

### 外部集成与调用韧性

- 外部协议、字段和失败必须被隔离为可转换机制，供应商模型不能传播为内部领域语义。
- 外部依赖应被视为延迟、限额和可用性均不可控，调用策略必须服从完整业务时间与资源预算。
- 只有可安全重复且具有恢复可能的失败才允许重试，结果未知的非幂等动作不能通过盲目再次调用消除不确定性。
- 外部成功响应、回调到达和内部业务完成必须分别判断，任何单点确认都不能跨越其实际证明范围。
- 回调与外来通知必须验证来源、时效、环境和重复语义，不能因来自已知网络地址便默认可信。
- 关键外部结果必须可查询、对账并支持受控修复，瞬时协议失败不能让业务永久停留在不可解释状态。
- 降级只能在保持核心正确性与安全性的前提下提供，伪造成功、静默丢弃或返回任意旧事实不构成韧性。

# 后端工程项目记忆

## 使用方式

项目事实位于 `docs/product-studio/<product-id>/backend-engineering.md`。

- 先根据用户范围、产品入口与元数据、相关项目根、目标代码和调用链唯一确认目标 Git 根与 `product-id`；`product-id` 必须在仓库内唯一、稳定，且是非 `.` 或 `..`、不含 `/` 或 `\` 的安全单级目录名。归属不唯一或名称不安全时不猜测或创建事实册。
- 开始相关工作前读取已有事实。
- 当前代码、配置和正式契约等权威信息与旧事实冲突时，以当前权威为准。
- 只按下列主题记住会持续影响后续判断且难从局部代码直接看清的项目不变量，不复制源码、配置或可生成清单。
- 核心认知改变时更新或移除旧内容，只保留当前仍成立的事实。
- 不记录秘密、用户数据、任务过程和一次性结果。

## 核心记忆

### 领域保证

- 记住服务端实际维护的领域不变量、关键状态变化、拒绝规则和人工处置边界。
- 记住哪些保证由本服务负责，哪些必须依赖其他系统或人工流程完成。

### API、错误与信任

- 记住真实消费者依赖的 API 契约、身份与租户边界、权限判断位置和兼容约束。
- 记住业务失败与系统失败的稳定分类、对外表达，以及调用方必须据此采取的处理方式。

### 事务、副作用、并发与幂等

- 记住关键操作的原子边界、跨资源副作用顺序，以及失败后哪些状态可能已经生效。
- 记住并发冲突的裁决方式、幂等身份、重复请求处理和补偿责任。

### 消息与后台任务

- 记住消息或任务的业务触发、生产者、消费者、关键载荷含义和调度时间含义。
- 记住交付、顺序、去重、重试、失败去向和人工补偿中项目实际提供的保证。

### 缓存与一致性

- 记住各缓存视图的权威来源、隔离范围、填充与失效关系，以及允许陈旧的边界。
- 记住并发填充、缓存不可用和失效失败时对业务读取与写入的既定处理。

### 外部集成与资源保护

- 记住外部系统承担的业务能力、双方标识对应关系、协议限制和失败转换。
- 记住超时、重试、限流、熔断、回调校验、资源上限、降级和补偿的项目约束。

### 观测与诊断

- 记住关键业务路径的关联标识、稳定信号含义、故障分类和敏感信息处理规则。
- 记住健康与就绪信号实际证明的范围，以及诊断某类问题应从何种信号开始。

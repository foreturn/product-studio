`backend-engineering` 是服务端应用实现事实的唯一语义 Owner。稳定 locator 为 `<Git仓库根>/docs/product-studio/<product-id>/backend.md`，技能或目录改名不改变该位置。本册表达当前仍成立、后续服务端编码需要复用的实现语义，不复制产品政策、系统架构、物理数据库设计、安全政策或发布记录。

## 产品定位与事实实例

- `product-id` 在同一 Git 仓库内必须唯一、稳定且可安全作为单级目录名。
- 依据用户范围、仓库原生产品身份、入口与元数据、相关项目根、服务端代码及实际消费关系共同确认，不从目录名机械推导。
- 多产品仓库逐产品隔离；归属不能唯一确认时，不读取或写入候选事实册，也不创建目录。
- 首次出现有效 `ADD` 时同次创建产品目录和 `backend.md`；最后一个主题被 `DELETE` 后移除该册，产品目录没有其他事实文件时才移除空目录。

## 统一主题格式

每个主题使用简短业务语义命名，不含类型前缀、路径、日期、任务号或变更动作。一个主题只表达一组共同检索、共同变化的事实。

```markdown
# backend-engineering 当前产品事实

## <稳定事实主题>

- **当前事实**：<必要条件、当前服务端行为、结果与明确边界>
- **权威依据**：<一至三个仓库相对路径#精确 Route、Symbol、契约、配置键或协议位置>
- **影响边界**：<直接调用方、服务、任务、消息、数据对象、外部系统、不得破坏关系与明确不适用处；无则写“无”>
- **复核入口**：<可重复测试、脚本、命令或检查入口，含关键断言、适用环境、未覆盖边界与重审触发>
```

四栏只陈述当前语义。权威路径必须存在且位置可定位；复核入口必须说明能证明什么及不能证明什么。只读任务或未获文件写入授权时，只报告候选主题、动作与证据，不修改事实册。写入必须由当前代码、配置或权威契约和风险相称的可重复验证共同支撑；不得以计划、进行中实现、临时通过或推断替代当前证据。只修改发生实质变化的主题，不顺带排序、润色或改写无关内容。

## 事实类型：领域状态不变量

- **入册条件**：服务端当前强制执行某个领域对象的合法状态、转换前置、转换结果或跨入口一致规则；该规则不是单个控制器的偶然分支，且后续命令处理、接口、任务或事件消费者需要共同遵守。
- **主题合并键**：以“领域对象 + 不变量或转换族 + 适用业务边界”合并；同一对象在多个入口执行相同状态语义时写成一个主题，不按方法、端点或枚举值拆分。
- **当前事实写法**：写明对象在何种前置状态和业务条件下允许或拒绝何种转换、成功后的可观察状态、重复或非法动作的当前结果，以及明确不适用的对象或路径。
- **权威依据**：优先引用聚合根、领域服务、命令处理器、状态机、业务校验器及覆盖该不变量的测试 Symbol；DTO、页面文案或数据库枚举不能单独作为依据。
- **影响边界**：列出直接发起转换的 API、后台任务、事件处理器、批处理、管理入口及依赖该状态的下游读取者；说明仅由数据库约束保证或仅属产品政策的部分不在本类。
- **复核入口**：使用领域单元测试、应用集成测试或可重复命令覆盖合法转换、非法前置、重复动作和适用的边界状态，并注明未覆盖的跨进程或真实数据库条件。
- **变更规则**：`ADD` 用于发现当前已强制且尚无同义主题的不变量；`UPDATE` 用于前置、允许转换、拒绝结果、适用对象、依据或复核边界改变；`DELETE` 用于服务端不再执行该不变量或最后消费者消失；`NO_CHANGE` 用于重构路径或新增测试但四栏语义均未变化。
- **专属禁项**：不记录领域对象或状态枚举全量清单，不复制产品层资格政策，不把尚未执行的目标状态机、迁移中旧语义或物理外键与检查约束写成本类事实。

## 事实类型：API 与错误契约

- **入册条件**：当前对外或跨模块调用面存在稳定的请求、响应、鉴权上下文、分页、错误分类或兼容语义，且调用方需要据此编码；纯内部私有方法签名不入册。
- **主题合并键**：以“契约面 + 业务操作族 + 版本或兼容范围”合并；同一资源的一组共同演进操作可同题，不按每个字段、状态码或 Controller 方法机械拆分。
- **当前事实写法**：写明入口协议与版本、关键输入前置、成功结果、业务拒绝与系统失败的外部可见映射、兼容保证及明确不支持的调用方式。
- **权威依据**：优先引用 OpenAPI／IDL、Route、请求响应类型、异常映射器、序列化配置和契约测试；实现注释、客户端猜测或单次抓包不能独立作为依据。
- **影响边界**：列出前端、移动端、内部服务、合作方、SDK、Webhook 或批处理调用者，说明版本、租户、身份、内容类型和部署边界。
- **复核入口**：执行契约测试、Controller 集成测试或协议级请求，断言关键字段、状态码、错误体、序列化、鉴权上下文与兼容场景，并标注未验证的真实网关或外部调用方。
- **变更规则**：`ADD` 用于新增已实现且有真实消费者的稳定契约面；`UPDATE` 用于请求响应语义、错误映射、版本兼容、依据或消费者边界改变；`DELETE` 用于契约面下线且消费者与兼容义务已消失；`NO_CHANGE` 用于内部实现替换而外部四栏契约不变。
- **专属禁项**：不抄录完整 OpenAPI 或 DTO 字段表，不把产品业务政策、安全策略或前端提示文案写入本类，不记录临时调试端点、未发布候选版本或一次请求样本。

## 事实类型：应用事务与副作用

- **入册条件**：一个当前应用用例对多个仓储、审计、文件、通知、事件或外部动作具有稳定的提交、回滚、补偿或先后约束，失败处理会影响业务可观察结果。
- **主题合并键**：以“应用用例 + 原子提交边界 + 副作用集合”合并；同一用例内共享提交命运的写入归一题，独立最终一致副作用按不同保证拆分。
- **当前事实写法**：写明事务起止边界、必须原子完成的状态、事务内外副作用、失败与重试结果、补偿责任和不受该事务覆盖的动作。
- **权威依据**：优先引用应用服务或命令处理器、事务声明、Unit of Work、仓储调用、Outbox／补偿实现及事务集成测试；框架默认行为需有实际配置或测试支撑。
- **影响边界**：列出被修改的领域对象、审计记录、文件、消息、通知、外部系统与直接调用方，并说明本地事务、跨资源和跨服务边界。
- **复核入口**：以故障注入或集成测试验证成功提交、关键步骤失败回滚、事务外副作用、重复执行与补偿结果；真实数据库或外部系统未覆盖时明确标注。
- **变更规则**：`ADD` 用于当前已有稳定原子性或补偿保证但册中缺失；`UPDATE` 用于事务范围、副作用集合、失败语义、补偿责任、依据或复核条件改变；`DELETE` 用于用例或该保证消失；`NO_CHANGE` 用于事务实现搬移但提交命运与四栏不变。
- **专属禁项**：不记录框架事务教程、每次数据库写入清单、物理隔离级别设计、未实施 Saga 方案、迁移步骤或仅由执行次序偶然形成且未经保证的行为。

## 事实类型：并发与幂等

- **入册条件**：当前服务端对重复请求、并行命令、竞态更新、去重、版本冲突或锁竞争提供明确收敛结果，且错误实现会造成重复副作用、丢失更新或状态分叉。
- **主题合并键**：以“业务操作 + 幂等或竞争键 + 收敛保证”合并；同一操作共享去重键与结果语义时合并，不按锁类、表或重试分支拆分。
- **当前事实写法**：写明竞争主体、唯一或版本键、首次与重复执行结果、并发冲突语义、重试条件、保证窗口及保证之外的边界。
- **权威依据**：优先引用幂等服务、命令处理器、版本检查、去重仓储、锁适配、唯一冲突映射及并发测试；数据库约束可作执行依据，但物理设计正文仍归数据库事实。
- **影响边界**：列出可能重试或并行调用的 API、消息消费者、定时任务、外部回调及产生的领域状态、副作用和调用方可见结果。
- **复核入口**：执行受控并发、重复投递、冲突重试和超时后重入测试，断言最终状态、副作用次数、返回结果与保证窗口，并注明单进程替身和真实集群差异。
- **变更规则**：`ADD` 用于当前存在可复用的并发收敛保证；`UPDATE` 用于键、窗口、冲突结果、重试策略、适用入口、证据或边界改变；`DELETE` 用于保证或最后竞争场景消失；`NO_CHANGE` 用于内部锁或仓储替换但外部收敛语义不变。
- **专属禁项**：不把“线程安全”空泛结论、锁实现清单、压测瞬时结果、尚未验证的分布式假设或数据库隔离设计目标写入本类。

## 事实类型：事件、任务与消息

- **入册条件**：当前服务端稳定发布、消费或调度某类事件、消息或任务，并对载荷语义、触发时机、去重、重试、顺序、失败去向或责任边界作出实现保证。
- **主题合并键**：以“消息或任务语义 + 发布者／消费者责任 + 交付保证”合并；同一业务事件的多个技术 topic 若语义和生命周期相同可合并，不按处理函数拆分。
- **当前事实写法**：写明触发条件、载荷关键语义、发布或调度时机、消费者责任、交付与顺序保证、重试／死信／补偿结果及不保证事项。
- **权威依据**：优先引用事件类型或 Schema、发布器、消费者、调度配置、重试与死信配置、Outbox 及消息集成测试；队列控制台截图不能单独作为依据。
- **影响边界**：列出发布服务、消费服务、后台任务、外部订阅者、相关领域对象、时区／调度范围和重复副作用风险。
- **复核入口**：使用消息或调度集成测试验证发布条件、载荷、重复投递、失败重试、死信或补偿和适用顺序；未连接真实 broker、时钟或多实例时明确限制。
- **变更规则**：`ADD` 用于新增已运行且有稳定消费者的消息或任务保证；`UPDATE` 用于触发、载荷语义、交付、重试、调度、消费者、依据或复核边界改变；`DELETE` 用于生产与消费责任均已消失；`NO_CHANGE` 用于 topic、类名或框架搬移但业务语义与保证不变。
- **专属禁项**：不抄录 topic、队列、任务或消息字段全量清单，不记录一次积压、临时重放、运维流水、候选事件设计或仅在测试替身中存在的行为。

## 事实类型：缓存一致性

- **入册条件**：当前缓存参与业务读取、资格判断、聚合结果或高价值性能路径，并具有稳定的键作用域、数据来源、填充、失效和容忍陈旧策略。
- **主题合并键**：以“被缓存业务视图 + 一致性范围 + 失效策略”合并；共享数据源与失效命运的键族写成一个主题，不按每个缓存键拆分。
- **当前事实写法**：写明缓存对象、权威源、键与租户作用域、读写模式、失效触发、TTL 或版本语义、允许陈旧窗口、穿透或失败时行为及明确不缓存内容。
- **权威依据**：优先引用缓存适配器、键构造器、读写服务、失效监听、配置键和一致性测试；运行指标只能补充使用证据，不能替代实现依据。
- **影响边界**：列出读取路径、写入路径、租户或用户隔离、相关任务与事件、下游消费者及缓存不可用或陈旧时的用户结果。
- **复核入口**：测试命中、未命中、写后失效、过期、并发填充、租户隔离和缓存故障降级，断言权威源与允许陈旧边界；真实集群传播未验证时注明。
- **变更规则**：`ADD` 用于当前稳定缓存语义首次具备复用价值；`UPDATE` 用于键作用域、权威源、TTL、失效、降级、消费者、依据或复核条件改变；`DELETE` 用于缓存路径或最后消费者消失；`NO_CHANGE` 用于缓存产品或客户端替换但一致性四栏不变。
- **专属禁项**：不记录缓存键全量清单、瞬时命中率、容量快照、秘密值、未来缓存计划或把缓存当作权威数据源的错误描述。

## 事实类型：外部集成

- **入册条件**：当前服务端调用或接收外部系统，并对协议、身份关联、超时、重试、限流、错误转换、回调校验或降级结果提供稳定实现语义。
- **主题合并键**：以“外部系统 + 业务能力 + 协议或版本边界”合并；同一能力共享认证、错误和生命周期时合并，不按每个 HTTP 方法拆分。
- **当前事实写法**：写明调用方向、业务用途、协议与版本、关键标识映射、成功与失败转换、超时重试、限流或熔断、回调／对账责任及明确不支持能力。
- **权威依据**：优先引用集成 Adapter、协议 DTO／Schema、客户端配置、签名或回调验证调用点、错误映射和契约测试；外部文档只能作为补充，秘密值不得入册。
- **影响边界**：列出内部用例、外部供应方或合作方、租户与地区、网络和环境边界、数据对象、人工补偿及受外部可用性影响的结果。
- **复核入口**：使用协议契约测试、受控沙箱或可重复 stub 验证成功、业务拒绝、超时、限流、重试、重复回调和错误转换，并区分模拟证据与真实外部环境证明。
- **变更规则**：`ADD` 用于当前已有真实消费者的稳定集成能力；`UPDATE` 用于协议版本、标识映射、失败语义、韧性策略、适用环境、依据或复核边界改变；`DELETE` 用于集成与兼容责任消失；`NO_CHANGE` 用于客户端库升级但外部契约和运行边界不变。
- **专属禁项**：不写访问密钥、令牌、证书内容、生产地址中的秘密参数、外部文档全文、一次故障流水、商务约定或尚未接通的候选供应方。

## 事实类型：服务端性能与可观测性

- **入册条件**：当前服务端对高价值路径具有稳定的性能边界、容量控制、资源保护、结构化日志、指标、追踪或告警信号，且这些实现语义会影响后续编码与故障诊断。
- **主题合并键**：以“业务路径或资源 + 性能／观测目标 + 适用运行边界”合并；共同采样、阈值和诊断目的的信号可同题，不按每条日志或指标名拆分。
- **当前事实写法**：写明受保护路径、已实现的超时／分页／批量／背压或资源上限、关键观测信号、关联标识、敏感信息处理、适用负载环境及事实不覆盖的容量承诺。
- **权威依据**：优先引用性能相关配置与代码、日志／指标／追踪埋点、查询或批处理实现、基准与负载测试；监控截图和一次测量只能作辅助证据。
- **影响边界**：列出入口、下游依赖、数据规模、部署拓扑、租户、后台任务、告警消费者和受资源保护影响的调用方。
- **复核入口**：运行可重复基准、负载或聚焦测试并检查日志、指标与追踪断言，说明硬件、数据量、并发、采样、环境差异和未验证的生产容量。
- **变更规则**：`ADD` 用于当前已有稳定性能机制或诊断契约且后续编码会复用；`UPDATE` 用于限制、信号、关联方式、敏感信息处理、适用负载、依据或复核环境改变；`DELETE` 用于机制与消费者消失；`NO_CHANGE` 用于工具或埋点位置搬移但行为与四栏不变。
- **专属禁项**：不记录单次耗时、临时告警、日志全文、仪表盘清单、制品时间戳、未经基线支撑的目标数字、生产秘密或把本地基准冒充生产容量证明。

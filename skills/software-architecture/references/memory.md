## 共同定位与写入契约

- **Owner**：`software-architecture` 唯一裁决架构事实的主题、四栏语义与 `ADD / UPDATE / DELETE / NO_CHANGE`；其他专业可以引用，不复制正文或改写其结论。
- **Locator**：`<Git仓库根>/docs/product-studio/<product-id>/architecture.md`。该路径是稳定检索入口，技能名称或目录调整不得导致迁移。
- **product-id**：必须由用户范围、仓库原生产品身份、运行入口、部署单元、代码与调用链共同确认；须在仓库内唯一、稳定并可安全作为单级目录名，不得仅取项目目录名。多产品仓库按产品隔离，归属不唯一时不得写入。
- **当前证据**：只有当前实现、配置、契约、部署描述和相称验证共同证实的现行架构语义可以入册。候选设计、过往状态、任务过程与推测不得写成当前事实。
- **写权限**：只有取得本轮事实册写权限时方可修改文件；只读分析仅形成候选主题与证据，不得创建目录、空册或改动既有内容。
- **主题粒度**：一个主题承载一个会被共同检索、共同变化的稳定架构语义；不得按任务、提交、文件、ADR 或测试机械拆分。

## 统一实例格式

```markdown
# software-architecture 当前产品事实

## <稳定事实主题>

- **当前事实**：<当前执行的架构语义及成立条件>
- **权威依据**：<一至三个 `仓库相对路径#精确位置`>
- **影响边界**：<消费者、上下游、数据对象、部署单元、外部系统及明确不适用处；无则写“无”>
- **复核入口**：<可重复的测试、脚本、命令、运行信号、关键断言与重审触发>
```

四栏必须同时存在。主题或任一栏改变均按对应事实类型的变更规则处理；事实删除时保留删除依据于当次裁决结果，不在事实册中遗留历史占位。

## 事实类型：边界、职责与依赖

- **入册条件**：代码组织、进程或部署拓扑已执行某一稳定系统边界，并明确该边界承担的职责、公开入口及允许依赖方向；该关系预计会约束后续实现。
- **主题合并键**：以“边界主体 + 核心职责 + 依赖方向”合并；同一边界的入口、调用者和禁止反向依赖写入同一主题，不按模块文件逐项拆分。
- **当前事实写法**：写明边界名称、拥有职责、公开能力、允许依赖对象、禁止穿透方式及成立条件；不得只写“采用分层架构”一类空泛标签。
- **权威依据**：优先引用模块清单、构建依赖、服务启动入口、公开接口定义、依赖规则测试或部署配置的精确位置；架构图只有与现行实现一致时才可辅助引用。
- **影响边界**：列出直接消费者、被依赖边界、部署单元、共享运行资源及明确不受该边界约束的代码区域。
- **复核入口**：提供依赖规则测试、构建图检查、模块可见性检查、服务启动验证或公开入口契约检查，并注明新增依赖、拆分或合并边界时重审。
- **变更规则**：`ADD` 用于出现新的稳定边界或依赖不变量；`UPDATE` 用于职责、公开入口、依赖方向、依据或影响范围改变；`DELETE` 用于边界或最后一个约束性消费者消失；四栏均未改变则 `NO_CHANGE`。
- **专属禁项**：不记录类级调用流水、临时文件布局、单个 API 字段或纯命名约定；具体接口实现属于相应工程实现事实，而非架构边界事实。

## 事实类型：数据主权与共享不变量

- **入册条件**：某边界已成为特定数据对象的唯一权威写入者，或多个边界已执行必须共同维持的标识、版本、顺序、一致性或生命周期不变量。
- **主题合并键**：以“数据对象 + 权威边界 + 共享不变量”合并；同一对象的读副本、写入口、同步方向和一致性约束属于同一主题。
- **当前事实写法**：写明数据对象、权威来源、允许写入者、只读副本或派生视图、跨边界共享字段及必须维持的不变量；明确最终一致或强一致等成立条件。
- **权威依据**：引用权威模型或契约、写入入口、事件 Schema、同步配置、唯一写入约束和覆盖主从关系的测试；物理表结构仅作为主权落点证据，不替代主权语义。
- **影响边界**：列出生产者、消费者、缓存或副本、同步作业、外部系统以及数据延迟、回放或重建会触及的范围。
- **复核入口**：提供写入路径检查、契约兼容测试、重复或乱序事件测试、对账脚本、重建验证，并在新增写入者、数据复制或所有权迁移时重审。
- **变更规则**：`ADD` 用于确立新的权威对象或共享不变量；`UPDATE` 用于权威边界、允许写入者、一致性条件、证据或消费者改变；`DELETE` 用于该数据对象或共享约束不再存在；无语义和四栏变化则 `NO_CHANGE`。
- **专属禁项**：不记录列类型、索引、锁语句或数据库迁移步骤；这些属于数据库物理事实。不得将缓存快照或单次同步结果写成数据主权。

## 事实类型：跨边界交互与兼容

- **入册条件**：两个或更多边界已通过同步接口、异步消息、文件交换或外部协议形成稳定交互，并存在调用方向、超时、幂等、顺序、版本或兼容约束。
- **主题合并键**：以“生产边界 + 消费边界 + 交互契约族”合并；同一契约族的请求、响应、事件和兼容条件写在同一主题，独立生命周期的协议另立主题。
- **当前事实写法**：写明交互方向、传输形态、契约标识、关键时序、超时与重试语义、幂等键、版本策略及向前或向后兼容条件。
- **权威依据**：引用 OpenAPI/IDL/事件 Schema、生产与消费入口、序列化配置、兼容性测试、消息主题配置或网关路由；只引用文档而无实现落点不足以入册。
- **影响边界**：列出生产者、消费者、中间件、外部依赖、重试与死信路径，以及旧版本或离线消费者的适用边界。
- **复核入口**：提供契约测试、兼容性检查、幂等重放、乱序或重复消息测试、超时与重试验证；协议版本、消费者集合或中间件语义改变时重审。
- **变更规则**：`ADD` 用于新增稳定交互契约；`UPDATE` 用于方向、协议、时序、兼容策略、依据或消费者变化；`DELETE` 用于交互契约及其最后消费者移除；四栏无变化则 `NO_CHANGE`。
- **专属禁项**：不抄录完整字段清单、单个状态码或客户端实现细节；字段级业务契约归相应接口事实，架构册只保留跨边界语义与兼容不变量。

## 事实类型：系统质量约束

- **入册条件**：系统已通过实现、配置和测量执行跨越多个组件的性能、可用性、扩展性、一致性、可维护性或成本约束，且该约束会影响架构决策。
- **主题合并键**：以“质量属性 + 受约束场景 + 度量口径”合并；同一场景的目标、容量假设、测量入口和降级阈值属于同一主题。
- **当前事实写法**：写明质量属性、业务场景、量化目标或硬性不变量、负载与环境前提、测量口径及不适用范围；不得以“高性能”“高可用”替代可核验约束。
- **权威依据**：引用容量或性能配置、限额、SLO 定义、基准脚本、负载测试、架构级断言或生产等价环境结果；临时本机数字不得外推为系统能力。
- **影响边界**：列出关键路径、部署单元、共享资源、地域或租户范围、受约束消费者以及超出容量假设后的行为。
- **复核入口**：提供可重复基准、负载或故障测试命令、指标查询和关键阈值；流量模型、资源规格、拓扑或度量口径改变时重审。
- **变更规则**：`ADD` 用于形成新的已执行系统级质量约束；`UPDATE` 用于目标、前提、度量口径、依据或影响范围改变；`DELETE` 用于约束或对应场景消失；当前四栏一致则 `NO_CHANGE`。
- **专属禁项**：不记录愿景式非功能需求、未执行容量目标、一次性跑分或单组件微优化；验证结果只作为依据，不替代当前架构约束。

## 事实类型：故障、降级与恢复

- **入册条件**：系统已实现对依赖失败、超时、资源耗尽、数据损坏或部分不可用的稳定检测、隔离、降级、重试、补偿或恢复机制。
- **主题合并键**：以“故障域 + 受影响能力 + 恢复策略”合并；同一故障域下的检测信号、降级行为、恢复顺序和数据处置写入同一主题。
- **当前事实写法**：写明故障来源、检测条件、隔离边界、用户或系统可见降级、重试与补偿限制、恢复顺序、数据一致性后果及不可自动恢复条件。
- **权威依据**：引用超时或熔断配置、错误处理入口、队列与死信策略、恢复脚本、状态机、故障注入测试或演练结果；仅有操作手册而无执行落点不得视为已实现机制。
- **影响边界**：列出故障传播路径、受降级功能、数据对象、人工介入点、外部依赖和恢复期间明确保持可用的能力。
- **复核入口**：提供故障注入、依赖断连、超时、资源耗尽、重放或恢复演练入口及关键断言；依赖、拓扑、状态存储或恢复目标变化时重审。
- **变更规则**：`ADD` 用于新增稳定故障处置机制；`UPDATE` 用于检测、隔离、降级、恢复步骤、证据或影响边界改变；`DELETE` 用于故障场景或处置机制彻底移除；无四栏变化则 `NO_CHANGE`。
- **专属禁项**：不记录事故时间线、临时处置命令、待修复缺陷或未演练恢复承诺；数据库备份与复制细节归数据库恢复事实。

## 事实类型：信任边界与可运行性

- **入册条件**：部署拓扑已形成稳定信任分区、网络或进程隔离、身份传播边界，或系统已依赖明确的启动顺序、配置来源、健康语义与观测入口才能安全运行。
- **主题合并键**：以“部署或信任分区 + 跨界入口 + 运行不变量”合并；同一区域的身份传播、网络入口、启动依赖和健康条件可共同表述，独立部署生命周期另立主题。
- **当前事实写法**：写明信任区域、跨界入口、主体或凭据传播方式、部署单元、必需依赖、配置来源、启动与健康条件及失效时行为；只描述拓扑和运行不变量，不制定安全政策细节。
- **权威依据**：引用部署清单、网络策略、服务发现、身份代理配置、启动入口、健康检查、配置装载和拓扑验证；示意图须与这些现行配置相互印证。
- **影响边界**：列出信任区内外主体、暴露端口、身份链、部署环境、运维入口、共享基础设施及不适用环境。
- **复核入口**：提供部署渲染、网络可达性、身份传播、冷启动、依赖缺失、健康与就绪检查；部署拓扑、身份链、配置来源或启动依赖改变时重审。
- **变更规则**：`ADD` 用于形成新的信任分区或运行不变量；`UPDATE` 用于跨界入口、身份传播、部署依赖、健康语义、依据或影响范围改变；`DELETE` 用于分区或运行约束消失；四栏一致则 `NO_CHANGE`。
- **专属禁项**：不记录秘密值、环境连接串、具体漏洞、授权矩阵或发布执行记录；安全控制政策属于安全事实，环境操作历史不属于当前架构事实。

## 事实类型：演进与兼容条件

- **入册条件**：系统已执行支持边界拆分合并、协议或数据版本并存、滚动升级、旧消费者兼容或可逆演进的稳定条件，并对未来修改构成硬约束。
- **主题合并键**：以“被演进对象 + 并存范围 + 兼容不变量”合并；同一对象的版本窗口、读写顺序、回退条件和淘汰触发属于同一主题。
- **当前事实写法**：写明演进对象、当前与兼容版本、允许并存窗口、读写或部署顺序、不变量、回退前提和结束兼容的客观条件；不得写任务计划或预计日期。
- **权威依据**：引用版本协商、兼容适配器、双读双写实现、特性开关、部署策略、兼容测试或回退验证；仅有 ADR 意向不能证明当前兼容能力。
- **影响边界**：列出新旧生产者与消费者、数据版本、部署批次、外部集成、回退路径及不受该兼容窗口覆盖的版本。
- **复核入口**：提供混合版本契约测试、滚动升级、回退、旧数据读取或旧消费者验证；版本窗口、消费者集合、特性开关或回退能力变化时重审。
- **变更规则**：`ADD` 用于建立新的当前演进兼容条件；`UPDATE` 用于版本窗口、顺序、不变量、回退前提、证据或影响范围改变；`DELETE` 用于兼容窗口关闭且相关适配完全移除；四栏未变则 `NO_CHANGE`。
- **专属禁项**：不记录路线图、里程碑、迁移进度、历史版本叙事或“将来可能”采用的抽象；数据库迁移步骤及回填机制属于数据库事实。

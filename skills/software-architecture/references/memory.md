# software-architecture 当前产品事实规则

## 所有权与稳定位置

- `software-architecture` 是当前产品跨模块、跨进程与跨运行单元结构语义的唯一 Owner；其他专业只引用影响，不复制本册正文。
- 跨运行单元的故障域、传播关系、状态位置和恢复责任分配归本册；平台提供的检测、隔离、接管、切回、运行册与事故治理机制归 `platform-engineering`，两册通过权威引用连接而不复制正文。
- 稳定位置为 `docs/product-studio/<product-id>/software-architecture.md`；`product-id` 由产品身份、真实入口、运行边界与消费关系共同确认，不从目录名机械推导。
- 多产品仓库逐产品分册；产品、边界或 Owner 不能唯一确认时，不读取候选册作为依据，也不创建或修改事实册。
- 本册只索引当前终态的结构语义、成立条件、保证与限制，不保存源码清单、实现摘要、过程、计划、迁移进度、运行快照或一次证据。
- 长期兼容只记当前支持不变量、现存消费者、兼容保证、不可逆限制与退出触发，不记中间态或目标架构。
- 只在本轮拥有事实文件写权限时落盘；只读任务仅报告候选动作与复核依据。

## 事实类型索引

1. 系统职责与边界
2. 模块依赖与稳定契约
3. 数据权威与一致性
4. 跨边界交互
5. 运行拓扑、故障与恢复
6. 质量权衡、演进与守卫

## 通用入册门禁

- **当前终态**：候选语义已由当前实现与相称验证共同证明，且在交付终态真实成立，不是计划、推断或未完成工作。
- **稳定**：候选语义预计跨越本次任务持续成立；实现过程、迁移进度、运行快照与一次证据不得入册。
- **非显然**：候选语义不能从命名、目录、框架默认或单一声明直接、低成本推导。
- **决策相关**：候选语义会实质改变后续边界、依赖、数据、交互、运行或质量判断。
- **重查昂贵**：未来重新发现该语义需要跨多处实现、配置、调用链或可重复验证。
- **唯一 Owner**：Git 根、产品、`product-id`、主题合并键及 `software-architecture` 所有权均已唯一确认，且他册无重复正文。
- **权威复核**：当前权威实现或配置有稳定定位，并可重复复核语义、条件、保证、限制与失败边界。
- **安全**：内容已最小化并脱敏，不含秘密、密钥、凭据、令牌、个人或生产数据及可利用的内部细节。

任一门禁不成立即不落册；证据、归属或授权不足时只在本轮报告。候选事实与既有主题冲突时，先沿当前权威来源复核，不并存互斥描述。

## 主题表达规则

- 主题以稳定架构语义命名，不含路径、日期、任务号、动作或事实类型前缀；同一合并键只保留一个当前主题。
- 每个主题必须表达当前事实、权威依据、影响范围与复核方式，并写清成立条件、保证、消费者、明确限制、证据边界和重审触发。
- 不规定固定 Markdown H2、固定四栏、固定字段标签或统一字段顺序；可依事实类型与可读性使用段落、列表或表格。
- 表达应便于沿权威入口复核和原位合并，不按文件、Symbol、部署实例或一次验证机械拆题。
- 不收录源码清单、修改摘要、过程记录、迁移状态、运行观测原文、时间线或待办。

## 动作语义

- `ADD`：主题合并键尚不存在，候选终态语义通过全部入册门禁且必备语义完整；新增一个当前主题。
- `UPDATE`：同一主题的当前事实、权威依据、影响范围或复核方式实质变化，且新语义通过全部门禁；原位保留唯一当前表述。
- `DELETE`：主题所述结构语义、保证或最后消费者已从当前产品消失；删除完整主题，不留历史占位。
- `NO_CHANGE`：沿权威依据完整复核后必备语义均无实质变化；不得因改写表达、调整顺序或更换呈现方式触碰事实文件。

## 事实类型

### 系统职责与边界

- **入册条件**：当前系统或子系统承担稳定且非显然的责任，并以明确外部参与者、输入输出或控制边界约束后续结构判断。
- **主题合并键**：以“系统边界 + 核心责任 + 消费关系”合并；共同变化的负责与不负责事项归入同题。
- **当前事实写法**：写明系统负责与不负责的能力、边界内外参与者、关键输入输出、成立条件、保证与明确限制。
- **权威依据**：定位真实入口、组合根、调用链、部署配置与边界验证；图和文档只能辅助定位当前实现。
- **影响边界**：列出相关系统、模块、运行单元、数据、外部参与者、消费者、环境与不适用范围。
- **复核入口**：追踪代表性调用或数据流，核对边界两侧的责任、失败结果与真实消费者，并说明环境证据限制。
- **变更规则**：责任、参与者、输入输出、边界保证、消费者或适用条件改变时 `UPDATE`；等价重命名时 `NO_CHANGE`。
- **排除项**：不记录组织分工、服务清单、目录树、目标架构、临时连接、推断边界、安全控制正文或一次调用结果。

### 模块依赖与稳定契约

- **入册条件**：当前模块间责任、允许或禁止依赖方向、抽象归属或稳定契约会约束多个后续实现选择。
- **主题合并键**：以“责任单元 + 依赖方向 + 契约族”合并；同一约束的模块责任与依赖保证归入同题。
- **当前事实写法**：写明各单元责任、允许与禁止方向、契约 Owner、公开保证、消费者、例外及不承担事项。
- **权威依据**：定位模块出口、组合根、构建依赖、架构规则、契约实现与边界测试，不复制源码或依赖清单。
- **影响边界**：列出依赖者、被依赖单元、构建单元、运行消费者、共享类型、测试与不适用关系。
- **复核入口**：运行依赖或架构检查并追踪公开入口，验证禁止旁路、契约归属和循环边界，注明动态依赖限制。
- **变更规则**：职责、方向、契约归属、消费者、例外或边界保证改变时 `UPDATE`；内部替换而语义不变时 `NO_CHANGE`。
- **排除项**：不记录 import、类、包、库或文件清单，不存理想分层、无消费者抽象、临时适配代码或重构过程。

### 数据权威与一致性

- **入册条件**：当前关键数据具有稳定权威责任、跨边界读写或复制关系及一致性保证，多个消费者必须据此判断。
- **主题合并键**：以“数据族 + 权威责任边界 + 一致性保证”合并；权威源、派生表示与共同消费者归入同题。
- **当前事实写法**：写明权威 Owner、允许写入者、读取与派生关系、一致性条件、冲突结果、恢复责任和不保证边界。
- **权威依据**：定位数据访问边界、服务契约、事务或复制实现、失效路径与一致性测试，不复制物理 Schema。
- **影响边界**：列出写入者、读取者、派生数据、缓存、消息、外部系统、恢复消费者、环境与不适用路径。
- **复核入口**：追踪创建、变更、读取、复制、冲突与恢复路径，验证旁路写入和陈旧边界，并注明真实基础设施限制。
- **变更规则**：权威责任、读写关系、一致性、冲突、恢复、消费者或适用条件改变时 `UPDATE`；物理命名改变时 `NO_CHANGE`。
- **排除项**：不记录表列、索引、查询、缓存键或数据样本，不复制数据库 Owner 正文，不写目标数据平台或运行状态。

### 跨边界交互

- **入册条件**：当前两个责任边界之间存在稳定且有真实消费者的交互语义、时序、交付或失败责任。
- **主题合并键**：以“发起边界 + 接收边界 + 业务交互族”合并；共同语义的同步、异步或批量关系归入同题。
- **当前事实写法**：写明交互目的、双方责任、关键语义、时序、交付、失败结果、兼容保证、消费者与不保证事项。
- **权威依据**：定位契约、调用或生产消费实现、适配器、协议配置与契约测试，不抄录完整字段或载荷。
- **影响边界**：列出双方系统、服务、消费者、数据、身份、网络、环境、故障耦合与外部责任边界。
- **复核入口**：以协议或集成检查覆盖成功、拒绝、超时、重复、乱序与失败去向中的适用部分，并标明替身限制。
- **变更规则**：责任、交互语义、时序、交付、失败、兼容保证、消费者或条件改变时 `UPDATE`；客户端替换时 `NO_CHANGE`。
- **排除项**：不记录端点、消息或字段清单，不保存秘密、原始载荷、外部文档全文、候选契约、商务条款或一次故障。

### 运行拓扑、故障与恢复

- **入册条件**：当前运行单元、状态位置、故障传播、隔离、降级或恢复保证稳定成立，并影响系统级判断。
- **主题合并键**：以“关键运行路径 + 故障域 + 恢复保证”合并；共同故障与恢复命运的运行单元归入同题。
- **当前事实写法**：写明运行关系、状态位置、故障边界、传播结果、隔离与降级条件、恢复保证、消费者及明确限制。
- **权威依据**：定位部署与启动配置、服务发现、网络关系、状态服务、恢复实现及故障验证，不复制拓扑或参数清单。
- **影响边界**：列出关键路径、运行单元、共享资源、数据、区域、平台、外部依赖、消费者与适用环境。
- **复核入口**：核对实际运行资源并重复适用的健康、故障与恢复检查，说明未演练故障及生产环境边界。
- **变更规则**：运行关系、状态位置、故障域、传播、降级、恢复、消费者或环境条件改变时 `UPDATE`；实例波动时 `NO_CHANGE`。
- **排除项**：不记录实例、地址、资源参数、监控图、事故过程、平台操作步骤、目标拓扑、未经验证的高可用结论或运行快照。

### 质量权衡、演进与守卫

- **入册条件**：当前结构对质量属性作出稳定取舍，或对现存消费者承担兼容不变量、不可逆限制与可验证守卫。
- **主题合并键**：以“结构决策 + 质量或兼容保证 + 消费者集合”合并；同一取舍的收益、代价与守卫归入同题。
- **当前事实写法**：写明当前结构响应、优先属性、接受损失、适用条件、现存消费者、兼容保证、不可逆限制、守卫与退出触发。
- **权威依据**：定位当前结构实现、兼容路径、消费者调用点、架构规则与可重复质量验证；决定记录只辅助复核。
- **影响边界**：列出关键场景、模块、运行单元、数据、现存消费者、资源成本、受保护关系与不适用环境。
- **复核入口**：验证当前质量保证、所有现存消费者、守卫规则与退出触发，说明负载、拓扑、外部消费者及环境限制。
- **变更规则**：取舍、保证、消费者、不可逆限制、守卫或退出触发改变时 `UPDATE`；退出已证实且义务消失时 `DELETE`。
- **排除项**：不记录目标架构、迁移阶段、推进进度、时间表、兼容期限、流量数据、历史方案、计划数字、单次基准或未来假设。

## 全册安全与删除规则

- 不记录秘密、密钥、凭据、密码、令牌、个人或生产数据、原始载荷、内部地址、完整拓扑及可直接利用的边界细节。
- 权威依据只写仓库相对路径和精确 Symbol、配置、契约或测试位置；不复制源码、配置全文、运行观测或原始证据。
- 删除前沿当前权威确认结构语义、保证、最后消费者与退出触发均已消失；不因改名、一次失败或暂时不可达而误删。
- 删除最后主题时移除事实文件；仅在产品目录无其他 Owner 事实册时移除空目录，不留空册或占位主题。
- 本册只裁定本 Owner 的 `ADD`、`UPDATE`、`DELETE`、`NO_CHANGE`；跨 Owner 的提示式汇总与终态结果结构由公共终态记忆协议定义。

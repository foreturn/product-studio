# 软件架构项目记忆

## 核心记忆

### 架构驱动、质量场景与硬约束

- 记住当前架构由哪些业务场景、真实消费者、法规与驻留要求、外部契约、团队能力和交付条件驱动，哪些属于不可协商硬约束，哪些只是可调整目标或仍待验证的假设。
- 记住性能、可靠性、安全、可演进性和成本等关键质量场景的触发条件、代表负载、适用环境、可观察结果、阈值与失败后果，以及冲突属性之间已经确定的优先顺序和牺牲。
- 记住仍然成立的结构决定所保护的性质、被淘汰方案不满足的当前条件、验证这些决定的证据入口，以及哪些业务、负载、法规、拓扑或消费者变化会使决定必须重审。

### 系统职责、业务边界与公共面

- 记住各系统、服务、子域和核心模块实际承担与明确不承担的业务职责，边界所保护的语言、不变量、变化节奏和故障范围，以及对这些职责拥有最终解释权的主体；存在依赖上下文的语义判断时，还要记住语义解释、确定性规则、证据核验、歧义处理与降级各自的责任边界。
- 记住每个边界公开的稳定概念、能力、事件和最小公共面，内部模型、存储形态与实现细节不得被哪些消费者直接依赖，以及共享能力和跨产品事实的唯一归属。
- 记住哪些边界能够独立发布、扩缩容、隔离与演进，哪些名义边界仍因同步发布、共享写入或共同故障而紧密耦合，以及合并、拆分或新增边界必须满足的现实条件。

### 模块内聚、依赖方向与结构守卫

- 记住模块、目录与文件按何种业务能力、职责和变化原因聚合，类型、类、组件、方法、函数、常量与配置遵循何种命名和归类约定，页面、协议、存储、供应商与平台机制分别经何种适配边界接入。
- 记住真实消费者依赖的公共类型、扩展点、替换边界和兼容承诺，项目现有实现、平台能力与成熟开源组件的复用顺序，哪些抽象隔离了真实变化，以及哪些自研或实现细节不得升级为跨模块契约。
- 记住用于发现循环依赖、反向依赖、越界访问和未声明共享的构建规则、静态检查或仓库约束，其覆盖范围、有效例外与尚不能机械保护的边界。

### 数据权威、信息流与生命周期

- 记住每类关键业务事实的唯一写入权威、稳定身份和责任边界，历史快照、派生视图、搜索索引、分析结果与缓存副本分别由谁生成、消费和重建。
- 记住数据跨边界传播的触发方式、顺序与允许陈旧度，缺口和冲突如何发现与裁决，写后可见、删除、匿名化、保留和重建怎样沿完整派生链收敛。
- 记住数据位置由哪些事务关系、访问模式、敏感等级、地域驻留、生命周期和恢复目标决定，以及哪些跨边界读取可以接受副本、哪些操作必须回到权威来源。

### 交互契约、时间耦合与一致性流程

- 记住关键跨边界调用为何采用同步、异步、事件或批处理，端到端等待与重试预算、必要与可选结果、部分失败语义和参与方可用性假设分别是什么。
- 记住各契约稳定的业务含义、版本窗口、身份与租户上下文传播、失败分类和消费者责任，以及“已受理”“已发送”“已发生”和“已完成”不可混同的边界。
- 记住跨边界流程的持久状态、完成条件、重复与乱序语义、补偿和人工处置责任，以及读取陈旧、冲突发现、写后可见和结果不确定时对用户与调用方的保证。

### 部署单元、运行拓扑与容量模型

- 记住各部署单元的入口、实例关系、网络路径、状态位置、共享依赖与真实故障域，以及代码模块同进程、服务、任务或第三方运行单元之间的映射。
- 记住新旧版本、配置和数据形态在发布窗口中的允许组合，进程存活、流量就绪与关键业务可用分别由何种信号判断，以及实例替换和扩缩容必须保持的状态假设。
- 记住容量模型使用的请求量、并发、数据增长、积压、访问比例与依赖放大关系，所有无界集合、队列、并发和重试的限制，以及计算、存储、锁、配额和串行依赖各自的瓶颈与扩展方式。

### 故障隔离、降级与恢复能力

- 记住主要失效模式从何处产生、会沿哪些同步调用、异步流程、共享资源和数据副本传播，以及租户、工作类型和依赖之间采用的隔离、限流与总重试预算。
- 记住每种降级允许省略或延迟的能力、必须继续保持的数据与安全不变量、对外可见语义和停止条件，哪些旧值、部分结果或人工路径可以使用，哪些绝不能伪装为成功。
- 记住恢复时状态重建、依赖启动、流量接回和未完成工作处理的顺序，自动恢复与人工接管的分界、无法自动逆转的影响，以及恢复目标由哪些演练或运行证据证明。

### 信任边界、安全结构与可运维性

- 记住客户端、服务、管理面、租户、存储和第三方之间的信任跨越，主体、数据、身份和租户上下文在每道边界由何处重新校验，以及普通业务路径不可绕过的控制点。
- 记住高权限能力、敏感数据和管理操作从采集、传输、处理、缓存、日志、导出到删除的结构边界，最小权限、隔离与追溯由哪些组件共同维持。
- 记住请求、消息、任务和外部交互之间的诊断关联，业务结果、失败位置、积压、恢复和重建所依赖的稳定信号，以及重放、修复、切换与补偿入口的权限、审计和已知观测盲区。

### 兼容演进、过渡状态与架构验证

- 记住契约、事件、数据和组件演进必须支持的旧消费者、新旧组合与兼容期限，迁移期间当前权威、差异发现、双路径作用域、完成判据和旧路径退出条件。
- 记住功能开关、适配层、回滚与前滚修复分别能覆盖的对象和不可逆边界，以及临时结构何时必须清理、何种新数据或外部副作用会使旧版本无法安全恢复。
- 记住架构假设分别由依赖检查、契约测试、故障演练、容量测量、恢复验证或运行证据中的哪一层支撑，以及图示、原型、模拟和局部验证不能外推证明的范围。

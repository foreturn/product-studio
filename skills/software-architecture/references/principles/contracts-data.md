# 软件架构 · 契约、数据与一致性

### 语义解释与确定性规则边界

- 每项业务判断都必须先确认其含义能否由当前权威以封闭词汇、完备映射和稳定结果定义；无法满足这些条件的判断属于依赖上下文的语义解释，不能伪装成确定性规则。
- 语义解释与确定性执行必须拥有明确且彼此独立的责任边界；前者裁定上下文相关含义，后者实施结构校验、权限、资源、证据和副作用约束，任何一方都不能静默接管另一方职责。
- 两个边界之间必须以结构化契约传递已确认含义、适用范围、歧义、证据要求和下一步，不得通过解析叙述文本、字段偶然存在或重新扫描原始输入取得隐含控制权。
- 业务关键词、句式正则、删词表和少量示例不能承担依赖上下文的语义解释，也不能据此强制数据路径；协议格式、标识符、封闭词表或正式规则定义的判断才可使用固定解析。
- 证据缺口、解释冲突、失败和未覆盖状态必须形成可观察反馈，并回到既定语义责任边界重新解释、补证或请求澄清；固定处理链和无界循环都不能替代明确的充分性与停止条件。
- 语义责任不可用或始终无法得到充分依据时，必须进入明确的保守降级、受控不可用或补充信息状态；验证应覆盖等价表达、相邻含义、歧义和边界失败，一个固定示例不能证明该边界成立。

### 数据权威与信息流

- 每类业务事实必须存在唯一权威来源和明确写入位置，多个边界不得各自更新同一事实并期望事后自然一致。
- 跨边界传递的数据必须区分当前权威、历史快照、派生视图和缓存副本，消费者不能把副本误用为原始事实。
- 数据复制必须明确允许陈旧程度、传播触发、缺口发现、重建方式和删除传播，不能只说明“最终会一致”。
- 共享读取需求应通过稳定契约或派生视图满足，不能以查询方便为由开放跨边界写入或直接依赖内部存储结构。
- 数据位置必须同时考虑事务关系、访问模式、敏感等级、驻留要求、生命周期和恢复目标，单一技术便利不能决定归属。
- 数据删除、匿名化和保留约束必须沿派生链传播，主来源发生改变后，搜索、缓存、分析与备份中的副本不能被忽略。

### 交互契约与时间耦合

- 交互方式应由结果是否必须即时取得、参与方可用性和端到端时间约束决定，不能把同步或异步当作默认先进方案。
- 跨界契约必须表达稳定业务语义、失败分类和版本边界，不能暴露内部异常、存储模型或供应商协议。
- 调用链中的等待、重试和并发会共同消耗整体预算，局部策略不得让上游失去控制或把故障流量逐层放大。
- 聚合多个依赖时必须区分必要结果与可选结果，并定义部分失败的对外语义，不能以无限等待换取表面完整。
- 异步事实与执行请求必须保持不同语义，发布方不能把“已受理”“已发送”和“已完成”混为同一结果。
- 任何跨界交互都应允许参与方独立演进到约定范围，必须同时发布才能工作的契约不具备真实解耦。

### 一致性语义与跨界流程

- 一致性强度必须来自业务不变量和用户可见承诺，不能因技术偏好一律追求强一致或一律接受最终一致。
- 必须共同成功或失败的改变应限制在可控原子范围内，不受控外部交互不能被伪装成本地原子提交的一部分。
- 跨边界流程必须具有可查询的当前状态、明确完成条件和失败归宿，不能把业务进度藏在短暂调用链或进程内状态中。
- 重复、乱序、延迟、部分完成和补偿必须有确定语义，不能依赖理想投递顺序或一次执行假设维持正确性。
- 补偿代表新的业务事实，只能逆转业务上可逆的效果，不能把已经外部可见的结果描述为从未发生。
- 读取一致性必须与用户期望相符；允许陈旧、写后可见、冲突发现和刷新行为不能留给各消费者自行猜测。

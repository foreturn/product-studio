# 软件架构

以当前代码、配置、契约和运行证据为起点，裁定最小且可验证的系统边界。架构产出必须令下游实现者无需猜测责任、交互、故障行为或演进条件。

## 唯一决策权

本技能是以下事项的唯一 Owner：

- 模块、服务、进程、部署单元与外部系统之间的职责边界。
- 核心数据的主权边界、唯一写入权威和跨边界共享不变量。
- 跨边界操作、查询、事件、任务的语义与兼容责任。
- 系统级性能、可靠性、可维护性、成本等质量属性之间的权衡。
- 跨资源故障模型、部分成功状态、降级、补偿与恢复责任。
- 信任边界拓扑、身份上下文传播责任和安全控制的系统落点。
- 系统级可观测性、可运行性以及受控运维入口。
- 跨边界演进顺序、兼容窗口和可独立交付的技术切片。

不得把唯一决策权扩大到具体 API 字段、表结构、索引、锁、组件或安全算法。

## 输入门禁

开始前确认：

- Git 仓库根、当前产品与稳定 `product-id`、仓库指令和本轮授权范围。
- 用户结果、业务规则、验收标准、不得破坏的现有行为及真实消费者。
- 相关代码路径、调用链、Schema、配置、部署单元、外部依赖和运行信号。
- 已核验事实、推断、未知项及其取证入口。

若目标用户、产品范围或业务规则未定，停止依赖这些语义的架构裁决，列明缺口、影响和所需产品输入；若任务流、交互状态或可用性未定，同样只陈述所需体验契约，不替其他专业补造结论。

## 专业能力

先查看 [软件架构能力准则](references/principles.md) 的能力索引，只完整读取本轮命中的段落。每项命中能力都必须给出判断、产出与证据，不机械展开未受影响领域。

## 工作流程

1. 从用户可见结果追踪参与者、入口、模块、进程、数据、外部依赖、部署单元和副作用。
2. 判断缺口是否真正跨越边界；仅属单模块实现时标记为非架构问题，不扩大本技能的裁决范围。
3. 标出数据主权、合法写入入口、共享不变量、消费者、权限上下文和失败责任。
4. 比较沿用现状、局部修补与必要结构调整，量化收益、代价、可逆性和重审触发。
5. 裁定采用方案、失败收敛、运行信号、兼容窗口与清理条件。
6. 拆成可独立实现和验证的纵向切片，逐项指定 Owner、输入契约、证据与停止条件。
7. 实现证据改变边界、主权、不变量或质量权衡时，只重审受影响决定，不重写整套架构。

## 交付物

- 系统上下文与受影响边界，注明事实、推断和未知。
- 每个边界的职责、非职责、数据主权和合法写入路径。
- 跨边界交互的正常、拒绝、超时、重复、乱序、兼容及恢复语义。
- 质量属性场景、候选方案比较、采用理由、代价和重审条件。
- 故障矩阵、运行信号、受控恢复入口及完成判据。
- 演进顺序、兼容组合、暂停点、回滚边界、清理条件和交付切片。

## 专业边界

- `$backend-engineering`：落实业务规则、应用服务、API/事件字段和服务端代码；不得改写架构边界。
- `$frontend-engineering`：落实组件、客户端状态和浏览器交互；不得创造第二套服务端权威状态。
- `$database-engineering`：裁定物理 Schema、约束、索引、执行计划、隔离与锁、数据库迁移和恢复机制。
- `$security-engineering`：裁定资产分类、威胁模型、身份会话、授权策略、加密秘密、隐私和漏洞处置。
- `$quality-engineering`：设计并执行风险相称的验证，最终判定实现证据是否满足架构约束。
- `$release-engineering`：编排和执行已批准的发布、生产迁移、切流、回滚与稳定观察。

架构拥有跨系统演进顺序；数据库拥有数据库内部迁移机制；后端拥有应用兼容代码；发布拥有生产执行；质量拥有最终证明。不得出现第二 Owner。

## 终态事实候选

请求范围已形成可交付终态并取得风险相称的当前验证时，依据 [架构事实规则](references/memory.md) 检查本次实际核验范围，对命中主题给出 `ADD`、`UPDATE`、`DELETE` 或 `NO_CHANGE` 语义裁决。只有事实确有新增、改变或消失才形成写入候选；`NO_CHANGE` 不触碰文件。

候选须包含唯一 `product-id`、稳定 locator、主题合并键、四态动作、四栏正文或删除依据及当前证据。本技能不自行写入 `architecture.md`；纯方案、进行中实现、失败或阻塞验证、未验证推断和迁移过程只报告 `DEFERRED`，不得入册。

## 禁区

- 不以未来可能扩展为由拆服务、引队列、建框架或预留通用扩展点。
- 不替 `$database-engineering` 决定物理表、列类型、约束、索引、执行计划、隔离级别或锁策略。
- 不替 `$security-engineering` 决定授权规则、密码算法、密钥生命周期、隐私处置或漏洞风险接受。
- 不替工程技能编写具体实现，不替 `$quality-engineering` 宣告通过，不替 `$release-engineering` 操作环境。
- 不把外部模式、供应商宣称、架构图或 ADR 当作当前产品已实现事实。

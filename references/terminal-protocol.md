# 终态记忆协议

本协议是由命中 Skill 在最终答复前主动执行的提示契约，不依赖客户端事件、机器回执或额外运行组件。每项 Skill 的 `references/memory.md` 是对应 Owner 的入册规则；当前事实只写入目标仓库 `docs/product-studio/<product-id>/<owner>.md`。

## 执行步骤

1. 在最终答复前执行本协议。交付物尚未形成可验证终态时保持事实册不变，并报告 `BLOCKED`。
2. 对本轮实际影响的每个 Owner，唯一确认 Git 根、产品、`product-id` 与 Owner。读取该 Skill `references/memory.md` 的所有权、事实类型索引、通用入册门禁、动作语义和全册安全规则，再只展开命中的事实类型与事实册既有主题。
3. 沿当前源码、Schema、配置、契约、制品或获准查询的环境重新复核命中主题。事实册只作语义导航，不得自证，也不得以本轮差异、计划、运行快照或单次验证代替权威证据。
4. 对每个主题只执行一种动作：新候选通过全部门禁且首次成立用 `ADD`；既有主题的新语义通过全部门禁，且当前语义、权威依据、影响边界或复核入口实质变化时用 `UPDATE`；当前权威证明既有主题或最后消费者消失时用 `DELETE`；完整复核后没有实质变化用 `NO_CHANGE`，并保持事实册字节不变。
5. 只有仓库写入已获授权时才执行 `ADD`、`UPDATE` 或 `DELETE`。归属、证据、当前性或写权限不足时不改事实册，报告 `DEFERRED` 及具体缺口；只读工作不得借终态记忆扩大写权限。
6. 写后重读事实册并检查最终差异，确认路径与 Owner 正确、同义主题已原位合并、跨 Owner 无重复、事实仍是当前终态且不含秘密、个人或生产数据、过程、计划、历史、原始差异或一次日志。终态实现或验证后来又改变时，重新执行本协议。
7. 最终答复逐 Owner 报告结果、检查主题、事实动作、权威依据和必要的证据边界。该报告是人类可读结果，不创建独立状态文件。

## 结果语义

每个 Owner 只报告一个结果，按 `BLOCKED` > `DEFERRED` > `SYNCED` > `NO_CHANGE` 裁定：

- `BLOCKED`：交付物尚未形成可验证终态，不进行事实同步。
- `DEFERRED`：交付已形成终态，但至少一个应检查主题因归属、证据、当前性或写权限不足而未安全收束；未通过项不写入，已安全完成的事实动作仍逐项报告。
- `SYNCED`：全部应检查主题已安全收束，至少执行一个 `ADD`、`UPDATE` 或 `DELETE`，并已复核事实册终态。
- `NO_CHANGE`：全部应检查主题已安全收束且没有事实变化，事实册保持字节不变。

每个 Skill 只维护自身 Owner。发现其他专业确受影响时，由编码代理依据当前请求与证据选择对应 Skill，再由该 Skill 独立复核和写入；不得替代其他 Owner 裁决，也不得规定固定技能链。

## 能力边界

提示契约依赖编码代理实际遵循 Skill，无法机械观察工具事件、阻断遗漏或证明所有受影响 Owner 均已选全。项目静态校验只能证明十一项 Skill 都包含完整终态记忆指令；真实任务中的专业选择、语义正确性、写入行为与跨会话读取仍须通过新上下文行为验收。

# 项目代码事实记忆契约

本契约约束 `design`、`backend`、`frontend`、`verification` 四册项目记忆。记忆服务于下一次编码，不是任务日志；源码、生成 Schema 与真实运行结果始终是权威来源。

## 收录门槛

一张事实卡必须同时满足：

- 已在当前代码中成立，并有与风险相称的验证入口。
- 预计后续编码仍会使用，且有唯一 Owner 与权威代码定位。
- 至少具备一项价值：跨多个消费者、无法从单一文件立即看出、重新查明成本高、误判后风险大。

一个键概括一个会被整体检索和共同失效的稳定语义单元。不得按任务、提交、文件、路由、字段、样式值、Symbol 或测试用例机械建卡；可从源码生成的完整 API、Schema、路由、令牌和测试清单不抄入记忆。

## Schema 4

每册 frontmatter 固定为：`schema: 4`、对应 `memory` Owner、`scope: current-project-code`、`project_root: "."` 与带时区 `updated_at`。`.` 固定指事实册所在仓库根，不接受绝对路径或父目录，避免记忆被误用于其他项目。每个三级标题是全项目唯一语义键，格式为 `owner:type:slug`；`slug` 只用小写字母、数字和短横线，表达稳定业务含义，不使用路径、method、日期、任务号或临时方案名。

每张卡按顺序且仅含下列五个单行列表项：

- **事实摘要**：一句话概括代码已经执行的行为、契约、边界或不变量，以及未来修改不得破坏的关键约束。
- **代码定位**：一至三个反引号包裹的 `仓库相对路径#精确位置`；精确位置可为 Route、Symbol、Schema、配置键、标题或测试名。
- **依赖与影响**：直接调用方、消费者、数据所有者及相关事实键；无则写“无”。
- **验证入口**：可重复使用的测试、脚本、命令或旅程、关键断言与稳定未覆盖边界；不写本轮通过时间、制品或命令流水。
- **失效条件**：哪些契约、所有权、源码、依赖或环境能力变化后必须重读代码并同步本卡。

## Owner 与事实类型

- `design`：`journey`、`rule`、`boundary`、`contract`、`invariant`、`migration`。只记已实现的用户旅程与规则，以及跨模块边界、数据所有权、共享契约、不变量和当前迁移阶段。
- `backend`：`domain`、`api`、`data`、`auth`、`event`、`integration`、`runtime`。只记非显然的领域行为、接口语义、数据与并发约束、授权、事件、外部集成和非秘密运行行为。
- `frontend`：`surface`、`component`、`state`、`layout`、`responsive`、`a11y`、`system`。只记核心界面任务、共享组件、状态恢复、布局、响应式、可访问性和设计系统约束。
- `verification`：`check`、`coverage`、`constraint`。只记稳定检查入口、风险覆盖边界和必须持续守住的验证约束。
- `router` 不拥有事实册；跨册共享事实由语义 Owner 保存一次，其他 Owner 用“依赖与影响”链接，不复制正文。

## 终态同步

每次编码任务进入“完成”，或“部分完成”中已有可独立使用且验证成立的切片时，受影响 Owner 必须在回复前执行一次同步检查：

1. 读取最终差异与现有相关卡，列出 `+` 新增、`~` 更新、`-` 删除的键。
2. 语义未变时原位更新；只搬代码时只改“代码定位”；事实或最后消费者消失时删除卡。
3. 只有五字段之一确有变化时才写文件并更新 `updated_at`；未受影响卡和其他 Owner 文件保持不变。
4. 文件不存在表示暂无事实；首次有事实时由对应模板创建。最后一张卡删除后移除整册，不保留空文件。
5. 无总结事实变化时报告 `memory: 0 keys changed`，不得为留痕制造时间戳差异。
6. 写后检查差分、语义键、跨卡链接、代码定位和模板残留，再运行项目校验。

失败、阻塞、纯设计、纯审阅、尚未落地的要求和未验证切片不写成当前代码事实。记忆同步失败须单独报告，但不得倒改已经成立的实现或验证结论。

静态校验只能证明 schema、定位和链接在当前快照中自洽，不能判断“锚点仍存在但语义已经陈旧”；语义新鲜度必须由执行者对照最终差异完成同步检查，不得把静态绿灯冒充该项证据。

## 禁止内容

- 任务摘要、修改文件列表、进度、待办、责任人、候选方案、过程推理和 `superseded` 历史。
- 单次命令输出、某轮绿色结果、临时失败、截图时间、commit SHA 和只对一个制品成立的结论。
- 尚未实现的目标、假设、建议、未来规划，以及未被当前代码采用的外部资料或其他项目事实。
- 密钥、令牌、用户数据、环境秘密，以及其他 Owner 已保存的同一事实正文。

历史由 Git 承担；本轮执行证据留在终态报告，长期设计缘由留在项目既有 ADR 或正式文档。

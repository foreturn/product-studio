# 项目记忆契约

## 定义与位置

`skills/`、各 Skill 的 `references/` 与 `templates/` 保存可跨项目复用的专业能力，不属于任何目标项目的记忆。各角色在获准执行写入任务时，将当前项目的事实、决策、状态与证据写入：

```text
<当前项目根>/docs/product-studio/
```

- 当前项目根是本次任务所针对的仓库根；没有版本库时，以用户指定的项目目录为准。
- `product-studio` 是固定的记忆目录名，不是产品标识；产品名称只作为文档元数据保存，不参与路径寻址。
- 插件中的模板是可复用来源；获准生成的项目记忆归属于当前项目根。插件安装目录与缓存目录承载插件副本，不是项目事实的持久化位置。

## 命名与寻址

- 七个 Skill 使用单个小写英文单词：`delivery`、`discovery`、`architecture`、`frontend`、`backend`、`verification`、`release`。
- 名称遵循严格恒等式：`skills/<skill>/SKILL.md`、`templates/<skill>.md`、`docs/product-studio/<skill>.md` 的 `<skill>` 必须完全一致。
- 角色由 Skill 名直接定位同名记忆；不存在时从同名模板创建。活跃寻址使用这一条同名路径，旧名称与旧文件只作为迁移历史保留。
- 中文角色名只用于说明职责，不参与文件寻址。

## 作用域与隔离

- 项目记忆在同一项目内提供跨会话连续性；当前项目根是事实归属与持久化隔离键，不同仓库中的同名 `docs/product-studio/` 分别描述各自项目。
- 同一仓库中的角色共享一套项目记忆；产品或功能名称写入文档正文，不再为其增加路径层级。
- 跨仓库或跨产品任务在各自项目根内分别维护 `docs/product-studio/`，项目之间通过带来源与适用范围的显式引用完成交接。

## 信息来源与适用性

- 当前用户指令、当前仓库、当前运行状态与本项目记忆共同构成当前项目事实基线；记忆中的旧结论仍需按修订与失效条件复核。
- 用户显式提供的链接、页面、截图、设计稿、文档或其他项目材料都是可用的外部参考。角色可按任务读取、分析、比较或仿照，并记录精确来源、提取特征、用途、时间与置信度。
- 外部参考可形成灵感、候选方案、风险提示或待验证假设；它不会自动成为当前项目事实。某项内容在得到当前用户确认、当前仓库实现、权威 Schema、运行证据或本项目验证支持后，才记录为当前决定或结论。
- 来源发生冲突时，当前用户指令与当前项目的权威事实决定现状；外部材料保留其参考身份与差异说明，而非被丢弃或静默覆盖。
- 信息读取与持久化写入是两条独立边界：参考材料可以进入分析上下文，并不因此获得项目记忆写入权限；只读任务可完成读取、分析与报告，项目记忆保持原状。

## 读取与更新

- 新会话或角色接手时，先读取当前项目记忆目录中与本角色输入有关的文件，再以当前状态开展工作。
- 当前用户指令与当前仓库事实优先于旧记忆。发生冲突时，保留可追溯依据，并将旧内容标记为陈旧、已取代或待复核。
- 只读任务不授权创建或更新项目记忆。只有用户请求本身允许写入，且写入属于该任务的最小必要产物时，角色才可更新其负责的文件或章节。
- 写入前检查现有内容与未提交改动，只做当前任务所需的最小更新，不覆盖其他角色拥有的契约。
- 项目记忆保存安全的配置名称、引用位置与待授权事项；凭据、令牌、私钥、会话密钥及其他秘密不属于记忆正文。
- 历史验收结果与发布授权可以留作追溯，但不能替代当前代码、制品、环境与权限的再次核验。

## AI 记忆结构

- 每份记忆使用统一头部记录 `schema`、`memory`、`scope`、`status`、`updated_at`、`verified_at`、`verified_revision`、`confidence` 与 `supersedes`；`memory` 必须等于 Skill 名。
- 正文至少提供恢复摘要、带稳定 ID 与精确来源的依据账本、动作队列、当前验证、交接与失效条件，再加入本角色真正需要的专属章节。
- `done` 或 `passed` 只对记录的源码修订、制品和环境有效。修订不匹配、来源无法复现或失效条件命中时，先将相关结论视为 `stale` 并重新核验。
- 当前快照原地更新，旧结论只保留取代 ID；完整演进交给 Git，不在记忆中持续追加旧命令与长篇历史。
- 不适用角色只记录原因、依据、重新适用条件和下一动作，不生成空表与空章节；时间戳本身不是更新证据。

## 动态收口

- 每次获准的氛围编程完成前，以本轮代码差异、当前验证、新决定和未解决项触发一次记忆收口；只读任务不触发写入。
- 由 `delivery` 或当前主责角色识别参与角色与受影响契约。每个参与或受影响角色必须复核并动态更新自己拥有的记忆文件或章节，记录最新决定、证据、状态与最近核验时间。
- 未受影响角色保持正文不变；在已有 `delivery.md` 的跨角色任务中，将其记为“已复核、无变化”，时间戳不单独构成更新理由。
- 先收口发生变化的产品与架构契约，再收口前端、后端等实现契约，随后由验收角色写入当前证据；发布适用时更新发布记忆，最后由交付负责人汇总恢复点。
- 有效收口同时核对正文、当前差异与验证；仅更新时间戳不构成新证据。责任角色尚未更新或必需证据缺失时，氛围编程仍处于未收口状态。

## 角色与记忆文件

| 固定责任角色 | 项目记忆文件 | 记忆边界 |
|---|---|---|
| `delivery` | `delivery.md` | 编排阶段、角色链、切片、风险、变更、阻塞与下一步 |
| `discovery` | `discovery.md` | 原始意图、产品事实、推断、范围、假设与验收标准 |
| `architecture` | `architecture.md` | 当前项目适用的架构不变量、决策、权衡、迁移与重审条件 |
| `frontend` | `frontend.md` | 用户可见行为、交互状态、前端约束与验证方案 |
| `backend` | `backend.md` | 服务端接口、数据、权限、兼容、失败恢复与调用方交接 |
| `verification` | `verification.md` | 当前实现的逐项证据、失败、阻塞、既有问题与验收结论 |
| `release` | `release.md` | 当前制品与环境的授权、门禁、执行、观测、回滚与反馈 |

`delivery.md` 保存跨角色编排状态。产品范围、架构决定、接口细节、验收证据与发布步骤由对应专项契约承载，交付记忆通过稳定 ID 引用它们。

所有模板与项目记忆均由同名 Skill 完整拥有，不再划分同一文件内的跨角色写入章节。其他角色可读取并引用稳定 ID；发现偏差时退回拥有者修订。

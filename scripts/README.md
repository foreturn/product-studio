# 脚本

`validate_project.py` 检查必需文件、双端 manifest 共享字段、七个生命周期 Skill 及其专业契约。对每个 Skill，它按 Markdown 章节核验角色定位、专业能力来源、项目记忆、执行流程、输出、交接门禁与边界，并确认主文件不再重复详细能力。对应 `references/` 能力手册必须包含能力目录、核心能力、能力组合与完成判据；每项角色专属能力都必须以三级标题定义，并依次具备“启用、输入、执行、裁决、产出、验证、完成、边界”八个能力卡字段。旧式角色职责、专业决策顺序、交付证据与常见误判章节会被视为退化。

校验器还会确认七个 Skill 均为唯一单词，Skill 与同名模板严格对应，已存在的项目记忆也只能使用同名角色文件；项目记忆允许仅存在本项目已有事实的角色子集，不要求为了凑齐七职创建空文件。它同时确认 Codex `default_prompt` 会调用对应 Skill 并采用该角色身份；确认七职既可按需直调，也只在门禁通过且写入不冲突时并行；确认每个 Skill 的“项目记忆”都自包含本角色的事实准入、稳定 ID、终态增量、原样边界和模板版本规则；并确认 `delivery` 独立定义跨角色收口顺序、单一写入所有权与失败隔离。已删除的根级记忆或平台引用、旧式过程记忆生命周期、全量覆盖语义与“只读当前项目材料”来源白名单都会被视为退化。

七份 schema 2 模板必须是轻量首建母版，而非任务恢复单或预填事实册。每份模板只能包含五字段文件头、角色事实家族索引和一张通用事实卡骨架；索引须与对应 Skill 的 ID 家族完全一致，专业能力细节仍只保存在 `skills/<skill>/references/`，不得为每个家族预铺空卡。模板仅用于首次创建；实例化时按有依据的真实事实复制骨架，再删除说明、索引、示例和占位内容。既有 schema 1 或 schema 2 记忆新增或更新事实时，不再读取或套用模板，只依据对应 Skill 的本角色事实卡规则、ID 家族与文件中的既有事实卡增量维护。每张实际事实卡仍须有本角色稳定 ID，并依次写明事实类型、已成立事实、角色专属细节、适用范围、精确定位、成立证据、核验基线、关联事实、下游约束、状态、置信度、取代关系和失效条件。额外模板章节、多张空骨架、恢复摘要、动作队列、执行流水、交接清单与角色无变化收口表都会被判为结构退化。

既有 schema 1 项目记忆继续可读，不会因模板改版而被要求全量迁移；其文件头状态必须是 `done`、`failed`、`blocked` 或 `not_applicable` 之一。所有实例记忆的 `updated_at` 必须是带时区的 RFC 3339 时间。schema 2 实例记忆额外校验事实 ID 唯一且属于本角色已声明家族、十三个字段恰好各一次且顺序固定、`## 现行事实` 唯一，以及模板说明、家族索引、过程章节和占位已经清除；合法泛型或比较符号不会仅因含有尖括号而被误判为占位。schema 2 `verification.md` 还必须恰有一张状态为 `current`、以明确终态句写出通过、失败、阻塞或不适用的 `VER-CONCLUSION-*` 事实卡，“是否通过尚未确定”一类不确定文本不能冒充终态。校验器不把正文中真实业务对象的 `pending`、`in_progress` 或 `draft` 误判为记忆生命周期错误，也不硬编码项目记忆必须是“通过”；失败、阻塞或不适用只要是已完成审计所得的当前事实，同样可以合法保存。schema 1 `verification.md` 的当前结论只从唯一 `## 最终结论` 段中的唯一 `- 结论：` 行解析，历史证据中的“通过”不能覆盖当前失败结论。

静态校验只证明当前文件结构与提示词契约，不能单独证明跨状态写入行为。成功终态的事实级合并、中断零写入及无事实增量不改时间戳，仍须以 fresh 场景的前后文件树与内容差异作为行为证据。

在插件根目录运行：

```powershell
python scripts/validate_project.py
```

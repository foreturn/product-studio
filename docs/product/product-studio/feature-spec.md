# 功能规格

- 产品标识：`product-studio`
- 关联产品简报：`docs/product/product-studio/product-brief.md`
- 决策状态：按已记录假设继续
- 当前责任角色：`product-delivery`

## 目标

把用户的短提示词转化为证据化、边界清晰、可分工实现且可独立验收的软件增量，同时保持氛围编程所需的低交互成本。

## 用户流程

1. 接收并原样保留用户意图。
2. 检查仓库、当前行为、已有改动和适用指令。
3. 将请求归类为产品探索、端到端交付、架构、前端、后端或验收任务。
4. 对模糊请求执行需求扩写，形成事实、推断、约束、开放问题和验收标准。
5. 对高影响决策请求确认；其他事项自行查明或记录假设后推进。
6. 选择最小必要角色链路，为每一阶段声明输入、输出与门禁。
7. 实施过程中以持久化产物交接；发现契约变化时退回责任角色。
8. 按验收标准逐项收集证据，失败则回到相应阶段修正。
9. 发布适用时，在明确授权后执行发布门禁、迁移、上线验证和回滚准备。
10. 将运行偏差与用户反馈交回产品角色，汇报已交付行为、验证证据、发布处置、未完成项和剩余风险。

## 需求扩写卡

产品角色必须补全以下信息，并保留可追溯来源：

- 原始意图：用户原话或忠实摘要，不得被扩写内容覆盖。
- 仓库事实：从代码、配置、文档、运行行为或用户明确说明中查明的事实。
- 推断需求：为形成完整旅程而补充的合理推断，每项说明依据与可逆性。
- 目标用户与待完成任务：谁在何种场景下为何使用。
- 核心旅程：从触发到成功结果的最短完整路径。
- 范围边界：本次包含、不包含及不得破坏的既有能力。
- 状态与异常：加载、空白、成功、失败、恢复及权限不足等适用状态。
- 约束：技术栈、兼容性、安全、时间、外部系统与现有设计约定。
- 验收标准：可观察、可判定，并可在交付阶段逐项映射证据。

## 决策分级

### 必须确认

- 会显著改变目标用户、核心旅程、MVP 边界或既有业务能力。
- 会产生不可逆数据变更、外部消息、付费操作、生产发布或安全权限扩大。
- 存在两个以上代价相近但产品结果明显不同的方向，且仓库没有权威依据。
- 缺失的凭据、业务规则或外部协调使当前路径无法安全推进。

### 记录假设后继续

- 可逆、局部且符合仓库既有惯例的命名、布局、组件或实现细节。
- 用户已授权自主推进，且选择不会扩大产品或安全边界。
- 有明确默认值或现有相邻功能可作为一致性依据。

### 自行查明

- 可从仓库结构、调用链、测试、配置、日志、现有 UI 或项目指令中获得的信息。
- 可通过只读命令或局部复现确认的当前行为。
- 已由上游持久化契约明确记录的决策。

## 路由规则

- 模糊产品想法或完整功能：`product-delivery` → `product-discovery` → 按需 `system-design` → 按需前端/后端 → `delivery-verification` → 按需 `release-operations` → 反馈回流。
- 仅需求梳理且明确不实现：只使用 `product-discovery`，停在已确认或待确认的产品简报。
- 明确的局部前端或后端改动：对应专项 Skill 先检查上游信息是否足够；不足时补最小产品契约，不强制生成无关文档。
- 架构任务：`system-design` 只做决策与切片；未经实现授权不进入代码修改。
- 独立验收或代码审查：`delivery-verification` 从现有契约和差异开始，不倒推虚构需求。
- 发布、部署或生产就绪任务：`release-operations` 必须从验收结论和明确授权开始；仅要求方案时不得执行部署。

## 变更与退回规则

- 新证据改变用户、核心旅程、范围或验收标准：退回 `product-discovery`。
- 新证据暴露跨模块不变量、部署、安全或迁移风险：退回 `system-design`。
- 前后端契约不一致：由契约拥有者修订，另一方不得私自兼容成新的隐含规则。
- 实现与验收标准不符：退回对应实现角色；验收角色不降低标准以换取通过。
- 发布门禁或上线信号失败：发布角色停止扩散并按既定方案回滚；运行偏差改变产品目标时退回产品角色。
- 用户改变目标：更新上游契约并标记被取代的决策，再重排剩余任务。

## 状态与恢复行为

- 无仓库：基于用户意图形成最小产品简报，并把技术选择标记为待架构决策。
- 仓库信息不足：先完成所有安全的只读查验，只把真正阻塞项交给用户。
- 用户暂未回应高影响问题：保存待确认项，暂停受影响切片；不受影响的只读分析可以继续。
- 验证失败：记录首个可行动错误、影响范围和责任阶段，修正后重跑受影响与必要回归验证。
- 会话中断：从 `docs/product/<product-slug>/` 恢复事实、决策、状态和未完成项。

## 兼容与迁移

- 保持现有六个 Skill 名称，新增 `release-operations` 补齐发布与反馈阶段，避免破坏已有显式调用。
- 扩充 SKILL.md、模板和 UI 元数据，不引入平台专属工具名。
- Codex 继续读取 `agents/openai.yaml`；Claude Code 忽略该适配元数据并共享 SKILL.md。
- 不执行安装、Marketplace 更新或缓存版本改写。

## 验证方案

- 运行项目静态校验，检查角色集合、必需章节、模板引用、共享 manifest 字段和占位符。
- 逐个运行 Skill Creator 校验器检查七个 Skill。
- 运行 Codex 插件清单校验与 Claude Code 插件校验。
- 用短提示词、局部前端、局部后端、独立验收和发布恢复五条纸面场景核对路由、追问和交接规则。
- 检索旧表述，确认不存在鼓励静默推断、越权改范围或无证据宣告完成的规则。

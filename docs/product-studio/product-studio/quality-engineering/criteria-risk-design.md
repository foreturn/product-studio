# quality-engineering 当前产品事实 · 判据、风险与用例设计

## 插件结构契约校验

- **当前事实**：仓库的 `validate-project.mjs` 机械核对恰好十一项 Skill、三类文件各自的精确章节、principles 瘦索引的读取协议三要素、索引表与 `references/principles/` 簇卷一一对应、簇卷合计八至十六个专业大类且每类四至八条通用约束、`references/memory/` 簇卷与 `references/principles/` 簇卷一一对应且每卷一至十二条“记住……”普通列表；对每份 SKILL 还核对决策中的目标政策、事实、推断与假设分层，具体方案来源不自证，完整流程复核，失效决定局部重开、无关决定保护与专业所有权边界，以及当前产品根目录不依赖 Git、用户目录与目标工件证据、Git 仅作佐证、进程目录与 Skill 目录不得决定根、Product Studio 仅作技能提供者时排除其源码与安装缓存、安全单级 `product-id`、根锚定按簇 Owner 目录、命中簇读取、当前权威优先、既有事实准入、只读边界、产品根写权限、证据闭环即时落册与收口对账、按簇首条建文件、空文件禁令、`· <簇名>` 实例标题与主题写法、末条删文件与空目录级联清理和敏感信息排除，并拒绝旧有“目标 Git 根”措辞。README 同样受决策反思及产品根、非 Git、提供者排除与锚定读取断言约束；现有簇事实文件必须以 `<owner> 当前产品事实 · <簇名>` 为题且至少包含一个非空当前事实主题，事实文件名越出该 Owner 簇卷集合即拒绝，OpenAI 界面元数据、已移除运行资产与公共协议及双端清单拓扑亦受校验，任一不一致以非零退出。
- **权威依据**：`scripts/validate-project.mjs`；`README.md#三层文件契约`；`.codex-plugin/plugin.json`
- **影响边界**：该入口证明源树结构、提示契约和声明一致，不证明专业内容在真实任务中被正确触发、判断或执行，也不证明任一客户端已安装当前快照或代理一定完成事实写入与后续读取。
- **复核入口**：运行 `node scripts/validate-project.mjs` 并检查退出码；技能集合、统一格式、memory 簇卷、manifest、项目记忆提示、事实册生命周期或 locator 规则变化时先更新机械断言，再更新实现。

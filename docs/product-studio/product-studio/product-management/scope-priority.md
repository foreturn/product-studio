# product-management 当前产品事实 · 范围与优先级

## 十一项通用专业底座

- **当前事实**：Product Studio 的通用产品软件范围为十一项独立专业能力：产品管理、软件架构、后端、Web、Android、iOS、数据库、平台、安全、质量与发布工程；产品管理同时拥有产品意图和产品体验语义，不设置第二个体验裁决入口。
- **权威依据**：`README.md#十一项通用底座`；`.codex-plugin/plugin.json#keywords`；`skills/`；`.claude-plugin/plugin.json`。
- **影响边界**：技能发现、插件说明、专业 Owner 和项目事实目录以此集合为准；数据工程与 AI 系统等条件专业不在当前通用底座内。
- **复核入口**：对照技能目录、元数据、双端清单和 README 核对专业集合与职责归属；新增、合并、删除或改名任何通用专业时重审。

## 可证伪的产品决定与整体简便性

- **当前事实**：产品管理比较能够形成同一必要结果的现实路径，以用户步骤、业务状态与交接、失败恢复、规则重复、变更扩散和维护总成本确定最小完整范围。方案依据的角色、问题、政策、依赖或结果假设被新证据推翻时，只重开受影响裁决并同步调整范围与验收，不以新增特例、隐藏状态或下游补救维持失效结论。
- **权威依据**：`skills/product-management/SKILL.md#执行协议`；`skills/product-management/references/principles/scope-priority.md`；`skills/product-management/references/memory/scope-priority.md`。
- **影响边界**：用户保留目标、政策和价值取舍的最终裁决权；产品范围判断不代替工程机制选择。各专业共有的前提核验与局部纠偏方法见 `docs/product-studio/product-studio/software-architecture/drivers-evolution.md`。
- **复核入口**：用局部省事但增加完整流程状态、连续特例修复、前提变化及无关局部失败核对范围与验收是否正确收敛；产品决策权、完整流程或验收语义变化时重审。

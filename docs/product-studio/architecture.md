## 恢复摘要

- 当前架构问题：专业能力语义、增量生命周期与事实卡结构已由 ADR-008 至 ADR-011 闭合；本轮须移除根级项目记忆与平台兼容 reference 这一重复权威层，让跨角色路由、角色本地记忆规则与确定性校验各有唯一归属。
- 当前有效决定：继续保留 Skill → reference 两层单向引用与八字段能力卡；ADR-010 规定终态按角色稳定 ID 增量合并，ADR-011 规定 schema 2 首建模板仅提供完整事实家族索引与一张可复制的十三字段通用骨架，ADR-012 将跨角色路由唯一归于 `skills/delivery/SKILL.md`、各角色事实规则归于各自 `SKILL.md` 的“项目记忆”章节、结构与冲突门禁归于 `scripts/validate_project.py`。既有 schema 1 或 schema 2 依据本角色规则与自身事实卡增量维护，不得再次读取模板、自动迁移或重建。
- 首个可执行动作：无；ADR-008 至 ADR-012 与 INV-007 至 INV-011 已取得当前结构、语义、负向及 fresh 行为证据，后续仅在能力内容、事实卡规则、加载契约、权威路由或记忆生命周期变化时重验。
- 阻塞：无源码架构阻塞；实际安装与发布未获授权，但不构成本轮源码交付阻塞。

## 架构上下文

- 共享内核：七个 `skills/<name>/SKILL.md`、角色 references 与七份 `templates/<name>.md`。
- 平台适配：Codex 使用 `agents/openai.yaml`，Claude Code 共享 SKILL.md 与插件 manifest。
- 项目状态：目标项目在自身 `docs/product-studio/` 保存七份同名记忆；外部项目材料保持可追溯的参考身份，经当前项目核验后再形成适用决定。
- 当前能力基线：七份 reference 从 HEAD 的 1015 行扩展至 2255 行，保留全部 52 个 H3 与 416 个八字段；行数只作完整性旁证，专业质量由旧版独有判断迁移、语义审计和前向裁决共同证明。
- 当前记忆基线：`delivery` 跨角色路由、七份 Skill 本地记忆规则、七份模板和校验器共同采用终态事实增量模型；七份 schema 2 首建模板分别保留本角色完整事实家族索引和一张可复制的十三字段通用骨架，全插件合计 7 个骨架、91 个字段，不按家族预铺空卡。实例化只生成有证据的事实，角色专业细节仍唯一保存在对应 `skills/*/references/`；既有 schema 1 或 schema 2 记忆不再读取模板，只依据本角色事实卡规则、角色 ID 家族与自身事实卡增量维护，并保留原格式、仍有效事实与未受影响章节。

| 边界 | Owner | 输入 | 输出 | 来源与归属约束 | 受影响调用方 |

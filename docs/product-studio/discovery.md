# discovery

- 固定责任角色：`discovery`（产品经理）
- 项目根：当前 `product-studio` 仓库
- 记忆路径：`docs/product-studio/discovery.md`

## 恢复摘要

- 当前产品问题：`SKILL.md` 同时铺陈职责、核心能力与专业决策顺序，使约束和专业知识重复，AI 难以定位详细角色判断依据。
- 当前范围结论：Skill 负责触发、约束、流程、产物与交接；同角色 reference 负责详细职责能力，并由 Skill 直接引用和加载。
- 首个可执行动作：新增或修订专业能力时只改对应 reference，再验证 Skill 引用、角色能力锚点与前向行为。
- 阻塞：无产品决策阻塞。

## 原始意图

- 用户要求七个技能的名称收紧为一个符合该技能的单词。
- 用户要求每个技能的记忆与技能名称一致，以提升阅读性。
- 用户要求记忆模板更有利于 AI 在氛围编程中恢复、判断和继续执行。
- 用户指出“只读取”“不得从”限定过死，会造成 AI 上下文缺失，并以参考链接页面进行仿照为具体反例。
- 用户要求检查其他位置的同类问题并一并修正。
- 用户要求删除七份 `SKILL.md` 中的职责、核心能力、专业决策顺序，并根据原核心能力详细扩充各角色 reference，由 Skill 引用该职责能力。

## 用户问题与目标结果

- 主要用户：在 Codex 或 Claude Code 中按需调用产品研发角色的氛围编程用户与后续 AI 会话。
- 待完成任务：既能从当前项目记忆恢复事实，又能使用任务相关的外部页面、截图、设计稿、文档与其他项目材料。
- 可感知结果：AI 不会因项目隔离拒绝显式参考，也不会把仿照对象的品牌、字段或权限语义冒充当前项目事实。
- 成功信号：每项外部输入都有精确来源、用途、适用性和采纳状态；读取范围与记忆写入授权彼此独立。

## 范围与非目标

### 本轮包含

- 七个 Skill 目录、frontmatter、显式调用与 UI 默认提示词迁移。
- 七份同名模板和当前项目记忆迁移。
- 模板统一 AI 恢复骨架与角色专属高价值结构。
- 校验器、README、共享契约、CHANGELOG 与当前记忆同步。
- 七职 Skill 与模板的来源边界改为当前项目事实、外部参考、明确采纳三层语义。
- 七职 Skill/reference 职责分层，以及七份角色能力手册的详细扩充与退化门禁。

### 本轮不包含

- 不保留七个旧名的兼容 Skill 壳。
- 不安装插件、不刷新本地缓存、不执行发布或外部变更。
- 不把模板变成长期流水日志；完整历史由 Git 保存。

### 不得破坏

- 七职角色身份、专业能力、按需直调、安全并行、单一写入所有权、事实归属、读取与写入授权分离及秘密保护边界。
